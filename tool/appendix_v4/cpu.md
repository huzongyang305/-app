## 补充：流水线、冒险与性能公式

### 五级流水线：一条指令的一生

```text
理想情况（每拍完成一条）
时钟  1     2     3     4     5     6     7
IF    指令1  指令2  指令3  指令4  指令5  指令6  指令7
ID          指令1  指令2  指令3  指令4  指令5  指令6
EX                指令1  指令2  指令3  指令4  指令5
MEM                     指令1  指令2  指令3  指令4
WB                            指令1  指令2  指令3

五级流水下，理想吞吐是每拍一条；但真实程序会出现「冒险」
```

| 阶段 | 全称 | 做什么 |
| --- | --- | --- |
| IF | Instruction Fetch | 取指令 |
| ID | Instruction Decode | 译码、读寄存器 |
| EX | Execute | 运算 |
| MEM | Memory | 访存 |
| WB | Write Back | 写回寄存器 |

### 三类冒险与解决手段

| 冒险 | 例子 | 解决 |
| --- | --- | --- |
| 结构冒险 | 取指与访存抢同一个内存端口 | 分离指令与数据缓存（I-Cache / D-Cache） |
| 数据冒险 | 后一条指令要用前一条还没写回的结果 | 转发（forwarding）、插入气泡 |
| 控制冒险 | 分支指令结果未知，下一条该取谁 | 分支预测 + 预测失败时冲刷流水线 |

```text
数据冒险示例
  add r1, r2, r3      ; r1 = r2 + r3
  sub r4, r1, r5      ; 需要 r1，但 add 还没写回

  解决：转发——把 EX 阶段算出的结果直接送给下一条指令，不等 WB
  无法转发时（如 load 后立即使用）插入一个气泡，代价是一拍
```

### 分支预测为什么关键

```text
一次预测失败要冲刷流水线，代价约等于流水线深度（10~20 拍）

现代处理器的做法
  · 记录分支历史，用模式识别预测走向（准确率常 >95%）
  · 预测「向后跳转」通常代表循环继续 → 预测跳转
  · 同时预取两个方向并保存结果（预测执行）

对写代码的启示
  · 分支可预测（同一方向反复）时快，随机分支代价高
  · 数据依赖密集、分支不可预测的代码，优化空间有限
```

### 乱序执行与超标量

| 概念 | 含义 | 好处 |
| --- | --- | --- |
| 超标量 | 一个周期发射多条指令 | 提高并行度 |
| 乱序执行 | 不按程序顺序执行，只在结果上保持顺序 | 掩盖访存与运算延迟 |
| 寄存器重命名 | 消除假的数据依赖 | 让指令真正并行 |
| 推测执行 | 提前执行分支后的指令 | 分支命中时零等待 |

**对开发者的意义**：写出「数据依赖少、访存规律、分支可预测」的代码，比纠结单条指令更有效。

### 缓存一致性：多核为什么不打架

```text
MESI 四状态
  M（Modified）  本核改了，与内存不一致，其他核没有副本
  E（Exclusive） 只有本核有副本，且与内存一致
  S（Shared）    多个核都有副本，与内存一致
  I（Invalid）   本核副本已失效

典型动作
  核 1 读同一地址 → 从 I 变 S（共享）
  核 2 想写入     → 先让其他核的副本失效，再进入 M
```

```text
伪共享（false sharing）
  · 两个线程操作同一个缓存行里的不同变量
  · 缓存行通常 64 字节：变量挨在一起会互相使对方失效
  · 表现：单线程很快，多线程反而更慢
  · 对策：填充（padding）让热点变量各占一行
```

### 性能估算公式

```text
程序时间 = 指令数 × CPI × 时钟周期
           └── 算法与编译器决定   └── 微架构决定

CPI（每条指令平均时钟数）= 理想 CPI + 各类停顿

IPC = 1 / CPI（每拍完成多少条指令）

三个优化方向
  ① 减少指令数：更好的算法与编译器优化
  ② 降低 CPI：更好的访存局部性、更少不可预测分支
  ③ 提高频率：受制程与功耗墙限制，现代提升有限
```

```text
一个实用推论
  缓存命中率对性能的影响往往大于指令条数：
  一次主存访问 ≈ 几百个时钟周期，而多数指令只要 1 拍
```
