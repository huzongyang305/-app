## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 条件类型 | TypeScript 根据类型关系在编译期选择结果类型的类型运算。 | 裸类型参数是联合时会按成员逐个分发再合并结果；它的行为在大版本里调整过，升级前先复现当前推导输出。 |
| 映射类型 | TypeScript 根据已有类型批量生成属性变换后的新类型。 | 它只变换类型层面的属性，接口返回的 JSON 在编译器眼里仍是宽类型；真正落地要靠 zod 解析或类型守卫。 |
| infer | 条件类型里的推断关键字：从待判断类型中提取局部类型变量，用来实现 ReturnType 一类工具类型。 | `ReturnType`、`Parameters`、`Awaited` 都靠它从函数签名或 Promise 结构里抽参数；别依赖推断的巧合，关键处显式标注。 |
| 模板字面量 | TypeScript 在类型层面拼接字符串模式，可约束命名格式或提取子串。 | 它按分隔符递归切分时，连续分隔符会留下空串；要跳过空串就得在递归里判断当前段是否为空再接着切。 |

## 代码/协议/SQL 示例

### 最小可验证示例

**教材衔接：最小可运行示例**

下面这段代码演示 条件类型 的最小路径，先原样运行，再按注释改一处：

```typescript
type Split<S extends string> = S extends `${infer Head},${infer Tail}`
  ? [Head, ...Split<Tail>]
  : [S];

const items: Split<"a,b,c"> = ["a", "b", "c"];
console.log(items.join("-"));
```

**教材衔接：预期输出**

```text
a-b-c
```

### 进阶示例：把分隔符做成类型参数

最小示例只按逗号切分；下面把分隔符抽成参数，并给出对应的推导结果：

```typescript
type SplitBy<S extends string, D extends string> =
  S extends `${infer Head}${D}${infer Tail}`
    ? [Head, ...SplitBy<Tail, D>]
    : [S];

type Parts = SplitBy<"x|y|z", "|">;   // ["x", "y", "z"]
const count = (p: Parts) => p.length; // 3
```

```text
Parts = ["x", "y", "z"]，count 返回 3；
SplitBy<"a,,b", ","> 得到 ["a", "", "b"]，连续分隔符会留下空串。
```

动手练习：把最后一条改成跳过空串的版本，思路是在递归时判断 Head 是不是 ""，是就直接递归 Tail。

## 与其他知识点的关系

**教材衔接：复习与迁移**

类型级编程和运行时校验是互补的两件事：编译期能用 `Pick`、`Omit`、`Partial` 这类映射类型把对象形状收窄，但接口返回的 JSON 在编译器眼里仍是宽类型，真正落地要靠 zod 解析器或手写类型守卫。模板字面量类型常和事件名、路由路径这类字符串约定配合，把键统一拼成 `on${Capitalize<K>}` 这样的回调名，改名时编译期会立刻报出来。infer 是这些工具类型的地基，`ReturnType`、`Parameters`、`Awaited` 都靠它从函数签名或 Promise 结构里抽出类型参数。
