## 本节知识框架

**课程定位**：所属分类 `security`（安全与合规），课程主题 `实战：安全审计与漏洞修复`，学习阶段 进阶，建议用时 60 分钟。

本课主线：对一个 Web 服务完成威胁建模、代码审计、漏洞验证、修复和复测。

**学完本课应当能够**
- 说清 `安全审计` 与 `漏洞修复` 的含义与区别，并各举一个正例和一个反例。
- 用本课示例验证 `OWASP` 的行为，记录输入、输出与失败条件。
- 遇到「只测功能不测越权」这类问题时，能说出触发条件与修复顺序。

### 从概念到验证的学习链条

1. `安全审计`：先掌握 按既定标准检查权限、日志和配置，用可追溯证据判断是否存在违规或漏洞，再用它解释 `漏洞修复` 为什么会出现。
2. `漏洞修复`：先掌握 确认漏洞根因后修补受影响路径，并验证利用条件已失效且没有引入回归，再用它解释 `OWASP` 为什么会出现。
3. `OWASP`：先掌握 发布 Web 应用安全风险清单、测试指南和防护资料的开放组织，再用它解释 `信任边界` 为什么会出现。
4. `信任边界`：先掌握 数据从低信任区进入高信任区的接口，校验与鉴权都必须落在这一层，再用它解释 本课示例的观察结果 为什么会出现。
