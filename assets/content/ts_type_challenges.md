## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 条件类型 | TypeScript 根据类型关系在编译期选择结果类型的类型运算。 | 条件类型对联合类型会自动分配，成员被拆开逐个判断，要整体判断得用 [T] extends [U] 这种方括号写法。 |
| 映射类型 | TypeScript 根据已有类型批量生成属性变换后的新类型。 | 映射类型批量改的是类型里的属性形状，运行时对象不会跟着被转换，深层结构也不会自动递归。 |
| infer | 在条件类型里声明待推断的类型变量，用来实现 ReturnType 一类工具类型。 | infer 只在 extends 右侧的模式里才推断得出来，位置放错或模式对不上就报错，示例里的 U 要靠 Unwrap 递归才剥得干净。 |
| 模板字面量类型 | 用反引号把字符串类型拼起来，可以对路由参数或事件名做类型约束。 | 模板字面量类型只能拼接字面量字符串，传入宽泛的 string 会退化成 string 让约束失效，拼路由或事件名要先收窄成字面量。 |
| 条件类型 | 按条件选择类型 | 条件类型少写假分支时，不匹配的输入会落到意外的结果上，必须明确 never 或其它兜底分支才不出错。 |
| infer | 在条件类型中提取类型 | infer 提取出的类型只在匹配到的那条分支里可用，条件走假分支时那个类型变量根本不存在，不能拿来到处用。 |
| 映射类型 | 批量改造属性 | 它一次变换类型里的全部属性，深层对象不会自动跟着改；键名要变还得靠键重映射，像本课的 `Getters`。 |
| 模板字面量类型 | 在类型层拼字符串 | 拼出的字符串要借映射类型的 as 重映射才能变成键名（示例的 Listeners），光在类型里拼字符串并不会给对象补字段。 |
| 只需要复用已有类型的部分字段 | `Pick` / `Omit` | 字段少到两三行就能写完时，直接手写一个新接口比套 `Pick` / `Omit` 更好读。 |
| 需要按条件分支 | 条件类型 | 类型层的条件分支编译完就定死了，运行时并不会照着它走 if；要按真实取值分派还得写普通判断。 |
| 需要从复杂类型中提取 | `infer` | 复杂类型要先用条件类型摆好形状才谈得上提取，一次只剥一层，套娃式的 `Promise<Promise<number>>` 得靠递归。 |
| 需要批量转换属性 | 映射类型 | 映射类型批量改属性只发生在类型层，运行时对象不会因此被加工，深一层的变换得另写递归类型。 |
| 需要构造字符串键 | 模板字面量类型 | 模板字面量拼出的字符串键只是类型约束，运行时对象把键名写错了也不会报错，仍需断言或校验兜底。 |
| 需要运行时校验 | zod 等库（类型只在编译期存在） | 这里靠的正是类型编译后被擦除、运行期无类型可用：接口返回的 JSON 要交给 zod 做运行时校验，光有静态类型挡不住脏数据。 |
| 条件类型 | if 判断 | 把它当普通 if 用会踩空：条件类型只在编译期按类型关系选分支，真实数据的取值分支还得靠运行时判断。 |
| infer | 拆包裹 | 包裹得先被条件类型认出形状才拆得开，例如 `T extends Promise<infer U>`；套娃的 Promise 要递归才剥到底。 |
| 映射类型 | 批量加工 | 加工只停在最外层属性上，往里一层就停住了；深层要一起变换得写成递归类型逐层剥开。 |
| 模板字面量 | 字符串拼接 | 拼出来的是类型层面的键名，如 `get${Capitalize<string & K>}`；运行时真实的键名它一个也不检查。 |
| 递归类型 | 逐层剥开 | 易错：编译报错或超深；正确做法是设计明确的递归出口。 |
| 从 schema 推导类型 | ✅ 用工具类型 | 从 schema 推导的类型只活在编译期，schema 与真实响应不一致时它照样通过检查，这类派生类型挡不住运行时脏数据。 |
| 包装库的类型（如 Result、Option） | ✅ 有条件类型 | 用条件类型拆 Result、Option 这层包装，靠的是库里声明的类型结构，包装形状一改就匹配不上；真实值仍要在运行时另行判断。 |
| 只想少写几个字段 | ❌ 直接写更清楚 | 省下的只是两三行声明，代价是别人得先展开工具类型才看得见字段形状。 |
| 团队没人看得懂 | ❌ 退回到简单写法 | 复杂到要靠注释才读得懂时就该拆成命名类型；没人能维护的类型等于没起约束作用。 |
| Partial<T> | 全部可选 | 可选之后每个字段读出来都可能缺，取用要先处理空值；它只是类型变化，运行时不会替你补默认值。 |
| Required<T> | 全部必填 | 去掉问号只发生在类型层，数据里缺的字段不会因此被填上；调用方仍要真的把每个字段传齐。 |
| Readonly<T> | 全部只读 | 它只锁最外层属性，深层对象不会自动只读；想连里层一起锁得像本课 `DeepReadonly` 那样递归加工。 |
| Pick<T, K> | 保留指定字段 | K 要和原类型的键名逐字对齐，原类型增删字段后这里跟着报错；它不会顺手把可选字段变成必填。 |
| Omit<T, K> | 排除指定字段 | 排除项一多，剩下的到底是什么形状就没人看得懂，属于「类型写得太绕」；想留的字段少时反过来用 `Pick`。 |
| Record<K, V> | 构造映射 | K 得是能当键的类型；`Record` 只描述形状，运行时那个对象还得自己构造，字段该缺还是缺。 |
| Exclude<T, U> | 从联合中排除 | 它只对联合类型有意义，传进去的是普通对象类型就筛不出东西；结果可能落到 `never`，不匹配分支要接住。 |
| Extract<T, U> | 从联合中提取 | 它和 `Exclude` 正好反着来，筛完可能是空联合；当白名单用时不匹配那条分支要显式写清楚。 |
| NonNullable<T> | 去掉 null 与 undefined | 类型层擦掉空值不等于数据里没有空值；运行时字段真是空，取属性照样出问题。 |
| ReturnType<F> | 取返回类型 | `ReturnType<F>` 取到的是声明的返回类型，异步函数会拿到 Promise 而不是里面的结果类型，要取内部值还得再套 Awaited。 |
| Awaited<T> | 解开 Promise | 它解的是类型上的 Promise，等不到真正的异步结果；套了几层就得递归几层，参考本课 `Unwrap`。 |
| 类型写得太绕 | 报错没人看得懂 | 易错：报错没人看得懂；正确做法是拆成命名类型并加注释。 |
| 忘了 as const | 推断成宽泛类型 | 忘了 as const 时字面量被推成 string、number 等宽泛类型，条件类型和模板字面量拿不到具体字面量就匹配不上。 |
| 递归层数太深 | 编译器报「实例化过深」 | 易错：编译器报「实例化过深」；正确做法是限制层数或改实现。 |
| 条件类型没写 never | 得到意外结果 | 假分支空着，不匹配的输入就会落到别的结果上；联合传进来还会被逐项处理，要整体判断就套方括号写法。 |
| 在运行时用类型 | 报错或无效 | 易错：报错或无效；正确做法是类型只在编译期存在。 |
| 用体操处理业务逻辑 | 难维护 | 易错：难维护；正确做法是用普通代码表达。 |
| 忽略分配式条件类型 | 联合被逐项处理 | 易错：联合被逐项处理；正确做法是需要整体判断时用 `[T] extends [U]`。 |
| 版本差异 | 老版本不支持某些语法 | 易错：老版本不支持某些语法；正确做法是先确认 TS 版本。 |

## 典型应用场景

- **类型写得太绕**：典型现象是报错没人看得懂；正确做法是拆成命名类型并加注释。
- **忘了 `as const`**：典型现象是推断成宽泛类型；正确做法是常量加 `as const`。
- **递归层数太深**：典型现象是编译器报「实例化过深」；正确做法是限制层数或改实现。
- **条件类型没写 `never`**：典型现象是得到意外结果；正确做法是明确不匹配时的分支。

### 选择与边界

- 使用 `条件类型` 时，先满足它的定义：TypeScript 根据类型关系在编译期选择结果类型的类型运算；易错：得到意外结果；正确做法是明确不匹配时的分支。
- 使用 `映射类型` 时，先满足它的定义：TypeScript 根据已有类型批量生成属性变换后的新类型；静态检查只在编译期成立，运行期输入仍需校验。
- 使用 `infer` 时，先满足它的定义：在条件类型里声明待推断的类型变量，用来实现 ReturnType 一类工具类型；静态检查只在编译期成立，运行期输入仍需校验。
- 使用 `模板字面量类型` 时，先满足它的定义：用反引号把字符串类型拼起来，可以对路由参数或事件名做类型约束；静态检查只在编译期成立，运行期输入仍需校验。

## 代码/协议/SQL 示例

### 最小可验证示例

```ts
// 1. 条件类型 + infer：取出函数返回类型与 Promise 内部类型
type Unwrap<T> = T extends Promise<infer U> ? Unwrap<U> : T;
type Value = Unwrap<Promise<Promise<number>>>;   // number
// 2. 映射类型 + 键重映射：把字段改成 getX 形式
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
interface User {
  id: string;
  name: string;
}
type UserGetters = Getters<User>;
// { getId: () => string; getName: () => string }
// 3. 递归条件类型：深层只读
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
// 4. 联合类型分配：自动对每个成员生效
type ToArray<T> = T extends unknown ? T[] : never;
type Result = ToArray<"a" | "b">;                // "a"[] | "b"[]
// 5. 模板字面量类型 + 映射：为事件总线生成类型安全的方法
type EventMap = { userCreated: { id: string }; userDeleted: { id: string } };
type Listeners = {
  [K in keyof EventMap as `on${Capitalize<string & K>}`]: (payload: EventMap[K]) => void;
};
```
