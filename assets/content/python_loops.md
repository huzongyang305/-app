## 本节知识框架

**本课目标**：掌握 `for` 循环、`while` 循环、`break` / `continue` 控制、`range()` 函数的用法，能写出正确的重复执行逻辑并避免死循环。

**先修**：《Python 输入与输出》——你需要会用 `print()` 和 `input()`，了解字符串与基本类型。
**下一课**：《Python 列表与字典入门》——循环会在那里用来遍历列表和字典。

学完本课你应当能够：

- 用 `for` 逐个处理列表或 `range()` 产生的数字序列
- 用 `while` 在条件满足时反复执行任务
- 用 `break` 提前退出循环，用 `continue` 跳过本轮
- 识别并修复死循环

## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| `for` 循环 | 把一组已知数量的东西逐个处理一遍（按点名册点名：名单上有几个人就点几次） |
| `while` 循环 | 只要条件为真就反复执行，直到条件变假（等水烧开：没开就继续等，开了就停） |
| `range()` | 生成一段整数序列，用来控制循环次数（像楼梯的台阶编号，从第几级到第几级） |
| `break` | 立即结束整个循环，跳到循环后面（找到东西就不找了，直接走人） |
| `continue` | 跳过本轮剩余语句，进入下一轮循环（翻到一页空白就跳过去，继续翻下一页） |
| 嵌套循环 | 循环里面再套一层循环（日历：外层是月，内层是日） |
| 可迭代对象 | 能被 `for` 逐个取出东西的对象：列表、字符串、字典、文件、`range()` 的结果都算 |
| `enumerate()` | 遍历时同时拿到"第几个"和"是什么"（点名时既报序号又报名字） |
| 循环的 `else` 分支 | 循环正常跑完、没有被 `break` 打断时才执行的收尾代码 |

## 原理与运行机制

### 循环就像重复做同一件事

想象你每天早上要刷牙。这件事的步骤是固定的：挤牙膏、刷 2 分钟、漱口。你不需要把"刷牙"这个动作写 365 遍——你只需要知道"每天都要做"，然后重复执行。

编程里的循环也是同样的道理。当你想让计算机重复做某件事时，不用把代码复制粘贴很多遍，而是用循环告诉它："把这段代码执行 N 遍"或者"一直做到条件不满足为止"。

### for 循环的执行流程

```text
开始
 ↓
取出序列中的下一个元素
 ↓
有元素吗？── 没有 → 结束循环，执行循环后面的代码
 ↓ 有
执行循环体（缩进的代码）
 ↓
回到"取出下一个元素"
```

`for` 循环的工作方式很简单：有一个序列（比如一组数字、一个列表），循环每次从里面拿出一个元素，交给循环体处理，拿完了就自动结束。

### while 循环的执行流程

```text
开始
 ↓
检查条件是否为真
 ↓
为假 → 结束循环
 ↓ 为真
执行循环体
 ↓
回到"检查条件"
```

`while` 循环不关心"有多少个元素"，它只关心"条件还成不成立"。所以你必须自己保证循环里有东西在改变条件，否则条件永远为真，程序就卡住了——这就是**死循环**。

### 从最简单的 for 开始

先看一个最基础的例子：

```python
for i in range(3):
    print(i)
```

输出：

```text
0
1
2
```

`range(3)` 产生 0、1、2 三个数字（注意不包含 3），`for` 依次把每个数字赋给变量 `i`，然后执行 `print(i)`。

### 加上累加逻辑

```python
total = 0
for i in range(1, 4):
    total = total + i
print(total)
```

执行过程拆解：

- 第一轮：`i = 1`，`total = 0 + 1 = 1`
- 第二轮：`i = 2`，`total = 1 + 2 = 3`
- 第三轮：`i = 3`，`total = 3 + 3 = 6`
- 循环结束，输出 `6`

### 用 while 实现同样的事

```python
total = 0
i = 1
while i <= 3:
    total = total + i
    i = i + 1      # 别忘了这行，否则 i 永远是 1
print(total)
```

对比 `for` 版本，`while` 需要你手动管理循环变量 `i`：先赋初值，再在循环体里更新它。好处是条件可以写得很灵活，坏处是忘了更新就会死循环。

### range() 的三种用法

```python
# Python 循环入门
range(5)          # 0, 1, 2, 3, 4

# 给两个参数：指定起点和终点（左闭右开）
range(1, 6)       # 1, 2, 3, 4, 5

# 给三个参数：加上步长
range(0, 10, 2)   # 0, 2, 4, 6, 8
```

记住一个口诀：**包含起点，不包含终点**。`range(1, 5)` 产生 1、2、3、4，不包含 5。这是新手最容易踩的坑。

### break 和 continue

`break` 用来提前退出循环——比如在一堆数据里找某个值，找到了就不用继续找了：

```python
for i in range(10):
    if i == 5:
        break
    print(i)
# 输出：0 1 2 3 4
```

`continue` 用来跳过本轮——比如遍历数字时跳过偶数：

```python
for i in range(6):
    if i % 2 == 0:
        continue
    print(i)
# 输出：1 3 5
```

### 嵌套循环

有时候你需要两层循环。比如打印一个 3×3 的坐标网格：

```python
for x in range(3):
    for y in range(3):
        print(f"({x},{y})", end=" ")
    print()
```

输出：

```text
(0,0) (0,1) (0,2)
(1,0) (1,1) (1,2)
(2,0) (2,1) (2,2)
```

外层循环每走一步，内层循环要完整跑一遍。所以 3×3 的嵌套循环，循环体总共执行 9 次。

### for 和 while 怎么选：三条判据

看到"重复"两个字，先问自己三个问题：

1. **手上有没有一堆现成的东西要处理？** 有列表、有文件、或者次数能由 `range()` 表达，就用 `for`——它天生就是"拿出来一个、处理一个"的结构。
2. **知不知道要循环多少次？** 如果答案是"不知道，用户输入 quit 才停"，`for` 无从下手，只能交给 `while`。
3. **结束条件是不是由状态决定的？** "直到余额被扣完""直到猜对为止"这类由外部状态决定终点的情形，是 `while` 的主场。

一句话记忆：**有名单用 `for`，没名单用 `while`。** 两者在功能上可以互相模拟（`while` 自己维护一个计数器就能当 `for` 用），但选错了会让代码读起来别扭，也会让死循环有可乘之机。

### 死循环的三个来源与三道保险

死循环几乎没人是故意写的，它来自三种疏忽：

- **忘了更新**：写了 `while n > 0:`，循环体里从头到尾没碰过 `n`。
- **更新方向反了**：条件要 `n` 变小，循环体里却写成 `n += 1`。
- **更新藏在走不到的分支里**：那行 `n -= 1` 被包在 `if` 里，而条件多数时候为假。

三道保险按顺序使用。第一道是**口头检查**：动手写循环体最后一行时问一句"这行让条件更接近变假了吗"。第二道是**打印循环变量**，把 `print(n)` 放在循环体开头，看它到底有没有动。第三道才是给循环加一个绝对上限：

```python
n = 5
guard = 0
while n > 0:
    guard += 1
    if guard > 1000:          # 兜底：无论条件如何，最多跑 1000 轮
        print("循环异常，提前退出")
        break
    print(n)
    n -= 1
```

`guard` 这种写法在正式项目里不算优雅，但它能在你还没经验时保住程序。真的在终端里卡死了，按 `Ctrl+C` 会抛出 `KeyboardInterrupt`，程序立刻停下，不会弄坏电脑。

### enumerate() 与 zip()：位置信息的正确取法

需要"第几个"的时候不要写 `for i in range(len(lst))`：

```python
scores = [88, 92, 75]

for idx, score in enumerate(scores, start=1):
    print(f"第 {idx} 名：{score} 分")

names = ["小明", "小红", "小刚"]
for name, score in zip(names, scores):
    print(f"{name} 的分数是 {score}")
```

`enumerate()` 把"序号 + 元素"一起打包给你，`start=1` 能让序号从 1 开始而不是从 0。`zip()` 把两个序列并排捆起来，但**谁短就以谁为准**——多出来的部分会被静默丢掉。上面名单有 3 个人、成绩有 3 个，刚好对齐；如果成绩只有 2 个，小刚就会被无声跳过，这类 bug 不报错，只能靠"输出条数对不对"来发现。

### for-else：用"有没有被打断"来表达搜索结论

Python 的循环可以挂一个 `else` 分支，它只在循环**没有被 `break` 打断**时执行：

```python
numbers = [4, 6, 8, 10]
target = 7

for n in numbers:
    if n % target == 0:
        print(f"{n} 能被 {target} 整除")
        break
else:
    print("一个都不能整除")
```

把它读成"找了一圈都没找到，就走 else"，比在外面额外维护一个 `found = False` 标志位干净得多。要特别提醒的是：这里的 `else` 不是"否则"的意思，绝不能按 `if-else` 的直觉去理解，否则读别人的代码会完全读反。

### 循环变量在循环结束后依然活着

```python
for i in range(3):
    pass
print(i)   # 输出 2，而不是报错
```

Python 没有"循环内部作用域"这回事，循环变量在循环外照样能访问，值是最后一次迭代留下的那个。这个特性会制造两类 bug：一是列表恰好为空时循环体一次都没执行，变量根本没被创建，后面引用它就抛 `NameError`；二是复用了同名变量，以为它是新循环的起点，其实带着上一轮的残留。习惯的写法是：循环变量用有业务含义的名字（`row`、`student`），并在循环之前给结果变量一个默认值，不依赖它的"遗产"。注意上面例子里必须写 `pass`，否则空循环体直接报 `IndentationError`。

## 典型应用场景

### 场景一：逐个打印列表中的元素

```python
fruits = ["苹果", "香蕉", "橘子"]
for fruit in fruits:
    print(fruit)
```

这是 `for` 循环最自然的用法——有一组东西，逐个处理。

### 场景二：计数 N 次

```python
for i in range(5):
    print(f"第 {i + 1} 次")
```

当你不关心具体的元素、只需要"重复 5 次"时，`range()` 是最好的搭档。

### 场景三：累加求和

```python
total = 0
for n in range(1, 101):
    total += n
print(total)  # 5050
```

准备一个累加器 `total`，每次循环把新值加进去。这是后续学数据处理的基础模式。

### 场景四：遍历文件每一行

```python
with open("data.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

文件对象本身是可迭代的，`for` 每次读一行，不需要手动管理读取位置。

### 场景五：把整数逐位拆开

```python
number = 20261006
digit_sum = 0
while number > 0:
    digit_sum += number % 10    # 取出最后一位
    number //= 10               # 砍掉最后一位
print(digit_sum)   # 17
```

身份证校验码、"判断是不是回文数"、"统计一个数里出现了几次 0"，全都是这个 `while` 模板的变体。这里的 `//=` 必须是整除而不是 `/=`：写成 `number /= 10` 会得到小数，`number > 0` 永远为真，一个不留神就又造出一个死循环。

### 场景六：反复追问直到拿到合法输入

程序让用户输入年龄，用户却敲了字母。标准做法是把"读入 → 校验 → 重来"装进 `while True`：

```python
while True:
    text = input("请输入年龄：")
    if text.isdigit() and 0 < int(text) < 120:
        age = int(text)
        break
    print("输入不合法，请重新输入。")
print(f"已记录年龄：{age}")
```

`while True` 本身不是禁忌，禁忌的是里面没有 `break`。只要退出路径由明确条件决定，它处理人工输入就很顺手。但要注意另一条失败路径：这段代码被放到自动评测脚本或非交互环境里运行时，会因为等不到键盘输入而一直挂着——所以"只在自己手敲一遍正常输入"是不够的，输入、输出和卡住的情形都得各自验证一次。

### 场景七：遍历时筛选并收集结果

```python
temps = [31, 28, 35, 26, 33]
hot_days = []
for i, t in enumerate(temps):
    if t >= 33:
        hot_days.append((i, t))
print(hot_days)   # [(2, 35), (4, 33)]
```

累加器不只是用来求和：把 `total = 0` 换成 `hot_days = []`、把 `+=` 换成 `.append()`，循环就从"算总数"变成了"挑东西"。这是统计超温天数、筛出不及格名单、过滤敏感词的共同骨架。

## 代码/协议/SQL 示例

### 最小可运行示例

```python
for i in range(3):
    print(i)
```

预期输出：

```text
0
1
2
```

### 完整示例：for + while + break + continue

```python
# 用 for 循环累加 1 到 5
total = 0
for n in range(1, 6):
    total += n
print(f"1 到 5 的和：{total}")  # 15

# 用 while 循环倒计时
countdown = 5
while countdown > 0:
    print(countdown)
    countdown -= 1
print("出发！")

# break 示例：找到第一个大于 3 的数就停
for x in [1, 2, 4, 5, 6]:
    if x > 3:
        print(f"找到了：{x}")
        break

# continue 示例：只打印奇数
for x in range(1, 7):
    if x % 2 == 0:
        continue
    print(x)
```

1. 把 `range(1, 6)` 改成 `range(1, 11)`，先心算总和，再运行验证。
2. 在 `for` 循环里加判断：遇到 3 就跳过，看看 `continue` 的效果。
3. 写一个 `while` 循环，条件改成 `True` 但忘记更新变量，观察死循环现象，然后用 `Ctrl+C` 强制停止。

### 练习参考答案：倒计时与阶乘

```python
# 从 10 倒数到 1，遇到 3 的倍数额外加一个标记
n = 10
while n >= 1:
    if n % 3 == 0:
        print(f"{n} ← 3 的倍数")
    else:
        print(n)
    n -= 1

# 用 for 求 6 的阶乘
factorial = 1
for k in range(1, 7):
    factorial *= k
print(factorial)   # 720
```

阶乘这段暴露了累加器的另一面：**初值必须是 1，不能是 0**。用 0 起步再往上乘，结果会永远躺在 0 上；而求和的初值恰恰必须是 0。写循环之前先确认这个变量的"什么都不加"的值是什么，比背模板重要。

### 练习参考答案：range 不接受小数怎么办

想从 0 走到 1、每步 0.25，直接写 `range(0, 1, 0.25)` 会报 `TypeError: 'float' object cannot be interpreted as an integer`。绕行办法是用整数计数再换算：

```python
steps = 4
for k in range(steps + 1):
    print(k / steps)     # 0.0 0.25 0.5 0.75 1.0
```

`range(steps + 1)` 给出 0 到 4 共 5 个整数，除以总份数就变成 5 个等距小数，最后一格正好落在 1.0。这个技巧在后面画坐标轴、做进度条、按时间采样时都会再遇到。

### 对照实验：字符串 += 与 join

```python
import time

parts = ["片段"] * 20000

start = time.perf_counter()
text_a = ""
for p in parts:
    text_a += p
concat_cost = time.perf_counter() - start

start = time.perf_counter()
text_b = "".join(parts)
join_cost = time.perf_counter() - start

print(f"+= 拼接耗时：{concat_cost:.4f} 秒")
print(f"join 耗时：{join_cost:.4f} 秒")
```

`+=` 每一轮都要新建一个字符串并把历史内容整段抄一遍，循环越长越吃亏；`join()` 先扫一眼列表算出总长度，再一次性写满。小脚本里两者可能都只要几十毫秒、看不出差别，把 `20000` 改成 `200000` 就会露馅——这正是"别凭感觉优化，先测一次"的活教材。

## 时间/空间复杂度或性能分析

对初学者来说，先关心**跑对**，再关心**跑快**。

不过你可以建立一个直觉：

- 循环执行 N 次，循环体里是简单操作 → 时间大致与 N 成正比，记作 O(N)。
- 嵌套循环，外层 M 次、内层 N 次 → 循环体执行 M×N 次，记作 O(M×N)。
- `for item in list` 和 `for i in range(len(list))` 速度差不多，但前者更易读。
- 在循环里反复用 `+=` 拼接字符串会每次都创建新对象，数据量大时明显变慢；更好的做法是收集到列表里，最后用 `"".join()` 一次拼好。

一句话原则：**先让程序正确运行，遇到性能瓶颈再用工具测量，不要凭感觉优化。**

### 数量级体感：循环一百万次要多久

在同一台机器上跑 Python 3.12，大致的时间感受是这样（不同机器会差好几倍，这里只用来建立量感，不要当标准答案背）：

- 空循环 `for i in range(1_000_000): pass`：约零点零几秒
- 循环体里多做一次整数加法：约零点几秒
- 循环体里再做一次字符串格式化或 `print`：直接翻好几倍
- 同样的逻辑套两层、总次数变成一亿：几十秒起步，界面就像卡死

结论很实用：**循环体里那一行的成本，通常比循环结构本身贵得多。** 想提速，优先把字符串拼接、`in` 查找、函数调用挪出循环，而不是纠结 `for` 和 `while` 谁更快——这两者的执行效率在入门规模上基本没有差别。

### 自己测量循环耗时

```python
import time

start = time.perf_counter()
total = 0
for i in range(1_000_000):
    total += i
cost = time.perf_counter() - start
print(f"耗时 {cost:.4f} 秒，结果 {total}")
```

`time.perf_counter()` 是专门用来比较"两段代码谁快"的高精度时钟。想让结论可复现，同一段代码至少跑三遍取中间值，跑之前先关掉占用 CPU 的程序，并记下你用的 Python 版本和机器——换一台机器、换一个版本就重新比一次，别把别人机器上的数字当成自己机器的结论。

### 嵌套循环要先做乘法再动手

内层跑 N 次、外层跑 M 次，循环体总次数就是 M×N。写双层循环前先在纸上乘一下：1000×1000 是一百万，还能接受；10000×10000 是一亿，在解释型语言里基本等于"转圈等待"。两个立刻可用的减负手段：能提前 `break` 就提前 `break`（找到答案就别再翻剩下的）；能用集合判断 `in` 解决的，就不要再用一层循环挨个比对。

## 常见误区与易错点

| 误区 | 实际现象 | 正确做法 |
| --- | --- | --- |
| `range(1, 5)` 以为会到 5 | 只产生 1, 2, 3, 4，少算一个 | 记住"左闭右开"，要包含 5 就写 `range(1, 6)` |
| while 循环忘记更新条件变量 | 死循环，程序卡住不动 | 每次循环体里都要有让条件趋向结束的操作 |
| 用下标遍历列表 | `for i in range(len(lst))` 代码冗长又容易越界 | 直接 `for item in lst`；需要下标时用 `enumerate()` |
| 循环里用 `=` 覆盖而不是 `+=` 累加 | 每次冲掉之前的结果，最后只剩最后一个值 | 分清"赋值"和"累加"，累加用 `+=` |
| 混淆 break 和 continue | 该退出时只跳过了本轮，该跳过时却退出了整个循环 | `break` = 彻底结束；`continue` = 跳过本轮 |
| 嵌套循环里变量名冲突 | 内外层用了同一个变量名，逻辑混乱 | 内外层用不同的变量名，比如外层 `i`、内层 `j` |
| 遍历列表的同时删除它的元素 | `for x in lst:` 里调用 `lst.remove(x)`，会跳掉紧跟着的几个元素，结果时对时错 | 遍历副本 `for x in lst[:]`，或者另建一个"保留下来"的新列表 |
| 以为 `break` 会跳出所有层 | 内层停了，外层照常进入下一轮，程序还是把整张表扫完 | `break` 只结束最近的一层；多层退出请封装成函数用 `return`，或配合循环的 `else` |
| 给 `range()` 传小数 | 报 `TypeError: 'float' object cannot be interpreted as an integer` | 起止与步长都必须是整数；需要小数刻度时用整数计数再除以总份数 |
| 循环体一时没内容就留空 | 报 `IndentationError: expected an indented block` | 写一句 `pass` 占位，保证缩进块至少存在 |
| 循环结束后依赖循环变量的残留值 | 数据为空时变量压根没被创建，后续引用抛 `NameError` | 循环前先给结果变量一个默认值，把"循环外要用的东西"和"循环里用的东西"分开命名 |
| 把 `for` 当成"必须配 `range`" | 明明有列表却写 `range(len(...))`，多两遍索引还容易越界 | 直接遍历元素；确实需要位置时改用 `enumerate()` |

## 与其他知识点的关系

**先修依赖**：

- 《Python 输入与输出》：你需要会 `print()` 来观察循环输出，会 `input()` 来在循环中读取用户输入。
- 《Python 条件判断》：`while` 的条件、`break` / `continue` 后面的 `if` 都用到了 `if-elif-else` 和布尔表达式。

**后续衔接**：

- 《Python 列表与字典入门》：用 `for` 遍历列表和字典是下一课的核心操作。
- 《Python 函数》：循环经常写在函数体里，返回值可以终止循环的效果。
- 《Python 异常处理与文件操作》：用 `for line in file` 逐行读文件，用 `while` 做重试逻辑。

**概念对比**：

- `for` vs `while`：已知次数或有序列用 `for`；不知道要循环多少次、只知退出条件用 `while`。
- `break` vs `continue`：`break` 跳出整个循环，`continue` 只跳出当前这一轮。

**本课内部的四个问题**：`range()` 决定跑几次，`for` 或 `while` 决定怎么跑，`break` 与 `continue` 决定什么时候不跑了，嵌套循环决定要跑几层。读任何一段循环代码，都可以按这四问逐个拆开回答，答案齐了代码就看懂了。

**验证口径**：本课的结论要靠"固定版本 + 覆盖边界输入"来确认。同一个累加循环至少喂三种数据——空序列（`[]` 或 `range(0)`）、只有一个元素、恰好等于边界的那个数。只拿一组正常数据跑出正确答案，说明不了边界写对了；`range(1, 5)` 少算一位、`while` 多跑一轮，都属于这种只有边界才能暴露的问题。

**与下一课的分工**：循环负责"重复做"，列表与字典负责"数据放在哪儿"。两者合起来才写得出词频统计、按分数分组这类真正有用的程序。所以本课练习不要停在 `range()` 上，务必回到列表和字典下面各写一个循环，把"遍历"这个动作练成条件反射。

**参考答案**：

```python
total = 0
i = 1
while i <= 5:
    total += i
    i += 1

```

### 自测 3

解释为什么下面这段代码会变成死循环，怎样修复？

```python
x = 10
while x > 0:
    print(x)
```

**参考答案**：循环体里没有修改 `x` 的值，`x` 永远是 10，条件永远为真。修复方法：在循环体里加上 `x -= 1`。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `for` 循环 | 遍历序列或可迭代对象，次数由元素个数决定 |
| `while` 循环 | 条件为真时反复执行循环体，需要自己保证条件最终会变假 |
| `range()` | 生成整数序列，常用 `range(n)` 或 `range(start, stop, step)` 控制次数 |
| `break` | 立即结束整个循环，跳到循环后面的代码 |
| `continue` | 跳过本轮剩余语句，进入下一轮循环 |
| 嵌套循环 | 循环内部再包含循环，总执行次数等于各层次数之积 |
| 死循环 | 条件永远为真导致循环无法结束，通常要检查更新语句是否被执行 |
| `enumerate()` | 遍历时同时给出序号与元素，用 `start=` 可以指定起始编号 |
| `zip()` | 把多个序列并排捆绑，长度不齐时以最短的那个为准 |
| 可迭代对象 | 能被 `for` 逐个取出元素的东西，列表、字符串、字典、文件都属于它 |
| 累加器 | 循环前赋初值、循环内不断更新的变量；求和从 0 起，求积从 1 起 |
| 哨兵值 | 一个约定用来终止输入循环的特殊取值，例如空字符串代表输入结束 |
| 循环的 `else` 分支 | 循环没有被 `break` 打断时才会执行的收尾代码 |
