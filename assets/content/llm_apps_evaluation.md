## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 离线评测集 | 固定问答对与判定规则，用于版本间可比。 | 易错：题目太少或长期不换，模型会过拟合到评测集。 |
| 忠实度 | 回答中的每个论断能否被检索上下文支撑。 | 易错：把它当准确率，它只管「有没有依据」。 |
| 答案相关度 | 回答与问题在语义上的贴合程度。 | 易错：多答无关内容同样扣分，容易被误读为召回问题。 |
| 上下文召回 | 标准答案所需信息是否出现在检索片段里。 | 易错：需要参考回答，缺失时无法计算。 |
| LLM-as-Judge | 用模型按评分标准给输出打分或两两比较。 | 易错：默认它中立，实际偏爱长答案与自家风格。 |
| 回归门禁 | 分数跌破阈值即阻断发布。 | 易错：阈值拍脑袋，导致天天误报被忽略。 |
| 追踪链路 | 把一次请求拆成多个跨度并记录输入输出。 | 易错：只记最终问答，中间步骤不可见等于没追踪。 |
| 越狱检测 | 识别试图绕过约束的提示并拦截或改写。 | 易错：以为存在万能分类器，需多层组合。 |
| PII 脱敏 | 在送检与落库前遮蔽个人可识别信息。 | 易错：只改日志不改请求，原文仍发给外部端点。 |

## 原理与运行机制

### 机制总览：三层防线的分工

离线评测回答「这次改动是否更好」，在线监控回答「真实用户身上发生了什么」，护栏回答「不该发生的事有没有被挡住」。三者输入不同、频率不同，不能相互替代：评测集无法覆盖长尾输入，线上抽样无法保证版本可比，护栏不判质量只判边界。

**教材衔接：四个常用指标的输入与解释**

| 指标 | 需要的输入 | 是否需要标准答案 | 分数下降通常说明 |
| --- | --- | --- | --- |
| 忠实度 | 问题、回答、上下文 | 否 | 生成在编，或上下文噪声过大 |
| 答案相关度 | 问题、回答 | 否 | 偏题、套话或答了没问的内容 |
| 上下文召回 | 问题、上下文、标准答案 | 是 | 分块或检索策略没覆盖到关键段 |
| 上下文精确度 | 问题、上下文、标准答案 | 是 | 召回里混入太多无关段落 |

前两项定位生成侧，后两项定位检索侧。把它们放在同一张看板上，能直接区分「没查到」与「查到了没用好」这两类完全不同的故障。

**教材衔接：评审模型的偏差与校准**

评审模型有三类系统性偏差：长度偏好、位置偏好与自家风格偏好。校准不是换个更强的评审模型，而是量化偏差并设法抵消。常见做法是成对比较时交换顺序各评一次，两次结论不一致就记为平局。

```python
def verdict(a_first, b_first):
    if a_first == 'A' and b_first == 'B':
        return 'A'
    if a_first == 'B' and b_first == 'A':
        return 'B'
    return 'tie'

print(verdict('A', 'A'), verdict('A', 'B'))
```

**教材衔接：回归配置的形状**

一条用例可以复用多个提示词，一个提示词也可以跑多条用例，两者数量相乘才是实际调用次数。忽略这一点会让评测成本估算低一个量级。

```python
import json
cfg = {'prompts': ['p1.txt', 'p2.txt'], 'providers': [{'id': 'openai:gpt-4o-mini'}], 'tests': [{'assert': [{'type': 'contains', 'value': '退款'}]}]}
print(len(cfg['prompts']), len(cfg['tests']))
```

**教材衔接：追踪链路的最小层级**

一次请求至少要拆成四层：入口请求、检索、生成、工具调用。每层记录输入摘要、输出摘要、耗时、Token 与错误。只有把跨度用同一请求号串起来，才能回答「这次慢在哪一步」。

| 层级 | 记录内容 | 典型用途 |
| --- | --- | --- |
| 请求 | 用户问题、渠道、总耗时 | 端到端体验与成本归因 |
| 检索 | 查询、命中片段与分数 | 定位召回问题 |
| 生成 | 提示词版本、模型、Token | 对比提示词与模型效果 |
| 工具 | 调用参数、返回、异常 | 排错与审计 |

**教材衔接：护栏的纵深**

单点护栏必然被绕过，可靠做法是纵深：输入侧做长度与注入特征检测，检索侧做来源白名单，输出侧做禁词与结构校验，落库侧做脱敏，最后用人工抽检兜底。

```python
import re
PII = [(re.compile(r'\b\d{11}\b'), 'PHONE'), (re.compile(r'[^@\s]+@[^@\s]+'), 'MAIL')]

def redact(text):
    for pat, tag in PII:
        text = pat.sub('[' + tag + ']', text)
    return text

print(redact('联系 13800138000 或 a@b.com'))
```

## 典型应用场景

| 场景 | 评测重点 | 护栏重点 |
| --- | --- | --- |
| 客服知识问答 | 忠实度与引用完整率 | 禁承诺性表述，超范围转人工 |
| 代码生成助手 | 单元测试通过率 | 危险调用静态扫描 |
| 面向公众写作 | 答案相关度与安全分 | 输出侧禁词与主题白名单 |
| 内部数据分析 | 结果可复算性 | 限制可访问表与查询超时 |
| 多轮助手 | 上下文利用率 | 长会话摘要防注入残留 |

- 典型现象：指标都在涨但用户投诉变多。正确做法：检查评测集是否与实际分布脱节，并补一批从线上抽样回来的用例。
- 典型现象：换了评审模型分数大涨。正确做法：用人工标注子集重算一致率，不一致时以人工为准。
- 典型现象：脱敏后仍泄露。正确做法：确认遮蔽发生在出站之前，而不是只处理了日志副本。

### 最小验证场景

- 准备：四十条问答，二十条正常、十条应拒答、十条含个人数据，固定同一份上下文。
- 观察：忠实度分布、答案相关度分布、应拒答条目实际拒答率、个人数据在出站请求体中的残留。
- 判定：正常条目无编造、应拒答条目全部被拦、出站请求体中不出现原始手机号与邮箱；任一不满足即视为未通过。

## 代码/协议/SQL 示例

**教材衔接：把评测结果与线上日志放同一张表**

```sql
CREATE TABLE eval_score (
  id           BIGSERIAL PRIMARY KEY,
  run_id       TEXT        NOT NULL,
  case_id      TEXT        NOT NULL,
  metric       TEXT        NOT NULL,
  score        NUMERIC(4, 3) NOT NULL,
  prompt_ver   TEXT        NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

SELECT run_id, prompt_ver, metric, ROUND(AVG(score), 3) AS mean
FROM eval_score
GROUP BY run_id, prompt_ver, metric
ORDER BY run_id DESC, metric;
```

**教材衔接：成本按维度归因**

```python
def cost(rows):
    return round(sum(r['in'] * 4 + r['out'] * 12 for r in rows) / 1000, 2)

print(cost([{'in': 900, 'out': 120}, {'in': 1500, 'out': 300}]))
```

Token 单价按输入与输出分别计价，输出通常是输入的数倍。把成本按渠道与提示词版本聚合，能很快发现是哪次改动让平均输入体积翻倍。

**教材衔接：流式响应也能算忠实度**

```python
chunks = ['退款', '政策', '适用', '于', '30 天']
answer = ''.join(chunks)
print(answer.endswith('30 天'), len(chunks))
```

错误表现：用一次抽样的人工印象决定是否发布。

```python
ok = '感觉还行' in review_note       # 无法复现，无法回归
```

正确写法：把判断条件写进配置，发布时机器比对，人只做异常复核。

```python

```

## 时间/空间复杂度或性能分析

| 指标 | 随什么增长 | 典型区间 | 优化手段 |
| --- | --- | --- | --- |
| 全量评测耗时 | 用例数乘提示词数乘供应商数 | 相乘关系 | 分层抽样，先跑小集再跑全量 |
| 评审调用成本 | 用例数乘被评文本长度 | 与被评内容同阶 | 截断上下文、两两比较代替打分 |
| 在线追踪存储 | 请求量乘记录字段数 | 全量记录代价高 | 采样加错误强制留存 |
| 护栏延迟 | 检测器数量与规则复杂度 | 十几到上百毫秒 | 轻量规则前置，重模型异步 |
| 人工复核量 | 阈值松紧 | 与误报率正相关 | 先校准再收紧，分渠道设阈 |

评测成本是乘法不是加法：两个提示词、三家供应商、五十条用例意味着两百次调用。工程上普遍采用漏斗式策略，先用二十条高置信用例做快速门禁，通过后再跑全量，避免每次提交都付出满额成本。

在线追踪的存储策略要区分「排错需要」与「统计需要」。排错需要完整链路但只关心少数请求，统计只需要聚合数字。可行折中是正常请求按比例采样、失败与被举报请求强制全量留存，并给原始内容设较短的保留期。

护栏的延迟预算必须显式分配。若端到端目标是四秒，输入检测与输出检测各给一百毫秒，剩下给模型，否则护栏会先成为瓶颈。把简单正则与长度检查放在前面、语义分类模型放在后面，可以用极小代价滤掉绝大多数明显违规。

## 常见误区与易错点

- **把评审模型当客观标尺。** 它有长度、位置与风格三类偏差，需要校准。
- **只测平均不测分位。** 尾部恶劣体验恰恰是投诉来源。
- **评测集长期不换。** 模型会针对固定题目优化，指标与真实效果脱钩。
- **混淆忠实度与准确率。** 前者只看有无依据，答案本身可能仍不相关。
- **答案相关度低就调检索。** 召回正常时问题多半在生成侧偏题。
- **只记最终问答。** 没有中间跨度就无法定位是检索还是生成出错。
- **脱敏只处理日志。** 出站请求体同样必须遮蔽，否则原文已经离开边界。
- **让模型自己判断是否违规。** 需要识别器与规则先遮蔽再送检。
- **一个万能分类器挡所有攻击。** 越狱形态多变，必须多层组合。
- **阈值设得过松或过紧。** 松则形同虚设，紧则天天误报最终被人忽略。
- **成本看板不分输入输出。** 两者单价差异大，混合统计会误导优化方向。

## 自测题与参考答案

**教材衔接：题号 1** — 用 LLM-as-Judge 打分时，最典型的系统性偏差是？

**参考答案**：偏向更长或自家模型的输出。

本题正确项是「偏向更长或自家模型的输出」。评审模型偏好冗长文本和与自身风格接近的答案，还会受候选位置先后影响，因此要做位置交换、长度控制和人工抽检校准。它并不会天然对齐人类相关性判断，也不会均匀给分或只盯格式，把这些当成默认属性会让评测报告系统性偏高却无人察觉。

**教材衔接：题号 2** — RAGAS 里答案相关度偏低但上下文召回正常，最可能的原因是？

**参考答案**：生成偏题或多答了无关内容。

本题正确项是「生成偏题或多答了无关内容」。答案相关度按回答反推问题来衡量它是否切题，检索正常而这一项偏低，说明问题出在合成阶段：提示词没约束回答范围，或模型补充了无关段落。索引类型和分块长度影响的是召回，评审维度多寡是评估器自身配置，都不会在这种组合下成为直接原因。

**教材衔接：题号 3** — 接入 LangFuse 一类可观测平台，最先要打通的是？

**参考答案**：一次请求到各步 Span 的追踪链路。

本题正确项是「一次请求到各步 Span 的追踪链路」。只有把用户请求、检索、工具调用和生成串成同一条追踪，才能定位是哪一步造成延迟或质量下降，并回溯到具体提示词版本。主题对齐属于体验细节，给每个模型单开数据库会让链路割裂且难运维，把提示词导出成文件反而丢掉版本与权限控制。

**教材衔接：题号 4** — 对外接口做 PII 脱敏，更可靠的做法是？

**参考答案**：用识别器加正则先遮蔽再送检。

本题正确项是「用识别器加正则先遮蔽再送检」。脱敏必须发生在数据离开边界之前，命名实体识别配合正则能覆盖身份证、手机号这类稳定模式，替换成占位符后再交给模型或外部服务。让模型自己改写既不确定也来不及，删除所有数字会破坏业务语义，限长只是减少暴露面并不识别敏感字段。

**教材衔接：题号 5** — 下面这段 Promptfoo 配置字典，print 输出的两个数字对应什么？
import json
cfg = {'prompts': ['p1.txt', 'p2.txt'], 'providers': [{'id': 'openai:gpt-4o-mini'}], 'tests': [{'assert': [{'type': 'contains', 'value': '退款'}]}]}
print(len(cfg['prompts']), len(cfg['tests']))

**参考答案**：2 个提示词与 1 条用例。

本题正确项是「2 个提示词与 1 条用例」。prompts 列了两个模板文件，tests 只有一条用例，用例里挂着 contains 这一个断言，因此打印 2 和 1。providers 才是供应商列表且只有一项，把它与提示词数量混起来会得到错误的组合，tests 的长度也不等于断言条数的总和。
