## 本课主题是什么

本课主题是一组**要么全部成功、要么全部失败**的数据库操作。最典型的例子是转账：A 扣钱和 B 加钱必须同时生效。

```sql
BEGIN TRANSACTION;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;   -- 成功则提交
-- ROLLBACK;  -- 出错则回滚
```

## ACID 四大特性

| 特性 | 含义 |
| --- | --- |
| 原子性 Atomicity | 本课主题内操作不可分割，要么全做，要么全不做 |
| 一致性 Consistency | 本课主题前后数据满足约束与业务规则 |
| 隔离性 Isolation | 并发本课主题互不干扰 |
| 持久性 Durability | 提交后的数据不会因故障丢失 |

## 并发问题

- **脏读**：读到了别的本课主题尚未提交的数据。
- **不可重复读**：同一本课主题内两次读取同一行结果不同。
- **幻读**：同一本课主题内两次范围查询，第二次多出了新行。

## 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 | 不会 | 可能 | 可能 |
| 可重复读 | 不会 | 不会 | InnoDB 基本不会 |
| 串行化 | 不会 | 不会 | 不会 |

隔离级别越高，一致性越好，但并发性能越低。多数数据库默认使用「读已提交」或「可重复读」。

## 实战建议

1. 本课主题要尽量短，不要在本课主题里做网络请求或等待用户输入。
2. 统一按固定顺序访问多张表，降低死锁概率。
3. 捕获异常后显式 `ROLLBACK` 并释放连接。

```python
import sqlite3

conn = sqlite3.connect("demo.db")
try:
    with conn:                       # 自动提交或回滚
        conn.execute("UPDATE accounts SET balance = balance - 100 WHERE id = 1")
        conn.execute("UPDATE accounts SET balance = balance + 100 WHERE id = 2")
except sqlite3.Error as error:
    print("本课主题失败，已回滚：", error)
```

## 隔离级别的并发时序演示

以「本课主题 A 修改、本课主题 B 读取」为例（初始 balance = 100）：

| 隔离级别 | 时序 | B 读到 | 现象 |
| --- | --- | --- | --- |
| 读未提交 | A 改成 200（未提交）→ B 读 | 200 | 脏读（A 若回滚，B 读的是假数据） |
| 读已提交 | A 改成 200 → B 读 → A 提交 → B 再读 | 100 → 200 | 不可重复读（同一本课主题两次结果不同） |
| 可重复读 | A 改成 200 并提交 → B 读 → B 再读 | 100 → 100 | 快照读保持一致（InnoDB 默认） |
| 串行化 | B 读时 A 的写被阻塞 | 100 | 完全串行，性能最低 |

当前读（`SELECT ... FOR UPDATE`）不受快照影响，会读取最新已提交数据并加锁，因此**同一本课主题里快照读与当前读可能看到不同结果**，这是排查"读到旧数据"类问题的关键。

## 本课主题的常见错误写法

1. 在本课主题中调用外部 HTTP 接口 → 网络抖动导致长时间持锁，应把外部调用移到本课主题外。
2. 本课主题里做大批量操作（几十万行）→ 产生大本课主题，日志膨胀、锁范围大、回滚代价高，应分批提交。
3. 捕获异常后忘记 `ROLLBACK` → 连接被占用且锁不释放。
4. 依赖默认隔离级别却不清楚其行为 → 至少明确写下并测试预期并发行为。

## 本课小结
本课主题保证数据在并发与故障下仍然正确。记住 **ACID** 和三种并发异常，就能理解隔离级别的取舍。

## 隔离级别速查

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现要点 |
| --- | --- | --- | --- | --- |
| 读未提交（RU） | 可能 | 可能 | 可能 | 几乎不使用 |
| 读已提交（RC） | 不会 | 可能 | 可能 | 每次查询生成新快照 |
| 可重复读（RR） | 不会 | 不会 | InnoDB 基本不会 | 本课主题内首次读生成快照 + 间隙锁 |
| 串行化（SERIALIZABLE） | 不会 | 不会 | 不会 | 加锁串行执行，并发最低 |

并发异常对照：

| 异常 | 场景 | 现象 |
| --- | --- | --- |
| 脏读 | 读到别的本课主题未提交的数据 | 对方回滚后数据消失 |
| 不可重复读 | 同一本课主题内两次读同一行 | 值变了 |
| 幻读 | 同一本课主题内两次按条件查询 | 行数变了 |
| 丢失更新 | 两人同时「读、改、写」 | 后写覆盖前写 |

## 加锁与并发控制速查

| 目的 | 写法 | 说明 |
| --- | --- | --- |
| 读一行并锁住 | `SELECT ... FOR UPDATE` | 排他锁，别的本课主题不能改 |
| 只禁止别人改 | `SELECT ... FOR SHARE` | 共享锁 |
| 无锁读最新快照 | 普通 `SELECT` | MVCC 快照读 |
| 防超卖 | `UPDATE stock SET n = n - 1 WHERE id = ? AND n >= 1` | 用条件更新避免「先读再写」 |
| 乐观锁 | 版本号字段 + `WHERE version = ?` | 冲突时重试 |
| 悲观锁 | `FOR UPDATE` 先锁再算 | 并发高时容易排队与死锁 |
| 分布式锁 | Redis / ZooKeeper | 跨服务互斥，必须有过期与续期 |

```sql
BEGIN;
-- 悲观锁：锁定账户行，避免并发扣减读到同一个余额
SELECT balance FROM account WHERE id = 1 FOR UPDATE;
UPDATE account SET balance = balance - 100 WHERE id = 1;
COMMIT;
```

## 常见错误对照表

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 本课主题里包含网络调用或发消息 | 本课主题变长，锁等待、超时 | 本课主题只包数据库操作，外部调用放到本课主题外或用本地消息表 |
| 本课主题里做大批量导入 | 锁表、主从延迟 | 分批提交，控制本课主题大小 |
| 忘记 `COMMIT` | 数据没落库、锁不释放 | 用框架管理本课主题，显式检查提交路径 |
| `try` 里捕获异常后不回滚 | 半成品数据留在库里 | 异常路径必须 `ROLLBACK`，或让框架识别异常类型 |
| 把只读查询放进长本课主题 | 快照长期持有，undo 膨胀 | 只读本课主题尽早结束，避免大本课主题 |
| 用「先查询再更新」实现扣库存 | 并发超卖 | 用条件更新或加锁 |
| 长本课主题配合 DDL | 阻塞所有人 | DDL 用在线工具，避开业务高峰 |
| 嵌套本课主题期望独立回滚 | 内层回滚导致外层一起回滚 | 明确传播行为，或用保存点 `SAVEPOINT` |
| 本课主题里更新顺序不一致 | 死锁 | 固定资源访问顺序，缩短本课主题，必要时重试 |
| 以为 RR 下完全没有幻读 | 特殊语句仍可能出现 | 范围查询加锁场景要理解间隙锁行为 |

## 考点精讲

### 考点 1：ACID 中的 A 指的是？

- **判断依据**：A 是 Atomicity 原子性，表示事务内的操作要么全部成功，要么全部回滚。其他选项：A 是原子性（全部成功或全部失败）。判断这类题时，要把「原子性」放回题干限定的对象、输入和边界，「一致性」、「隔离性」 等说法虽然包含相关术语，但范围或前提与本题不一致。

### 考点 2：围绕“事务”中的 事务、ACID、隔离级别，下列哪两项是本课强调的实践判断？

- **判断依据**：正确答案包括「学习 事务 时要同时说明输入、输出和失败路径，不能只看正常流程」、「验证 ACID 时要固定版本并覆盖边界输入，结论才可复现」。本题应选学习 本课主题 时要同时说明输入、输出和失败路径（transaction 第 2 题）。在本课主题里，判断 ACID 时要固定版本与边界输入，所以“验证 ACID 时要固定版本并覆盖边界输入，结论才可复现”才可复现。解题的关键不是记住孤立术语，而是确认学习 本课主题 时要同时说明输入、输出和失败路径，不能只看正常流程。

### 考点 4：不可重复读与幻读的区别是？

- **判断依据**：可重复读级别通过 MVCC 解决不可重复读，靠间隙锁抑制幻读。其他选项：不可重复读是同一行的值被改动，幻读是结果集行数变化。这道题要求区分概念与边界，「不可重复读是同一行的值被改动」只有在题干给出的前提下才成立，而「不可重复读由插入引起」、「幻读只发生在读已提交级别」缺少同一组条件。

### 考点 5：MySQL InnoDB 的默认事务隔离级别是？

- **判断依据**：正确答案是「可重复读（REPEATABLE READ）」。默认级别配合 MVCC 与间隙锁，在一致性与并发之间取得平衡。判断这类题时，要把「可重复读（REPEATABLE READ）」放回题干限定的对象、输入和边界，「读未提交（READ UNCOMMITTED）」、「读已提交（READ COMMITTED）」 等说法虽然包含相关术语，但范围或前提与本题不一致。
