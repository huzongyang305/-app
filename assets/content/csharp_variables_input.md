## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 强类型 | 变量类型在编译期确定，类型不匹配不能通过编译。 | 易错：`强类型` 让类型不符当场编译失败，却挡不住合法类型里的非法值；`Console.ReadLine` 读回的字符串编译合法，仍要 TryParse 校验。 |
| var 与显式类型 | var 让编译器推断类型，类型本身仍然是静态的。 | 易错：`var` 按初始值推断后类型就固定，不是动态类型；换不兼容的值再赋会编译报错，声明时也不能省初始值。 |
| Console.ReadLine | 从标准输入读一行，返回 string?，可能为 null。 | 易错：把返回值当普通字符串直接用；它是 string?，读到空值时后面每一次访问都得先判空。 |
| 类型转换 | 用 int.Parse 或 int.TryParse 把字符串转成数字，后者不会抛异常。 | 易错：`int.Parse` 碰到非数字串直接抛 `FormatException`；改用 `int.TryParse` 并接住返回 false 的分支，别让异常打断计算。 |
| 程序集 | 程序集是部署和版本控制的基本单位，包含类型、方法和资源 | 易错：别把命名空间当文件夹、把程序集当源码目录；程序集是部署与版本单位、打包类型和资源，命名空间只组织名字不决定文件位置。 |
| 类型 | 结构体、枚举和大多数基元类型是值类型，赋值时复制内容；类、数组、委托和字符串是引用类型，赋值时复制引用 | 易错：值类型（struct）赋值复制内容、引用类型（class）赋值复制引用，改一个对象会牵动另一处；struct 频繁装箱才有额外分配成本。 |
| 核心结论 | C# 是强类型语言，变量先声明类型再使用；Console.ReadLine 返回字符串，要参与计算必须先转换。 | 易错：`Console.ReadLine` 只给字符串，先声明的类型编译期不会替你转换；参与算术前必须显式 TryParse，合法类型仍可能装着脏值。 |
| 最少要写的代码 | `using System;` | 这一行只是把 System 引进来好让 Console 可用；漏掉它是编译不过，跟运行期输入合不合法无关。 |
| 正确做法 | 输入「小明」后回车，name 得到「小明」。 | name 拿到的是字符串，能打印不等于能计算；下一步要参与算术就得先转换并处理失败分支。 |
| 最常见的错误 | 直接对 ReadLine 的结果做算术：它是字符串，编译器直接报错。 | 易错：`ReadLine() + 1` 这类字符串参与算术 C# 编译期就拦下；这跟运行期值合不合法是两码事，转成数字后仍要靠 TryParse 兜住脏输入。 |

### 编译、CLR 与程序集

C# 代码先编译成中间语言和元数据，运行时由 CLR 通过即时编译或提前编译转换为机器码。程序集是部署和版本控制的基本单位，包含类型、方法和资源。命名空间只负责组织名字，不决定物理文件位置。`dotnet new` 创建项目，`dotnet build` 编译，`dotnet run` 运行，`dotnet test` 执行测试，理解工具链能快速定位“编译失败”和“运行失败”。

### 类型、值与引用

C# 类型分为值类型和引用类型。结构体、枚举和大多数基元类型是值类型，赋值时复制内容；类、数组、委托和字符串是引用类型，赋值时复制引用。装箱把值类型转成对象，拆箱再转回来，频繁发生会增加分配和复制成本。`var` 只是让编译器推断类型，不会变成动态类型；`dynamic` 才把类型检查推迟到运行时。

### 方法、重载与参数

方法可以有重载、可选参数、命名参数、`params` 可变参数和扩展方法。重载根据参数列表选择，返回类型不参与。`ref`、`out`、`in` 控制参数的传递方式：`ref` 可读可写，`out` 必须在方法内赋值，`in` 只读引用。局部函数和 lambda 可以捕获外部变量，但要注意闭包生命周期和循环变量捕获。异步方法返回 `Task` 或 `Task<T>`，调用方通常使用 `await`。

### 集合、LINQ 与可空性

`List<T>`、`Dictionary<TKey,TValue>`、`HashSet<T>` 是最常用的泛型集合。LINQ 提供筛选、投影、分组、连接和聚合，延迟执行意味着查询只有在枚举时才真正运行；重复枚举可能重复计算或看到数据变化。可空引用类型在编译期提示可能的 null，公共方法仍要校验参数，边界层要把外部数据转换成有效对象。

### 资源管理与并发

实现 `IDisposable` 的对象应使用 `using` 或 `await using` 及时释放文件句柄、连接和锁。异常只用于异常情况，不要用异常处理正常分支。异步代码不要阻塞等待 `.Result` 或 `.Wait()`，否则可能造成线程池饥饿和死锁。并发集合、`lock`、`SemaphoreSlim` 和 `Channel` 各有适用场景，选择时要看清读写比例、公平性和取消需求。

### 选择与边界

- 使用 `强类型` 时，变量类型在编译期确定，类型不匹配不能通过编译；静态检查只在编译期成立，运行期输入仍需校验。

- 使用 `Console.ReadLine` 时，从标准输入读一行，返回 string?，可能为 null。
- 使用 `类型转换` 时，用 int.Parse 或 int.TryParse 把字符串转成数字，后者不会抛异常；易错：直接参与计算时抛格式异常；正确做法是用 TryParse 并处理失败分支。
- 使用 `程序集` 时，程序集是部署和版本控制的基本单位，包含类型、方法和资源；不同版本与依赖组合的行为可能不同，升级或换环境前要按官方变更说明重新验证。
