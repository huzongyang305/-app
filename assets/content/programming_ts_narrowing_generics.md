## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| TypeScript | 在 JavaScript 上增加静态类型系统的语言，编译后可运行在浏览器或 Node.js。 | 类型只活在编译期，编译产物是普通 JS，浏览器或 Node.js 运行时拿到的外部 JSON 不会被类型拦下。 |
| 类型收窄 | 在条件判断后让编译器知道变量属于更具体的类型。 | 收窄只改编译器观感，运行期实际值仍可能与窄化后的类型不符，来源是外部数据时还得靠守卫真校验。 |
| 泛型 | TypeScript 的类型能力集中在两处：收窄（把宽类型变窄） 与 泛型（让类型随输入变化）；掌握这两点，就能用类型把业务约束表达清楚。 | 泛型靠类型参数随输入变化，若 T 没出现在任何参数位置，编译器无从推断，只能回退成 unknown 或默认类型。 |
| 可辨识联合 | 可辨识联合 + switch 是建模业务状态最实用的模式：订单状态、请求结果、表单校验结果都可以这样写，新增一种状态时编译器会提示所有需要处理的位置。 | 判别字段要每个成员都带上且被推断成字面量，写成宽 string 时 switch 分不出分支，新增状态也不再提示漏处理。 |
| infer | TypeScript 在条件类型里声明待推断类型变量的关键字。 | infer 只在条件类型的 extends 右侧才有意义，写在别处或推断不出片段时会退化成 unknown，取不到想要的类型。 |
| 条件类型 | TypeScript 根据类型关系在编译期选择结果类型的类型运算 | 条件类型是编译期运算，输入若是 any 会让真假两个分支同时命中，得出意料之外的结果类型。 |
| typeof | 区分 string/number/boolean 等原始类型 | typeof 的返回值只精确到 string、number、boolean 这几类原始值，object、数组、null 都挤在一起，靠它区分对象会判错。 |
| instanceof | 区分类实例 | 只对类构造出来的实例管用，`string`、`number` 这些原始值得走 typeof，数组归 Array.isArray，别当万能开关。 |
| in | 判断属性是否存在 | 键在不在和值是不是空是两回事；只判了键就去取嵌套字段，仍会撞上类型守卫只判一层的报错。 |
| 可辨识联合 | 用共同字段（如 `type`）区分成员，配合 switch 穷尽检查 | 共同字段要每个成员都带上；switch 不写 default 兜底，新增一种状态时编译器就不会提示漏处理。 |
| 类型守卫 | 自定义 `x is T` 函数或断言函数 `asserts x is T` | 返回的 `x is T` 只是对编译器的承诺，函数体没真把字段查一遍就等于给 `as` 换皮，坏数据照样放行。 |
| typeof | `if (typeof v === "string")` | 只分得出 string、number、boolean 这几类原始值，数组要走 Array.isArray，类实例要走 instanceof。 |
| 真值判断 | `if (v) {}` | 它会把 0 和空字符串也当成假，误杀合法值；只想排除空值时应改用 `if (v != null)` 那一种。 |
| 空值判断 | `if (v != null)` | 只挡外层这一个值，嵌套里的字段还要逐层判；用 `obj!.field` 顶替它会把 TypeError 留到运行期。 |
| in 运算符 | `if ("id" in v)` | 判断只在这个分支里生效，出了分支变量就退回宽类型；键名要写成字符串字面量才认。 |
| instanceof | `if (e instanceof Error)` | `e` 只在这个 if 分支里算 Error，换个分支再取 message 照样报错，要复用就得封装成守卫。 |
| 字面量判别 | `if (r.status === "ok")` | status 得推断成 `"ok"` 这个字面量而不是宽 string，否则比不出分支；必要时用 `as const` 把推断变窄。 |
| 自定义类型守卫 | `function isUser(v: unknown): v is User` | 函数体里要真把字段查一遍；只挂签名不做检查等于给 `as` 换皮，外部 JSON 仍得靠运行时校验。 |
| 断言函数 | `function assert(cond: unknown): asserts cond` | 它只在调用之后的代码里生效，条件不满足就直接抛错中断流程，替不了对数据的真实校验。 |
| Array.isArray | `if (Array.isArray(v))` | 它只证明这是个数组，元素类型还推不出来，数组里的每个元素仍要逐个再收窄一次。 |
| 穷尽检查 | `default: const _x: never = v;` | 易错：新增状态漏处理；正确做法是用穷尽检查兜底。 |
| 联合类型 A \| B | 命中任一分支即可，用之前要先窄化 | 窄化只在当前控制流内有效，变量被重新赋值或传到别的函数就失效；判一次不会全程有效。 |
| 收窄 | 开箱验货 | 易错：类型检查失效，错误延后到线上；正确做法是用 unknown + 类型守卫逐层收窄。 |
| 泛型 | 可调模具 | 模具要按来料定型：调用时不显式传类型参数、T 又不体现在入参上，泛型套不出具体形状只能退成 unknown。 |
| 约束 extends | 模具的尺寸范围 | 约束只要求「至少具备该形状」，写成具体类就把调用方挡在门外；按字段取值时用 `K extends keyof T` 更稳。 |
| 类型守卫 | 贴标签 | 标签由自己贴，编译器不复核：`is` 断言标错就把值窄化到错误分支，问题留到运行期暴露。 |
| typeof | 原始类型判断 | 只有原始值才交给 typeof，对象、数组、null 都会被它一并说成 object，误用会窄化到错误分支。 |
| instanceof | 类实例判断 | 开箱验货时它只管验类实例这一格，原始值和数组分别归 typeof、Array.isArray，验错格子等于没验。 |
| in | 判断某个属性是否存在 | 各分支的键不一样时才用它分辨；守卫只判这一层，嵌套字段还得再往下逐层校验。 |
| 字面量字段（可辨识联合） | 状态机、事件对象 | 判别字段得被推断成 `"ok"` 这样的字面量而非宽 string，少了 `as const` 时 switch 分不出状态，收窄随之失效。 |
| 自定义类型守卫 | 外部数据校验 | 标签是人为承诺，编译器不替你查字段；`JSON.parse(text) as User` 编译能过，运行时照样缺字段。 |
| 用 as 强行断言 | 运行时照样出错 | `as` 只改编译器怎么看，不改数据本身；来源是外部 JSON 时要换成守卫或 zod 这类真校验。 |
| 泛型没用上参数 | 推断成 unknown | 写了 `<T>` 却没让 T 出现在参数或返回位置，调用时无从推断，T 直接落成 unknown，泛型形同虚设。 |
| 约束写太死 | 调用方传不进去 | 易错：调用方传不进去；正确做法是用 `keyof` 等结构性约束。 |
| 忘了处理 null | `strictNullChecks` 报错 | 把 `strictNullChecks` 关掉报错就没了，空值风险也一起藏进运行期；正解是先判空或用 `?.`。 |
| 类型守卫只判一层 | 嵌套字段仍报错 | 易错：嵌套字段仍报错；正确做法是逐层校验。 |
| 用 any 绕过报错 | 类型安全全丢 | any 让编译器彻底放弃检查，用它顶掉报错等于把类型安全全丢掉，错误被推迟到运行期才炸。 |
| 默认分支不写 assertNever | 新增状态漏处理 | switch 的 default 不拿 `never` 兜底时，联合类型多加一个成员编译器不会报警，漏处理的状态悄悄走到运行期。 |
| 泛型嵌套太深 | 没人看得懂 | 易错：没人看得懂；正确做法是拆成命名类型。 |

## 原理与运行机制

### 机制总览

**教材衔接：泛型与约束**

泛型让函数与组件在保持类型安全的前提下复用：`function first<T>(list: T[]): T | undefined`。约束用 `extends`：`<T extends { id: number }>` 要求必须有 id；默认类型参数 `<T = string>` 提供缺省。

**教材衔接：版本与时效**

- 版本提示：TypeScript 的行为在最近几个大版本里有过调整，升级「TypeScript 类型收窄与泛型」前先用 message 复现当前输出，再对照官方发布说明逐条核对。

## 典型应用场景

- **用 `as` 强行断言**：典型现象是运行时照样出错；正确做法是用类型守卫真校验。
- **泛型没用上参数**：典型现象是推断成 unknown；正确做法是让 T 出现在参数位置。
- **约束写太死**：典型现象是调用方传不进去；正确做法是用 `keyof` 等结构性约束。
- **忘了处理 `null`**：典型现象是`strictNullChecks` 报错；正确做法是先判空或用 `?.`。

## 代码/协议/SQL 示例

### 最小可验证示例

```ts
type Result =
  | { status: "ok"; data: string }
  | { status: "error"; message: string };

function render(result: Result): string {
  switch (result.status) {
    case "ok":
      return result.data;        // 自动收窄到 ok 分支
    case "error":
      return result.message;
    default: {
      const never: never = result;   // 新增成员时这里会编译报错
      return never;
    }
  }
}
```

**教材衔接：泛型约束速查**

| 写法 | 含义 |
| --- | --- |
| `<T>` | 任意类型 |
| `<T extends object>` | 必须是对象类型 |
| `<T extends { id: string }>` | 至少具备该形状 |
| `<T extends keyof U>` | 只能是 U 的键 |
| `<T = string>` | 提供默认类型参数 |
| `<T extends string \| number>` | 联合约束 |
| `function f<T>(x: T): T` | 返回值与入参类型联动 |
| `ReturnType<typeof f>` | 取函数返回值类型 |
| `Parameters<typeof f>[0]` | 取第一个参数类型 |
| `as const` | 让字面量推断变窄 |

```ts
// 约束 + keyof：安全地按字段取值
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

const users = [{ id: 1, name: "小明" }];
const names = pluck(users, "name");   // string[]
// pluck(users, "age");               // 编译报错，及时发现问题
```
