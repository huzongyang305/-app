## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 协程 | 可挂起和恢复的轻量执行单元，由运行时或语言调度。 | 易错：调度器被占用，并发能力下降；正确做法是使用挂起函数并选择合适的调度器。 |
| suspend | Kotlin 协程中的挂起标记，函数可在不阻塞线程的情况下暂停并稍后恢复。 | 易错：在 suspend 函数里写阻塞调用；线程没被挂起反而被占住，调度器并发能力下降，取消也得等下个挂起点。 |
| Flow | Kotlin 的冷异步数据流，按需依次发出值并支持背压与取消。 | 冷流每个订阅者各自触发一次生产，多处同时收集就重复请求；要共享得改用热流并定好重放策略。 |
| 取消 | 协程的协作式取消：取消会传播到子协程，挂起点抛出取消异常，需在 finally 里释放资源。 | 易错：页面退出后任务仍在运行；正确做法是用作用域管理并在耗时点检查取消。 |
| 结构化并发 | 让子任务的生命周期受父作用域约束的并发模型 | 易错：子任务起在父作用域之外，取消不向下传播，页面退出后仍在运行；父作用域只约束它管理的子任务。 |

## 典型应用场景

**课程内置实验入口**：`sandbox:kotlin`，用于动手验证《Kotlin 协程与 Flow》的机制；实验结论不替代概念定义与复杂度分析。

- **在协程里阻塞线程**：典型现象是调度器被占用，并发能力下降；正确做法是使用挂起函数并选择合适的调度器。
- **取消不向下传播**：典型现象是页面退出后任务仍在运行；正确做法是用作用域管理并在耗时点检查取消。
- **冷流被重复订阅**：典型现象是重复请求与资源浪费；正确做法是需要共享时使用共享流并明确重放策略。

### 选择与边界

- 使用 `协程` 时，可挂起和恢复的轻量执行单元，由运行时或语言调度；易错：调度器被占用，并发能力下降；正确做法是使用挂起函数并选择合适的调度器。
- 使用 `suspend` 时，Kotlin 协程中的挂起标记，函数可在不阻塞线程的情况下暂停并稍后恢复；共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。
- 使用 `Flow` 时，Kotlin 的冷异步数据流，按需依次发出值并支持背压与取消。
- 使用 `取消` 时，协程的协作式取消：取消会传播到子协程，挂起点抛出取消异常，需在 finally 里释放资源；易错：页面退出后任务仍在运行；正确做法是用作用域管理并在耗时点检查取消。
- 使用 `结构化并发` 时，让子任务的生命周期受父作用域约束的并发模型；共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。
