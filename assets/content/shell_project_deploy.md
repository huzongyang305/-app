## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| Bash | 常见 Unix Shell，用命令、变量、管道和脚本组合自动化系统任务。 | 本课靠 set -euo pipefail 管住命令返回非零、未定义变量与管道中任一命令失败，再配 shellcheck 零告警才算静态检查到位。 |
| 部署 | 把构建产物、配置和依赖发布到目标环境并使其可对外服务。 | 易错：把构建、上传与切换混成一段，失败时说不清是制品还是软链的问题；三段要能各自单独重跑并留下日志。 |
| 健康检查 | 周期性探测进程或依赖是否可服务，并据此摘除或重启实例。 | 易错：切完流量才发现服务异常；正确做法是切换前验证健康检查与关键接口。 |
| 回滚 | 用 Bash 实现构建、切换、健康检查和自动回滚的部署脚本。 | 易错：脚本没写回滚分支，失败后停在中途服务不可用；切换前先记下当前版本，健康检查不过就退回旧版本。 |
| 幂等 | 本课涉及：Bash、部署、健康检查、回滚、幂等。 | 易错：同一版本连跑两次多出副本、软链指向也变了；要用幂等键和锁文件让第二次运行不产生新副作用并拦住并发调用。 |
| Shell | 接收命令并调用操作系统程序的命令行解释器与脚本环境 | 本课只聚焦 Bash 5 / POSIX Shell 这一层：切换靠 ln -sfn 换软链，构建、上传、切换要拆成能各自重跑的三段。 |

```text
用户/输入 → 接口或命令 → 领域逻辑 → 存储/外部依赖 → 输出与监控
```

### 验收场景

1. 正常路径：最小输入得到预期输出，并留下日志与指标。
2. 边界路径：部署 在重复提交与超长输入下不产生额外副作用。
3. 失败路径：依赖超时或不可用时能快速失败、重试或降级。
4. 幂等路径：同一请求执行两次不会产生重复副作用。
5. 回滚路径：撤掉 APP_DIR 的变更后，数据与资源都回到变更前的状态。

### 选择与边界

- 使用 `Bash` 时，常见 Unix Shell，用命令、变量、管道和脚本组合自动化系统任务。
- 使用 `部署` 时，把构建产物、配置和依赖发布到目标环境并使其可对外服务；易错：发布失败后停在中途，服务不可用；正确做法是记录当前版本并实现一键回滚。
- 使用 `健康检查` 时，周期性探测进程或依赖是否可服务，并据此摘除或重启实例；易错：切完流量才发现服务异常；正确做法是切换前验证健康检查与关键接口。
- 使用 `回滚` 时，用 Bash 实现构建、切换、健康检查和自动回滚的部署脚本；易错：发布失败后停在中途，服务不可用；正确做法是记录当前版本并实现一键回滚。
- 使用 `幂等` 时，本课涉及：Bash、部署、健康检查、回滚、幂等；隔离级别与并发事务会影响可见性，换级别或换存储引擎后要重新验证。

## 代码/协议/SQL 示例

### 最小可验证示例

**教材衔接：示例数据与边界**

**教材衔接：关键代码**

```bash
#!/usr/bin/env bash
set -euo pipefail

APP_DIR=/srv/app
VERSION=$(git rev-parse --short HEAD)
NEW_DIR="$APP_DIR/releases/$VERSION"

mkdir -p "$NEW_DIR"
rsync -a --delete ./dist/ "$NEW_DIR/"
```
