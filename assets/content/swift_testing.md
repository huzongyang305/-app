### 从最小示例走到能进流水线的测试

`assert` 只在本地有效，一失败就把整个程序停下，也报不出用例名。写成测试目标里的用例，才能单独跑、单独看结果：

```swift
import XCTest

func minutesToSeconds(_ minutes: Int) -> Int { minutes * 60 }

final class ConversionTests: XCTestCase {
    func testZeroAndNegative() {
        XCTAssertEqual(minutesToSeconds(0), 0)
        XCTAssertEqual(minutesToSeconds(-1), -60)
    }
}
```

```bash
swift test --filter ConversionTests/testZeroAndNegative
```

Xcode 里点用例左边的灰点只跑一条，按 Cmd+U 跑整个目标；命令行用 `--filter 类名/方法名`，回归时先复现失败那一条。预期输出：

```text
Test Case '-[ConversionTests testZeroAndNegative]' passed (0.001 seconds).
Executed 1 test, with 0 failures (0 unexpected) in 0.001 seconds
```

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 只测正常路径 | 异常分支没有覆盖。 | 覆盖失败、超时与空数据。 |
| 测试依赖真实网络 | 测试慢且不稳定。 | 用假实现替换外部依赖。 |
| 性能测试没有基线 | 无法判断是否回归。 | 记录基线并在流水线中自动比较。 |
