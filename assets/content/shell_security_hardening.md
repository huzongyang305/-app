## 典型应用场景

- **直接执行外部输入**：典型现象是留下命令注入风险；正确做法是校验输入并避免拼接命令。
- **脚本权限过宽**：典型现象是任意用户都能修改或执行；正确做法是限制文件权限与属主。
- **敏感信息写在脚本里**：典型现象是泄露范围难以收敛；正确做法是改用环境变量或密钥管理服务。

### 选择与边界

- 使用 `命令注入` 时，先满足它的定义：攻击者把 Shell 元字符拼进命令参数，使服务执行未预期的系统命令；易错：留下命令注入风险；正确做法是校验输入并避免拼接命令。
- 使用 `权限` 时，先满足它的定义：主体对资源允许执行的操作集合，访问时必须在服务端校验；易错：任意用户都能修改或执行；正确做法是限制文件权限与属主。

### 考点 7：`命令注入`

- **要点**：攻击者把 Shell 元字符拼进命令参数，使服务执行未预期的系统命令。
- **命令注入 的边界**：易错：留下命令注入风险；正确做法是校验输入并避免拼接命令。

### 考点 8：`权限`

- **要点**：主体对资源允许执行的操作集合，访问时必须在服务端校验。
- **权限 的边界**：易错：任意用户都能修改或执行；正确做法是限制文件权限与属主。

### 考点 9：`临时文件`

- **要点**：脚本用的中间文件：要用 mktemp 生成、设好权限并及时清理，否则有被抢占或泄露的风险。
- **临时文件 的边界**：权限与密钥策略变化会让结论失效，按最小权限并用真实凭据流程复验。
