## 本节知识框架

想象你开了一家蛋糕店。你有一张"蛋糕配方"（类），上面写着需要什么原料、怎么烘烤；而每一位顾客拿到的蛋糕（对象），都是按这张配方做出来的具体成品。Python 的面向对象编程（OOP）就是这套"配方→成品"的思维工具。

**本课主线**：构造方法、封装、继承多态、dataclass 与魔术方法。

**学完本课你应当能够**
- 用自己的话解释 `__init__` 和 `class` 分别是什么，并各举一个正例和一个反例。
- 运行本课示例，观察对象的行为，记录输入、输出与出错情况。
- 遇到"忘了写 `self`"这类报错时，能快速定位并修复。

**先修与衔接**：本课是 Python 分类的第 12 课。先修内容为《列表、元组、字典与集合》。后续课程包括《异常处理与文件操作》、《类与面向对象》、《继承、接口与多态》、《对象、原型与类》。

## 核心概念定义

下面这些术语是理解面向对象的基础。别急着一口气全记住——先混个脸熟，后面每节都会反复出现。

| 术语 | 一句话解释（类比） | 常见坑 |
| --- | --- | --- |
| 类（class） | 一张"图纸"或"模具"，定义了对象长什么样、能做什么。就像蛋糕配方。 | 静态检查只在编译期成立，运行期输入仍需校验。 |
| 对象（实例） | 按图纸造出来的"实物"。就像按配方做出的那块蛋糕。 | 用可变对象作类属性会导致所有实例共享同一个列表。 |
| `__init__` | 构造方法——对象"出生"时自动执行的初始化流程。就像蛋糕出炉后自动涂奶油。 | 忘记在 `__init__` 里创建实例属性，会导致共享状态。 |
| self | 指向"对象自己"。就像每块蛋糕知道自己叫什么名字。 | 忘了写 self 会报 TypeError。 |
| 实例属性 | 每个对象独有的数据。就像每块蛋糕有自己的口味和重量。 | 可变默认值应放在 `__init__` 里。 |
| 类属性 | 所有对象共享的数据。就像配方上写的"品牌名"，所有蛋糕都一样。 | 可变的类属性最容易被误改。 |
| 封装 | 把数据藏起来，只通过方法访问。就像把保险箱锁上，只留一个取钱口。 | 直接改 `_` 属性会绕过校验。 |
| 继承 | 在已有图纸基础上做修改，不用从零画起。就像在基础蛋糕上加水果变水果蛋糕。 | 继承层次过深会改一处牵动全身。 |
| 多态 | 同一个指令，不同对象有不同反应。就像你说"叫！"，狗汪汪叫，猫喵喵叫。 | 需要配合继承使用。 |
| 魔术方法 | Python 内置的"暗号"方法，如 `__str__`、`__eq__`，让对象支持内置操作。 | 实现了 `__eq__` 后 `__hash__` 会被置空。 |

## 原理与运行机制

### 从配方到蛋糕：面向对象的运行流程

让我们用"开蛋糕店"的类比来理解整个过程：

**第一步：设计图纸（定义类）**

你先在纸上写下蛋糕的配方——需要什么原料（属性），怎么加工（方法）。在 Python 里，这就是用 `class` 关键字定义一个类。

**第二步：开工生产（实例化对象）**

每当有顾客下单，你就按配方做一块蛋糕。`Dog("旺财", 3)` 这样的调用就像下了一张订单——Python 会先创建一块"空白蛋糕"，然后自动调用 `__init__` 给它"涂奶油"（初始化属性）。

**第三步：使用成品（调用方法与属性）**

蛋糕做好了，你可以查看它的信息（访问属性），也可以让它执行动作（调用方法）。当你 `print(dog)` 时，Python 会自动调用 `__str__` 方法，就像给蛋糕贴上一张可读的标签。

### 三条设计建议

1. **一个类只做一件事**——方法围绕同一份数据，就像一把瑞士军刀不如专用工具可靠。
2. **优先组合而不是深层继承**——把对象作为属性嵌入，就像乐高积木拼接，而不是俄罗斯套娃层层嵌套。继承不超过两层。
3. **数据简单时用 `@dataclass`**——不要手写一堆样板代码，就像有现成模板就不用每次从头写邮件。

### 魔术方法速查表

| 魔术方法 | 什么时候被触发 | 常见用途 |
| --- | --- | --- |
| `__init__` | 创建实例后 | 初始化属性 |
| `__repr__` | `repr()`、调试器、容器展示 | 给开发者看的精确描述 |
| `__str__` | `print()`、`str()` | 给用户看的友好文本 |
| `__eq__` | `==` | 定义相等语义 |
| `__hash__` | `hash()`、放进 `set`/`dict` 键 | 不可变对象才适合哈希 |
| `__len__` | `len(obj)` | 容器类语义 |
| `__getitem__` | `obj[key]` | 支持下标与切片 |
| `__iter__` | `for x in obj` | 定义可迭代行为 |
| `__enter__` / `__exit__` | `with obj:` | 上下文管理（自动释放资源） |
| `__call__` | `obj()` | 让实例像函数一样被调用 |

## 典型应用场景

面向对象几乎在 every Python 项目里都会用到。下面列举几个最典型的场景，帮你建立直觉。

**场景 1：用类组织相关数据和行为**
当你发现一组函数总是在操作同一份数据时，就该把它们打包成一个类。比如一个银行账户——余额（数据）和存款、取款（行为）天然属于同一个类。

**场景 2：用继承减少重复代码**
如果你有"猫"和"狗"两个类，它们都需要"吃"和"睡"的方法，那就抽出一个"动物"父类，让猫和狗继承它。就像连锁店的各个分店共享总店的运营手册，但可以有各自的特色。

**场景 3：用封装保护数据安全**
银行账户的余额不应该被直接修改——必须通过"存款"和"取款"方法，这样才能检查金额是否合法。封装就像给数据加了一把锁。

**场景 4：用 dataclass 快速创建数据容器**
当你只需要一个"数据包裹"（比如坐标点、配置项），用 `@dataclass` 可以省掉大量样板代码。就像用现成的快递盒，不用自己裁纸板。

### 选择与边界

- 使用 `__init__` 时，先确保 `self` 作为第一个参数，并在其中创建实例属性（而不是用可变对象作类属性）。
- 使用 `class` 时，记住它只是模板——静态检查只在编译期成立，运行期输入仍需校验。
- 使用继承时，优先组合，继承不超过两层，并确保调用 `super().__init__(...)`。

## 代码/协议/SQL 示例

### 示例 1：最小可验证示例——定义一只狗

```python
class Dog:
    species = "犬科"          # 类属性，所有实例共享——就像所有狗都属于犬科

    def __init__(self, name, age):
        self.name = name      # 实例属性——每只狗有自己的名字
        self.age = age        # 实例属性——每只狗有自己的年龄

    def bark(self):
        return f"{self.name} 在叫"

    def __str__(self):        # 打印对象时的显示内容
        return f"Dog({self.name}, {self.age})"

dog = Dog("旺财", 3)
print(dog.bark(), dog.species)  # 输出：旺财 在叫 犬科
```

**逐行解读**：
- `class Dog:` —— 画出图纸
- `species = "犬科"` —— 所有狗共享的信息，写在类里
- `def __init__(self, name, age):` —— 每只狗"出生"时要填的信息
- `self.name = name` —— 把名字记到这只狗自己的档案里
- `dog = Dog("旺财", 3)` —— 按图纸造一只叫旺财、3岁的狗

### 示例 2：封装——保护银行账户

```python
class Account:
    def __init__(self, balance=0):
        self._balance = balance      # 单下划线：约定内部使用，别直接碰

    @property
    def balance(self):               # 只读属性——只能看，不能直接改
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("金额必须为正")
        self._balance += amount

account = Account()
account.deposit(100)
print(account.balance)               # 输出：100，像属性一样访问，实际调用方法
```

**类比**：`_balance` 就像保险箱里的钱，`@property` 就像保险箱上的透明窗口——你能看到余额，但想改钱必须通过存款/取款方法。

### 示例 3：继承与多态——动物说话

```python
class Animal:
    def speak(self):
        raise NotImplementedError

class Cat(Animal):
    def speak(self):
        return "喵"

class Duck(Animal):
    def speak(self):
        return "嘎"

for animal in [Cat(), Duck()]:
    print(animal.speak())     # 输出：喵 \n 嘎 —— 同一个方法名，行为不同
```

**类比**：你对一群动物说"叫！"——猫喵喵叫，鸭子嘎嘎叫。指令相同，反应各异，这就是多态。

子类用 `super().__init__(...)` 调用父类构造方法，就像分店开业时先执行总店的标准化流程，再添加自己的特色。

### 示例 4：数据类——简洁的坐标点

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

a = Point(1, 2)
b = Point(1, 2)
print(a == b)          # True，dataclass 自动生成 __eq__
```

**类比**：`@dataclass` 就像自动填表——你只需要声明"我有 x 和 y 两个字段"，Python 自动帮你生成 `__init__`、`__repr__`、`__eq__` 等方法。

**运行方式**：保存为 `.py` 文件后用 `python 文件名.py` 运行；第三方依赖先在虚拟环境里安装。

## 时间/空间复杂度或性能分析

### 性能关注点

面向对象的主要开销来自解释执行与对象分配。创建大量小对象时，内存和 GC（垃圾回收）压力是需要关注的重点。

**本课特有开销**：
- **类定义**：类本身的定义在模块加载时执行一次，开销可忽略。
- **实例创建**：每次 `Dog("旺财", 3)` 都会分配内存并调用 `__init__`，小规模使用几乎无感；大规模创建（如百万级对象）时需要测量。
- **属性查找**：`dog.name` 会触发属性查找链（实例 → 类 → 父类），比局部变量访问稍慢。

### 测量方法

以本课的 `Dog` 类为例，固定输入跑一遍记录基线，再把对象数量提高一个数量级复测；两次结果的差值才是结论依据。

```text
# 测量示例（使用 timeit）
python -m timeit "Dog('旺财', 3)" "from mymodule import Dog"
```

### 优化手段

| 手段 | 适用场景 | 效果 |
| --- | --- | --- |
| `__slots__` | 需要创建大量实例 | 减少内存，阻止动态添加属性 |
| `@dataclass` | 数据容器 | 减少手写样板，性能与普通类相当 |
| 类属性缓存 | 不变的计算结果 | 避免重复计算 |
| 组合替代继承 | 继承层次过深 | 减少方法解析链长度 |

### 需要控制的变量

- 固定 Python 版本（3.12+），不同版本的对象分配策略可能不同。
- 固定输入规模，分别记录创建时间、内存峰值与 GC 次数。
- 达到边界时不要外推，必须重新测量。

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 忘了写 `self` | `TypeError: takes 1 positional argument but 2 were given` | 实例方法第一个参数必须是 `self` |
| 用可变对象作类属性 | 所有实例共享同一个列表 | 在 `__init__` 里创建实例属性 |
| 直接改 `_` 属性 | 绕过校验，数据不一致 | 提供方法或 `@property` |
| 继承层次过深 | 改一处牵动全身 | 优先组合，继承不超过两层 |
| 忘了调用 `super()` | 父类初始化没执行 | `super().__init__(...)` |
| 用 `is` 比较对象值 | 结果不符预期 | 实现 `__eq__` 并用 `==` |
| 把类当函数用 | 忘了加括号 | `Dog("旺财")` 才是实例 |
| 只用 `__eq__` 不写 `__hash__` | 类变成不可哈希，无法放进 `set` | 定义了 `__eq__` 后 `__hash__` 会被置空 |
| 直接访问 `self.__x` | `AttributeError` | 双下划线会被改名成 `_类名__x` |
| `@property` 里写耗时 IO | 访问属性变慢且难察觉 | 属性应是廉价操作 |

### 现场排错 1：忘了写 `self`

**症状**：`TypeError: takes 1 positional argument but 2 were given`。

**根因**：Python 调用实例方法时会自动把对象本身作为第一个参数传入。如果你没在定义时写 `self`，Python 还是会传一个参数进来，方法就会"多收一个参数"而报错。

**修复**：实例方法第一个参数必须是 `self`。

### 现场排错 2：用可变对象作类属性

**症状**：所有实例共享同一个列表。

**根因**：类属性在类定义时只创建一次。如果你写 `items = []` 在类里，所有实例会共享同一个列表。

**修复**：在 `__init__` 里创建实例属性：`self.items = []`。

### 现场排错 3：把类当函数用

**症状**：忘了加括号，拿到的是类本身而不是实例。

**根因**：`Dog` 是类（图纸），`Dog("旺财")` 才是实例（蛋糕）。

**修复**：`Dog("旺财")` 才是实例。

| 魔术方法 | `__str__`、`__eq__`、`__len__` 等，让对象支持 Python 内置操作。 |

**术语关系链**：`class`（图纸）→ `__init__`（开工指令）→ `对象`（成品）→ `实例属性`（成品上的具体信息）。
