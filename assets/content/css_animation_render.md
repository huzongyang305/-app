## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 渲染 | 浏览器把 HTML/CSS 转成屏幕上可见像素的过程，动画性能取决于是否触发重排、重绘或合成。 | 小规模元素动画流畅，但大量元素同时动画可能导致卡顿，需要重新评估性能策略。 |
| 回流（重排） | 浏览器重新计算元素位置和大小的过程，比如改变宽度、高度、位置等，这是最耗性能的操作。 | 每次改变元素几何属性都会触发，连续多次改变会严重影响性能。 |
| 重绘 | 浏览器重新绘制元素外观的过程，比如改变颜色、背景等，但不影响元素的位置和大小。 | 比回流快，但频繁重绘仍会影响性能。 |
| 动画 | 用 transition 或 @keyframes 描述属性随时间变化；只动 transform 与 opacity 才能留在合成层，获得最佳性能。 | 易错：使用 left/top/width 等属性做动画会触发回流；正确做法是使用 transform 和 opacity。 |
| 合成 | 浏览器将页面的不同层组合成最终图像的过程，通常使用 GPU 加速，性能最好。 | 只有特定属性（如 transform 和 opacity）能触发合成。 |

## 原理与运行机制

### 机制总览

**教材衔接：浏览器渲染过程**

想象一下浏览器就像一个画家，它需要经过几个步骤才能完成一幅画：

1. **解析 HTML 建 DOM**：读取 HTML 文档，创建文档对象模型（DOM 树）
2. **样式计算**：读取 CSS，确定每个元素的样式规则
3. **布局（Reflow）**：计算每个元素在页面上的确切位置和大小
4. **绘制（Paint）**：将元素绘制到屏幕上的具体像素
5. **合成（Composite）**：将不同图层合并成最终显示的图像

其中，布局和绘制是最耗性能的步骤。

| 阶段 | 触发条件 | 性能代价 |
| --- | --- | --- |
| 解析 HTML 建 DOM | 首次加载或结构变化 | 高 |
| 样式计算 | 选择器匹配、变量变化 | 中 |
| 布局（Reflow） | 几何属性变化（宽高、位置等） | 高，需要重新计算布局 |
| 绘制（Paint） | 颜色、阴影、背景变化 | 中 |
| 合成（Composite） | transform / opacity 变化 | 低，可走 GPU 加速 |

![浏览器渲染管线](images/browser_rendering_pipeline.webp)

**教材衔接：动画性能优化**

| 属性类型 | 性能 | 原因 |
| --- | --- | --- |
| transform / opacity | 最好 | 只触发合成，走 GPU 加速 |
| 位置、尺寸（left, top, width, height） | 较差 | 触发回流和重绘 |
| 颜色、背景 | 中等 | 只触发重绘 |

**教材衔接：动画实现方式**

| 方式 | 特点 | 适用场景 |
| --- | --- | --- |
| CSS transition | 简单的状态切换动画，性能好 | 按钮悬停、菜单展开等 |
| CSS animation + @keyframes | 复杂的多阶段动画，性能好 | 页面入场、图标动画等 |
| JavaScript 动画 | 灵活控制，但性能较差 | 需要复杂逻辑控制的动画 |

要点：优先使用 transform 和 opacity 做动画，避免使用 left、top、width、height 等会触发回流的属性。

## 典型应用场景

- **流畅的按钮悬停效果**：使用 transform 做按钮的悬停动画，避免页面抖动。
- **卡片翻转动画**：使用 transform 和 opacity 实现卡片的翻转效果，性能良好。
- **页面入场动画**：使用 transform 实现元素的滑入效果，不会影响页面布局。
- **布局偏移（CLS）**：典型现象是图片、广告、字体加载后尺寸变化；正确做法是预留宽高、`aspect-ratio`、`font-display`。

### 最小验证场景

- 准备：创建一个简单的 div 元素，准备测试不同的动画方式。
- 观察：先使用 transform 做动画，再使用 left 属性做动画，比较性能差异。
- 判定：transform 动画应该更加流畅，不会触发回流。

### 选择与边界

- 使用 `transform` 时，先满足它的优势：不触发回流和重绘，利用 GPU 加速；这种优化在大多数现代浏览器中有效。
- 使用 `opacity` 时，先满足它的优势：只触发合成，性能优异；适用于淡入淡出效果。
- 使用 `left/top/width/height` 时，先了解它们的缺点：会触发回流，性能较差；尽量避免在动画中使用。

**教材衔接：动画方式速查**

| 方式 | 性能 | 适用场景 |
| --- | --- | --- |
| CSS 过渡与动画 | 高（可走合成） | 大多数交互动画 |
| Web Animations API | 高 | 需要 JS 控制的动画 |
| JS 改样式逐帧 | 低 | 尽量不用 |
| `requestAnimationFrame` | 中 | 需要逐帧计算的场景 |

```css
/* 推荐：只动画 transform 与 opacity - 性能最佳 */
.card {
  transition: transform 200ms ease, box-shadow 200ms ease;
}

.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 4px 8px rgba(0,0,0,0.1);
}

/* 入场动画：避免使用 top/left/margin */
@keyframes slide-in {
  from {
    opacity: 0;
    transform: translateY(12px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.list-item {
  animation: slide-in 220ms ease-out both;
}

/* 避免：这些属性会触发回流 */
.bad-animation {
  transition: left 200ms ease, width 200ms ease; /* 触发回流，性能差 */
}

.bad-animation:hover {
  left: 10px;
  width: 200px;
}

/* 尊重用户的减少动效偏好 */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**教材衔接：深入理解浏览器渲染与 CSS 动画**

前面我们了解了基本概念。现在我们来看浏览器渲染的具体流程和如何优化动画性能。

### 一、核心模型

浏览器渲染把 HTML/CSS 转成像素，动画性能取决于是否触发重排、重绘或合成。优先使用 transform 和 opacity，避免在动画中频繁读写布局属性。

```text
HTML 解析 → DOM → CSSOM → 渲染树 → 布局 → 绘制 → 合成 → 屏幕
```

### 二、关键机制拆解

1. 布局计算元素几何位置，改变宽高、边距、字体等会触发布局（回流）。
2. 绘制填充像素，改变颜色、阴影和背景会触发重绘。
3. 合成把图层交给 GPU 合并，transform 和 opacity 通常只触发合成，性能最好。
4. requestAnimationFrame 与浏览器刷新同步，适合逐帧动画。
5. 动画要尊重 prefers-reduced-motion，为敏感用户提供减少动态效果。

### 三、对照表：容易混淆的动画方式

| 动画属性 | 触发 | 性能 |
| --- | --- | --- |
| transform / opacity | 合成（GPU 加速） | 最好 |
| left / top / right / bottom | 回流（重新布局） | 最差 |
| color / background | 重绘 | 中等 |
| width / height / margin / padding | 回流（重新布局） | 最差 |

### 四、工作示例

实现元素移动时使用 `transform: translateX()`，而不是修改 `left`。前者通常走合成层，利用 GPU 加速，后者每帧触发布局和绘制，容易造成卡顿。

### 五、常见误区与失效边界

| 错误做法 | 后果 | 正确做法 |
| --- | --- | --- |
| 动画 width/left/top | 每帧重排，卡顿明显 | 改用 transform 和 opacity |
| 不考虑无障碍需求 | 用户可能感到不适 | 用 `prefers-reduced-motion` 尊重用户偏好 |
| 忽略低端设备 | 桌面流畅、手机卡顿 | 在真实设备上测试动画性能 |

### 六、场景推演

假设你需要做一个卡片悬停效果，当鼠标悬停时卡片向上移动并添加阴影。正确的做法是使用 transform，而不是改变 top 值：

错误做法：
```css
.card:hover {
  top: -4px; /* 触发回流 */
}
```

正确做法：
```css
.card:hover {
  transform: translateY(-4px); /* 只触发合成 */
}
```

### 七、自测问答

**Q1：为什么 transform 动画比 left 动画更流畅？**

A: transform 通常只触发合成，利用 GPU 加速，而 left 会触发布局（回流），需要重新计算元素位置，性能消耗大得多。

**Q2：什么是回流和重绘？**

A: 回流（重排）是重新计算元素位置和大小，重绘是重新绘制元素外观。回流比重绘更消耗性能。

**Q3：哪些 CSS 属性适合做动画？**

A: transform 和 opacity 最适合，因为它们只触发合成，性能最好。

**Q4：为什么要考虑无障碍需求？**

A: 部分用户对动态效果敏感，使用 `prefers-reduced-motion` 可以为他们提供更舒适的浏览体验。

### 需要关注的性能指标

- `浏览器渲染与 CSS 动画` 的 `动画`：关注帧率是否稳定在 60fps，是否有卡顿现象。
- `浏览器渲染与 CSS 动画` 的 `回流`：关注是否频繁触发，影响页面流畅度。
- `浏览器渲染与 CSS 动画` 的 `重绘`：关注是否在必要时触发，避免不必要的重绘。

## 常见误区与易错点

| 容易犯错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 布局偏移（CLS） | 图片、广告、字体加载后尺寸变化 | 预留宽高、`aspect-ratio`、`font-display` |
| 图片抖动 | 未设置尺寸 | 写 `width`/`height` 或用 `aspect-ratio` |
| 字体闪烁 | 字体文件较晚加载 | `font-display: swap` 并预加载关键字体 |
| 滚动条跳动 | 内容高度变化 | 预留占位或固定容器高度 |
| 动画 left/top/width/height | 每帧重排，卡顿明显 | 改用 transform 和 opacity |
| 用 `top`/`left` 做动画 | 每帧触发布局，掉帧 | 改用 `transform` |
| 用 `margin` 做位移动画 | 触发布局 | 用 `transform: translate` |
| 图片不设尺寸 | 布局偏移 | 预留宽高或用 `aspect-ratio` |
| 动画不尊重减少动效 | 部分用户感到不适 | 用 `prefers-reduced-motion` |

### 现场 1：布局偏移（CLS）

**症状**：图片、广告、字体加载后尺寸变化，导致页面内容突然跳动。

**根因与修复**：预留宽高、`aspect-ratio`、`font-display`。

**自检**：在项目中确保所有媒体元素都有预设尺寸，使用 aspect-ratio 保持比例。

### 现场 2：动画性能差

**症状**：动画卡顿、掉帧。

**根因与修复**：避免使用会触发回流的属性，改用 transform 和 opacity。

**自检**：检查动画使用的 CSS 属性，确保使用的是性能友好的属性。

### 现场 3：忽略无障碍需求

**症状**：动画可能让用户感到不适。

**根因与修复**：使用 `prefers-reduced-motion` 尊重用户偏好。

**自检**：在项目中添加媒体查询，检测用户是否开启了减少动效选项。
