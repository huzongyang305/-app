## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| Object.prototype | 访问属性时会沿原型链向上查找，直到 Object.prototype，仍找不到才返回 undefined。 | 拿到 `undefined` 也说明不了属性不存在，可能值本身就是 `undefined`；判存在要改用 `in` 或 `Object.hasOwn`。 |
| class | class 是原型继承的语法糖，但语义更清晰，extends 会自动维护原型链。 | 派生类构造器里必须先 `super` 才能碰 `this`，父类的 `#field` 私有字段子类也读不到。 |
| JSON | 用对象、数组、字符串和数字等表示结构化数据的文本格式。 | 易错：比的是引用；正确做法是逐字段比较或用 `JSON.stringify`。 |
| 原型链 | 属性查找会沿原型向上追溯，class 只是原型继承的语法糖。 | 链上的属性是共享的：改了原型对象，已经建好的实例跟着一起变；再用 `obj.constructor` 判类型还容易被伪造。 |
| 读取可能不存在的属性 | `obj?.a?.b` | 只在遇到 `null` 或 `undefined` 时短路；属性存在但值是 `0` 或空串仍会继续往右取。 |
| 取默认值 | `obj.a ?? "默认"` | 只有 `null` 和 `undefined` 才取默认值；`0`、空串、`false` 会原样保留，别把它当判空兜底。 |
| 解构并重命名 | `const { a: x, b = 1 } = obj` | 重命名后本地变量是 `x` 而不是 `a`；`b` 的默认值仅在该属性值为 `undefined` 时才生效。 |
| 剩余属性 | `const { a, ...rest } = obj` | `rest` 只收自身的可枚举属性，不含原型链上的键；里层嵌套属性仍是共享引用。 |
| 合并对象 | `{ ...a, ...b }` | 后展开的 `b` 会整键覆盖 `a` 的同名键，且嵌套字段仍指向同一引用。 |
| 复制并改字段 | `{ ...user, name: "新名字" }` | 只生成新的顶层对象，未改到的嵌套属性仍与原对象共用同一引用。 |
| 安全修改嵌套字段 | `{ ...s, user: { ...s.user, age: 18 } }` | 路径每一层都要展开，漏一层引用就不变；`s.user` 为 `undefined` 时展开会报错，需先判空。 |
| 取键 / 值 / 键值对 | `Object.keys/values/entries` | 只返回自身可枚举属性，拿不到原型链上的键；传入 `null` 或 `undefined` 会抛 `TypeError`。 |
| 转成 Map | `new Map(Object.entries(obj))` | 只会带进对象自身的可枚举属性，原型链上的键丢失；且键仍全是字符串。 |
| 冻结对象 | `Object.freeze(obj)` | 只锁当前一层，嵌套对象仍可改；改冻结属性在非严格模式静默失败，严格模式抛错。 |
| 判断自有属性 | `Object.hasOwn(obj, "key")` | 只认自身属性，原型链上的同名键会返回 `false`；要连继承一起判就得改用 `in`。 |
| 对象 | 一张信息卡 | 易错：把卡当值传来传去；`user.email = ...` 会同时反映到每个引用它的变量上，要一份独立的就写 `{ ...user }`。 |
| 属性 | 卡片上的条目 | 易错：键还在；正确做法是用 `delete obj.k`。 |
| 方法 | 卡片能做的事 | `greet()` 内部靠 `this.name` 取名字：方法只是挂在卡上的函数，调用方式一变 `this` 就不再是这张卡，取值会错甚至抛错。 |
| 原型 | 家族遗传 | `cat` 自己没有 `speak`，`hasOwnProperty` 返回 false 却照样能调用；只按自身键统计条目时这份遗传会被漏掉。 |
| 解构 | 按需摘取 | 键名要和源对象的属性名对齐；源为 `null` 或 `undefined` 时直接抛错，数组解构按下标取值。 |
| obj.method() | `obj` 本身 | 点号调用时 `this` 才绑定到 `obj`；方法被单独取出再调用就丢 `this`，要 `bind` 或箭头函数。 |
| fn() 直接调用 | 严格模式下是 `undefined` | 非严格模式直接调用时 `this` 落到 `globalThis` 而非 `undefined`，会悄悄写到全局对象。 |
| new Fn() | 新建的对象 | 漏写 `new` 直接调用时 `this` 就不再是新建对象；严格模式下变成 `undefined` 直接抛错。 |
| 箭头函数 | 继承定义时的外层 `this`，不受调用方式影响 | 正因 `this` 在定义时就定死，把它当卡片方法写反而拿不到调用者；需要按调用方绑定时得用普通函数或 `bind`。 |
| "k" in obj | 含 | `in` 会沿原型链向上查，原型上的同名键也返回 `true`；只想看自身属性得改用 `Object.hasOwn`。 |
| Object.hasOwn(obj, "k") | 只查自身 | 键继承自原型链时返回 `false`；要判含继承来的键必须改用 `in`，两者口径不同别混用。 |
| obj.k !== undefined | 含（沿链） | 分不清键不存在还是键值本就是 `undefined`，还会沿原型链匹配，不能当作判存在的依据。 |
| if (obj.k) | 含 | 易错：0、空串被当成不存在；正确做法是用 `in` 或 `Object.hasOwn`。 |
| 用 if (obj.k) 判存在 | 0、空串被当成不存在 | 键存在但值是 `0`、`""`、`false` 时同样被当成不存在；要判存在改用 `in` 或 `Object.hasOwn`。 |
| 对象赋值当复制 | 改一处全变 | 判据是赋值后 `copy === user` 仍为 `true`；只有改成 `{ ...user }` 或 `structuredClone`，这个等式才不再成立。 |
| 浅拷贝嵌套对象 | 内层仍互相影响 | 易错：内层仍互相影响；正确做法是用 `structuredClone`。 |
| 方法被单独取出 | `this` 丢失 | 把 `user.greet` 当回调交出去时，调用方身上已经没有 `user`，`this` 落空；包一层箭头函数或先 `bind` 才保得住。 |
| 遍历时用 for...in | 拿到继承来的键 | 会沿原型链把可枚举属性一起遍历进来；只要自身键就改用 `Object.keys` 或 `entries` 并用 `Object.hasOwn` 过滤。 |
| 用对象当 Map | 键只能是字符串或 Symbol | 易错：键只能是字符串或 Symbol；正确做法是需要任意类型键就用 `Map`。 |
| 删除属性用 = undefined | 键还在 | 只改值不删键，`in`、`Object.keys` 里仍看得到它；要真正移除得用 `delete obj.k`。 |
| 比较对象用 === | 比的是引用 | 内容相同的两个字面量用 `===` 仍返回 false，因为它只认引用；要判是否等价得逐字段比或退一步用 `JSON.stringify`。 |

## 典型应用场景

- **用 `if (obj.k)` 判存在**：典型现象是0、空串被当成不存在；正确做法是用 `in` 或 `Object.hasOwn`。
- **对象赋值当复制**：典型现象是改一处全变；正确做法是用展开做浅拷贝。
- **浅拷贝嵌套对象**：典型现象是内层仍互相影响；正确做法是用 `structuredClone`。
- **方法被单独取出**：典型现象是`this` 丢失；正确做法是用 `bind` 或箭头函数。

- 使用 `Object.prototype` 时，先满足它的定义：访问属性时会沿原型链向上查找，直到 `Object.prototype`，仍找不到才返回 `undefined`。

- 使用 `JSON` 时，先满足它的定义：用对象、数组、字符串和数字等表示结构化数据的文本格式；易错：比的是引用；正确做法是逐字段比较或用 `JSON.stringify`。

## 代码/协议/SQL 示例

### 最小可验证示例

```javascript
const user = {
  name: 'tom',
  'favorite color': 'blue',
  greet() { return `你好 ${this.name}`; },
};

user.name;                      // 点号访问
user['favorite color'];         // 键含空格时用方括号
user.email = 'tom@example.com'; // 新增属性
delete user.email;              // 删除属性

Object.keys(user);              // 键数组
Object.entries(user);           // [[key, value], ...]
const copy = { ...user, city: '上海' };   // 浅拷贝 + 合并

const { name, age = 0 } = user;  // 解构 + 默认值
```

**教材衔接：原型链**

```javascript
const animal = { speak() { return '...'; } };
const cat = Object.create(animal);

cat.speak();                       // 沿原型链找到 speak
Object.getPrototypeOf(cat) === animal;
cat.hasOwnProperty('speak');       // false：属性在原型上
```

访问属性时会沿原型链向上查找，直到 `Object.prototype`，仍找不到才返回 `undefined`。

**教材衔接：class 语法**

```javascript
class Animal {
  #secret = 'private';            // 私有字段
  static category = 'animal';

  constructor(name) { this.name = name; }
  speak() { return `${this.name} 发出声音`; }
  get label() { return this.name.toUpperCase(); }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);                  // 必须先调用 super
    this.breed = breed;
  }
  speak() { return `${super.speak()}：汪`; }
}
```

`class` 是原型继承的语法糖，但语义更清晰，`extends` 会自动维护原型链。

**教材衔接：Map、Set 与 JSON**

```javascript
const map = new Map([['a', 1]]);   // 键可以是任意类型，保留插入顺序
const set = new Set([1, 1, 2]);    // 自动去重，size = 2

JSON.stringify({ a: 1 });          // 对象 → 字符串
JSON.parse('{"a":1}');             // 字符串 → 对象
Object.freeze(obj);                // 冻结对象
```

**教材衔接：class 与原型速查**

| 概念 | 说明 |
| --- | --- |
| `class Dog extends Animal` | 语法糖，底层仍是原型链 |
| `super()` | 子类构造器中必须先调用，才能使用 `this` |
| `#field` | 真正的私有字段，外部无法访问 |
| `static` | 挂在类本身而非实例上 |
| `get` / `set` | 属性访问器，可做校验 |
| `instanceof` | 沿原型链判断类型 |
| `Object.getPrototypeOf(obj)` | 查看原型对象 |
| `obj.hasOwnProperty(k)` | 是否为自身属性（推荐 `Object.hasOwn`） |

```js
class Counter {
  #count = 0;                       // 私有字段
  static created = 0;

  constructor() {
    Counter.created += 1;
  }

  increment() {
    this.#count += 1;
    return this;
  }

  get value() {
    return this.#count;
  }
}

new Counter().increment().increment().value;   // 2，支持链式调用
```
