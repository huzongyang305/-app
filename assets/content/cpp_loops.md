## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| for 循环 | 把初始化、条件、更新写在一行，适合次数确定的循环。 |
| while 循环 | 条件为真就执行，适合次数由运行情况决定的循环。 |
| do-while | 先执行一次再判断条件，循环体至少执行一次。 |
| break 与 continue | `break` 结束整个循环，`continue` 跳过本轮剩余语句。 |
| 循环变量作用域 | 在 `for` 的括号里声明的变量只在循环内可见。 |
| 无限循环 | 条件永远为真的循环，必须用 `break` 或外部条件退出。 |
| 循环嵌套 | 一个循环体内再放一个循环，总迭代次数是内外两层次数相乘。 |
| 循环不变式 | 每轮开始前都成立、循环退出时能直接推出结论的性质，用来把"跑一次对不对"变成"逻辑上一定对"。 |
| 范围 for 循环 | `for (auto x : container)` 由编译器代管迭代器，遍历容器时最省写法。 |
| 哨兵值 | 用一个约定输入告诉循环"到此为止"，常见于次数不定的读入。 |

## 原理与运行机制

### for 循环：计数器式重复

```cpp
for (int i = 0; i < 5; ++i) {
    std::cout << i << " ";
}
// 输出：0 1 2 3 4
```

`for` 循环把三件事写在一行：
1. **初始化** `int i = 0`：循环开始前做一次
2. **条件** `i < 5`：每轮开始前检查，为假就停
3. **更新** `++i`：每轮结束后做一次

把它想象成跑步训练：先站到起跑线（初始化），每跑一圈看是否到了 5 圈（条件），跑完一圈就计数器加 1（更新）。

### while 循环：条件式重复

```cpp
int n = 100;
while (n > 1) {
    if (n % 2 == 0) n = n / 2;
    else n = 3 * n + 1;
    std::cout << n << " ";
}
```

`while` 只关心条件：条件为真就执行循环体，条件为假就退出。适合"不知道要循环多少次，但知道什么时候该停"的场景。

### do-while：至少执行一次

```cpp
int choice;
do {
    std::cout << "请输入 1-3：";
    std::cin >> choice;
} while (choice < 1 || choice > 3);
```

`do-while` 先执行循环体，再检查条件。这意味着循环体**至少执行一次**。适合"先做一次，不满意就重来"的场景，比如菜单选择。

### break 与 continue

```cpp
for (int i = 0; i < 10; ++i) {
    if (i == 5) break;       // i 到 5 就彻底退出循环
    if (i % 2 == 0) continue; // 偶数就跳过本轮剩余代码
    std::cout << i << " ";
}
// 输出：1 3
```

- `break`：立刻结束整个循环，跳到循环后面的代码
- `continue`：跳过本轮循环体剩余的代码，直接进入下一轮

### ++i 与 i++

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << i;
}
// 输出：012
```

在 `for` 循环的更新表达式里，`++i` 和 `i++` 效果完全相同——都让 `i` 加 1。它们的区别只在作为表达式使用时才体现（`++i` 先加后用，`i++` 先用后加），但作为独立的更新语句没有差别。

### 循环嵌套：把两层 for 拆成表

C++ 允许一个循环体里再放一个循环。上一节的九九乘法表就是典型嵌套：外层 `i` 从 1 到 9 控制行，内层 `j` 从 1 到 `i` 控制列。每一轮外层 `i`，内层都会从头跑到尾——总迭代次数是两层次数相乘，而不是相加。

写嵌套循环时有两个习惯能少出错：

1. **给每层循环一个明显的角色名**：外层叫 `row`、内层叫 `col`，比 `i/j/k` 更容易看清依赖关系。
2. **让每层循环独立可测**：把内层的表达式先单独打印出来，一次只改外层或一次只改内层，观察输出矩阵的形状变化。

嵌套层数直接决定复杂度上限——三层各 100 次的循环就是 1,000,000 次操作。动笔前先估算"最坏情况总共跑多少次"，比事后拿 profiler 追因更划算。

### 循环不变式：为什么循环停下时结果是对的

一个循环能不能信，靠的不是"跑一次看输出对不对"，而是**循环不变式**——一个每轮开始前都成立、退出时能直接给出结论的命题。

以"求 1..n 的和"为例：

```cpp
int sum = 0;
int i = 1;
while (i <= n) {
    sum += i;
    ++i;
}
// 不变式：sum == 1 + 2 + ... + (i - 1)
```

进入循环前 `i = 1, sum = 0`，不变式成立；每一轮 `sum += i; ++i` 让右边同步扩一项，不变式仍然成立；退出时 `i == n + 1`，代入不变式得到 `sum == 1 + 2 + ... + n`。这样"停下的那一刻 sum 就是答案"就有了逻辑依据，而不是运气。

日常写代码不必每步都写证明，但心里过一遍"这一轮改完之后，什么等式还成立"，就能挡掉大多数少算一次或多算一次的问题。

### 范围 for：让迭代器代管

C++11 起，只要目标是容器或数组，都可以不写循环变量：

```cpp
#include <vector>

std::vector<int> nums{4, 8, 15, 16, 23, 42};
int evens = 0;
for (int x : nums) {
    if (x % 2 == 0) ++evens;
}
```

编译器会自动展开为 `begin()/end()` 上的迭代，把每个元素拷进 `x`。要省掉拷贝就写 `const int& x`；要就地修改就写 `int& x`。**千万不要在范围 for 里对容器 push_back 或 erase**——迭代器会失效，属于未定义行为，本课"常见误区与易错点"表里那一行说的就是这条。

## 典型应用场景

循环是编程中最常用的结构之一：

- **遍历数据**：逐个处理数组或列表中的每个元素
- **累加计算**：求 1+2+...+100 的和
- **重复提示**：直到用户输入合法值为止
- **搜索**：在一堆数据中查找目标
- **模拟**：重复执行某个过程直到收敛

### 一个实际的小例子

```cpp
#include <iostream>

int main() {
    int sum = 0;
    for (int i = 1; i <= 100; ++i) {
        sum += i;
    }
    std::cout << "1 到 100 的和是：" << sum << "\n";
    return 0;
}
```

输出：`1 到 100 的和是：5050`

### 场景：哨兵值结束输入

有时候你不知道用户要输入多少个数，只知道"输入 -1 就算结束"：

```cpp
#include <iostream>

int main() {
    const int SENTINEL = -1;
    int x = 0, count = 0;
    long long sum = 0;
    std::cout << "输入整数，输入 -1 结束：\n";
    while (std::cin >> x && x != SENTINEL) {
        sum += x;
        ++count;
    }
    if (count > 0) {
        std::cout << "共 " << count << " 个数，平均 "
                  << static_cast<double>(sum) / count << "\n";
    } else {
        std::cout << "一个数都没输入\n";
    }
    return 0;
}
```

这段代码把三条路径都覆盖了：正常累计、只输入哨兵（`count == 0`）、`std::cin` 失败（输入不是整数时 `>>` 返回 false 直接跳出循环）。写循环时不要只测正常流程，把"空输入""只有一个元素""最大规模"这三档一起跑一遍，才算把结论钉死。

### 场景：反复逼近直到收敛

牛顿迭代求平方根是"次数不固定，靠条件退出"的典型：

```cpp
#include <cmath>

double sqrtNewton(double a) {
    if (a < 0) return -1.0;      // 失败路径：负数返回哨兵
    if (a == 0) return 0.0;      // 边界：0 单独处理，避免除零
    double x = a;
    int guard = 0;
    while (guard++ < 100) {      // 硬上限，防止极端输入死循环
        double nx = 0.5 * (x + a / x);
        if (std::abs(nx - x) < 1e-9) break;
        x = nx;
    }
    return x;
}
```

`guard++ < 100` 是一个安全阀：理论上迭代到 `|Δx| < 1e-9` 就会 `break`，但如果浮点精度或异常输入让它永远达不到，100 次后强制退出，程序不会挂死。给不确定的循环加一个上限，是入门阶段最廉价也最关键的一道保险。

### 场景：字符串里数字母频率

把嵌套循环和数组配合起来，可以统计一句话里每个字母出现了几次：

```cpp
#include <iostream>
#include <string>

int main() {
    std::string s;
    std::getline(std::cin, s);
    int freq[26] = {0};
    for (char c : s) {
        if (c >= 'a' && c <= 'z') ++freq[c - 'a'];
        else if (c >= 'A' && c <= 'Z') ++freq[c - 'A'];
    }
    for (int i = 0; i < 26; ++i) {
        if (freq[i] > 0) std::cout << char('a' + i) << ":" << freq[i] << " ";
    }
    std::cout << "\n";
}
```

外层负责"遍历输入"，内层负责"遍历统计结果"，两者角色分明；把 `++freq[c - 'a']` 单独拎出来测一下大小写字母混排有没有漏计，比把整个程序重跑一遍更快定位错。空字符串（外层循环一次都不进）与"只包含空格和数字"（`freq` 全零）就是这段代码的两条边界。

### 完整示例：九九乘法表

```cpp
#include <iostream>

int main() {
    for (int i = 1; i <= 9; ++i) {
        for (int j = 1; j <= i; ++j) {
            std::cout << j << "x" << i << "=" << i * j << "\t";
        }
        std::cout << "\n";
    }
    return 0;
}
```

### 动手练一练

- 用 `for` 循环输出 1 到 100 中所有偶数
- 用 `while` 循环实现：不断读取输入，直到用户输入 0 为止
- 用 `do-while` 实现：要求用户输入一个正数，输入不对就重新提示

### 边界三件套：0 次 / 1 次 / 最大次数

写完循环先跑这三档：

```cpp
#include <iostream>

long long sumTo(int n) {
    long long s = 0;
    for (int i = 1; i <= n; ++i) s += i;
    return s;
}

int main() {
    for (int n : {0, 1, 1000000}) {
        std::cout << "n=" << n << " sum=" << sumTo(n) << "\n";
    }
}
```

期望结果：

- `n = 0`：循环一次都不跑，`sum = 0`。这一档最容易漏——`i <= n` 从 1 开始，条件直接为假。
- `n = 1`：只跑一轮，`sum = 1`。
- `n = 1000000`：如果累加器用 `int` 会溢出（5e11 超过 2^31），必须换成 `long long` 才可信。

同一份代码固定编译器版本、固定 `-O2` 或 `-O0`、固定输入规模跑一次，把三档结果记录到注释里；换机器或换编译选项再复跑一次，两次结果的差值才是能引用的结论。

## 时间/空间复杂度或性能分析

循环是时间复杂度的主要来源：

- 一层 `for` 循环从 0 到 n：O(n)
- 两层嵌套循环：O(n^2)
- 循环体内有常数操作：不改变量级

注意：循环次数很多时（百万级以上），循环体内的操作效率就变得重要。避免在循环内做不必要的内存分配或函数调用。

### 步长不是 1 时怎么算次数

循环次数约等于 `(终止值 − 起始值) / 步长`，向上取整。

- `for (int i = 0; i < n; i += 2)`：约 `n / 2` 次，量级仍是 O(n)。
- `for (int i = 1; i < n; i *= 2)`：`⌈log₂ n⌉` 次，是 O(log n)。二分查找、平衡树的高度都长这样。
- `for (int i = n; i > 0; i /= 2)`：同样 O(log n)。

看到 `i *= 2` / `i /= 2` 就条件反射地想"这是 log 级"，看到 `i++` / `i += k` 想"这是线性"，比死记表更可靠。

### 循环体的缓存友好性

同样是从 0 到 `n*n` 的迭代次数，按行扫描二维数组通常比按列扫描快几倍。原因是 CPU 缓存抓的是一整行内存，`a[i][j]` 按 `j` 递增访问正好命中缓存；`a[j][i]` 每次跳一整个 stride，缓存几乎全 miss。写循环时把最内层循环的下标对齐到内存里的连续方向，是入门阶段能立刻见效的一条性能技巧，也是本课"两层嵌套 O(n^2)"结论在实际机器上会漂几倍的常见原因。

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 边界差一（off-by-one） | 少循环一次或多循环一次 | 仔细检查 `<=` 还是 `<` |
| 用无符号数反向遍历 | 减到 0 后回绕成很大的数，循环不结束 | 用带符号下标，或先判断再自减 |
| 循环里修改容器大小 | 迭代器失效，程序崩溃 | 不要在范围 for 里增删元素 |
| `continue` 与 `break` 混用 | 逻辑混乱，循环提前结束 | `break` 跳出整体，`continue` 只跳本轮 |
| 忘记更新循环变量 | 无限循环 | 确认 `for` 的第三个表达式或 `while` 体内有更新 |
| 循环条件写成赋值 `=` | 条件恒真或恒假，行为诡异且没有编译错误 | 打开 `-Wall`，编译器会警告 "suggest parentheses around assignment" |
| 每轮重复求值的昂贵条件 | 例如 `i < v.size()` 在 `std::vector` 变动时反复算 | 把不变量提到循环外，或改用范围 for |
| 范围 for 里增删容器 | 迭代器失效，可能当场崩溃或结果错乱 | 需要边遍历边删就改用 `std::erase_if` 或显式迭代器 |

### 现场 1：用无符号数反向遍历

**症状**：循环不结束，或者访问了越界的下标。

**根因与修复**：无符号数减到 0 后再减 1 会回绕成最大值。用带符号下标，或先判断再自减。

### 现场 2：忘记更新循环变量的死循环

**症状**：程序看起来卡住，CPU 占用 100% 但没有任何输出。

**根因与修复**：`while` 里没有让条件趋近 false 的语句。以"读到 0 停止"为例：

```cpp
int x = 1;
while (x != 0) {
    std::cin >> x;   // 若漏掉这句，x 永远是初值，循环永不退出
}
```

修法是先明确"这一轮里谁向终止条件靠近"，如果找不到，就说明循环结构写错了。对不确定的循环再加一层 `guard` 计数上限兜底，是最后一道保险。

### 现场 3：`break` 与 `continue` 用反

**症状**：本该跳过奇数的循环，跑了两轮就整体退出。

**根因与修复**：`break` 是"整个循环到此为止"，`continue` 是"这一轮到此为止、下一轮继续"。以筛选偶数为例：

```cpp
for (int i = 0; i < 10; ++i) {
    if (i % 2) continue;   // 奇数：跳过本轮，进入下一轮
    std::cout << i << " "; // 偶数：打印
}
// 输出：0 2 4 6 8
```

如果这里错写成 `break`，`i == 1` 就会终止整个循环，永远看不到 2、4、6、8。判断标准很直接：**只想忽略一个元素就 `continue`，整个任务已经达成就 `break`**。

## 与其他知识点的关系

- **先修课**：《C++ 条件判断》——循环条件本质上是每轮都要重新求值的布尔表达式。
- **后续课**：《C++ 函数入门》——循环体一旦超过十几行就应该抽成函数；《STL 容器与算法》用范围 for、`std::for_each` 与算法取代手写计数器。
- **相关概念**：《时间复杂度》（算法与数据结构）——嵌套层数与每层迭代次数直接相乘，循环结构是复杂度结论的主要来源。
- **相关概念**：《内存与缓存》——二维数组按行遍历远快于按列遍历，同样的迭代次数会因为缓存命中率差出数倍。
- **跨语言对照**：`for (int i = 0; i < n; ++i)` 对照 Python 的 `range(n)` 与 Java 的增强 for，关键差别是 C++ 把循环变量的作用域直接声明在括号里，出了括号就不可见；本课的无符号下标回绕问题在《变量、类型与运算符》里还会继续讨论。

### 循环与浮点误差

`for (double x = 0; x < 1.0; x += 0.1)` 里，`x` 因为二进制表示 `0.1` 不精确，可能永远差一点点不到 `1.0`，或者多走一轮踩到边界。入门阶段的规矩是：**循环变量用整数**，需要浮点时用 `x = i * 0.1` 现算，别让浮点数当累加器；比较浮点用 `std::abs(a - b) < eps` 而不是 `a == b`。这条坑与《变量、类型与运算符》和后续《误差与浮点数》直接相连。

### 循环与函数抽取

循环体一旦超过十几行，就该像下一课《C++ 函数入门》里那样抽成函数：外层 `for` 只负责"遍历"，函数负责"对每个元素做什么"。这样循环不变式可以搬到函数签名上——参数是输入、返回值是输出——可读性和可测性都会明显提升。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `for 循环` | 把初始化、条件、更新写在一行，适合次数确定的循环。 |
| `while 循环` | 条件为真就执行，适合次数由运行情况决定的循环。 |
| `do-while` | 先执行一次再判断条件，循环体至少执行一次。 |
| `break` | 立刻结束整个循环，跳出后执行循环后面的语句。 |
| `continue` | 只跳过本轮剩余语句，直接进入下一次条件判断。 |
| `循环变量作用域` | 在 `for` 的括号里声明的变量只在循环内可见。 |
| `无限循环` | 条件永远为真，必须用 `break` 退出。 |
| `循环嵌套` | 一个循环体里再放另一个循环，总次数是两层相乘。 |
| `循环不变式` | 每轮开始前都为真、退出时能直接给出结论的性质。 |
| `范围 for 循环` | `for (auto x : container)`，由编译器代管迭代器。 |
| `哨兵值` | 用一个约定输入告诉循环"到此为止"。 |
