## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 变量 | 类型与变量：九种语言横向对照解决了什么问题，而不是只背术语。 | 声明写法与默认语义各家不同：Shell 的 `x=1` 存进去是字符串，Rust 不写 `mut` 连重新赋值都不允许，照搬别家习惯当场就编不过。 |
| 不可变 | 对象创建后状态不再改变，更新时生成新对象，从而减少共享状态和并发错误。 | 易错：以为 `const`、`val` 锁住了对象内容；它只挡重新赋值，对象内部字段照样能改，共享出去仍会被并发改坏。 |
| 装箱与拆箱 | 值类型转成堆上对象再取回，每次都会分配或复制，是循环里常见的隐形开销。 | 只在值类型被当成对象用时才发生：循环里反复装箱把对象头开销放大成热路径瓶颈，包装值为空时取回又直接抛空指针。 |
| 隐式转换 | 编译器自动完成的类型转换，可能静默丢精度或改变比较结果，跨类型运算时要显式写清。 | 易错：隐式转换与溢出行为完全不同；正确做法是先查目标语言的数据模型与转换规则再迁移代码。 |
| Python | `x = 1` | 类型运行期才确定；`"1" + 1` 这类类型错误编译期拦不住，跑到才抛 `TypeError`。 |
| JavaScript | `let x = 1` | 隐式转换最容易踩坑：`"1" + 1` 拼成 "11"，`"1" - 1` 又算成 0；运算前要显式 `Number` 转换。 |
| TypeScript | `let x: number = 1` | 注解只在编译期拦截，转译后类型消失；数据来自运行期外部输入时这条保障不再存在。 |
| Java | `int x = 1;` | 类型编译期定死；数字与字符串相加看顺序：`1 + 2 + "a"` 得 "3a"，`"a" + 1 + 2` 得 "a12"。 |
| C# | `int x = 1;` | 数字与字符串直接相加要先注意顺序；示例给出的更安全的写法是插值 `$"{1 + 1}"`。 |
| C++ | `int x = 1;` | 两个整数相除是这条声明的经典坑：`double a = 5 / 2;` 得 2.0，要 2.5 须写 `5 / 2.0`。 |
| Go | `x := 1` | `:=` 推断出类型后就定死；不能像别的语言那样混着浮点用，须写 `b := float64(a) + 1.5`。 |
| Rust | `let mut x = 1;` | 不写 `mut` 就无法重新赋值；`mut` 也不让整数浮点混算，`1i32` 仍要显式 `as f64` 再参与运算。 |
| Shell | `x=1` | 存进去的是字符串不是数字：`echo "$a + 2"` 原样输出 "1 + 2"，要 `b=$((a + 2))` 才得 3。 |
| 静态 / 动态 | 类型在编译期还是运行时确定 | 它只回答类型何时确定，不说检查严不严：静态语言也有靠反射与强转才暴露的问题，动态语言则一次编译期拦截都没有。 |
| 强 / 弱 | 是否允许隐式跨类型转换 | 易错：把强类型当成静态类型；Python 强而动态、JavaScript 弱而动态，这一维只看敢不敢自动跨类型，与何时检查无关。 |
| 显式 / 推断 | 是否必须手写类型 | 推断省掉的只是书写：右侧表达式一确定结果就定死，它既不替你判空，也不改变可变性，更不能当成动态类型。 |
| 可变 / 不可变 | 默认能否重新赋值 | 各语言默认不同：Rust 要加 `mut`、Kotlin 用 `val`、TS 用 `const`；别把一门语言的默认搬到另一门。 |
| Python | 近似不允许（数字间除外） | 字符串与数字之间没有隐式转换：`"1" + 1` 直接抛 `TypeError`，须自己写 `str(1)` 或 `int("1")`。 |
| JavaScript | **大量隐式转换** | 同一个运算符结果类型不定：`"1" + 1` 变字符串 "11"，`"1" - 1` 变数字 0；比较运算前先用 `Number` 统一。 |
| TypeScript | 编译期拦截大部分 | 「大部分」不等于全拦：本课示例里 `a + "1"` 照样被放行、只是结果变成字符串，且转译之后注解整体消失。 |
| Java | 小范围到大范围自动 | 自动只覆盖小到大；反向和混用宽度会踩误区表「忽略数值宽度与默认类型」，触发整型溢出或浮点精度丢失。 |
| C# | 同上，另有 `checked` | 「同上」的自动同样只管小到大；范围外和溢出要动用这条多出的 `checked`，不能指望默认行为兜底。 |
| C++ | 大量隐式（含构造转换） | 构造转换与数值转换一样在调用处静默发生；再叠上整数除法 `5 / 2` 丢小数成 2.0 的经典坑，跨类型要显式写。 |
| Go | **不允许隐式数值转换** | 从 JavaScript、Python 迁来会处处被拦：`var b float64 = a` 是编译错误，只能显式 `float64(a)`。 |
| Rust | 不允许隐式转换 | 整数浮点混算要写 `let a = 1i32` 再显式 `a as f64`；与 C++ 的构造转换路径相反，编译器不会替你转。 |
| Shell | 一切皆字符串 | 没有数值类型兜底：离开 `$(( ))` 直接相加只会拼字符串，别指望 `+` 是其他语言里的数字加法。 |
| 内存 | 每个包装对象有对象头开销 | 对象头只在装箱发生时逐个增加；值类型不装箱就没有这项，要警惕的是循环里「每次都会分配或复制」。 |
| 性能 | 频繁装箱在热路径上会显著变慢 | 小流量下察觉不到，是循环次数把它放大；先固定输入跑基线，再把规模提高一个数量级复测才能下结论。 |
| 空值 | 包装类可能为 `null`，拆箱会抛空指针 | 易错：不同语言里空、未定义与默认值语义不同；正确做法是明确区分空值、缺失与默认值，并在序列化时写清约定。 |
| Java | `var list = new ArrayList<String>()` | 推断靠右侧完整构造，结果仍是写死的具体类型，之后不能换；这是编译期推断，不是动态类型。 |
| C# | `var user = new User()` | `var` 只推断出类型是 `User`；是否为空是另一回事，要按本课空值行的可空引用类型单独判断，别混为一谈。 |
| C++ | `auto p = std::make_unique<T>()` | `auto` 只是推断出右侧类型；空值检查仍要按本课空值行用 `nullptr` 判空，推断不会替你处理。 |
| Go | `n := 42` | 推断出的 `int` 当场定死；结合「不允许隐式数值转换」，之后不能与 float64 混用，须显式 `float64(n)`。 |
| Rust | `let x = 5;` | 类型推断不改变可变性：不写 `mut` 就不能重新赋值，要改须换成本表声明行的 `let mut x = 1;` 形式。 |
| Kotlin | `val x = 5` | 右侧 `5` 定类型、`val` 锁绑定，推断与不可变是这一行的两件事；不能因为没写类型就当成可变。 |
| TypeScript | `const x = 5` | 锁的是绑定可变性；且按本课检查时机行，TypeScript 只在编译期起作用，转译后这套约束就消失了。 |
| TypeScript | 编译期（转译后类型消失） | 它是这几行里唯一「检查做完就消失」的：产物是纯 JavaScript，同一段代码一到运行期就回到 JavaScript 那套隐式转换行为。 |
| Java / C# | 编译期 + 运行时（反射、强转） | 编译器给的绿灯只覆盖前半段：反射拿到的对象和向下强转要执行时才暴露，这一段静态检查管不到。 |
| Rust | 编译期 | 检查全压在编译期：漏写 `mut`、没处理 `Option<T>` 当场就编不过，所以运行期几乎不报这类错，别拿运行期没报错当作它没生效。 |
| Go | 编译期 + 运行时断言 | 断言那一步要执行时才定成败，编译通过不代表猜对了接口里装的实际类型；`nil` 也只出现在指针、切片、map 与接口这几类值上。 |
| Python / JavaScript | 运行时 | 没有编译期兜底：同一类输入 Python 抛 `TypeError`、JS 静默拼成 "11"，都要跑到才见分晓。 |
| 错误处理 | 显式返回或抛出 | 各语言口径不同：Python 类型错误直接抛异常，Rust 用 `Option<T>` 靠 `match`、`?` 强制处理；别只带一家的习惯去套另一家。 |
| 并发模型 | 线程、协程或事件循环 | 三种模型的调度顺序不同，串行跑一遍通过不代表共享状态在真并发下也安全；本课只做类型对照，没给各家的同步写法。 |
| 依赖管理 | 官方包管理器 | 这条只说明每种语言有自己的官方入口；正文未给出各家命令与版本策略，最忌把一门语言的依赖习惯套到另一门。 |

## 原理与运行机制

### 机制总览

**教材衔接：一句话目标**

变量「怎么声明、能不能改、能不能换类型」，最能体现一门语言的性格。
本文把九种语言放在同一张表里对照。

**教材衔接：空值怎么表达**

| 语言 | 空值 | 检查方式 |
| --- | --- | --- |
| Python | `None` | `if x is None:` |
| JavaScript | `null` / `undefined` | `x == null` 或 `x === undefined` |
| TypeScript | 同 JavaScript，加 `strictNullChecks` | 用 `?.` 与 `??` |
| Java | `null` | `Optional` 或判空 |
| C# | `null`（可空引用类型） | `?.` 与 `??` |
| C++ | `nullptr` | 判空或 `std::optional` |
| Go | `nil`（仅指针、切片、map、接口等） | `if x == nil` |
| Rust | 没有 null，用 `Option<T>` | `match`、`?`、`unwrap_or` |
| Shell | 空字符串 `""` | `[[ -z "$x" ]]` |

**Rust 用类型系统消灭了空指针**：想表达「可能没有」，就必须用 `Option<T>`，编译器强制你处理。

## 典型应用场景

- **用一门语言的类型规则套另一门**：典型现象是隐式转换与溢出行为完全不同；正确做法是先查目标语言的数据模型与转换规则再迁移代码。
- **忽略数值宽度与默认类型**：典型现象是整型溢出或浮点精度丢失；正确做法是明确位宽与精度，必要时显式指定类型。
- **把空值与缺失混为一谈**：典型现象是不同语言里空、未定义与默认值语义不同；正确做法是明确区分空值、缺失与默认值，并在序列化时写清约定。

### 选择与边界

- 使用 `变量` 时，类型与变量：九种语言横向对照解决了什么问题，而不是只背术语；静态检查只在编译期成立，运行期输入仍需校验。
- 使用 `不可变` 时，对象创建后状态不再改变，更新时生成新对象，从而减少共享状态和并发错误；共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。
- 使用 `装箱与拆箱` 时，值类型转成堆上对象再取回，每次都会分配或复制，是循环里常见的隐形开销；静态检查只在编译期成立，运行期输入仍需校验。
- 使用 `隐式转换` 时，编译器自动完成的类型转换，可能静默丢精度或改变比较结果，跨类型运算时要显式写清；易错：隐式转换与溢出行为完全不同；正确做法是先查目标语言的数据模型与转换规则再迁移代码。

## 代码/协议/SQL 示例

**教材衔接：数字与字符串的坑：九种语言对比**

```python
# Python：类型错误会直接抛异常
"1" + 1          # TypeError
"1" + str(1)     # "11"
int("1") + 1     # 2
```

```javascript
// JavaScript：会隐式转换，最容易踩坑
"1" + 1          // "11"（字符串拼接）
"1" - 1          // 0（转成数字）
Number("1") + 1  // 2
```

```typescript
// TypeScript：编译期就拦住
const a: number = 1;
// a + "1" 会被允许（结果为 string），但类型会变化
```

```java
// Java：字符串与数字相加会拼接，且顺序影响结果
System.out.println(1 + 2 + "a");   // "3a"
System.out.println("a" + 1 + 2);   // "a12"
```

```csharp
// C#：字符串插值是更安全的写法
Console.WriteLine($"{1 + 1}");      // "2"
```

```cpp
// C++：整数除法丢小数是最经典的坑
double a = 5 / 2;                  // 2.0，不是 2.5
double b = 5 / 2.0;                // 2.5
```

```go
// Go：类型严格，必须显式转换
var a int = 1
// var b float64 = a        // 编译错误
b := float64(a) + 1.5
```

```rust
// Rust：同样严格，整数与浮点不能混算
let a = 1i32;
let b = a as f64 + 1.5;
```

```bash
# Shell：一切皆字符串，需要算术时用 (( ))
a=1
b=$((a + 2))
echo "$b"                        # 3
echo "$a + 2"                    # 1 + 2（字符串）
```
