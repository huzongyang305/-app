## 本节知识框架

今天的目标很简单：**写一个 Python 文件，运行它，看到屏幕上出现你写的文字。**

学完这一课，你会：
- 知道 Python 是什么、解释器是什么
- 会创建 `.py` 文件并用命令行运行它
- 能用 `print()` 让屏幕显示内容
- 遇到常见报错时知道怎么修

**先修与衔接**：本课是 Python 分类的第 1 课，不需要任何编程基础。下一课：《Python 输入与输出》。

### 复习清单

- [ ] 能独立创建一个 `.py` 文件并运行它
- [ ] 能用 `print()` 输出文字和计算结果
- [ ] 能看懂 `SyntaxError` 并修好引号问题

## 核心概念定义

先认识几个名词，后面会反复遇到：

| 术语 | 一句话说明 |
| --- | --- |
| Python | 一种编程语言，写法接近英语，适合入门。你用键盘写的文字、做的计算，它都能处理。 |
| 解释器 | 帮你"翻译"并运行 Python 代码的程序。在命令行输入 `python` 就能启动它。 |
| 脚本文件 | 以 `.py` 结尾的文本文件，里面写着你让 Python 执行的命令。 |
| print | Python 内置的命令，作用是把内容显示到屏幕上。学编程的第一行代码几乎总是它。 |
| 缩进 | Python 用行首的空格来表示代码的层级关系。同一层代码必须对齐，否则报错。 |
| 虚拟环境 | 给每个项目创建一个独立的 Python 空间，避免不同项目的依赖互相冲突。初学阶段可以先不管它。 |
| 标准输出 | 程序默认把 `print` 的内容送往屏幕的那条通道；学编程第一天看到的所有文字都从这里出来。 |
| `python -c` | 不新建文件，直接在命令行里跑一小段代码，用来临时验证一个表达式对不对。 |
| 解释器路径 | 一台电脑可能同时装着好几个 Python，只有看清完整路径，才知道刚才运行的是哪一个。 |

## 原理与运行机制

### 你的代码是怎么跑起来的

```text
你写的代码（hello.py）
    ↓
解释器读取文件，从上到下一行行执行
    ↓
遇到 print() → 把内容送到屏幕
    ↓
你看到输出结果
```

整个过程就像你把一张便条交给厨师：你写"先洗菜、再切菜、最后下锅"，厨师就照顺序做一遍。解释器就是那个厨师，它按顺序读你的代码，一行行执行。

### 为什么用缩进而不用大括号

很多语言用 `{}` 表示代码块，Python 选择了缩进。好处是代码天然整齐，坏处是少一个空格就会报错。习惯就好——用 4 个空格作为一级缩进，保持统一就行。

### 变量就是贴了标签的盒子

```python
name = "小明"
```

这行的意思是：创建一个字符串 `"小明"`，给它贴上 `name` 这个标签。之后你用 `name`，Python 就知道你在说 `"小明"`。等号 `=` 在这里读作"把右边装进左边的盒子"，不是数学里的"相等"。

### 字符串拼接：把两段文字连起来

```python
greeting = "你好，"
name = "小明"
print(greeting + name)  # 输出：你好，小明
```

用 `+` 可以把两个字符串首尾相连。这在需要动态组合输出时非常有用——比如欢迎信息里包含用户的名字。

### 数字也能 print

```python
print(1 + 2)      # 输出：3
print(10 * 5)     # 输出：50
print(10 / 3)     # 输出：3.3333333333333335
```

`print` 不仅能输出文字，还能直接输出计算结果。Python 支持加减乘除，写法跟数学差不多。

### 注释：写给自己和别人看的笔记

```python
# 这行是注释，Python 会跳过它
print("这行会执行")  # 这行末尾的注释也会被跳过
```

以 `#` 开头的文字是注释，用来解释代码在做什么。好的注释能帮你在一周后回头看代码时快速理解当时的思路。

### 让代码跑起来的三种方式

第一种是本课的主线：**写成文件再运行**。

```bash
python hello.py
```

第二种是**临时验算**，不建文件，把代码塞进 `-c` 后面的引号里：

```bash
python -c "print(1 + 2)"
```

它适合确认"这个表达式到底等于几""这台机器上的 Python 是哪个版本"，但代码一长就很难敲对引号，不要拿它当正式写法。第三种是**交互模式**：只输 `python` 回车，出现 `>>>` 提示符后可以一行一行地敲，按 `Ctrl+D`（Windows 上是 `Ctrl+Z` 再回车）退出。

三种方式共用同一个解释器，同一段代码在哪儿结果都一样。区别只在于：文件里的代码保存下来还能反复跑，交互模式敲过就没了——初学时最常见的失误是在 `>>>` 里写了一堆代码，然后困惑"我的文件在哪儿"。

### 文件名和目录：解释器去哪儿找脚本

`python hello.py` 里的 `hello.py` 是**相对路径**，解释器按"当前终端所在目录"去找它。所以两类失败很典型：

- 终端还停在用户主目录，文件却放在桌面 —— 报 `No such file or directory` 或"无法打开文件"。先用 `cd` 切到脚本所在目录再看一眼 `dir` 或 `ls`。
- 文件名敲错、后缀写成 `.py.txt` —— Windows 默认隐藏已知扩展名，看起来是 `hello.py`，实际是 `hello.py.txt`。在文件夹选项里把"隐藏扩展名"关掉再确认。

另外，脚本内部用相对路径打开的数据文件，同样是相对**运行时的工作目录**，而不是相对脚本文件本身——这一条等你写到"读取同目录下的 csv"时一定会撞上。

### print 为什么是观察程序状态最直接的工具

程序不会主动告诉你它脑子里在想什么，`print()` 就是让它开口说话的唯一低门槛手段。除了输出文字，它还有三个立刻用得上的能力：

```python
print("2026", "10", "06", sep="-")        # 自定义分隔符：2026-10-06
print("正在计算", end="")                  # 不换行，接着往后面写
print("分数：", 95, sep=" ", end="\n")
```

```python
import sys
print("这条写到标准错误", file=sys.stderr)
```

学习阶段建议养成一个习惯：每当程序行为不符合预期，就在可疑位置插一行 `print(变量)`，看它此刻到底是什么值、什么类型（用 `print(type(x), x)`）。等程序长大以后你会接触到日志框架，但它的底层仍然是"把内容写到标准输出/标准错误"，`print` 的直觉完全复用。

### 缩进的三条硬规矩

1. **同一层代码缩进必须完全一致**，差一个空格就报 `IndentationError`。
2. **只用 4 个空格做一级缩进**，不要用 Tab 和空格混着敲——编辑器看起来一样，解释器却认为是两种层级。
3. **空行不参与缩进判断**，随便空几行都不会报错，可以用来分隔逻辑段落。

Python 用缩进代替大括号，代价是"看不见的一个空格"就能毁掉一次运行，好处是代码永远排版整齐，读别人代码时不会看晕。

### 版本、虚拟环境与解释器路径

这台电脑上到底跑的是哪个 Python？先把这个问题问清楚，再谈"我这能跑但那儿不能跑"：

```bash
python --version
where python        # Windows；macOS/Linux 用 which python
```

如果系统里同时装着 3.11 和 3.13，你可能把包装进了一个解释器，运行的却是另一个，一执行就抛 `ModuleNotFoundError`——这是用系统解释器装依赖最容易踩的坑。解决办法是给项目建一个独立空间，并固定用它的解释器路径来跑：

```bash
python -m venv .venv
.venv\Scripts\python hello.py     # Windows：直接用虚拟环境里的解释器跑脚本
```

初学阶段只用一个标准库都够，可以先不建虚拟环境；但等你开始 `pip install` 第三方包，就立刻回来用这套流程。同时记住：把 `python --version` 的输出和代码一起记进笔记，别人才能复现你的结果。

## 典型应用场景

Python 脚本能做很多事情，这里列几个初学者马上能用的：

- **自动化重复操作**：批量重命名文件、整理下载文件夹、把一堆照片按日期归类
- **数据处理**：读取 CSV 表格，统计某列数据的总和、找出最大值
- **写小工具**：计算器、密码生成器、倒计时提醒、单位转换器
- **爬虫入门**：从网页抓取天气、新闻标题、商品价格
- **文本处理**：统计文章字数、替换敏感信息、提取邮件地址

这些都不需要复杂的基础，学完前几课就能开始做。

### 一个实际的小例子

假设你想把一段文字重复打印 5 次：

```python
for i in range(5):
    print("Python 真有趣！")
```

`for` 是循环语句，`range(5)` 生成 0 到 4 共 5 个数字，每次循环 `print` 执行一次。注意 `print` 前面有 4 个空格的缩进——这告诉 Python 这行代码属于循环体。

## 代码/协议/SQL 示例

### 最小可运行示例

```python
print("hello from Python")
```

运行方式：把这段代码保存为 `hello.py`，在终端执行：

```bash
python hello.py
```

输出：

```text
hello from Python
```

### 完整示例：打招呼

```python
# 把这一行保存成 hello.py，然后在终端执行：python hello.py
print("你好，Python")

name = "小明"
print("欢迎，" + name)
```

逐行解释：

- `# 把这一行保存成...`：以 `#` 开头的是注释，写给人看的，Python 会跳过。
- `print("你好，Python")`：调用 `print` 把引号里的文字原样输出到屏幕，末尾自动换行。
- `name = "小明"`：把字符串 `"小明"` 存进变量 `name`。
- `print("欢迎，" + name)`：用 `+` 把两段文字拼起来，再输出。屏幕上会出现 `欢迎，小明`。

### 运行过程

1. 打开终端，进入脚本所在目录
2. 输入 `python hello.py`，回车
3. 第一行 `print` 执行 → 屏幕显示 `你好，Python`
4. 第二行赋值 → 内存里多了一个 `name`，屏幕无变化
5. 第三行拼接并输出 → 屏幕显示 `欢迎，小明`

### 动手练一练

- 把 `"小明"` 换成你自己的名字，保存后重新运行，确认输出跟着变
- 新加一行 `print(1 + 2)`，先在心里算结果再看屏幕——`print` 既能输出文字也能输出计算结果
- 故意删掉一个右引号，运行一次，把完整的报错信息抄下来

### 完整示例：一份带计算的月账单脚本

上面的打招呼只输出文字，真正实用的脚本会"存数据 → 算一算 → 报结果"。把下面这段存成 `bill.py`：

```python
# bill.py —— 计算一个月的水电网费总开销
water = 68.5          # 水费，单位：元
electric = 142.0      # 电费
internet = 99         # 网费，写成整数

total = water + electric + internet
print("本月总支出：", total, "元", sep="")
print("日均支出：", round(total / 30, 2), "元", sep="")
print(type(total))    # 结果会被谁变成小数？看一眼类型
```

运行后你会看到总金额、日均金额，以及一行 `<class 'float'>`——因为只要参与相加的数里有一个带小数点，结果就自动变成浮点数，最后一行就是验证这件事。想改数字时只动最上面三行，不用碰下面的计算，这就是"数据与逻辑分开"的第一课。

把结论写下来核对一遍：输入是三个费用数字，输出是三行屏幕文字，失败路径是"数字被写成字符串"（把 `68.5` 改成 `"68.5"` 再运行，会抛出 `TypeError`，提示 `can only concatenate str`）。三条都亲自验证过，这一页才算读完。

### 报错复现练习：故意写坏三次

第一次运行成功之后，最有价值的练习是反过来把代码弄坏，看看每种错误长什么样：

```python
print("你好，Python)         # SyntaxError：右引号缺失，解释器读到行尾也没找到结尾
   print("缩进多了")          # IndentationError：这一行没有理由被缩进
print(未定义的变量)           # NameError：名字从来没被赋值过
```

三种报错都出现在**运行之前或运行的那一行**，报错信息最后一行会写明类型和行号。把它们抄进笔记，比多看十页教程有用——下次再撞见，你已经知道去哪里找。

## 时间/空间复杂度或性能分析

第一课的代码只有一行 `print`，暂时不需要关心性能。

等你写到处理大文件或循环几万次时，再回来关注：
- **时间**：代码跑了多久？用 `time` 模块可以测量
- **内存**：占了多少内存？列表装 100 万条数据时会明显增加

现在记住一点就好：**先让代码跑对，再让它跑快。**

### 一行脚本要不要关心性能

不需要。解释器启动本身就要几十毫秒到上百毫秒，比你那几行代码的执行时间还长——这也是为什么"敲 `python` 到看见输出"之间会有轻微停顿。在脚本只负责打印、算几个数的阶段，任何优化都是白费力气。

### 什么时候开始变慢

当你开始读文件，写法不同差距会显出来：

```python
# 方式一：一次读成一个大字符串（小文件方便，大文件占内存）
text = open("notes.txt", encoding="utf-8").read()

# 方式二：一次读成所有行的列表（方便按下标取某一行，整个文件仍留在内存里）
lines = open("notes.txt", encoding="utf-8").readlines()

# 方式三：逐行处理，边读边算（大文件的默认选择）
count = 0
with open("notes.txt", encoding="utf-8") as f:
    for line in f:
        if line.strip():
            count += 1
print(count)
```

第三种只在内存里放"当前这一行"，所以十万行的日志也能跑；前两种会把整个文件先搬进内存。这里还藏着一个细节：`open(...)` 不写 `encoding="utf-8"` 时，中文 Windows 上默认可能是 GBK，同一个文件在一台机器正常、另一台乱码——遇到乱码先怀疑编码声明，而不是怀疑文件坏了。

### 怎么确认"我的结论可复现"

测量之前先把环境钉死：记下 `python --version` 的输出、操作系统、数据文件的行数，同一段代码连续跑三遍取中间值。只凭一次运行得到的数字，很可能只是那一次系统恰好空闲。等你真的需要精确计时，再用 `time.perf_counter()` 包住要测的那几行。

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 文件存成 `hello.txt` | 终端报「找不到文件」 | 确认后缀是 `.py`，不是 `.txt` |
| 引号只用一半 `print("你好)` | 报 `SyntaxError: EOL while scanning string literal` | 补上缺失的右引号 |
| 用了中文引号 `"你好"` | 报 `SyntaxError` | 切换到英文输入法，用半角引号 `""` |
| `Name` 和 `name` 混用 | 报 `NameError: name 'Name' is not defined` | Python 区分大小写，统一用同一个名字 |
| 在编辑器里改了代码没保存 | 运行的还是旧版本 | 运行前先按 Ctrl+S 保存 |
| 在 `>>>` 交互模式里敲 `python hello.py` | 报 `SyntaxError` 或把 `python` 当成未定义的名字 | 交互模式里只写 Python 代码；要运行脚本先退回普通命令行提示符 |
| 脚本内部用相对路径读数据文件 | 明明文件就在旁边，却报「找不到文件」 | 相对路径是以终端当前目录为起点的，运行前先 `cd` 到正确位置或用完整路径 |
| Tab 和空格混着缩进 | 编辑器看着整齐，运行却报 `IndentationError` | 统一用 4 个空格，打开编辑器的"显示空白字符"检查 |
| 用系统解释器 `pip install`，却用另一个解释器运行 | 代码里 `import` 时抛 `ModuleNotFoundError` | 明确虚拟环境，并固定用它的解释器路径启动脚本 |
| 只在正常输入上跑一次就宣布学会 | 换一份数据就乱码、崩溃或结果不对 | 至少再试空文件、只有一行、以及含中文的一行 |

### 遇到报错怎么办

1. **读第一行报错信息**——它会告诉你错在哪一行、什么类型的错
2. **回到最小示例**——先确认最小示例能跑通
3. **只改一个地方**——每次只改一处，再运行看结果
4. **搜索报错信息**——把报错信息复制到搜索引擎，通常第一条结果就是答案

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `Python` | 一种编程语言，写法接近英语，适合入门 |
| `解释器` | 读取并运行 Python 代码的程序，命令行输入 `python` 启动 |
| `脚本文件` | 以 `.py` 结尾的文本文件，保存你的代码 |
| `print` | 把内容显示到屏幕上的内置命令 |
| `缩进` | 用行首空格表示代码层级，同一层必须对齐 |
| `虚拟环境` | 给项目创建独立的 Python 空间，初学可先不管 |
| `标准输出` | 程序默认的文字出口，`print` 的内容就送到这里，屏幕上看到的正是它 |
| `交互模式` | 输入 `python` 后出现的 `>>>` 提示符，逐行敲代码、不留文件 |
| `python -c` | 在命令行里直接执行一小段代码，用来临时验算或确认版本 |
| `SyntaxError` | 代码写得不合语法，解释器还没运行就拒绝，最常见是引号或括号不成对 |
| `NameError` | 用到的名字从没被赋值过，先检查拼写和大小写 |
| `ModuleNotFoundError` | 当前这个解释器找不到你要 `import` 的模块，多半是装错了环境 |
