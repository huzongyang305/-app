## 本节知识框架

**课程定位**：所属分类 `ruankao`（软考初级与中级），课程主题 `操作系统与系统结构`，学习阶段 进阶，建议用时 45 分钟。操作系统与计算机组成、体系结构在上午卷里通常合并出现在第 11~20 题区间，合计 8~11 分，是「公式固定、算错就丢分」的硬骨头。

本课主线：把「进程怎么切换」和「数据放在哪一层存储」当成一对孪生问题。前者管时间——谁在 CPU 上、排多久、会不会僵死；后者管空间——这一位数据在 Cache、内存还是磁盘上，取它要花多久。最后加一条流水线，把指令也排成队伍。

**学完本课应当能够**
- 说出进程三态五态的转移条件，并用 PV 操作解释信号量取负值的含义。
- 手算直接映射下标记位、行号、块内地址各占几位，再算平均访问时间。
- 用 FIFO、LRU、OPT 三种规则跑同一条引用串，解释 Belady 异常为什么只在 FIFO 上出现。
- 用 T = (k + n − 1)Δt 计算流水线总耗时，并进一步求吞吐率与加速比。

## 核心概念定义

| 术语 | 操作性定义（白话版） | 常见边界与风险 |
| --- | --- | --- |
| 进程 | 程序的一次执行过程，有独立的地址空间与 PCB（进程控制块），是资源分配的基本单位。 | 易错：线程才是 CPU 调度的基本单位，同一进程内线程共享地址空间。 |
| 三态五态 | 就绪、运行、阻塞是三个基本状态，加上创建与终止成五态。 | 易错：阻塞到运行没有直接通路，必须先回到就绪再等调度。 |
| 时间片轮转 | 每个就绪进程轮流占用一个固定时间片，用完就剥夺回就绪队列。 | 易错：时间片过大退化成 FCFS，过小则切换开销占比过高。 |
| 信号量与 PV | S 是计数器加等待队列；P 操作申请（减 1，不够就阻塞），V 操作释放（加 1，有人等就唤醒）。 | 易错：S 为负时绝对值表示等待的进程数，不是「出错了」。 |
| 死锁 | 一组进程互相持有对方需要的资源并都在等待，谁也不肯放手，全体无法推进。 | 易错：四个必要条件必须同时成立，破坏任意一个即可预防。 |
| 银行家算法 | 分配前先假设批准，检查系统是否还存在安全序列；存在才真分配，是死锁避免。 | 易错：它是「避免」不是「预防」，也不是「检测」。 |
| 虚拟存储器 | 用地址位数造出一个比物理内存大得多的逻辑地址空间，靠页表与对换区补齐差额。 | 易错：容量由地址位数与外存决定，不受物理内存限制。 |
| 请求页式管理 | 页面不必全部驻留内存，访问到不在内存的页就触发缺页中断，由系统调入。 | 易错：缺页中断是内部中断（陷阱），执行完要重新执行原指令。 |
| 页面置换 | 内存满了要腾位置，按 FIFO、LRU、OPT 或 CLOCK 规则挑一个牺牲页。 | 易错：OPT 需预知未来引用串，只是理论基准，无法实现。 |
| Belady 异常 | 某些置换算法会出现「物理块变多、缺页反而变多」的反常现象。 | 易错：只有 FIFO 等栈式外算法会有，LRU 与 OPT 不会出现。 |
| 段式与段页式 | 段按程序的逻辑模块划分、长度可变；段页式先把段再分页，兼顾客观地址空间与内存利用。 | 易错：分页对用户透明，分段用户可见，因此段表要带段长做越界检查。 |
| 存储层次 | 寄存器、Cache、主存、外存按速度、容量、成本折中排成金字塔。 | 易错：Cache 由硬件管理，主存与外存之间的对换由操作系统管理。 |
| Cache 映射 | 决定主存块能落在 Cache 的哪些行：直接映射只一行、全相联任意行、组相联一组 N 行。 | 易错：全相联无冲突但要做并行比较，代价最高。 |
| 命中率与平均访问时间 | 平均时间 = 命中率 × Cache 时间 +（1 − 命中率）× 主存时间，未命中一般不再另算访存。 | 易错：题目若给「写回法」并让算写操作时间，要另算一次访存。 |
| 指令流水线 | 把取指、译码、执行、访存、写回叠起来，让不同指令在同一时刻处于不同阶段。 | 易错：流水线周期取最慢那一段，不是各段平均。 |
| 流水线三大相关 | 结构相关（抢同一硬件）、数据相关（后一条要前一条的结果）、控制相关（转移打断流水）。 | 易错：转移造成的代价叫控制开销或「流水线断流」，不是数据冲突。 |

## 原理与运行机制

**一、进程这条队伍怎么排。** 把 CPU 想成一张唯一的手术台，进程是排队等手术的病人。就绪队列是候诊区，运行态是正在手术，阻塞态是被推去做了别的检查（等 I/O）。所以「阻塞 → 运行」这种转移不可能发生：检查回来还得重新排队。

并发访问共享变量会出错，于是有了信号量。可以把它想象成停车场的余位显示屏：进场（P 操作）先看屏，有余位就减 1 开进去；没余位就在入口熄火等待。出场（V 操作）加 1，并喊醒一位等待者。如果屏上显示 −2，意思是「车位为 0，另外还停着 2 辆等位的车」，这就是 S 为负值时绝对值代表等待进程数的由来。互斥用初值 1 的信号量，同步则用初值 0 的信号量：前者管资源，后者管先后顺序。

死锁更像「四个条件同时成立」的合谋：互斥（资源一次只能一人用）、请求与保持（占着 A 还要 B）、不可剥夺（不能强行抢走）、循环等待（绕成一个圈）。预防就是提前打破其一，最省事的工程做法是按同一顺序申请资源，圈就画不出来。银行家算法则是「避免」：批准之前先试算一遍，看还剩不还剩得下一个安全序列（一种能让所有进程先后跑完的发放顺序）；算不出来就宁可让这位申请者等着。

**二、数据那一摞存储怎么选层。** 程序看到的都是虚拟地址。页式管理下，地址被切成「页号 + 页内偏移」两段：页号查页表得到物理块号，与偏移拼成物理地址；为了少查表，最近用过的映射会放进快表 TLB。以 4KB 页为例，偏移天然占 12 位，逻辑地址 0x1234 的页号就是 0x1234 ÷ 4096 = 1，页内偏移是 0x1234 % 4096 = 564。

页表一多，内存放不下全部页面，就出现请求页式：要用的页不在内存 → 硬件触发缺页中断 → 系统暂停当前指令（注意是「重新执行」这条指令，而不是继续往下）、在外存找到该页、挑一个牺牲页腾位置（内存已满时）、填页表、恢复执行。牺牲页怎么选，就是置换算法。

用一条真实引用串把三种算法跑一遍：3 个物理块，引用串 1、2、3、4、1、2、5、1、2、3、4、5。FIFO 缺页 9 次，LRU 缺页 10 次，OPT 只需 7 次。LRU 比 FIFO 还差？这不是题目写错，而是这两种规则都没有「看未来」的能力，谁都不是次次最优。更有意思的是把物理块从 3 个加到 4 个：FIFO 的缺页反而升到 10 次，这就是 Belady 异常；而 LRU、OPT 这类「栈式算法」不会出现，因为更多页框时它访问的旧页仍然是旧页。

Cache 的考点更机械，按三步走：① 先算块内地址位数（每行多少字节 → log2）；② 再算行号或组号位数（多少行/多少组 → log2）；③ 剩下全是标记位。以 32 位地址、64 行、每行 32 字节的直接映射为例：块内 5 位、行号 6 位、标记 32 − 6 − 5 = 21 位。直接映射的麻烦在于某段主存只能落在某一行，两个热点块抢同一行就互相踢（冲突缺失），全相联没这个烦恼但每次要并行比较所有行，组相联是教材与考题默认的折中方案。最后用平均访问时间收尾：0.95 命中率、Cache 1 纳秒、主存 60 纳秒，平均 0.95×1 + 0.05×60 = 3.95 纳秒。

**三、指令流水线。** 洗菜、切菜、炒菜、装盘四道工序，一个厨师从头做到尾 4 道菜要 16 分钟，四个厨师各管一道工序则 4 + 3 = 7 分钟就出完——这就是流水线的全部直觉：总时间 = 段数 + 任务数 − 1，再乘以周期。

关键在「周期取最慢那一段」。5 段流水线各段耗时 1、2、1、1、1 纳秒，周期必须是 2 纳秒，否则快的那几段会等下一拍。于是连续执行 100 条指令的时间是 (5 + 100 − 1) × 2 = 208 纳秒；不分流水、单条耗时 6 纳秒，100 条要 600 纳秒。加速比 600 ÷ 208 ≈ 2.88，吞吐率 100 ÷ 208 ≈ 0.48 条每纳秒。注意流水线效率永远小于 1，段数越多、任务数越少，建立与排空的时间占比越大，所以「段数越多越好」是错的。

**应试视角**：这一域的选择题只有四种算式，认清题面套哪个即可——① Cache/虚地址的位数划分；② 平均访问时间；③ 缺页次数与置换序列；④ 流水线 T、吞吐率、加速比。其余是概念判断（死锁、银行家、三态转移、段页式区别），干扰项通常把「避免」写成「预防」、「重新执行」写成「继续执行」。

## 典型应用场景

| 场景 | 典型输入或前提 | 期望产物 |
| --- | --- | --- |
| 交互式系统选调度算法 | 要求响应快、进程数多且长短混合 | 时间片轮转或多级反馈队列，配优先级防饿死 |
| 实时控制任务 | 任务有硬截止时刻 | 静态优先级用 RMS（周期越短优先级越高），动态用 EDF |
| 数据库服务器内存管理 | 热点页集中、访问有局部性 | LRU 或 CLOCK 近似置换，配合预读 |
| 高并发短任务 CPU 分配 | 任务粒度小、切换成本高 | 加大时间片或改用它进程协作，减少上下文切换 |
| 嵌入式主控芯片选型 | 指令序列规整、分支少 | 深流水 + 分支预测；分支多则加深反而掉性能 |
| 事务型系统存储设计 | 主存容量有限、数据量大 | 请求页式 + 足够对换区，按工作集定常驻页帧数 |

## 代码/协议/SQL 示例

把页面置换三种规则做成可复现的小实验，同一条引用串给出三个数字，比背结论可靠得多：

```python
def replace(ref, frames, policy):
    """policy 取 fifo / lru / opt，mem 列表头部永远是最该被淘汰的那一页。"""
    mem, faults = [], 0
    for idx, page in enumerate(ref):
        if page in mem:
            if policy == "lru":
                mem.remove(page)
                mem.append(page)          # 刚用过，挪到最新的一端
            continue
        faults += 1
        if len(mem) == frames:
            if policy == "opt":
                future = ref[idx + 1:]
                victim = max(mem, key=lambda p: future.index(p) if p in future else float("inf"))
            else:
                victim = mem[0]           # fifo 看最早进来，lru 看最久未用
            mem.remove(victim)
        mem.append(page)
    return faults

REF = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
for policy in ("fifo", "lru", "opt"):
    for frames in (3, 4):
        print(policy, frames, replace(REF, frames, policy))
```

输出里 fifo 那两行是 9 与 10：页框从 3 个加到 4 个，缺页反而变多，这就是 Belady 异常的现场；lru 两行是 10 与 8，opt 两行是 7 与 6，后两者都单调下降，因为它们属于栈式算法。

再验一遍位数划分与流水线公式，两段可以直接当草稿纸模板：

```python
addr_bits, lines, line_bytes = 32, 64, 32
block_bits = line_bytes.bit_length() - 1      # 5：块内地址
line_bits = lines.bit_length() - 1            # 6：行号
tag_bits = addr_bits - block_bits - line_bits # 21：标记
print(block_bits, line_bits, tag_bits)

hit, t_cache, t_mem = 0.95, 1, 60
print(round(hit * t_cache + (1 - hit) * t_mem, 2))   # 平均访问时间 3.95

stages, n = [1, 2, 1, 1, 1], 100
period = max(stages)                                  # 周期取最慢一段
total = (len(stages) + n - 1) * period                # 208
serial = n * sum(stages)                              # 600
print(period, total, round(serial / total, 2), round(n / total, 2))
```

## 时间/空间复杂度或性能分析

这一课的性能分析有三笔账，考场都用得上。

第一笔是**存储层次的成本账**。同一份数据放在不同层，代价差几十倍；层次设计的核心是局部性——刚用过的还会再用（时间局部性），用过的地址附近还会用到（空间局部性）。拿 Cache 1 纳秒、主存 60 纳秒这组数字算：命中率 0.90 时平均 0.90×1 + 0.10×60 = 6.9 纳秒，命中率提到 0.95 就降到 3.95 纳秒，只涨了 5 个百分点却省掉四成多时间。这个量级足以解释为什么加大 Cache 容量通常比抬高主存频率更划算。冲突缺失则要靠改映射方式（组相联加大路数）或改内存交织来缓解。

第二笔是**置换算法的开销账**。FIFO 只需维护一个队列，代价 O(1)，但会出现 Belady 异常；LRU 需要为每次访问更新「最近使用」信息，硬件实现要栈或计数器，代价高；CLOCK（近期未使用）用一位引用位近似 LRU，把成本压回 O(1) 摊销，是真实系统最常选的方案；OPT 不可实现，只作为下界衡量别人好坏。同一引用串上 3 块的结果 9 / 10 / 7 三个数字，是判断「谁在瞎猜」的直观教材。

第三笔是**流水线与调度的收益账**。

| 指标 | 公式 | 本课例子的数值 | 结论 |
| --- | --- | --- | --- |
| 流水线周期 | 最慢一段耗时 | 2 纳秒 | 决定一切上限 |
| 总执行时间 | (k + n − 1)Δt | 208 纳秒 | n 越大越接近 nΔt |
| 吞吐率 | n ÷ 总时间 | 0.48 条每纳秒 | 上限是 1/Δt |
| 加速比 | 顺序时间 ÷ 流水时间 | 2.88 | 永远小于段数 k |
| 流水线效率 | 加速比 ÷ k | 0.577 | 段数多任务少则效率低 |

调度侧同理：FCFS 对短作业不友好，平均周转时间被长作业拖高；SJF 最短作业优先能给到理论最优的平均等待，但短任务不断涌入时长的可能饿死；响应比高者优先（HRRN）用「(等待时间 + 要求服务时间) ÷ 要求服务时间」这个比值同时照顾等待时长与任务长短，是作业调度里性价比最高的一条规则；时间片轮转牺牲一点吞吐换响应时间，片长要按上下文切换开销占总时间的比例来定。

## 常见误区与易错点

| 容易答错的做法 | 考场上的实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 认为阻塞态能直接变运行态 | 状态转移图题丢分 | 阻塞解除只回到就绪队列，仍需调度器选中 |
| 把流水线周期取成各段平均 | T、吞吐率、加速比全错 | 周期 = 最慢一段，这是流水线的节拍来源 |
| 见到物理块变多就断定缺页变少 | 选不出 Belady 异常 | 只有 FIFO 这类非栈式算法会反常 |
| 说 LRU 缺页次数一定最少 | 与算出的数字矛盾 | 下界是 OPT，LRU 只是历史信息的近似 |
| 认为银行家算法能预防死锁 | 概念题选错 | 它是死锁避免，靠试算安全序列决定是否发放 |
| 说信号量为负是异常状态 | 判断 PV 结果时算错等待数 | 负值绝对值就是阻塞等待的进程数 |
| 以为虚拟内存容量受物理内存限制 | 概念题丢分 | 由地址位数与外存对换区共同决定 |
| 缺页处理完直接执行下一条指令 | 流程题顺序写错 | 缺页属于故障类中断，要重新执行引起缺页的指令 |
| 把段说成对用户透明 | 段式页式对比题错 | 分页透明、分段可见，段长可变因此要越界保护 |
| 认为全相联没有任何缺失 | 映射方式选择题错 | 无冲突缺失，但仍有容量缺失与冷启动缺失 |

### 自测 1

主存地址寄存器 32 位，Cache 有 64 行、每行存 32 字节，采用直接映射时标记项、行号、块内地址各占几位？

- A. 标记 21 位、行号 6 位、块内地址 5 位
- B. 标记 20 位、行号 6 位、块内地址 6 位
- C. 标记 22 位、行号 5 位、块内地址 5 位
- D. 标记 21 位、行号 5 位、块内地址 6 位

**答案：A（标记 21 位、行号 6 位、块内地址 5 位）**

**解析**：本题正确项是「标记 21 位、行号 6 位、块内地址 5 位」。位数划分只有三步：每行 32 字节意味着块内地址要 5 位（2 的 5 次方等于 32）；64 行意味着行号要 6 位；32 位地址减去这两段，剩下 21 位全给标记，硬件比较这 21 位加上行号就能判定命中。干扰项「标记 20 位、行号 6 位、块内地址 6 位」把每行 32 字节误当成 64 字节；干扰项「标记 22 位、行号 5 位、块内地址 5 位」把 64 行的行号少算一位；「标记 21 位、行号 5 位、块内地址 6 位」两段各错一位，总和凑巧还是 32，因此最容易蒙混过关，必须一段一段核对。

### 自测 2

某系统给一个进程分配 3 个物理块，页面引用串为 1、2、3、4、1、2、5、1、2、3、4、5，关于缺页次数的结论正确的是？

- A. FIFO 与 LRU 的缺页次数相同，在此引用串上两者等价
- B. FIFO 缺页 9 次而 LRU 缺页 10 次，把块数加到 4 时 FIFO 反而缺页 10 次
- C. LRU 的依据是最近最久未使用，因此它的缺页次数必定最少
- D. FIFO 缺页 11 次，OPT 缺页 8 次，两者相差三次的规律恒定不变

**答案：B（FIFO 缺页 9 次而 LRU 缺页 10 次，把块数加到 4 时 FIFO 反而缺页 10 次）**

**解析**：本题正确项是「FIFO 缺页 9 次而 LRU 缺页 10 次，把块数加到 4 时 FIFO 反而缺页 10 次」。按引用串逐个模拟：3 个物理块时 FIFO 依次淘汰最早进入的页，共缺页 9 次；LRU 淘汰最久没被访问的页，缺页 10 次，比 FIFO 还多一次；把块数增到 4，FIFO 的缺页反而升到 10 次，这正是 Belady 异常的定义，而它只出现在 FIFO 这类非栈式算法上。干扰项「FIFO 与 LRU 的缺页次数相同，在此引用串上两者等价」把两组不同的数字混成一个；干扰项「LRU 的依据是最近最久未使用，因此它的缺页次数必定最少」把「比 FIFO 更贴近历史」夸成了理论下界，真正下界是预知未来的 OPT；「FIFO 缺页 11 次，OPT 缺页 8 次」两组数字都取自另一条引用串，与本串无关。

### 自测 3

某指令流水线分 5 段，各段耗时依次为 1、2、1、1、1 纳秒，连续执行 100 条指令，下列结论正确的是？

- A. 流水线周期取各段平均 1.2 纳秒，总耗时 118.8 纳秒
- B. 流水线周期为 6 纳秒，总耗时 600 纳秒，加速比等于 1
- C. 流水线周期为 2 纳秒，总耗时 208 纳秒，加速比约为 2.88
- D. 流水线周期为 2 纳秒，总耗时 200 纳秒，加速比约为 3.00

**答案：C（流水线周期为 2 纳秒，总耗时 208 纳秒，加速比约为 2.88）**

**解析**：本题正确项是「流水线周期为 2 纳秒，总耗时 208 纳秒，加速比约为 2.88」。周期必须取最慢那一段，否则快段要空等，所以 Δt = 2 纳秒；总时间按 (k + n − 1)Δt = (5 + 100 − 1) × 2 = 208 纳秒；不流水时一条指令要走完六纳秒，100 条共 600 纳秒，加速比 600 ÷ 208 ≈ 2.88，永远小于段数 5。干扰项「流水线周期取各段平均 1.2 纳秒，总耗时 118.8 纳秒」把节拍当成了平均值，是这一题型最高频的错误；干扰项「流水线周期为 6 纳秒，总耗时 600 纳秒，加速比等于 1」算的是顺序执行的时间，把它当成流水线结果就等于否认了流水；「总耗时 200 纳秒」漏掉了建立流水线的 (k − 1) 项，把 k + n − 1 写成 n。

### 自测 4

关于死锁的四个必要条件与相应处理策略，下列说法正确的是？

- A. 只要资源分配图中出现环，系统就一定已经陷入死锁
- B. 银行家算法通过破坏不可剥夺条件来预防死锁的发生
- C. 互斥条件在操作系统中可以彻底破坏，因此死锁能够完全消除
- D. 银行家算法在分配前试算是否仍存在安全序列，属于死锁避免

**答案：D（银行家算法在分配前试算是否仍存在安全序列，属于死锁避免）**

**解析**：本题正确项是「银行家算法在分配前试算是否仍存在安全序列，属于死锁避免」。它的动作顺序是：先假设把资源批给申请者，再检查是否还能找到一种让所有进程先后跑完的发放顺序，即安全序列；找得到才真的分配，否则让申请者等待。因为不破坏任何条件、只在运行期把关，所以是避免而不是预防。干扰项「只要资源分配图中出现环，系统就一定已经陷入死锁」漏了前提：只有每类资源仅一个实例时环与死锁才等价，多实例时环可能因资源释放而解开；干扰项「银行家算法通过破坏不可剥夺条件来预防死锁的发生」把避免说成预防，手段也张冠李戴；「互斥条件在操作系统中可以彻底破坏」更是方向性错误，打印机一类资源天生互斥，破坏互斥等于放弃独占使用。

### 自测 5（读代码）

阅读下面这段求虚地址对应页号与页内偏移的 Python，它的输出结果是什么？

```python
addr = 0x1234
page_size = 4096
print(addr // page_size, addr % page_size)
```

- A. 1 564
- B. 1 580
- C. 2 564
- D. 4660 0

**答案：A（1 564）**

**解析**：本题正确项是「1 564」。0x1234 等于十进制 4660，页大小 4096 是 2 的 12 次方，整除得页号 1，取余得页内偏移 564；换成位运算就是右移 12 位与低 12 位相与，这两步与硬件的页表变换完全一致。算的时候有个捷径：十六进制下页号取最高一位、偏移取后三位，因为 4096 正好对应 3 个十六进制位，所以 0x1234 拆成 1 与 0x234，而 0x234 折成十进制就是 564。选成 580 通常是把 0x234 按 0x244 折算，选成 2 564 则是把页数当成了 2048 或把整除写成了向上取整。

### 自测 6（多选）

关于存储管理与文件系统的下列说法中，正确的有哪几项？

- A. 请求页式管理用页表记录虚页与物理块对应关系，页不在内存时由缺页中断处理程序调入
- B. 段式存储管理中各段长度由系统统一规定，用户程序感知不到段的边界
- C. 索引分配用索引块保存逻辑块号到磁盘块号的映射，因而支持随机访问且便于增删记录
- D. 虚拟存储器的容量上限只由物理内存大小决定，与地址位数和外存空间无关

**答案：A、C（请求页式管理用页表记录虚页与物理块对应关系，页不在内存时由缺页中断处理程序调入；索引分配用索引块保存逻辑块号到磁盘块号的映射，因而支持随机访问且便于增删记录）**

**解析**：多选题要同时选中「请求页式管理用页表记录虚页与物理块对应关系，页不在内存时由缺页中断处理程序调入」与「索引分配用索引块保存逻辑块号到磁盘块号的映射，因而支持随机访问且便于增删记录」。前者正是请求页式的三步：查页表、发现有效位为 0、触发缺页中断把页调入并修改页表项；后者的关键是索引块把离散的外存块串成逻辑上连续的地址空间，代价是每次访问要多读一次索引。第三、第四两项是错的：分段是按程序的逻辑模块划分的，段长可变、用户看得见段，正因如此段表里要带段长做越界保护；虚拟存储器的容量由指令地址位数与外存对换区共同决定，物理内存只影响运行时的缺页率而不决定地址空间上限。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| PCB | 进程控制块，存放进程状态、优先级、现场与资源清单，是进程存在的唯一标志。 |
| 时间片 | 轮转调度里分配给一个进程的一次连续占用 CPU 的额度，用完即被剥夺回就绪队列。 |
| 安全序列 | 一种能让所有进程依次拿到所需资源并跑完的发放顺序，存在它即处于安全状态。 |
| 工作集 | 某段时间窗口内进程实际访问的页面集合，常驻页帧数应不小于工作集才不抖页。 |
| 快表 TLB | 页表项的高速缓存，用少量条目覆盖最活跃的虚页映射，减少一次内存访问。 |
| 缺页中断 | 访问不在内存的页时触发的内部中断，处理完须重新执行那条指令。 |
| 冲突缺失 | 直接映射下多个主存块争同一 Cache 行造成的失效，与程序访问模式有关。 |
| 写回法 | Cache 行被改脏后先不写主存，被替换时才回写，减少访存但要维护脏位。 |
| 流水线断流 | 因转移或相关导致某几拍没有新指令可流入，是流水线的三大开销之一。 |
| 抖页 | 页面反复调入调出、缺页率飙升的现象，多因分配的页帧数低于工作集。 |
