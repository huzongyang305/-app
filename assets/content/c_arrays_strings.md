## 典型应用场景

- **把数组长度当成可用上界**：典型现象是越界写入覆盖相邻内存；正确做法是容量与已用长度分开记录，写入前检查剩余空间。
- **字符串忘记结尾的空字符**：典型现象是打印与复制一直读到随机内存；正确做法是为终止符预留一字节，用带长度上限的函数并手动补零。
- **用等号比较字符串内容**：典型现象是实际比较的是两个地址；正确做法是用 strcmp 系列比较内容，并处理返回值的正负含义。

### 选择与边界

- 使用 `数组` 时，参考判断：学习 数组 时要同时说明输入、输出和失败路径，不能只看正常流程、验证 字符串 时要固定版本并覆盖边界输入，结论才可复现；易错：越界写入覆盖相邻内存；正确做法是容量与已用长度分开记录，写入前检查剩余空间。
- 使用 `缓冲区` 时，二、运行时与内存模型：围绕「数组、字符串、缓冲区、越界」说明变量生命周期、资源释放、并发模型和错误传播；共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

- 使用 `字符串终止符` 时，C 字符串以 \0 结尾，长度靠扫描终止符得到，忘记留这一位就会越界或截断；索引命中与数据分布决定实际开销，判断前先看执行计划而不是只看结果是否正确。

- **要点**：C 字符串以 \0 结尾，长度靠扫描终止符得到，忘记留这一位就会越界或截断。
- **字符串终止符 的边界**：索引命中与数据分布决定实际开销，判断前先看执行计划而不是只看结果是否正确。

### 考点 11：排错——把数组长度当成可用上界

- **现象**：越界写入覆盖相邻内存。
- **处理**：容量与已用长度分开记录，写入前检查剩余空间。

### 考点 12：排错——字符串忘记结尾的空字符

- **现象**：打印与复制一直读到随机内存。
- **处理**：为终止符预留一字节，用带长度上限的函数并手动补零。

### 考点 13：综合辨析——`数组` 与 `字符串终止符`

- **辨析点**：`数组` 的定义是 参考判断：学习 数组 时要同时说明输入、输出和失败路径，不能只看正常流程、验证 字符串 时要固定版本并覆盖边界输入，结论才可复现；`字符串终止符` 的定义是 C 字符串以 \0 结尾，长度靠扫描终止符得到，忘记留这一位就会越界或截断。
- **答题要求**：面对 `C 数组、字符串与缓冲区` 的题目，先判断描述的是 `数组` 还是 `字符串终止符`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 14：排错评分点

- **现象分**：能写出 越界写入覆盖相邻内存，而不是只写“程序有错”。
- **证据分**：保留触发 把数组长度当成可用上界 的输入、版本和错误原文。
- **修复分**：按 容量与已用长度分开记录，写入前检查剩余空间 只改一处，并同时回归正常路径与边界路径。
