## 本节知识框架

今天的目标很简单：**写一个 C++ 文件，编译它，运行它，看到屏幕上出现你写的文字。**

学完这一课，你会：
- 知道 C++ 程序长什么样、怎么编译运行
- 理解 `main` 函数是程序的入口
- 能用 `std::cout` 在屏幕上输出文字
- 了解从头文件到可执行文件的构建流程
- 遇到常见编译报错时知道怎么修

**先修与衔接**：本课是 C++ 分类的第 1 课，不需要任何编程基础。下一课：《C++ 变量与输入输出》。

### 复习清单

- [ ] 能独立创建一个 `.cpp` 文件并编译运行它
- [ ] 能用 `std::cout` 输出文字并解释 `<<` 的作用
- [ ] 能说出从 `.cpp` 到可执行文件经历了哪几个阶段

## 核心概念定义

先认识几个名词，后面会反复遇到：

| 术语 | 一句话说明 |
| --- | --- |
| main 函数 | 程序入口，返回 0 表示正常结束。每个 C++ 程序都必须有一个 `main`。 |
| 编译与链接 | 先把源码翻译成目标文件，再把库和多个目标文件合成可执行程序。C++ 是编译型语言，不像 Python 那样边读边跑。 |
| 命名空间 std | 标准库所在的命名空间，`std::` 前缀用于避免名字冲突。`cout`、`cin`、`string` 都住在 `std` 里。 |
| 入门练习 | 用最小输入和明确验收标准完成第一次动手验证。第一个程序就是最好的入门练习。 |
| 头文件 | 头文件通常放声明，源文件放定义。`#include` 在预处理阶段把头文件内容插入当前文件。 |
| 引用 | 值语义会复制对象，引用是已有对象的别名且必须初始化，指针保存地址并可以为空。 |

## 原理与运行机制

### 你的代码是怎么跑起来的

```text
你写的代码（hello.cpp）
    ↓ 预处理：展开 #include
    ↓ 编译：翻译成汇编代码
    ↓ 汇编：生成目标文件（.o）
    ↓ 链接：合并库和目标文件
可执行程序（hello.exe）
    ↓ 运行
屏幕上出现你写的文字
```

整个过程就像你把一份手写菜谱交给厨师团队：预处理先把"参见第 3 页的酱料做法"替换成真正的酱料配方；编译把中文步骤翻译成厨房术语；汇编变成具体的操作动作；链接把需要的调料和工具全部备齐。最后厨师（CPU）就能按步骤做菜了。

### main 函数：程序的大门

```cpp
int main() {
    // 你的代码写在这里
    return 0;
}
```

每个 C++ 程序都从 `main` 开始执行。`int` 表示 `main` 会返回一个整数给操作系统——返回 0 表示"一切正常"，返回其他数字表示"出错了"。你可以把 `main` 想象成一扇大门：程序启动时从这扇门走进来，结束时从这扇门走出去。

### std::cout：把文字送上传送带

```cpp
#include <iostream>

int main() {
    std::cout << "你好，C++" << std::endl;
    return 0;
}
```

把 `std::cout` 想成一根传送带：`<<` 是把包裹放上传送带的动作，你可以连续放好几件，它们就按顺序出现在屏幕上。`std::endl` 不仅换行，还会立刻刷新缓冲区，保证内容马上显示出来。

### #include：借别人的工具箱

```cpp
#include <iostream>
```

这行告诉编译器："我需要用到输入输出功能，请把 `iostream` 这个头文件的内容加进来。"没有这行，`std::cout` 就找不到——编译器会报一个"未声明的标识符"错误。

### 编译命令

```bash
g++ hello.cpp -o hello
```

`g++` 是 C++ 编译器，`hello.cpp` 是你的源文件，`-o hello` 表示输出的可执行文件叫 `hello`。编译成功后，Linux/macOS 用 `./hello` 运行，Windows 用 `hello.exe` 运行。

## 典型应用场景

C++ 的编译运行流程看起来比 Python 麻烦，但它换来了速度和可控性：

- **系统级开发**：操作系统、驱动程序、嵌入式固件都需要直接编译成机器码
- **游戏引擎**：Unity 的底层、Unreal Engine 全部用 C++ 编写，编译后才能跑
- **高性能计算**：科学模拟、金融建模、图像处理都靠编译型语言的速度优势
- **竞赛编程**：ACM/ICPC、Codeforces 等平台要求提交 C++ 源码并编译运行
- **学习其他语言的基础**：理解了编译链接，再学 Java、Rust、Go 的构建流程就轻松了

### 一个实际的小例子

假设你想在屏幕上打印两行文字：

```cpp
#include <iostream>

int main() {
    std::cout << "第一行" << std::endl;
    std::cout << "第二行" << std::endl;
    return 0;
}
```

编译运行后，屏幕上会出现：

```text
第一行
第二行
```

注意每条语句末尾的分号 `;`——C++ 用分号表示一条语句结束，漏掉就会报编译错误。

## 代码/协议/SQL 示例

### 最小可运行示例

```cpp
#include <iostream>

int main() {
    std::cout << "hello from C++\n";
    return 0;
}
```

运行方式：把这段代码保存为 `hello.cpp`，在终端执行：

```bash
g++ hello.cpp -o hello
./hello
```

输出：

```text
hello from C++
```

### 完整示例：打招呼

```cpp
#include <iostream>

int main() {
    std::cout << "你好，C++" << std::endl;
    std::cout << "欢迎来到编程世界！" << std::endl;
    return 0;
}
```

逐行解释：

- `#include <iostream>`：引入输入输出流库，`std::cout` 和 `std::endl` 都由它提供。
- `int main()`：程序入口，返回整数给操作系统表示结束状态。
- `std::cout << "你好，C++"`：把字符串送进标准输出流。
- `std::endl`：输出换行并立刻刷新缓冲区。
- `return 0;`：告诉操作系统"程序正常结束"。

### 动手练一练

- 把输出文字改成自己的名字，重新编译运行，确认输出跟着变
- 再写一条 `std::cout << "第二行" << std::endl;`，观察两行的效果
- 把 `std::endl` 换成 `"\n"`，说明两者在刷新时机上的差别
- 故意删掉 `#include <iostream>`，编译一次，把完整的报错信息抄下来

## 时间/空间复杂度或性能分析

第一课的代码只有几行 `cout`，暂时不需要关心性能。

等你写到处理大文件或循环几万次时，再回来关注：
- **编译时间**：C++ 编译速度跟头文件数量和模板复杂度有关
- **运行时间**：编译后的 C++ 程序运行速度接近硬件极限，比解释型语言快几十倍
- **可执行文件大小**：链接的标准库越多，文件越大；用 `-O2` 优化可以减小体积

现在记住一点就好：**先让代码编译通过，再考虑优化。**

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 写成 `#include <iostream.h>` | 编译器报"找不到文件" | 去掉 `.h`，现代 C++ 用 `#include <iostream>` |
| 漏掉 `std::` 前缀 | 报 `cout was not declared` | 加上 `std::` 前缀 |
| 忘写分号 | 报错常常指向下一行 | 每条语句末尾加分号 `;` |
| 直接双击 `.cpp` 文件 | 打开文本编辑器，不是运行 | 先编译再运行 |
| 编译后运行旧文件 | 输出没变化 | 改动代码后重新编译 |

### 现场 1：缺少头文件或命名空间

**症状**：编译器报 `cout was not declared` 或类似错误。

**根因与修复**：忘了写 `#include <iostream>` 或者漏掉 `std::` 前缀。加上头文件，补上前缀，重新编译就好。

### 现场 2：编译命令与源文件不匹配

**症状**：运行程序后发现输出没变化，还是上次的结果。

**根因与修复**：改了代码但忘了重新编译。养成习惯：每次改完代码都重新执行编译命令。

### 现场 3：忽略程序退出码

**症状**：程序运行出错了，但你看不到任何提示。

**根因与修复**：`main` 正常返回 0，失败返回非零并输出错误信息。这样操作系统和 CI 流水线才能知道程序是否成功。
