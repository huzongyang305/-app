## 本节知识框架

前几课你写了所有代码都在 `main` 里。当程序变复杂时，把所有东西堆在一起会变得很难维护。这一课我们学习把重复逻辑拆成**函数**——就像把菜谱里的"做酱汁"单独写成一张卡片，需要时拿出来用。

学完这一课，你会：
- 理解函数声明和定义的区别
- 会写带参数和返回值的函数
- 知道 `void` 表示函数不返回值
- 理解值传递和引用传递的差异
- 了解函数重载的基本概念

**先修与衔接**：先修《C++ 循环入门》。函数会把循环里的重复逻辑提取出来。

## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| 函数声明与定义 | 声明给出签名供调用方使用，定义提供函数体。声明像目录，定义像正文。 |
| 参数与返回值 | 参数是输入，返回值是输出，类型都要显式写出。 |
| void | 表示函数不返回任何值。用于"只做事情，不给结果"的函数。 |
| 值传递与引用传递 | 值传递复制实参，引用传递直接操作原对象，用 `&` 声明。 |
| 函数重载 | 同名函数通过参数列表不同来区分，编译器按实参选择。 |
| 头文件 | 头文件通常放声明，源文件放定义；`#include` 在预处理阶段展开。 |
| 默认参数 | 声明里给形参一个默认值，调用方可以省略该实参；默认值只能出现在参数列表右侧连续一段。 |
| 翻译单元 | 一个 `.cpp` 加上它 `#include` 的所有头文件，经预处理后编译成一个 `.o`；链接阶段合并这些 `.o`。 |
| inline 函数 | 建议编译器把函数体就地展开到调用点，多翻译单元下允许重复定义，但语义仍是一份。 |
| 返回类型推导 | C++11 起支持 `auto f() -> int` 或 C++14 的 `auto f()` 省略返回类型，入门阶段仍推荐显式写。 |

## 原理与运行机制

### 函数就像一台自动售货机

你投币（传入参数），按下按钮（调用函数），机器给你一瓶饮料（返回值）。你不需要知道机器内部怎么工作的——这就是函数的核心思想：**封装**。

```cpp
int square(int n) {
    return n * n;
}
```

这个函数接收一个整数 `n`，返回 `n` 的平方。调用方式：

```cpp
int result = square(7);  // result = 49
std::cout << "square(7)=" << result << "\n";
```

### 声明与定义分离

```cpp
// 声明（放在头文件里）
int add(int a, int b);

// 定义（放在源文件里）
int add(int a, int b) {
    return a + b;
}
```

声明告诉编译器"有这么一个函数，参数是什么类型，返回什么类型"；定义提供函数的具体实现。分离的好处是：头文件里只需要声明，多个源文件都能调用，最后由链接器合并。

### 值传递：给你一份副本

```cpp
void increment(int x) {
    x = x + 1;  // 只修改了副本
}

int main() {
    int a = 10;
    increment(a);
    std::cout << a;  // 输出 10，a 没有被改变
}
```

值传递时，函数拿到的是实参的**副本**。修改副本不会影响原来的变量。就像你把文件复印一份给别人，别人在复印件上涂改，你的原件不受影响。

### 引用传递：直接操作原件

```cpp
void increment(int& x) {
    x = x + 1;  // 直接修改原件
}

int main() {
    int a = 10;
    increment(a);
    std::cout << a;  // 输出 11，a 被改变了
}
```

引用传递时，函数里的 `x` 就是 `a` 的别名。修改 `x` 就是修改 `a`。对于大对象（比如很长的字符串），引用传递避免了复制的开销。

### const 引用：只读不复制

```cpp
void print(const std::string& s) {
    std::cout << s << "\n";  // 只能读，不能改
}
```

`const std::string&` 表示"给我一个字符串的引用，但我保证不修改它"。这是 C++ 中最常用的参数传递方式——既避免了复制，又保证了安全。

### 函数重载

```cpp
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }
```

同名函数可以有多个版本，只要参数列表（类型或数量）不同。编译器根据你传入的实参自动选择匹配的版本。

### 从源码到可执行文件：声明与定义分离的实际过程

C++ 编译分成两步。第一步把每个 `.cpp` 独立翻译成一个目标文件（`.o`），预处理会原样展开 `#include`，编译器只需要知道"存在一个 `int add(int, int)`"就能通过语法检查。第二步链接器把多个 `.o` 拼起来，把每个调用点解析到具体函数体。

```text
math.h   声明：int add(int a, int b);
math.cpp 定义：int add(int a, int b) { return a + b; }
main.cpp 使用：#include "math.h"  ... add(3, 4);

g++ -c math.cpp  →  math.o   （里面有一个 add 的函数体）
g++ -c main.cpp  →  main.o   （里面只有一个"我要调 add"的引用）
g++ math.o main.o -o prog    （链接器把引用指向 math.o 里的定义）
```

如果 `main.cpp` 里 `#include "math.h"` 时把头文件里写成了定义（`int add(...) { ... }`），两个 `.o` 里就都会有一份 `add` 的函数体，链接期会报 `multiple definition of add`；这条正好对应本课"常见误区"表里那一行。

### 为什么每条路径都必须 return

声明了非 `void` 返回类型的函数，如果控制流走到函数末尾还没遇到 `return`，标准里定义这是**未定义行为**。GCC/Clang 在开启 `-Wall -Wreturn-type` 后会警告 "no return statement in function returning non-void"，但不会拦下编译。

```cpp
int abs(int x) {
    if (x >= 0) return x;
    // 忘了写 else return -x;
}
```

这段代码在 `-O0` 下多半"看起来能跑"，返回一个恰好留在返回值寄存器（x86-64 是 `eax`）里的旧值；`-O2` 之后可能直接崩掉，也可能给出一个和调用方类型对不上的数。修法是：让函数只有一个出口，或者每个分支都显式 `return`；实在写不出来时用 `std::abort()` / `throw` 明确表达"这里不该到达"。

### 默认参数与重载的相互作用

```cpp
int add(int a, int b, int c = 0) { return a + b + c; }
int add(int a, int b)             { return a + b; }

add(1, 2);   // 二义性：到底走默认参数版还是走两参版？编译器直接报 reference to add is ambiguous
```

默认参数会把"三参调用"和"两参调用"都变成合法候选，如果同时存在两参重载，编译器就不知道选哪一个。规矩很朴素：**要么用默认参数、要么用重载，不要混着用**。要真的需要同时表达"可选参数 + 不同类型"，改用 `std::optional<int>` 作参数会更明确。

### 返回值语义的三档

入门阶段先掌握三种：

- `T` 返回值：给调用方一份拷贝，调用方拥有它。小对象（`int`、`double`）首选。
- `const T&` 返回值：交回一份"只读视图"，前提是它指向的对象在调用方使用期间一直存活——**不要返回局部变量的引用**，函数一返回局部对象就销毁，引用悬空。
- `T&` 非 const 引用：允许调用方就地修改原对象，很少必要，一般改用指针或返回索引。

大对象（`std::string`、`std::vector`）按值返回时，编译器通常会做 RVO/NRVO 直接把对象构造在调用方的存储里，不发生实际拷贝；C++11 起还可以 `std::move` 明确交回所有权。这些细节到《移动语义与智能指针》会展开，本课先记一条：**能按值返回就按值返回，别急着返回引用**。

### constexpr：让函数在编译期就算

```cpp
constexpr int square(int n) { return n * n; }

constexpr int s = square(7);   // 编译期就算出 49
int x = 7;
int y = square(x);             // 运行期正常调用，同一个函数两种用法
```

`constexpr` 只是"承诺这个函数**可以**在编译期求值"，编译器会在能算的时候算、不能算的时候退回普通调用。对 `square(7)` 这类小函数，加上 `constexpr` 是零成本的收益；对数组大小、`static_assert` 校验等需要常量的位置，`constexpr` 函数几乎是唯一的写法。

## 典型应用场景

函数是代码复用的基础：

- **数学计算**：把公式封装成函数，如 `double area(double r) { return 3.14159 * r * r; }`
- **数据处理**：读取、清洗、转换数据各用一个函数
- **输入验证**：检查用户输入是否合法，不合法就要求重新输入
- **游戏逻辑**：移动角色、检测碰撞、计算分数各拆成函数
- **代码组织**：把 `main` 里的长代码拆成几个有名字的小函数，可读性大增

### 一个实际的小例子

```cpp
#include <iostream>

int square(int n) { return n * n; }

int main() {
    std::cout << "square(7)=" << square(7) << "\n";
    return 0;
}
```

输出：`square(7)=49`

### 场景：把输入校验抽成函数

```cpp
#include <iostream>
#include <string>

bool parseAge(const std::string& s, int& out) {
    if (s.empty()) return false;              // 失败路径 1：空串
    for (char c : s) if (c < '0' || c > '9') return false;   // 失败路径 2：非数字
    long v = std::stol(s);
    if (v < 0 || v > 150) return false;       // 失败路径 3：越界
    out = static_cast<int>(v);
    return true;
}

int main() {
    std::string in;
    int age;
    std::cout << "请输入年龄：";
    std::getline(std::cin, in);
    if (parseAge(in, age)) std::cout << "OK, age=" << age << "\n";
    else                    std::cout << "输入不合法\n";
}
```

这个函数把"输入解析"三件事一次做完：读、验、转。三条失败路径都用 `return false` 明确交回，成功才通过 `out` 参数带出结果。相比在主流程里堆一串 `if`，把它抽成函数之后：主函数只剩下"看返回值决定下一步"这一层逻辑；单测时可以针对每条失败路径各构造一个输入验证——空串、含字母、越界——而不用先把 `main` 跑起来。

### 场景：字符串小工具

```cpp
#include <algorithm>
#include <cctype>
#include <string>

std::string toUpper(std::string s) {            // 按值传：调用方愿意付拷贝，函数就"拥有"一份可改的
    std::transform(s.begin(), s.end(), s.begin(),
                   [](unsigned char c) { return std::toupper(c); });
    return s;
}

void toUpperInPlace(std::string& s) {           // 按引用传：直接改调用方那份
    std::transform(s.begin(), s.end(), s.begin(),
                   [](unsigned char c) { return std::toupper(c); });
}
```

两个函数语义相同、接口不同：前者返回新串（调用方原文不变）、后者就地修改（不返回）。选择依据很直接——**需要保留原文就用返回新串；不需要保留就用 `&` 就地改**。避免同时提供一个"看起来能选"的重载，否则调用方要读两遍文档才知道走哪条。

### 完整示例：温度转换

```cpp
#include <iostream>

double celsiusToFahrenheit(double c) {
    return c * 9.0 / 5.0 + 32.0;
}

void printConversion(double c) {
    std::cout << c << "°C = " << celsiusToFahrenheit(c) << "°F\n";
}

int main() {
    printConversion(0);
    printConversion(100);
    printConversion(37);
    return 0;
}
```

逐行解释：

- `celsiusToFahrenheit`：接收一个 `double` 参数，返回转换后的华氏温度。
- `printConversion`：返回类型是 `void`，表示不返回值，只做打印。
- `main` 调用 `printConversion` 三次，每次传入不同的摄氏温度。

### 多文件示例：`math_ops.h` + `math_ops.cpp` + `main.cpp`

```cpp
// math_ops.h
#pragma once
int add(int a, int b);
double average(const int* data, int n);   // 只读指针参数，返回可能为 NaN 表示空数组
```

```cpp
// math_ops.cpp
#include "math_ops.h"
#include <limits>

int add(int a, int b) { return a + b; }

double average(const int* data, int n) {
    if (n <= 0 || data == nullptr) return std::numeric_limits<double>::quiet_NaN();
    long long s = 0;
    for (int i = 0; i < n; ++i) s += data[i];
    return static_cast<double>(s) / n;
}
```

```bash
g++ -std=c++17 -Wall -Wextra -c math_ops.cpp
g++ -std=c++17 -Wall -Wextra -c main.cpp
g++ math_ops.o main.o -o prog
```

头文件里只声明、源文件里放定义，`#pragma once` 保证同一个头文件在一个翻译单元里只被展开一次。三个命令分开跑，是为了让 `-Wall -Wextra` 的告警分别落在两个 `.cpp` 上；如果图省事写成 `g++ *.cpp -o prog`，一个文件报错会遮住另一个文件的告警，反而更难查。

## 时间/空间复杂度或性能分析

函数调用本身的开销很小（通常只是一次跳转），但参数的传递方式会影响性能：

- **值传递**：每次调用都复制一份参数。对于 `int`、`double` 等小类型没问题，但对于 `std::string`、`std::vector` 等大对象，复制开销明显
- **const 引用传递**：不复制，只传一个引用（本质是指针），开销极小
- **返回值优化（RVO）**：编译器通常会优化掉返回临时对象的复制

原则：**只读参数用 `const &`，需要修改用 `&`，小类型用值传递。**

### 值传递的复制代价

参数按值传递时，函数入口必须构造一份副本；对 `int/double` 就是一条 mov 指令，对 `std::string`（小串优化下大概 32 字节）就是一次 memcpy，对 `std::vector<T>`（24 字节的三元指针组）也还行，但如果元素本身有大对象那才叫贵。规则可以简化成一句：**小于两个指针宽度的类型按值传，其他按 `const&` 传**；这个阈值与本课"按值传大对象"那条易错点是同一件事的两面。

### inline 与调用开销

现代编译器对短小、频繁调用的函数会自动做内联——把函数体直接嵌入调用点，省掉一次 call/ret。`inline` 关键字在 C++ 里更重要的作用是**允许多个翻译单元看到同一份定义而不冲突**（不是强迫内联），这也是它常出现在头文件的原因。真正需要提示编译器内联时，用 `__attribute__((always_inline))` 或 `[[gnu::always_inline]]`，但入门阶段完全不需要动它，交给 `-O2` 就够。

### 递归 vs 循环：栈空间与速度

`long long factorial(int n)` 用递归写，每次调用压一帧栈，10 万层就会 stack overflow；改写成一圈 `for` 只要常数空间。速度上，编译器通常不能把尾递归优化成循环（GCC 需要 `-O2` 且写法严格），递归版本每层都有压栈/弹栈成本。入门阶段的原则：**能用 `for` 表达的就不用递归**，非要递归时把可能出现的最大深度写进注释。

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 按值传递大对象 | 每次调用都复制，性能明显下降 | 只读参数用 const 引用，需要拷贝时再按值传递 |
| 忘记写 return | 函数返回值未定义，结果不可预测 | 非 void 函数每条路径都要有 return |
| 声明和定义参数名不一致 | 不影响编译但容易混淆 | 声明和定义用相同的参数名 |
| 在头文件里写函数定义 | 多个源文件包含时链接报重复定义 | 头文件只放声明，定义放 .cpp 文件 |
| 混淆重载和默认参数 | 调用时出现歧义 | 重载靠参数类型/数量区分，默认参数从右往左设置 |
| 返回局部变量的引用/指针 | 悬空引用，运行时读到垃圾数据或崩溃 | 按值返回，或返回静态/堆上对象并用智能指针管理 |
| 声明和定义只在头文件里给一份定义、`.cpp` 又不 include 自己 | 链接器找不到符号 | `.cpp` 一定要 `#include` 对应头文件，让声明和定义在同一份语法环境里核对 |
| 忘记参数类型隐式转换 | `add(3.5, 4.5)` 悄悄截断为 `int` | 打开 `-Wconversion`；对精度敏感的场景写明确的 `double` 重载 |

### 现场 1：按值传递大对象

**症状**：程序运行变慢，尤其是循环中频繁调用时。

**根因与修复**：只读参数用 const 引用，需要拷贝时再按值传递。

### 现场 2：头文件里写了函数定义

**症状**：单个 `.cpp` 编译没事，一旦两个源文件都 `#include` 同一个头就报 `multiple definition of f`。

**根因与修复**：预处理把 `#include` 展开成一份份拷贝，头文件里的定义就会在每个翻译单元里都生成一个同名符号，链接器拒绝合并。三种常见修法：

- 头文件里只留声明，定义放 `.cpp`。
- 定义确实必须留在头文件（模板、`inline` 函数）时，加上 `inline` 关键字。
- 用匿名命名空间把定义包起来，让它只在该翻译单元可见。

### 现场 3：声明和定义参数名不一致

```cpp
// math.h
double average(const int* values, int count);

// math.cpp
double average(const int* ptr, int n) { ... }
```

**症状**：编译、链接都能通过，但 IDE 补全时看到的名字是一套、`.cpp` 里读代码时看到的是另一套。改参数含义时容易只改一边——比如 `count` 从"个数"变成"最后一个下标"，两边同步不上就是隐性 bug。

**根因与修复**：声明和定义使用**完全一致**的参数名；这一条对可读性和未来重构都有直接好处，也是多数团队 style guide 里都会写的。

### 现场 4：忘了写 return

**症状**：函数看起来"能跑"，但返回值随编译选项变化——`-O0` 给一个合理数，`-O2` 给一个奇怪的旧寄存器值。

**根因与修复**：见上文"为什么每条路径都必须 return"一节。修法是给每个分支都补上 `return`；实在写不出所有分支时，末尾用 `throw std::logic_error("unreachable")` 或 `std::abort()` 明确"这里不该到达"。别依赖"编译器大概会给个 0"这种未定义行为。

## 与其他知识点的关系

- **先修课**：《C++ 循环入门》——函数最常封装的就是重复出现的循环逻辑。
- **后续课**：《指针与引用》——本课的引用传递只要求会写 `&`，那一课才解释别名与地址的差别；《类与面向对象》把一组相关函数绑回数据身上。
- **相关概念**：《编译与程序运行原理》与《链接与加载》——声明与定义分离是链接期符号解析的前提，重复定义与缺失定义都在这一阶段暴露出来。
- **相关概念**：重载决议按实参类型挑选候选函数，因此 `int` 与 `long` 的同名函数可以共存；`void` 返回值意味着调用点不能把结果放进表达式。
- **动手延伸**：只读参数用 `const` 引用、需要拷贝才按值传递这条规则，到《内存管理与智能指针》会更精确；多文件拆分后的编译与链接在《实战：CMake 多文件项目》里落地。

### 与指针与引用

本课的引用传递只要求会写 `int& x`，它背后的"引用是别名、不能重新绑定，指针是变量、可以换指向"这一层差别到《指针与引用》才展开。到时候会看到 `int& x` 与 `int* const x` 生成的机器码几乎相同，但语义和可读性差很多——只读大对象用 `const&`，允许为空用指针，需要就地修改用 `&`，这三条边界就靠那一课钉死。

### 与模板与概念

`template <typename T> T maxOf(T a, T b) { return a < b ? b : a; }` 是"一份源码对应多个具体函数"，编译器在实例化时按调用点的 `T` 生成对应的 `maxOf<int>`、`maxOf<double>`……这些实例都遵守本课的所有规则（值传/引用传/`return` 语义）。到《模板》一课会看到模板参数推导、SFINAE 与 C++20 concepts 如何把"参数类型对不上"的报错信息变得可读。

### 与编译与运行原理

声明与定义分离、链接期符号解析、头文件重复定义这三条只有到《编译与程序运行原理》里才看得见机器码级的证据。本课先把"哪些错误在编译期被抓、哪些在链接期才暴露"的经验建立起来：语法/类型错在编译期；缺定义、多定义在链接期；未定义行为要跑起来才浮现。

写一个函数 `double average(double a, double b)` 返回两个数的平均值。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `函数声明与定义` | 声明给出签名供调用方使用，定义提供函数体。 |
| `参数与返回值` | 参数是输入，返回值是输出，类型都要显式写出。 |
| `void` | 表示函数不返回任何值。 |
| `值传递与引用传递` | 值传递复制实参，引用传递直接操作原对象。 |
| `函数重载` | 同名函数通过参数列表不同来区分。 |
| `const 引用` | 只读引用，避免复制又禁止修改。 |
| `默认参数` | 声明里给形参默认值，只能出现在右侧连续一段。 |
| `翻译单元` | 一个 `.cpp` 加上它展开的所有头文件，独立编译成一个 `.o`。 |
| `inline 函数` | 允许多翻译单元看到同一份定义而不冲突，同时提示可内联。 |
| `RVO/NRVO` | 编译器把返回的临时对象直接构造在调用方存储里，省掉一次拷贝。 |
| `constexpr 函数` | 承诺可以在编译期求值的函数，能算时算、不能算时退回普通调用。 |
