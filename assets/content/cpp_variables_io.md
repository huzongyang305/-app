## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| 变量与类型 | C++ 是静态类型语言，变量声明时必须给出类型。`int` 装整数，`double` 装小数，`string` 装文字。 |
| 初始化 | 定义变量的同时给初值，未初始化的局部变量内容是未定义的（垃圾值）。 |
| 类型安全 | 读取时类型不匹配会让流进入失败状态，需要检查或清理。 |
| 字符串类型 | `std::string` 负责管理字符序列，比 C 风格字符数组更安全，支持 `+` 拼接。 |
| 头文件 | 头文件通常放声明，源文件放定义。`#include` 在预处理阶段展开，头文件保护或 `#pragma once` 防止重复包含。 |
| 引用 | 值语义会复制对象，引用是已有对象的别名且必须初始化，指针保存地址并可以为空。 |
| 输入流状态 | `std::cin` 内部记着好与坏的标记，一旦读失败，后续所有提取都会被直接跳过，必须 `clear()` 才救得回来。 |
| 提取与整行 | `>>` 按目标类型取一段、以空白分隔；`std::getline` 一次拿走一整行，中间的空格照单全收。 |
| 插入链 | `std::cout << a << b` 是一路往流里塞，`std::endl` 除了换行还会刷新缓冲区。 |
| 显示格式 | `std::fixed` 与 `setprecision` 改的是打印出来的样子，变量里存的值一位都没动。 |

## 原理与运行机制

### 变量就是贴了标签的盒子

```cpp
int age = 25;
double price = 9.99;
std::string name = "Ada";
```

想象你面前有三个盒子：一个标着 `age` 只能装整数，一个标着 `price` 只能装小数，一个标着 `name` 只能装文字。C++ 是"静态类型"语言——你必须提前告诉编译器每个盒子装什么类型的东西，编译器才能帮你检查。

### 初始化：别让盒子空着

```cpp
int x;       // 危险！x 的值是内存里的垃圾
int y = 0;   // 安全，y 明确是 0
```

未初始化的局部变量就像你没贴标签也没放东西的盒子——里面可能残留着上次使用这块内存的人留下的"垃圾"。养成习惯：**声明变量时就给初值**。

### std::cin：让程序听你说话

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name;
    std::cout << "请输入你的名字：";
    std::cin >> name;
    std::cout << "你好，" << name << "！\n";
    return 0;
}
```

`std::cin` 是标准输入流，`>>` 是提取运算符——它把用户从键盘输入的文字"提取"出来，放进变量里。`>>` 以空白（空格、Tab、换行）作为分隔符。

### 链式读取

```cpp
int a, b;
std::cin >> a >> b;
```

这行代码会从输入中依次读取两个整数，以空白分隔，分别存入 `a` 和 `b`。用户输入 `3 5` 回车后，`a` 就是 3，`b` 就是 5。

### 类型不匹配会怎样

```cpp
int num;
std::cin >> num;  // 用户输入了 "abc"
```

如果用户输入的不是数字而是字母，`std::cin` 会进入"失败状态"——`num` 不会被赋值，后续的 `cin` 操作也会全部跳过。这就是**类型安全**的含义：C++ 不会自动帮你把 `"abc"` 变成数字，而是让流报错，由你来处理。

### 一次 `cin >> a` 其实做了四步

把 `std::cin >> a;` 拆开看，顺序很清楚：先跳过前面剩下的空白（空格、Tab、换行都算），再按 `a` 的类型逐字符取值，然后做转换写进 `a`，最后把流本身作为返回值交出去——这正是 `std::cin >> a >> b;` 能连写的原理：前一次返回的还是那个流，于是继续在剩下的输入里取下一个值。

所以 `std::cin >> a >> b;` 的行为是"按类型解析、以空白分隔、依次写入 `a` 和 `b`"。用户输入 `3 5` 回车，`a` 得 3、`b` 得 5；输入 `3    5`、`3` 换行再 `5`，结果一样——空白数量不影响。但输入 `3,5` 就不行了：逗号不是空白，读完 3 之后下一个字符是 `,`，取 `int` 立刻失败。

### 失败状态怎么救回来

流一旦置坏，后面所有 `>>` 都不干活，`a`、`b` 保持旧值，程序继续用这些旧值算——这正是最阴险的地方：不崩，只是答案全错。恢复要两步：

```cpp
#include <iostream>
#include <limits>

int main() {
    int value = 0;
    while (true) {
        std::cout << "请输入数量（输入 0 结束）：";
        if (std::cin >> value) {                   // 读成功才用这个值
            if (value == 0) break;                 // 唯一的退出出口
            std::cout << "收到 " << value << "\n";
        } else {
            std::cin.clear();                      // 1. 把失败标记擦掉
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            std::cout << "刚才那行不是整数，已丢弃，请重输\n";
        }
    }
}
```

`clear()` 只是把"坏了"的标记擦干净，缓冲区里那个惹祸的字符还躺着，必须用 `ignore()` 把它连同整行丢掉；少了第二步，下一轮 `>>` 会立刻再次失败，重输循环就转成刷屏。`if (std::cin >> value)` 这个写法值得记住：流本身能当条件用，读成功为真，读失败为假。

### `>>` 和 getline 混用的换行陷阱

```cpp
int age = 0;
std::string city;
std::cin >> age;                       // 输入 28 回车：取走 28，换行符留在缓冲区
std::getline(std::cin, city);          // 立刻读到那个残留的换行，city 变成空串
```

`>>` 不吃行尾的换行，`getline` 却把换行当"这一行结束了"。两个连用时，中间要插一句 `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');` 把残留的行尾清掉。凡是"先读数字再读一行文字"的程序——登记姓名、填地址——都会撞上这一条。

### 初始化的三种写法和它们的差别

```cpp
int a = 0;      // 赋值式初始化，最常见
int b(0);       // 直接初始化，对基本类型效果相同
int c{0};       // 列表初始化，会拒绝把 double 塞进 int 这类窄化转换
int d;          // 局部变量不初始化：值是这块栈内存的残留，读它就是未定义行为
```

日常写 `=` 就够，但当你想让编译器帮忙挡住"把 3.9 塞进 int"这种事时，`{}` 会当场报错而 `=` 只是悄悄截断。全局变量和静态变量不写初值也会被清零，这份"好处"局部变量没有——所以本课的规矩只有一条：**声明的那一刻就把初值写上**。

### 输出格式：改的是显示，不是数据

```cpp
#include <iomanip>
#include <iostream>

int main() {
    double ratio = 1.0 / 3.0;
    std::cout << ratio << "\n";                                       // 默认 6 位有效数字：0.333333
    std::cout << std::fixed << std::setprecision(4) << ratio << "\n"; // 固定小数 4 位：0.3333
    std::cout << std::setw(8) << 42 << "\n";                          // 右对齐占 8 格
    return 0;
}
```

`fixed` 与 `setprecision` 会一直作用在这个流上，直到你改掉它，所以放进一次就整段程序都变。要临时效果可以换 `std::setprecision` 配合每次输出，或者干脆另开一个 `std::ostringstream` 拼好再打印。

## 典型应用场景

变量和输入输出是几乎所有 C++ 程序的基础：

- **计算器**：读取两个数字，输出加减乘除结果
- **信息登记**：读取姓名、年龄、邮箱，存储并显示
- **成绩统计**：读取一组分数，计算平均分和最高分
- **单位转换**：读取摄氏温度，输出华氏温度
- **简单游戏**：读取玩家选择，判断对错并计分

### 一个实际的小例子

```cpp
#include <iostream>

int main() {
    int a, b;
    std::cout << "请输入两个整数：";
    std::cin >> a >> b;
    std::cout << "它们的和是：" << a + b << "\n";
    return 0;
}
```

运行后输入 `3 5`，输出 `它们的和是：8`。

### 场景一：读一整行文字，再拆成字段

登记表格里"姓名 年龄 城市"经常是一行输入，中间有空格。这时候不该用三次 `>>` 硬拼，而是先 `getline` 拿整行，再交给 `std::istringstream` 拆：

```cpp
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::string line;
    std::cout << "请输入“姓名 年龄 城市”：";
    std::getline(std::cin, line);

    std::istringstream in(line);
    std::string name, city;
    int age = 0;
    if (in >> name >> age >> city) {
        std::cout << name << " 今年 " << age << " 岁，住在" << city << "\n";
    } else {
        std::cout << "信息不完整，请确认三个字段都填了\n";
    }
    return 0;
}
```

输入 `李雷 19 北京` 走成功分支；输入 `李雷 19` 走失败分支。同一段逻辑既能读带空格的名字，又能对缺字段给出明确回应——这就是"输入、输出、失败路径都要说明白"落到代码上的样子。

### 场景二：连续读数并统计，处理中途的坏输入

```cpp
#include <iostream>

int main() {
    double sum = 0.0;
    int count = 0;
    double value = 0.0;

    std::cout << "依次输入成绩，用 Ctrl+Z（Windows）或 Ctrl+D（macOS/Linux）结束：\n";
    while (std::cin >> value) {          // 读到文件结束或坏字符时，条件为假，循环自然退出
        sum += value;
        ++count;
    }

    if (count > 0) {
        std::cout << "共 " << count << " 条，平均分 " << sum / count << "\n";
    } else {
        std::cout << "一条有效成绩都没读到\n";
    }
    return 0;
}
```

`while (std::cin >> value)` 是 C++ 里最常见的读数骨架：它同时完成了"取一个值"和"检查取没取到"。注意 `sum` 和 `count` 都带了初值，否则 `sum / count` 会拿垃圾数据算出一个看似合理的平均分。

## 代码/协议/SQL 示例

### 最小可运行示例

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name = "Ada";
    int year = 1815;
    std::cout << name << " born in " << year << "\n";
    return 0;
}
```

输出：

```text
Ada born in 1815
```

### 完整示例：打招呼程序

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name;
    int age;

    std::cout << "你叫什么名字？ ";
    std::cin >> name;

    std::cout << "你几岁了？ ";
    std::cin >> age;

    std::cout << "你好，" << name << "！你 " << age << " 岁了。\n";
    return 0;
}
```

逐行解释：

- `std::string name;`：声明一个字符串变量 `name`，用来存放用户输入的名字。
- `int age;`：声明一个整数变量 `age`。
- `std::cin >> name;`：从键盘读取一个单词存入 `name`。
- `std::cout << "你好，" << name`：用 `<<` 把多段内容拼接输出。

### 渐进示例：一个能扛住乱输的读数程序

第一步，最小可跑，只验证声明、初始化、读取、输出这条链：

```cpp
#include <iostream>

int main() {
    int a = 0;
    std::cout << "请输入一个整数：";
    std::cin >> a;
    std::cout << "两倍是 " << a * 2 << "\n";
    return 0;
}
```

第二步，把"读没读到"变成显式判断，失败时给出口：

```cpp
#include <iostream>

int main() {
    int a = 0;
    std::cout << "请输入一个整数：";
    if (std::cin >> a) {
        std::cout << "两倍是 " << a * 2 << "\n";
    } else {
        std::cout << "那不是整数，程序结束\n";
        return 1;
    }
    return 0;
}
```

第三步，把单次判断升级成"读不满就重问"的循环，并把整数除法的坑一起处理掉：

```cpp
#include <iostream>

int main() {
    int total = 0, count = 0;

    while (count < 3) {
        std::cout << "第 " << count + 1 << " 个整数：";
        int value = 0;
        if (std::cin >> value) {
            total += value;
            ++count;
        } else {
            std::cout << "只收整数，请重输\n";
            std::cin.clear();
            std::cin.ignore(1000, '\n');
        }
    }

    std::cout << "总和 " << total << "，平均 "
              << static_cast<double>(total) / count << "\n";
    return 0;
}
```

注意最后一行的 `static_cast<double>(total) / count`：两个 `int` 相除会直接砍掉小数，`7 / 2` 得到 `3`；先把其中一个转成 `double`，才拿得到 `3.5`。这是本课"变量类型决定它能装什么、也决定运算怎么做"最直接的体现。

## 时间/空间复杂度或性能分析

本课的变量都是基本类型，占用空间很小：

| 类型 | 典型大小 | 说明 |
| --- | --- | --- |
| `int` | 4 字节 | 大约 ±21 亿 |
| `double` | 8 字节 | 约 15 位有效数字 |
| `std::string` | 32 字节 + 堆内存 | 短字符串有内联优化 |

`std::cin` 的速度比 `scanf` 慢，如果处理大量输入可以加 `std::ios::sync_with_stdio(false)` 加速。初学阶段不必担心，等遇到性能瓶颈再优化。

### 那行加速开关做了什么

```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```

第一句关掉"和 C 的 `stdio` 保持同步"这条默认约定，流的缓冲策略就自由了，逐字符取数的开销大幅下降；代价是从此不能把 `cin` 和 `scanf` 混着用在同一个输入上，否则两边看到的缓冲区进度不一致。第二句解除 `cin` 与 `cout` 的绑定——默认每次读之前都会先把输出刷出去（保证提示语先显示），关掉之后提示可能会"迟到"，需要自己补 `std::cout.flush()` 或改用 `std::endl`。

也就是说：加速从来不是免费的，它拿掉的是"帮你把顺序和一致性兜住"的那些默认保护。初学阶段保持默认最省心。

### 变量放在哪里，成本就不一样

`int`、`double` 这样的基本类型直接躺在栈上，声明时就占定那块内存，读写都是一条指令级的事；`std::string` 则不同，栈上那个对象只是一段"描述符"，真正的内容在堆上，超过小字符串优化阈值时还要走一次分配。变量越多、越长寿，栈帧就越大；把大数组声明成局部变量是新手最常见的爆栈方式之一，那种场景应该用 `std::vector` 让它把数据放到堆上。

本课的例子只有几个变量，谈性能为时过早，但"声明即分配、类型决定占多少字节"这条从第一天就成立。

### 判断结论之前，先把环境和输入钉住

同一份读数代码，在不同编译器版本、不同标准开关下行为可能不同——比如列表初始化对窄化转换的拒绝，就是新标准才严格起来的。所以每次记录"这段程序的行为是什么"时，顺手写清三件事：编译器与版本（`g++ --version`）、语言标准（`-std=c++17`）、以及你实际喂进去的输入。

输入这一项尤其重要。本课的读取逻辑至少要过四类样本：正常两个整数 `3 5`、多空格与换行分隔 `3` 换行 `5`、混进非数字 `3 abc`、直接结束（Ctrl+Z 或 Ctrl+D）。四类都跑过，才可以说"这个程序对乱输是安全的"；只跑第一条就写结论，往往在真实数据上立刻翻车。

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 忘初始化局部变量 | 变量值是垃圾数据，输出不可预测 | 声明时就赋初值：`int x = 0;` |
| 读取输入不检查是否成功 | 失败后变量保持旧值，程序继续计算 | 检查输入流状态，失败时清空缓冲并重新提示 |
| `cin >>` 读不了带空格的字符串 | 输入 "Zhang San" 只读到 "Zhang" | 用 `std::getline(std::cin, name)` 读整行 |
| 整数除法丢小数 | `5 / 2` 结果是 `2` 不是 `2.5` | 至少一侧转成 `double`：`5.0 / 2` |
| 混用 `cin >>` 和 `getline` | `getline` 读到空行 | 在 `cin >>` 后加 `std::cin.ignore()` 吃掉换行符 |
| 读失败后只 `clear()` 不清缓冲区 | 下一轮读取立刻又失败，重输循环刷屏 | `clear()` 之后紧跟 `ignore()` 丢掉那行坏输入 |
| 用 `int` 装手机号、大计数 | 数值越界后变成负数，越算越奇怪 | 先估数据范围，必要时换 `long long` 或 `std::string` |
| 把 `std::cin >> x` 当成"返回读到的个数" | 条件判断的语义完全跑偏 | 记住流本身可当布尔：读成功为真 |
| 高频输出都用 `std::endl` | 每行都触发一次缓冲区刷新，明显变慢 | 普通换行写 `"\n"`，确实要立刻可见时才 `endl` |

### 现场 1：读取输入不检查是否成功

**症状**：用户输入了字母而不是数字，程序继续运行但结果奇怪。

**根因与修复**：`cin >>` 失败后流进入错误状态。检查输入流状态，失败时清空缓冲并重新提示。

### 现场 2：姓名只存下了第一个词

**症状**：让用户输入 `Zhang San`，程序打印出来的是 `Zhang`，中间的空格像被吃掉了一样。

**根因与修复**：`>>` 是"按类型提取一段"，空白就是它的结束信号，所以一次只会拿到一个词。想连空格一起收，就换成 `std::getline(std::cin, name)` 拿整行；如果整行里还藏着好几个字段，先 `getline` 再交给 `std::istringstream` 逐个拆。

### 现场 3：变量没赋值就被打印

**症状**：`int maxScore;` 之后直接 `std::cout << maxScore;`，本机打印一个巨大数字，换台机器又变成 0，甚至偶尔是对的。

**根因与修复**：局部变量不初始化时，里面是那块栈内存上一次留下的残留，读它属于未定义行为——"看起来偶尔正常"恰恰是最危险的形态。声明就写初值：`int maxScore = 0;`，或者用 `int maxScore{};` 让编译器保证清零。

## 与其他知识点的关系

- **先修课**：《C++ 第一个程序》——知道程序从哪里进入、如何结束，才能理解输入输出流挂在运行期的哪个位置。
- **后续课**：《C++ 条件判断》——读进来的值要判断才有用途；《变量、类型与运算符》把本课的 `int`、`double`、`string` 推进到类型推导、`static_cast` 与未定义行为。
- **相关概念**：《C 基础语法与编译流程》——`scanf` 与 `printf` 靠格式串工作，C++ 的流靠类型匹配工作；读入时类型不符会让流进入失败状态，这是两种风格最大的分水岭。
- **相关概念**：《内存与缓存》——变量不是抽象的盒子，而是栈上一段有对齐要求的字节；理解布局才能明白为什么未初始化的局部变量拿到的是垃圾值。
- **延后展开**：`std::string` 与 C 风格字符数组的取舍会在《指针与引用》里重新出现，那时才需要真正比较两者的复制成本。
- **下一课《C++ 条件判断》**：读进来的值只有被判断才有用途。本课留下的 `if (std::cin >> value)` 骨架，到那一课会展开成完整的分支写法。
- **《变量、类型与运算符》**：`int` 与 `double` 相除的截断、`static_cast` 的显式转换、整数溢出后的回绕，都在那一课继续深挖；本课只要求你先记住"类型既决定装什么，也决定怎么算"。
- **《C++ 循环入门》**：本课"读不满三个数就重问"的循环雏形，到那一课会变成正式的 `while` 与 `for`，配合 `break`、`continue` 才真正好用。
- **《STL 容器与算法》**：当变量从"两三个"涨到"几百个"，就要换 `std::vector`；单个变量存不下批量数据这件事，越早明白越少绕路。
- **《环境与编译流程》**：`-Wall -Wextra` 会直接指出未初始化变量和窄化转换，本课不少"跑起来才发现"的问题，其实编译阶段就能拦住。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `变量与类型` | C++ 是静态类型语言，变量声明时必须给出类型。 |
| `初始化` | 定义变量的同时给初值，未初始化的局部变量内容是未定义的。 |
| `类型安全` | 读取时类型不匹配会让流进入失败状态，需要检查或清理。 |
| `字符串类型` | `std::string` 管理字符序列，比 C 风格字符数组更安全。 |
| `头文件` | 放声明的文本文件，`#include` 在预处理阶段展开。 |

| `缓冲区刷新` | 把攒下的输出立刻交出去，`std::endl` 每次换行都顺手做一遍这件事。 |
