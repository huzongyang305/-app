## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 异常 | 程序执行中偏离正常控制流的错误事件，需要捕获、传播或转换。 | 易错：部分数据静默丢失；正确做法是记录失败的条目与原因。 |
| try | 异步错误要额外注意：try/catch 只能捕获 await 的错误，未处理的 Promise 拒绝需要 .catch() 或 window.addEventListener('unhandledrejection', ...)。 | 易错：出现未处理的拒绝；正确做法是加 `try/catch` 或 `.catch`。 |
| 调试 | 通过日志、断点和最小复现定位程序偏差，确认根因后再修改代码。 | 易错：复现步骤不稳定就打断点，停下来的现场不是出错那一刻的状态；先把复现做稳再改代码。 |
| 性能 | 系统在给定负载下表现出的吞吐、延迟、资源占用和稳定性。 | 易错：泄露信息、性能损耗；正确做法是提交前清理或用日志库。 |
| SyntaxError | 语法错误 | 易错：语法错误；正确做法是少括号、少逗号。 |
| ReferenceError | 使用未声明的变量 | 易错：使用未声明的变量；正确做法是拼写错误、作用域外访问。 |
| TypeError | 类型不匹配或访问空值 | 易错：类型不匹配或访问空值；正确做法是`undefined.foo`、调用非函数。 |
| RangeError | 数值越界或栈溢出 | 易错：数值越界或栈溢出；正确做法是递归过深、`new Array(-1)`。 |
| URIError | URI 编解码错误 | 易错：URI 编解码错误；正确做法是`decodeURIComponent("%")`。 |
| AggregateError | 多个错误聚合 | 易错：多个错误聚合；正确做法是`Promise.any` 全部失败。 |
| 断点 | 源码面板打断点 | 易错：循环里每轮都停在同一个断点上；只有条件断点能留下真正出错的那一次现场。 |
| 条件断点 | 设置表达式为真时暂停 | 易错：条件表达式引用了当前作用域还没有的变量，断点永不触发，还以为代码没执行到。 |
| debugger 语句 | 代码里直接写 | 易错：忘了删就带进发布包；DevTools 没打开时它根本不暂停，问题照样漏到用户那边。 |
| 调用栈 | 面板查看 Call Stack | 易错：只盯栈顶那一帧，它常是 throw 的位置；要顺着 error.stack 点开自己写的那一帧。 |
| 网络面板 | 查看请求与响应 | 易错：请求与响应看着正常就收工；页面仍报错时缺陷多在拿到响应之后的解析里，要回到控制台的第一条报错继续定位。 |
| try / catch | 捕获并记录 | 易错：用空 catch 吞掉错误掩盖问题，或只捕获不再 throw 让上层以为成功；至少记录并继续抛出。 |
| 全局兜底 | `window.onerror`、`unhandledrejection` | 易错：只有冒泡到顶层的错误才接得到；本地被 catch 吞掉的异常它看不见，仍会上报不到。 |
| Source Map | 构建时生成并上传 | 易错：只在本地能复现就放过；线上没有配 source map 与错误上报，用户先撞上问题你才后知后觉。 |

## 典型应用场景

- **`SyntaxError`**：典型现象是语法错误；正确做法是少括号、少逗号。
- **`ReferenceError`**：典型现象是使用未声明的变量；正确做法是拼写错误、作用域外访问。
- **`TypeError`**：典型现象是类型不匹配或访问空值；正确做法是`undefined.foo`、调用非函数。
- **`RangeError`**：典型现象是数值越界或栈溢出；正确做法是递归过深、`new Array(-1)`。

### 最小验证场景

- 准备：保留 `javascript` 示例的原始输入，先记录 `错误处理与调试` 的基线输出和完整运行命令。
- 观察：先核对 调用了 `Error()`，再改变一个与 `异常` 相关的条件。
- 判定：新结果与 `错误处理与调试` 的基线不同不等于错误；只有当差异破坏了 `异常` 的定义或错误表中的约束，才判定为失败。

### 选择与边界

- 使用 `异常` 时，程序执行中偏离正常控制流的错误事件，需要捕获、传播或转换；易错：部分数据静默丢失；正确做法是记录失败的条目与原因。
- 使用 `try` 时，异步错误要额外注意：try/catch 只能捕获 await 的错误，未处理的 Promise 拒绝需要 .catch() 或 window.addEventListener('unhandledrejection', ...)；易错：出现未处理的拒绝；正确做法是加 `try/catch` 或 `.catch`。
- 使用 `调试` 时，通过日志、断点和最小复现定位程序偏差，确认根因后再修改代码。
- 使用 `性能` 时，系统在给定负载下表现出的吞吐、延迟、资源占用和稳定性；易错：泄露信息、性能损耗；正确做法是提交前清理或用日志库。

**教材衔接：try / catch / finally**

```javascript
function parse(json) {
  try {
    return JSON.parse(json);
  } catch (error) {
    if (error instanceof SyntaxError) {
      console.warn('JSON 格式错误', error.message);
      return null;
    }
    throw error;              // 处理不了的错误继续抛出
  } finally {
    console.log('解析结束');    // 无论成功失败都执行
  }
}
```

异步错误要额外注意：`try/catch` 只能捕获 `await` 的错误，**未处理的 Promise 拒绝**需要 `.catch()` 或 `window.addEventListener('unhandledrejection', ...)`。

```javascript
window.onerror = (message, source, line) => { /* 上报 */ };
```

**教材衔接：零基础详解：错误处理与调试方法**

### 一句话说清它是什么

错误处理让程序在出错时走可预期的分支，调试则是「在不知道原因时，用工具一步步缩小范围」。
关键在于：**先看报错类型，再定位行号，最后用断点验证猜测**。

### 用生活比喻理解

| 工具 | 比喻 | 说明 |
| --- | --- | --- |
| `try/catch` | 安全网 | 出问题时不至于整个掉下去 |
| `throw` | 主动报警 | 自己发现异常时上报 |
| `Error` 对象 | 病历 | 含类型、消息与调用栈 |
| 断点 | 暂停键 | 停在关键位置检查现场 |
| `console` 家族 | 记录仪 | 不同级别留痕 |

### 错误处理的完整结构

```javascript
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

function parseAge(raw) {
  const n = Number(raw);
  if (!Number.isInteger(n) || n < 0 || n > 150) {
    throw new ValidationError(`年龄不合法：${raw}`);
  }
  return n;
}

try {
  console.log(parseAge("abc"));
} catch (error) {
  if (error instanceof ValidationError) {
    console.warn("输入问题：", error.message);
  } else {
    console.error("意外错误：", error);       // 保留完整堆栈
    throw error;                              // 处理不了就继续往上抛
  }
} finally {
  console.log("处理结束");
}
```

### 异步代码的错误处理

```javascript
// Promise 方式
fetch("/api/user")
  .then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .catch((error) => console.error("请求失败：", error.message));

// async/await 方式（推荐）
async function loadUser() {
  try {
    const res = await fetch("/api/user");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (error) {
    console.error("请求失败：", error.message);
    return null;
  }
}
```

**注意**：`await` 之后如果不加 `try/catch`，错误会变成未处理的 Promise 拒绝。

### 断点调试的标准流程

1. **复现**：先找到稳定复现的步骤。
2. **定位**：在可疑函数入口打断点，看参数对不对。
3. **二分**：范围太大时，在中间位置验证，排除一半。
4. **验证**：看调用栈与作用域变量，确认是「数据错」还是「逻辑错」。
5. **收尾**：修完补一个测试或断言，避免复发。

### 新手最容易踩的八个坑

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| 用 `catch {}` 什么都不做 | 问题被完全掩盖 | 至少记录日志 |
| 只 `catch` 不 `throw` | 上层以为成功了 | 处理不了就继续抛 |
| 把 `console.log` 留在生产 | 泄露信息、性能损耗 | 提交前清理或用日志库 |
| 直接打印对象 | 看不到当前值 | 打印副本 `{...obj}` 或 `JSON.stringify` |
| 捕获了但丢掉了 `error` | 失去堆栈 | 打印 `error` 本身而不是 `error.message` |
| 在循环里吞异常 | 部分数据静默丢失 | 记录失败的条目与原因 |
| 依赖字符串比较错误信息 | 文案一变就失效 | 用自定义错误类与 `instanceof` |
| 忘了异步错误也需处理 | 出现未处理的拒绝 | 加 `try/catch` 或 `.catch` |

### 手把手练习：带容错的批量处理

```javascript
class DataError extends Error {
  constructor(index, reason) {
    super(`第 ${index} 条数据有问题：${reason}`);
    this.name = "DataError";
    this.index = index;
  }
}

function processAll(rows) {
  const ok = [];
  const failed = [];

  rows.forEach((row, i) => {
    try {
      const value = Number(row.value);
      if (!Number.isFinite(value)) throw new Error("不是数字");
      ok.push({ id: row.id, value });
    } catch (error) {
      failed.push(new DataError(i, error.message));
    }
  });

  return { ok, failed };
}

const result = processAll([
  { id: 1, value: "10" },
  { id: 2, value: "abc" },
  { id: 3, value: "30" },
]);

console.log(`成功 ${result.ok.length} 条，失败 ${result.failed.length} 条`);
for (const e of result.failed) console.warn(e.message);
```

## 时间/空间复杂度或性能分析

**教材衔接：内存与性能**

- 全局变量、未清理的定时器、未移除的监听器、闭包长期引用大对象 → 内存泄漏。

**测量方法**：以 `错误处理与调试` 的 `异常` 场景为对象，固定输入跑一遍记录基线，再把规模或并发度提高一个数量级复测；两次结果的差值与波动范围才是结论依据。
