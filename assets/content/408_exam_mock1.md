## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 链表逆置 | 将单链表中所有节点的 next 指针方向反转，使链表从头到尾变为从尾到头。 | 易错：需要三个指针（prev、curr、next）配合，注意保存后继节点防止断链。 |
| 直接映射 Cache | 主存每个块只能映射到 Cache 唯一确定的块，映射规则为 Cache 块号 = 主存块号 mod Cache 总块数。 | 易错：多个主存块竞争同一 Cache 行会导致频繁替换（冲突缺失）。 |
| 信号量 PV 操作 | P（wait）操作申请资源，信号量减 1；V（signal）操作释放资源，信号量加 1。 | 易错：互斥信号量初值为 1，同步信号量初值为 0；P/V 必须成对出现。 |
| 子网划分 | 将一个大网络划分为多个小网络，通过借用主机位来增加网络位实现。 | 易错：每个子网的可用主机数 = 2^主机位数 - 2（减去网络地址和广播地址）。 |
| 快速排序 | 基于分治思想的排序算法，选基准元素分区，递归排序子序列，平均 O(n log n)。 | 易错：最坏情况（已排序 + 固定基准）退化为 O(n²)；需随机化或三数取中优化。 |
| 子网掩码 | 32 位二进制数，网络位全 1、主机位全 0，用于区分 IP 地址中的网络号和主机号。 | 易错：/26 的子网掩码是 255.255.255.192，不是 255.255.255.196。 |

## 原理与运行机制

### 机制一：单链表逆置算法

**教材衔接：链表逆置的核心思想**

单链表逆置的核心操作是将每个节点的 next 指针指向前驱节点。由于单链表只有后继指针没有前驱指针，必须在修改 next 之前保存前驱和后续节点，否则链表会断裂。

算法步骤：
1. 初始化三个指针：`prev = NULL`（前驱），`curr = head`（当前），`next = NULL`（后继）。
2. 遍历链表，对每个节点执行：
   - `next = curr->next`（保存后继节点）
   - `curr->next = prev`（反转指针方向）
   - `prev = curr`（前驱前移）
   - `curr = next`（当前前移）
3. 遍历结束后，`prev` 指向原链表尾节点，即新链表的头节点。
4. 将 `head` 指向 `prev`。

边界情况：空链表（head == NULL）和单节点链表（head->next == NULL）无需处理，算法自然兼容。

```c
typedef struct ListNode {
    int data;
    struct ListNode* next;
} ListNode;

ListNode* reverseList(ListNode* head) {
    ListNode* prev = NULL;
    ListNode* curr = head;
    ListNode* next = NULL;

    while (curr != NULL) {
        next = curr->next;    // 保存后继
        curr->next = prev;    // 反转指针
        prev = curr;          // 前驱前移
        curr = next;          // 当前前移
    }
    return prev;  // 新的头节点
}
```

时间复杂度 O(n)，空间复杂度 O(1)，只需一次遍历即可完成逆置。

### 机制二：直接映射 Cache 计算

**教材衔接：Cache 地址划分**

直接映射 Cache 中，主存块号与 Cache 块号的关系是：Cache 块号 = 主存块号 mod Cache 总块数。

假设主存容量为 256MB，Cache 容量为 2MB，块大小为 64B：
- 主存总块数 = 256MB / 64B = 4M 块 = 2^22 块
- Cache 总块数 = 2MB / 64B = 32K 块 = 2^15 块
- 主存地址 = 28 位（256MB = 2^28）
- 块内地址 = 6 位（64B = 2^6）
- Cache 行号（字块标记）= 15 位
- 主存字块标记 = 28 - 15 - 6 = 7 位

地址格式：`| 主存字块标记 (7位) | Cache 行号 (15位) | 块内地址 (6位) |`

映射规则：给定主存地址，先提取中间 15 位作为 Cache 行号，再比较高 7 位标记是否匹配。若匹配且有效位为 1，则 Cache 命中；否则缺失，需从主存调入。

**教材衔接：Cache 命中率计算**

设 Cache 访问次数为 Nc，主存访问次数为 Nm，则：
- 命中率 h = Nc / (Nc + Nm)
- 平均访问时间 ta = h × tc + (1-h) × tm
- 其中 tc 为 Cache 访问时间，tm 为主存访问时间

### 机制三：PV 操作设计

**教材衔接：信号量与互斥**

用信号量实现互斥时，信号量的初值应为可用资源的数量（通常为 1）。互斥信号量 mutex 初值为 1，表示临界区可用。进程进入临界区前执行 P(mutex)，离开后执行 V(mutex)。

**教材衔接：生产者-消费者问题**

```java
// 信号量定义
Semaphore empty = new Semaphore(n);   // 空缓冲区数量，初值为 n
Semaphore full = new Semaphore(0);    // 满缓冲区数量，初值为 0
Semaphore mutex = new Semaphore(1);   // 互斥信号量，初值为 1

// 生产者进程
void producer() {
    while (true) {
        produce_item();        // 生产一个产品
        P(empty);              // 等待空位
        P(mutex);              // 进入临界区
        put_item_to_buffer();  // 放入缓冲区
        V(mutex);              // 离开临界区
        V(full);               // 增加一个满位
    }
}

// 消费者进程
void consumer() {
    while (true) {
        P(full);               // 等待产品
        P(mutex);              // 进入临界区
        take_item_from_buffer();// 取出产品
        V(mutex);              // 离开临界区
        V(empty);              // 增加一个空位
        consume_item();        // 消费产品
    }
}
```

关键原则：
1. P 操作的顺序：先 P 资源信号量（empty/full），再 P 互斥信号量（mutex）。顺序反了可能导致死锁。
2. V 操作的顺序：先 V 互斥信号量（mutex），再 V 资源信号量（empty/full）。
3. 互斥信号量初值为 1，同步信号量初值为 0 或资源总数。

### 机制四：子网划分

**教材衔接：子网划分计算**

将 192.168.1.0/24 划分为 4 个子网，每个子网最多 62 台主机（/26，2^6-2=62）。

计算过程：
1. 原网络 /24，主机位 8 位。
2. 需要 4 个子网 → 借 2 位主机位作为子网位（2^2 = 4）。
3. 新前缀长度 = 24 + 2 = /26。
4. 剩余主机位 = 8 - 2 = 6 位。
5. 每个子网可用主机数 = 2^6 - 2 = 62 台（减去网络地址和广播地址）。

4 个子网划分：

| 子网 | 网络地址 | 可用范围 | 广播地址 |
| --- | --- | --- | --- |
| 子网 1 | 192.168.1.0/26 | 192.168.1.1 ~ 192.168.1.62 | 192.168.1.63 |
| 子网 2 | 192.168.1.64/26 | 192.168.1.65 ~ 192.168.1.126 | 192.168.1.127 |
| 子网 3 | 192.168.1.128/26 | 192.168.1.129 ~ 192.168.1.190 | 192.168.1.191 |
| 子网 4 | 192.168.1.192/26 | 192.168.1.193 ~ 192.168.1.254 | 192.168.1.255 |

子网掩码：255.255.255.192（二进制 11111111.11111111.11111111.11000000）

### 机制五：快速排序

**教材衔接：快速排序核心思想**

快速排序的平均时间复杂度是 O(n log n)。它采用分治策略：选一个基准元素，将数组分为两部分——小于基准的放左边，大于基准的放右边——然后递归排序两部分。

```python
def quick_sort(arr, low, high):
    if low < high:
        pivot_index = partition(arr, low, high)
        quick_sort(arr, low, pivot_index - 1)
        quick_sort(arr, pivot_index + 1, high)

def partition(arr, low, high):
    pivot = arr[high]
    i = low - 1
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1
```

时间复杂度分析：
- 平均情况：每次分区较均匀，递归深度 O(log n)，每层 O(n)，总计 O(n log n)。
- 最坏情况：每次分区极度不均匀（已排序数组 + 固定选首/尾元素为基准），退化为 O(n²)。
- 优化方法：随机选基准、三数取中法、小数组切换插入排序。

## 时间/空间复杂度或性能分析

**性能关注点（四科综合）**：不同算法和系统设计的性能指标各有侧重。

**测量方法**：
- 链表逆置：时间 O(n)，空间 O(1)。遍历一次链表，仅使用三个指针变量。
- Cache 映射：直接映射查找时间 O(1)，但冲突率较高。全相联映射冲突率低但查找慢。组相联是折中方案。
- PV 操作：信号量操作本身时间 O(1)，但设计不当可能导致死锁或饥饿。
- 子网划分：不涉及时空复杂度，但影响网络性能和地址利用率。
- 快速排序：平均时间 O(n log n)，空间 O(log n)（递归栈）；最坏时间 O(n²)。

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 链表逆置时忘记保存后继节点 | 链表断裂，丢失后续节点 | 必须先 `next = curr->next` 再修改 `curr->next` |
| Cache 映射公式记反 | 计算出错误的 Cache 行号 | 正确公式：Cache 块号 = 主存块号 mod Cache 总块数 |
| PV 操作中 P 的顺序写反 | 可能导致死锁 | 先 P 资源信号量，再 P 互斥信号量 |
| 子网划分忘记减 2 | 主机数多算 2 台 | 每个子网需减去网络地址和广播地址 |
| 快速排序基准选择不当 | 已排序数据退化为 O(n²) | 随机选择基准或三数取中 |
| 信号量初值设错 | 互斥失效或同步错误 | 互斥信号量初值为 1，同步信号量初值为 0 |
| 子网掩码计算错误 | 混淆十进制和二进制 | 先写二进制再转十进制，/26 = 11111111.11111111.11111111.11000000 = 255.255.255.192 |
| 链表逆置后忘记更新头指针 | 链表仍从原头节点开始 | 逆置函数返回新的头节点（原尾节点），并赋值给 head |

### 现场 1：链表逆置代码调试

**症状**：运行逆置代码后，链表只保留了第一个节点，其余节点丢失。

**根因与修复**：在修改 `curr->next = prev` 之前，没有先用临时变量保存 `curr->next`（即后继节点）。导致后继指针被覆盖后，无法继续遍历。修复：在循环开头先 `next = curr->next`。

**自检**：用 3 个节点的链表手动模拟每一步，检查指针变化是否正确。

### 现场 2：Cache 映射计算错误

**症状**：计算主存地址中各字段位数时出错，导致映射关系不正确。

**根因与修复**：没有按照"块内地址 → Cache 行号 → 主存字块标记"的顺序从低位到高位划分。正确步骤：先确定块大小得到块内位数，再确定 Cache 大小得到行号位数，剩余为主存字块标记位数。

**自检**：用具体数值验证——主存 256MB、Cache 2MB、块 64B，地址 28 位 = 标记 7 位 + 行号 15 位 + 块内 6 位。

### 现场 3：PV 操作死锁分析

**症状**：两个进程互相等待，系统陷入死锁。

**根因与修复**：P 操作顺序不当。例如生产者先 P(mutex) 再 P(empty)，当缓冲区满时，生产者持有 mutex 并等待 empty，消费者因无法获取 mutex 而不能执行 V(empty)，形成死锁。修复：始终先 P 资源信号量再 P 互斥信号量。

**自检**：画出资源分配图，检查是否存在环路。

### 现场 4：子网划分主机数计算

**症状**：计算出的每个子网可用主机数为 64 台，答案错误。

**根因与修复**：忘记减去网络地址（主机位全 0）和广播地址（主机位全 1）。/26 子网有 6 位主机位，总地址 2^6 = 64 个，可用主机 = 64 - 2 = 62 台。

**自检**：写出每个子网的网络地址和广播地址，确认可用范围。

## 典型应用场景

**场景一：算法设计大题——单链表逆置**

408 真题中多次出现单链表逆置或其变体（如部分逆置、判断回文链表）。解题关键在于三指针法一次遍历完成逆置，时间 O(n)、空间 O(1)。考试中需手写完整代码并标注注释，注意边界条件（空链表、单节点链表）。

**场景二：Cache 映射计算题**

给出主存容量、Cache 容量和块大小，要求计算地址格式划分、映射关系及命中率。直接映射的公式「Cache 块号 = 主存块号 mod Cache 总块数」是解题核心。常考变体包括组相联映射的标记位计算和缺失率分析。

**场景三：PV 操作设计大题**

以生产者-消费者、读者-写者或哲学家进餐问题为背景，要求设计信号量及 P/V 操作。评分要点：信号量初值正确（互斥为 1、同步为 0 或资源数）、P/V 顺序正确（先资源后互斥）、无死锁和饥饿。

**场景四：子网划分综合题**

给出网络地址和子网需求，要求确定子网掩码、各子网地址范围及可用主机数。计算步骤为「借位 → 新前缀 → 主机位 → 减 2」。常与 CIDR 和路由聚合结合考查。

## 代码/协议/SQL 示例

### 示例 1：单链表逆置完整 C 程序（含测试）

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct ListNode {
    int data;
    struct ListNode* next;
} ListNode;

/* 创建新节点 */
ListNode* createNode(int data) {
    ListNode* node = (ListNode*)malloc(sizeof(ListNode));
    node->data = data;
    node->next = NULL;
    return node;
}

/* 链表逆置：三指针法，一次遍历 O(n) 时间 O(1) 空间 */
ListNode* reverseList(ListNode* head) {
    ListNode* prev = NULL;
    ListNode* curr = head;
    ListNode* next = NULL;

    while (curr != NULL) {
        next = curr->next;    // 1. 保存后继节点
        curr->next = prev;    // 2. 反转指针方向
        prev = curr;          // 3. 前驱前移
        curr = next;          // 4. 当前前移
    }
    return prev;  // prev 即为新的头节点
}

/* 打印链表 */
void printList(ListNode* head) {
    while (head != NULL) {
        printf("%d -> ", head->data);
        head = head->next;
    }
    printf("NULL\n");
}

int main() {
    /* 构建链表 1->2->3->4->5 */
    ListNode* head = createNode(1);
    head->next = createNode(2);
    head->next->next = createNode(3);
    head->next->next->next = createNode(4);
    head->next->next->next->next = createNode(5);

    printf("原始链表: ");
    printList(head);

    head = reverseList(head);

    printf("逆置链表: ");
    printList(head);
    /* 输出: 5 -> 4 -> 3 -> 2 -> 1 -> NULL */
    return 0;
}
```

### 示例 2：子网划分计算 Python 脚本

```python
def subnet_calculator(network_ip, prefix_len, num_subnets):
    """子网划分计算器：根据需求确定子网掩码和可用主机数"""
    import ipaddress

    network = ipaddress.ip_network(f"{network_ip}/{prefix_len}", strict=False)
    # 计算需要借用的主机位数
    borrow_bits = (num_subnets - 1).bit_length()  # ceil(log2(num_subnets))
    new_prefix = prefix_len + borrow_bits

    # 划分子网
    subnets = list(network.subnets(new_prefix=new_prefix))

    print(f"原子网: {network}")
    print(f"借用位数: {borrow_bits}, 新前缀: /{new_prefix}")
    print(f"子网掩码: {subnets[0].netmask}")
    print(f"每子网可用主机: {2 ** (32 - new_prefix) - 2} 台\n")

    for i, subnet in enumerate(subnets):
        hosts = list(subnet.hosts())
        print(f"子网 {i+1}: {subnet}")
        print(f"  可用范围: {hosts[0]} ~ {hosts[-1]}")
        print(f"  广播地址: {subnet.broadcast}")

# 示例：192.168.1.0/24 划分为 4 个子网
subnet_calculator("192.168.1.0", 24, 4)
# 输出：每个子网 /26，可用主机 62 台
# 子网掩码 255.255.255.192
```

## 自测题与参考答案

**题目 1**：单链表逆置算法的核心操作是？

<details>
<summary>参考答案</summary>

将每个节点的 next 指针指向前驱节点。具体实现需要三个指针配合：prev 记录前驱节点（初始为 NULL），curr 指向当前节点，next 保存后继节点。遍历链表时，先将 next 指向 curr->next 保存后继，再将 curr->next 指向 prev 完成反转，最后 prev 和 curr 各前进一步。遍历结束后 prev 即为新的头节点。空链表和单节点链表是边界情况，算法自然兼容无需特殊处理。
</details>

**题目 2**：直接映射 Cache 中，主存块号与 Cache 块号的关系是？

<details>
<summary>参考答案</summary>

Cache 块号 = 主存块号 mod Cache 总块数。这是直接映射的核心规则——每个主存块只能映射到 Cache 中唯一确定的位置。例如 Cache 有 8 块，则主存第 0、8、16... 块都映射到 Cache 第 0 块，第 1、9、17... 块都映射到 Cache 第 1 块。这种映射方式硬件简单、查找快（O(1)），但容易产生冲突缺失。
</details>

**题目 3**：用信号量实现互斥时，信号量的初值应为？

<details>
<summary>参考答案</summary>

可用资源的数量（通常为 1）。互斥信号量 mutex 初值设为 1，表示临界区当前可用。第一个到达的进程执行 P(mutex) 后信号量变为 0，成功进入临界区；后续进程执行 P(mutex) 时发现信号量为 0，被阻塞等待。离开临界区时执行 V(mutex) 将信号量恢复为 1，唤醒等待的进程。注意区分：同步信号量初值通常为 0。
</details>

**题目 4**：将 192.168.1.0/24 划分为 4 个子网，每个子网最多多少台主机？

<details>
<summary>参考答案</summary>

62 台。计算过程：需要 4 个子网则借 2 位主机位（2^2 = 4），新前缀为 /26。每个子网剩余 6 位主机位，总地址数 2^6 = 64，减去网络地址（主机位全 0）和广播地址（主机位全 1），可用主机数 = 64 - 2 = 62 台。子网掩码为 255.255.255.192。
</details>

**题目 5**：快速排序的平均时间复杂度是？

<details>
<summary>参考答案</summary>

O(n log n)。在平均情况下，每次分区操作能将数组较均匀地分为两部分，递归树深度为 O(log n)，每层的分区操作耗时 O(n)，因此总时间复杂度为 O(n log n)。但最坏情况（已排序数组 + 固定选首/尾元素为基准）会退化为 O(n^2)，可通过随机化基准或三数取中法来避免。空间复杂度为 O(log n)（递归栈深度）。
</details>
