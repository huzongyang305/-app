## 原理与运行机制

### 机制总览

**教材衔接：一句话说清**

JVM 把内存划分成**线程私有**与**线程共享**两类区域，垃圾回收主要发生在堆里。
看懂分区与 GC 流程，就能解释 `OutOfMemoryError`、`StackOverflowError` 与长暂停从哪来。

**教材衔接：一次 Young GC 的流程**

```text
① Eden 满 → 触发 Young GC
        │
        ▼
② 标记 Eden + S0 中的存活对象
        │
        ▼
③ 复制到 S1（年龄 +1），清空 Eden 与 S0
        │
        ▼
④ S0 与 S1 角色互换
        │
        ▼
⑤ 年龄达到阈值或 S 区放不下 → 晋升老年代

老年代空间不足 → Full GC / Mixed GC（停顿更长）
```

**失败路径（来自本课错误表）**
- `OutOfMemoryError: Java heap space` → 内存泄漏或堆太小 → 堆快照 + 支配树分析。
- `OutOfMemoryError: Metaspace` → 类加载过多（热部署、动态代理） → 看类加载数量。
- `StackOverflowError` → 递归过深 → 检查出口条件。
- GC 频繁 → 分配速率高或堆太小 → 看分配速率与 GC 日志。

**教材衔接：JVM 运行时内存分区**

```text
┌──────────────────────── JVM 进程内存 ────────────────────────┐
│                                                              │
│  线程共享区                                                   │
│  ┌────────────────────────┐  ┌───────────────────────────┐  │
│  │  堆 Heap（GC 主战场）   │  │ 方法区 / 元空间 Metaspace  │  │
│  │  · 新生代 Young         │  │ · 类元信息、常量、静态变量 │  │
│  │    - Eden              │  │ · JDK 8 起用本地内存        │  │
│  │    - Survivor S0 / S1  │  └───────────────────────────┘  │
│  │  · 老年代 Old           │                                 │
│  └────────────────────────┘                                 │
│                                                              │
│  线程私有区                                                   │
│  ┌──────────┐ ┌──────────────┐ ┌──────────────────────────┐ │
│  │程序计数器 │ │ 虚拟机栈 VM   │ │ 本地方法栈 Native Stack  │ │
│  │ PC       │ │ Stack        │ │                          │ │
│  └──────────┘ └──────────────┘ └──────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

| 区域 | 线程 | 存放 | 溢出时报错 |
| --- | --- | --- | --- |
| 堆 | 共享 | 对象实例、数组 | `OutOfMemoryError: Java heap space` |
| 方法区 / 元空间 | 共享 | 类元信息、常量池 | `OutOfMemoryError: Metaspace` |
| 虚拟机栈 | 私有 | 栈帧、局部变量 | `StackOverflowError` |
| 程序计数器 | 私有 | 当前字节码行号 | 不会溢出 |
| 本地方法栈 | 私有 | native 方法调用 | `StackOverflowError` |

```bash
# 常用参数
-Xms2g -Xmx2g                  # 堆初始与最大值设成一样，避免动态扩缩容抖动
-Xmn1g                         # 新生代大小

-XX:MaxTenuringThreshold=15    # 晋升老年代的年龄阈值
-XX:MetaspaceSize=256m
-Xss1m                         # 每个线程栈大小
```

### 考点 6：`JVM`

- **要点**：JVM 把内存划分成线程私有与线程共享两类区域，垃圾回收主要发生在堆里。
- **JVM 的边界**：易错：暂停加剧；正确做法是交给 JVM 决定。

### 考点 7：`内存模型`

- **要点**：编程语言或硬件对多线程读写可见性、原子性和重排序给出的规则集合。
- **内存模型 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 8：`垃圾回收`

- **要点**：运行时自动识别并回收不再可达的对象，避免手动释放并控制停顿。
- **垃圾回收 的边界**：越界、悬垂引用与释放顺序会破坏结论，必须在边界输入下复验。

### 考点 9：`G1`

- **要点**：JVM 面向大堆的垃圾收集器，用分区和可预测停顿目标平衡吞吐与延迟。
- **G1 的边界**：结论随输入规模变化，小规模成立不代表大规模成立，需要重新测量。

### 考点 10：`OOM`

- **要点**：内存溢出：堆或元空间耗尽时抛 OutOfMemoryError，需要区分泄漏、堆太小还是元数据过多。
- **OOM 的边界**：易错：最终 OOM；正确做法是用有容量限制的缓存。

### 考点 11：排错——`OutOfMemoryError: Java heap space`

- **现象**：内存泄漏或堆太小。
- **处理**：堆快照 + 支配树分析。

### 考点 12：排错——`OutOfMemoryError: Metaspace`

- **现象**：类加载过多（热部署、动态代理）。
- **处理**：看类加载数量。
