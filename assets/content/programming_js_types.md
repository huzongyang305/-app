## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 隐式转换 | 三条铁律：**默认 const、比较用 ===、空值判断用 ?? 或 == null**。理解 `+` 与 `-` 的隐式转换差异，能解释多数「诡异」行为。 | `==` 会按类型规则改值，`'' == 0` 与 `null == undefined` 都是坑；从别的模块拿到值时先归一化再比较。 |
| 类型 | 值允许的表示、取值范围和可执行操作集合。 | 动态类型下类型只跟着值走，变量本身不带类型，同一变量先后放 `number` 和 `string` 都合法，分支要按当前值判断。 |
| 类型转换 | 把值按目标形态重新取一次：`Number('42')` 得 `42`，`'1' + 1` 得 `'11'`，`'1' - 1` 得 `0`。 | `+` 碰到字符串走拼接，`-`、`*`、`/` 一律先把操作数转成数字，混写时要先定结合顺序。 |
| null | null == undefined // true 规定如此。 | 易错：`null == undefined` 恒真，用 `== null` 判空会把从未赋值的 undefined 也当成 null；要严格区分两者只能靠 `===`。 |
| JavaScript | 动态类型、基于原型的脚本语言，标准名为 ECMAScript；既能跑在浏览器里操作页面，也能用 Node.js 跑在服务端。 | 易错：JavaScript 动态类型没有编译期类型检查，`let x;` 后直接 `x.toFixed(2)` 要到运行期才抛 `TypeError`，只能自行校验。 |
| typeof "a" | `"string"` | `typeof` 返回的是小写类型关键字字符串，原始值判定够用，但它认的是当前值的类型而非变量声明。 |
| typeof 1 | `"number"` | 整数和浮点都归 `number`，`typeof 1` 区分不了整数还是小数，精度仍受浮点规则限制。 |
| typeof 1n | `"bigint"` | 只有带 `n` 后缀才返回 `bigint`，它不在 `Number` 系列里，判断时别把它和 `number` 混为一类。 |
| typeof true | `"boolean"` | 原始布尔值才返回 `boolean`；条件里的真值不等于布尔类型，只有 `Boolean(x)` 转完才得到 `true` 或 `false`。 |
| typeof undefined | `"undefined"` | 未赋值、函数无返回、属性不存在都返回 `undefined`，只看 `typeof` 分不出究竟来自哪一种。 |
| typeof null | `"object"` | 历史遗留误报：判空要用 `x === null` 或 `== null`，靠 `typeof` 会把 `null` 当成对象放过。 |
| typeof [] | `"object"` | 数组也报 `object`，`typeof` 分不出数组和普通对象，要判定数组得改用 `Array.isArray`。 |
| typeof function(){} | `"function"` | 函数是唯一返回 `function` 而非 `object` 的类型，可据此先判断它能不能被调用再执行。 |
| typeof Symbol() | `"symbol"` | 它作为原始类型返回 `symbol`，和 `string` 不是一回事，判类型时别拿字符串的规则去套它。 |
| Number.isNaN(NaN) | `true` | `typeof NaN` 仍是 `number`，只有这个函数能把 `NaN` 单独挑出来，判非数别只靠 `typeof`。 |
| Array.isArray([]) | `true` | 分数组只能靠它；`typeof` 对数组返回 `object`，会把普通对象和数组混在一起。 |
| x instanceof Date | 布尔值 | 它沿原型链确认对象身份，对 `null` 或原始值没意义；数组和 `NaN` 还得回 `Array.isArray` 或 `Number.isNaN`。 |
| Number("12") | `12` | 整串能解析成数字才返回 `12`；空串也会变 `0` 而非报错，转换前要先校验输入非空。 |
| parseInt("12px", 10) | `12` | 显式传 `10` 才稳：它取前导数字丢掉 `px`，省掉进制参数时老浏览器可能把 `08` 当八进制。 |
| parseFloat("3.14abc") | `3.14` | 它只吃掉开头合法的数字段、丢弃 `abc`，小数只认第一个点，别指望解析带单位或千分位的串。 |
| String(12) | `"12"` | 结果 `"12"` 是字符串，后面再接 `+` 就走拼接，和 `"1" + 2` 得到 `"12"` 是同一个坑。 |
| Boolean("") | `false` | 空串是少数假值才返回 `false`；注意 `"0"`、`"false"` 这类非空字符串转换后仍是 `true`。 |
| Boolean("0") | `true` | 只要字符串非空就为真，内容写着 `"0"` 也一样；想按数值判真假得先 `Number()` 再比较。 |
| [1, 2] + "" | `"1,2"` | 数组和字符串相加会先 `toString` 成 `"1,2"`；要参与数值运算前必须显式转换，别让它悄悄变成拼接结果。 |
| 0.1 + 0.2 | `0.30000000000000004` | 浮点精度有限，`0.1 + 0.2` 实际得 `0.30000000000000004`，用 `===` 比 `0.3` 恒为 false，判等要改用误差比较。 |
| null == undefined | `true` | 宽松相等规定两者互等；用 `== null` 判空可同时覆盖 `null` 和 `undefined`，但 `0`、`""` 不会被算进来。 |
| null === undefined | `false` | 严格相等先比类型，两者类型不同所以 `false`；用 `===` 判空时得把 `null` 和 `undefined` 分开写。 |
| "5" - 1 | `4` | 减号强制把 `"5"` 转数字再算得 `4`，它不像 `+` 会走拼接，非数字串喂进来只会得 `NaN`。 |
| number | `1`、`3.14`、`NaN` | 整数和小数同属 `number`，精度有限导致 `0.1 + 0.2 !== 0.3`，金额要退回整数分处理。 |
| string | `"hi"`、`` `hi` `` | 单双引号和模板串都是 `string`，它一进 `+` 就触发拼接、把数字拉成文本，算术前别混进来。 |
| boolean | `true` / `false` | 只有这两个字面量；条件表达式会把非布尔值折成真假分支，判断前先确认值到底属于哪一类。 |
| undefined | `let x;` | 易错：`let x;` 后 `x` 是 undefined，用 `if (x)` 会把 `0`、`""` 也当成没值；判真正缺失要用 `x === undefined` 或 `typeof x`。 |
| null | `let y = null;` | 显式赋 `null` 表示故意留空，用逻辑或兜默认值会连 `0`、`""` 一起替换掉；只在 null/undefined 时兜底要用 `??`。 |
| symbol | `Symbol("id")` | 它有独立的 `typeof` 结果，每次 `Symbol()` 生成的是新值，判等时别把它当普通标签字符串比。 |
| bigint | `10n` | 字面量以 `n` 结尾才成立，超出 `number` 安全整数范围时才用它，别和 `number` 塞进同一个算术表达式。 |
| object | `{}`、`[]`、函数 | `typeof` 下数组也归 `object`（函数除外），比较看的是引用，`{ a: 1 } === { a: 1 }` 得到 `false`。 |
| 含义 | 还没有值 | `undefined` 只代表还没有值；空串和 `0` 是有效值，判缺失时别把它们一并当成 undefined 扔掉。 |
| 谁产生的 | JS 引擎自动 | 由引擎在 `let x;` 未赋值或函数无返回时自动给出，不是显式写的 `null`，判空要分清来源。 |
| 典型场景 | 未赋值、函数无返回、属性不存在 | 三种场景都给出 `undefined`；要区分"键不存在"还是"值就是 undefined"，得改用 `"name" in obj`。 |
| Number("12") | `12` | 它走显式数字转换，和 `+` 的隐式拼接不同；输入里只要掺了非数字字符结果就不是 `12`，别拿它代替校验。 |
| Number("") | `0` | 易错：`0`；正确做法是空输入要先校验，别直接转换。 |
| parseInt("12px") | `12` | 不写进制时它仍取前导数字得 `12`，但省略第二参在老环境有八进制隐患，稳妥写法是补上 `, 10`。 |
| String(12) | `"12"` | 它显式产出文本 `"12"`，效果和 `12 + ""` 接近；一旦进了字符串轨道，再想拿回数值必须重新转换。 |
| Boolean("") | `false` | 空串、`0`、`NaN` 这类才算假值；判字符串是否为空别借它，直接比长度更直白。 |
| Boolean("false") | `true` | 非空字符串一律为真，内容写着 `"false"` 也返回 `true`；表单传来的布尔文本必须自己解析，靠 `Boolean` 会反。 |
| "1" + 2 | `"12"` | 易错：`+` 只要有一边是字符串就走拼接，`"1" + 2` 得 `"12"` 而不是 3；想要求和得先 `Number("1")`。 |
| "3" * 2 | `6` | 乘号先把 `"3"` 转成数字得 `6`；它没有拼接分支，任何一边是非数字串就整体塌成 `NaN`。 |
| 用 == | 结果反直觉 | 宽松相等会隐式改值，`[] == false` 这类都成立；判空可留 `== null`，其余一律换成 `===`。 |
| 把 NaN 当相等 | `NaN === NaN` 是 false | 用 `===` 判 `NaN` 永远不成立，别写 `x === NaN`；要识别它得走 `Number.isNaN(x)`。 |
| 直接调 parseInt 忘传进制 | 老浏览器把 `08` 当八进制 | 省略第二参时 `08`、`09` 在老引擎可能按八进制解析；统一写 `parseInt(s, 10)` 才没有歧义。 |
| 数字精度 | `0.1 + 0.2 !== 0.3` | 多次浮点运算误差会累积，`number` 精度有限；比较要留误差、金额退回整数分，别直接 `===`。 |
| 字符串拼数字 | `"1" + 2` 得到 `"12"` | 字符串与数字用 `+` 混算会被拉成文本而非相加，参与计算前先 `Number()` 显式转成数字再运算。 |
| 判断属性是否存在 | `if (obj.name)` 漏掉 0 和 "" | 易错：`if (obj.name)` 漏掉 0 和 ""；正确做法是用 `"name" in obj` 或 `??`。 |
| 引用赋值当复制 | 改一处全变 | 易错：改一处全变；正确做法是用展开运算符浅拷贝。 |

## 典型应用场景

- **用 `==`**：典型现象是结果反直觉；正确做法是用 `===`。
- **把 `NaN` 当相等**：典型现象是`NaN === NaN` 是 false；正确做法是用 `Number.isNaN(x)`。
- **直接调 `parseInt` 忘传进制**：典型现象是老浏览器把 `08` 当八进制；正确做法是写 `parseInt(s, 10)`。
- **数字精度**：典型现象是`0.1 + 0.2 !== 0.3`；正确做法是用误差比较，金额用整数分。

### 选择与边界

- 使用 `与` 时，三条铁律：**默认 const、比较用 ===、空值判断用 ?? 或 == null**。理解 `+` 与 `-` 的隐式转换差异，能解释多数「诡异」行为。
- 使用 `类型` 时，值允许的表示、取值范围和可执行操作集合。
- 使用 `类型转换` 时，Number('42'); // 42。
- 使用 `null` 时，null == undefined // true 规定如此；易错：空字符串或 0 被当成缺失；正确做法是明确判断：`obj.name !== undefined && obj.name !== null` 或 `obj.name ?? ""`。
- 使用 `JavaScript` 时，JavaScript 是动态类型、基于原型的脚本语言，标准名为 ECMAScript。它既能跑在浏览器里操作页面；静态检查只在编译期成立，运行期输入仍需校验。
