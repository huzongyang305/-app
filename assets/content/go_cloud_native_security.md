## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 云原生 | 以容器、编排、声明式配置、微服务和可观测性为基础构建和运行应用。 | 本地容器里跑通不等于集群里同样行为：存活与就绪探针、关闭信号都要在编排环境验证，镜像不固定摘要还会让构建不可复现。 |
| mTLS | 双向 TLS：客户端与服务端互相验证证书，常用于服务网格中确认双方身份。 | 易错：以为内网隔离就够；证书或令牌仍要逐跳实际校验，否则任何进程都能冒充对端。 |
| 限流 | 按时间窗口限制请求速率（令牌桶或漏桶），保护后端不被突发流量打垮。 | 限流阈值要和超时、熔断、重试一起设计，单改一处会在故障时放大流量；只在小流量下试过的阈值挡不住突发。 |
| 优雅关闭 | 服务停止时先停止接收新请求，再等待在途任务完成并释放资源。 | 易错：没有健康检查与优雅退出，滚动发布时请求被中断；要先停接收、处理关闭信号，再等在途任务收尾。 |

## 典型应用场景

- **容器默认以 root 运行**：典型现象是逃逸后权限过大；正确做法是用非 root 用户运行并限制内核能力。
- **基础镜像不固定版本**：典型现象是构建结果不可复现，镜像可能被替换；正确做法是固定镜像摘要并定期扫描依赖漏洞。
- **没有健康检查与优雅退出**：典型现象是滚动发布时请求被中断；正确做法是提供存活与就绪探针，并处理关闭信号。

### 选择与边界

- 使用 `云原生` 时，以容器、编排、声明式配置、微服务和可观测性为基础构建和运行应用；容器与集群环境差异会改变行为，本地通过后仍需在目标编排环境复验。
- 使用 `mTLS` 时，双向 TLS：客户端与服务端互相验证证书，常用于服务网格中确认双方身份。
- 使用 `限流` 时，按时间窗口限制请求速率（令牌桶或漏桶），保护后端不被突发流量打垮；网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。
- 使用 `优雅关闭` 时，服务停止时先停止接收新请求，再等待在途任务完成并释放资源；网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。
