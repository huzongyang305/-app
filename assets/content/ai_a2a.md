## 故障现场

### 现场 1：把 A2A 当成普通模型接口

**症状**：在《A2A Agent 协作协议》的复现场景中，只用自然语言约定调用，缺少任务、角色与能力描述。

**根因**：触发点是把“把 A2A 当成普通模型接口”当成安全做法。它没有满足《A2A Agent 协作协议》要求的前提，因此先表现为“只用自然语言约定调用，缺少任务、角色与能力描述”；排查时先完整复现这一段，再核对输入、配置与依赖。

**修复**：针对《A2A Agent 协作协议》的问题，按 Agent Card 声明能力，用任务与消息结构描述状态和结果。

**验证**：先在《A2A Agent 协作协议》中记录“把 A2A 当成普通模型接口”留下的失败证据，再执行“按 Agent Card 声明能力，用任务与消息结构描述状态和结果”并重放；确认错误路径变为明确结果，且修复没有掩盖同类故障。

### 现场 2：任务状态不幂等

**症状**：在《A2A Agent 协作协议》的复现场景中，重复投递同一任务导致对方 Agent 重复执行。

**根因**：当出现“任务状态不幂等”时，执行路径已经绕过了《A2A Agent 协作协议》的关键约束，最终以“重复投递同一任务导致对方 Agent 重复执行”暴露出来；修复前必须先确认约束在哪里失效。

**修复**：针对《A2A Agent 协作协议》的问题，任务带唯一 ID 与状态机，接收方按 ID 去重并回传终态。

**验证**：保留《A2A Agent 协作协议》里触发“重复投递同一任务导致对方 Agent 重复执行”的输入、版本和日志，按“任务带唯一 ID 与状态机，接收方按 ID 去重并回传终态”完成修改后原样重放；只有失败现象消失且相邻场景仍可解释，才保留改动。

### 现场 3：长任务只等一次响应

**症状**：在《A2A Agent 协作协议》的复现场景中，请求超时后直接重试，任务被重复触发。

**根因**：触发点是把“长任务只等一次响应”当成安全做法。它没有满足《A2A Agent 协作协议》要求的前提，因此先表现为“请求超时后直接重试，任务被重复触发”；排查时先完整复现这一段，再核对输入、配置与依赖。

**修复**：针对《A2A Agent 协作协议》的问题，用流式事件或回调跟踪进度，超时后先查任务状态再决定是否重试。

**验证**：在《A2A Agent 协作协议》中按“用流式事件或回调跟踪进度，超时后先查任务状态再决定是否重试”调整后，从“长任务只等一次响应”的触发条件重放同一条路径，确认“请求超时后直接重试，任务被重复触发”不再出现，并补一个相邻边界用例检查没有引入新问题。

## 深入补充：A2A Agent 协作协议 的取舍与边界

### 一、把概念放回真实约束

学习A2A Agent 协作协议时，最容易只记住结论而忽略前提。先写出三个约束：数据规模、时间预算、可接受的失败方式；再判断 A2A 与 多智能体 在这些约束下是否仍然成立。只要约束改变，原来的最优解就可能变成错误解。

| 维度 | 要回答的问题 | 常见做法 | 失败信号 |
| --- | --- | --- | --- |
| 数据 | A2A 的训练或检索数据从哪来、质量如何 | 清洗、去重、标注与版本化 | 评测集泄漏或分布漂移 |
| 模型 | 多智能体 的能力边界与成本是多少 | 基线对比、离线评测、灰度发布 | 指标好看但线上任务失败 |
| 评测 | 如何证明改动真的有效 | 固定评测集、人工抽检、A/B | 只比较单例输出 |
| 安全 | 失败时会不会泄露或越权 | 权限校验、内容过滤、审计 | 提示注入或数据外泄 |
