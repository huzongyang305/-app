## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| DFS 回边 | 深度优先搜索中指向已访问且未完成节点的边，无向图中回边的存在等价于图中有环。 |
| 寄存器间接寻址 | 指令地址码字段给出寄存器编号，该寄存器中存放的是操作数的内存地址，而非操作数本身。 |
| SCAN 调度 | 又称电梯算法，磁头沿一个方向移动并服务沿途请求，到达最远请求后反向，避免饥饿。 |
| TCP 滑动窗口 | 接收方在 TCP 首部窗口字段中通告的可用缓冲区大小，发送方据此控制未确认报文段的连续发送量。 |
| Dijkstra 算法 | 基于贪心策略的单源最短路径算法，每次选取距离最小且未确定的顶点，要求所有边权非负。 |
| 基址寻址 | 指令给出形式地址与基址寄存器编号，有效地址 EA = (BR) + A，用于程序重定位与分段保护。 |
| SSTF 调度 | 最短寻道时间优先，每次选择距当前磁头位置最近的请求服务，可能导致远端请求饥饿。 |
| 拥塞窗口 | TCP 发送方根据网络拥塞程度动态调整的发送窗口 cwnd，实际发送窗口 = min(rwnd, cwnd)。 |

## 原理与运行机制

### 一、图的 DFS 遍历与回边判环

深度优先搜索（DFS）在遍历图时为每条边赋予角色：

| 边的类型 | 定义 | 作用 |
| --- | --- | --- |
| 树边（Tree Edge） | DFS 递归中首次发现未访问顶点时经过的边 | 构成 DFS 生成树 |
| 回边（Back Edge） | 指向当前递归栈中已访问但未完成（灰色）顶点的边 | 无向图中回边 ⟺ 图中有环 |
| 前向边（Forward Edge） | 指向已完成（黑色）后代顶点的边 | 有向图中有用 |
| 交叉边（Cross Edge） | 指向已完成且非后代顶点的边 | 有向图中有用 |

**判环原理**：对无向图做 DFS，维护每个顶点的颜色（白=未访问，灰=在栈中，黑=已完成）。当从顶点 u 探索邻接点 v 时，若 v 为灰色且 v 不是 u 的父节点，则 (u, v) 是一条回边，说明图中存在环。

**BFS 对比**：BFS 无法直接判环，因为 BFS 生成树中同一层的顶点之间可能存在边（交叉边），这些边不构成环的充分条件。因此 408 常考「DFS 回边判环」而不会用 BFS 来判环。

### 二、指令寻址方式

指令寻址方式决定了如何从指令中获取操作数的有效地址（EA）。408 常考的寻址方式对比如下：

| 寻址方式 | EA 计算 | 特点 |
| --- | --- | --- |
| 立即寻址 | 操作数直接在指令中 | 最快，但操作数范围受指令字长限制 |
| 直接寻址 | EA = A（形式地址） | 一次访存，地址范围受地址码位数限制 |
| 间接寻址 | EA = (A) | 两次访存，速度慢但地址范围大 |
| 寄存器直接寻址 | 操作数在寄存器 Ri 中 | 最快，不需访存 |
| **寄存器间接寻址** | **EA = (Ri)** | **一次访存，地址在寄存器中** |
| 基址寻址 | EA = (BR) + A | 利于程序重定位，BR 由操作系统管理 |
| 变址寻址 | EA = (IX) + A | 利于数组遍历，IX 由用户控制 |
| 相对寻址 | EA = (PC) + A | 利于程序浮动和转移指令 |

**寄存器间接寻址 vs 基址寻址**：两者都需要一次额外的加法运算来获取 EA，但寄存器间接寻址中寄存器存放的是完整的操作数地址，而基址寻址中基址寄存器存放的是段的起始地址，需要与形式地址相加。考试中常通过「寄存器中存放的是地址本身还是地址的基值」来区分。

### 三、磁盘调度算法

磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间。磁盘调度主要优化寻道时间。

| 算法 | 策略 | 优点 | 缺点 |
| --- | --- | --- | --- |
| FCFS | 按请求到达顺序服务 | 公平 | 寻道距离大，性能差 |
| SSTF | 选最近磁道服务 | 平均寻道短 | 可能饥饿远端请求 |
| **SCAN（电梯）** | **单方向移动，到最远后反向** | **避免饥饿，性能稳定** | **两端请求等待时间长** |
| C-SCAN | 单方向服务，到尽头后快速回起点 | 等待时间更均匀 | 回程不服务请求 |
| N-Step-SCAN | 将请求队列分段处理 | 避免磁臂粘着 | 实现复杂 |

**SCAN 算法推演示例**：磁头当前在 100 号磁道，方向向内（磁道号增大方向），请求队列为 {55, 58, 39, 18, 90, 160, 150, 38, 184}。

服务顺序：90 → 150 → 160 → 184 → 58 → 55 → 39 → 38 → 18

总移动磁道数 = (184 - 100) + (184 - 18) = 84 + 166 = 250。

### 四、TCP 滑动窗口计算

TCP 使用滑动窗口实现流量控制和可靠传输。发送方的实际发送窗口由两个因素共同决定：

**发送窗口 = min(接收方通告窗口 rwnd, 拥塞窗口 cwnd)**

- **rwnd**（接收窗口）：接收方在 TCP 首部中通告的剩余缓冲区大小，体现接收方处理能力。
- **cwnd**（拥塞窗口）：发送方根据网络拥塞状况动态调整，体现网络承载能力。

**慢开始与拥塞避免**：

| 阶段 | 条件 | cwnd 增长方式 |
| --- | --- | --- |
| 慢开始 | cwnd < ssthresh | 每收到一个 ACK，cwnd 翻倍（指数增长） |
| 拥塞避免 | cwnd >= ssthresh | 每个 RTT 增加 1 个 MSS（线性增长） |
| 快重传 | 收到 3 个重复 ACK | 立即重传丢失报文段 |
| 快恢复 | 快重传后 | ssthresh = cwnd/2，cwnd = ssthresh，进入拥塞避免 |

**计算示例**：设 ssthresh = 16，MSS = 1KB。慢开始阶段 cwnd 依次为 1, 2, 4, 8, 16；到达 ssthresh 后转为拥塞避免，cwnd 依次为 17, 18, 19...。若 cwnd = 24 时发生超时，则 ssthresh = 24/2 = 12，cwnd 重置为 1，重新慢开始。

### 五、Dijkstra 算法要点

Dijkstra 算法是 408 数据结构与算法部分的经典考点：

```c
#include <stdio.h>
#define MAXVEX 100
#define INFINITY 65535

typedef struct {
    int vexs[MAXVEX];
    int arc[MAXVEX][MAXVEX];
    int numVertexes;
} MGraph;

int dist[MAXVEX];
int visited[MAXVEX];

void Dijkstra(MGraph *G, int v0) {
    int i, j, min, u;
    for (i = 0; i < G->numVertexes; i++) {
        dist[i] = G->arc[v0][i];
        visited[i] = 0;
    }
    visited[v0] = 1;
    dist[v0] = 0;
    for (i = 1; i < G->numVertexes; i++) {
        min = INFINITY;
        for (j = 0; j < G->numVertexes; j++) {
            if (!visited[j] && dist[j] < min) {
                min = dist[j];
                u = j;
            }
        }
        visited[u] = 1;
        for (j = 0; j < G->numVertexes; j++) {
            if (!visited[j] && dist[u] + G->arc[u][j] < dist[j]) {
                dist[j] = dist[u] + G->arc[u][j];
            }
        }
    }
}
```

**关键约束**：Dijkstra 算法要求图中所有边的权值非负。若存在负权边，贪心选择可能失效——已确定最短路径的顶点可能被后续更短的路径更新，导致结果错误。此时应改用 Bellman-Ford 算法（时间 O(VE)）或 SPFA 算法。

## 时间/空间复杂度或性能分析

| 算法 | 时间复杂度 | 空间复杂度 | 备注 |
| --- | --- | --- | --- |
| DFS 判环 | O(V + E) | O(V) | 邻接表存储；递归栈深度最大 V |
| BFS 遍历 | O(V + E) | O(V) | 队列最大宽度为图的 BFS 层最大宽度 |
| Dijkstra（朴素） | O(V²) | O(V) | 适合稠密图 |
| Dijkstra（堆优化） | O((V+E)logV) | O(V) | 适合稀疏图，用优先队列 |
| SCAN 磁盘调度 | O(n) | O(1) | n 为请求数，排序后线性扫描 |
| TCP 滑动窗口 | O(1) | O(W) | W 为窗口大小，维护已发送未确认队列 |

**性能关注点**：
- DFS 判环时，无向图需额外记录父节点以避免将树边的反向误判为回边。
- Dijkstra 在负权图上不仅结果错误，而且不会报错——这是最危险的陷阱。
- SCAN 算法在请求均匀分布时性能最优，但在请求集中于一端时退化为近似 FCFS。

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 用 BFS 判无向图环 | 误判或漏判 | BFS 交叉边不代表环；应使用 DFS 回边判环 |
| 认为寄存器间接寻址的操作数在寄存器中 | 答案错误 | 寄存器中存放的是操作数的内存地址，还需一次访存取操作数 |
| SCAN 算法到达最远后不反向 | 退化为 FCFS | SCAN 的核心是到达端点后反向扫描，类似电梯往返运行 |
| TCP 发送窗口只看 rwnd | 忽略拥塞控制 | 实际发送窗口 = min(rwnd, cwnd)，两者共同约束 |
| Dijkstra 用于含负权边的图 | 结果错误但不报错 | Dijkstra 要求边权非负；负权图用 Bellman-Ford |
| 混淆基址寻址与寄存器间接寻址 | 概念不清 | 基址寻址 EA = (BR) + A；寄存器间接寻址 EA = (Ri) |
| SSTF 一定比 FCFS 好 | 忽略饥饿问题 | SSTF 可能导致远端请求长期得不到服务 |
| 慢开始阶段 cwnd 线性增长 | 概念混淆 | 慢开始是指数增长（每个 RTT 翻倍），拥塞避免才是线性增长 |

### 现场 1：DFS 判环时忘记排除父节点

**症状**：无向图 DFS 中每个顶点都会回到父节点，如果不排除父节点则每条树边都会被误判为回边。

**根因与修复**：在 DFS 递归调用时传入父节点参数 `parent`，当邻接点 `v == parent` 时跳过。正确代码模式为 `DFS(u, parent)` → 遍历 `u` 的邻接点 `v`，若 `v` 为灰色且 `v != parent` 则有环。

**自检**：对一条链状图 1-2-3-4 做 DFS 判环，结果应为「无环」。

### 现场 2：TCP 窗口计算混淆发送与接收

**症状**：计算发送方可以发送的数据量时，只考虑了接收方通告窗口而忽略了拥塞窗口。

**根因与修复**：TCP 流量控制是双约束——发送窗口 = min(rwnd, cwnd)。即使接收方有足够缓冲区，如果网络拥塞导致 cwnd 很小，发送方也不能多发。做题时需同时关注两个参数。

**自检**：若 rwnd = 16KB，cwnd = 4KB，则发送窗口 = 4KB 而非 16KB。

### 现场 3：Dijkstra 初始化遗漏

**症状**：算法运行后部分顶点距离为 0 或错误值。

**根因与修复**：初始化时必须将源点 dist[v0] 设为 0，其余顶点 dist[i] 设为 G.arc[v0][i]（直接相连的边权）或 INFINITY（不相连）。visited 数组全部初始化为 0（未访问）。

**自检**：对 3 个顶点的完全图手动推演，检查每轮选取的 u 和更新的 dist 是否正确。

### 现场 4：SCAN 算法方向判断错误

**症状**：推演服务顺序时，磁头移动方向搞反，导致结果完全错误。

**根因与修复**：做题时第一步必须明确当前磁头位置和移动方向。SCAN 算法先沿当前方向服务所有请求，到达最远请求后反向。建议画数轴标注请求位置，按方向依次标记服务顺序。

**自检**：磁头在 50，方向向外（减小），请求 {20, 80, 10, 90}，服务顺序应为 20 → 10 → 80 → 90。

## 典型应用场景

**场景一：图的遍历应用——DFS 判环**

408 常考无向图中利用 DFS 回边判断环的存在。回边是指向递归栈中灰色顶点的边，无向图中回边的存在是图中有环的充要条件。考试中常要求手写 DFS 判环代码，并注意排除父节点方向的树边以免误判。

**场景二：指令寻址方式辨析**

寄存器间接寻址与基址寻址的区分是计算机组成原理高频选择题。核心区别在于：寄存器间接寻址中寄存器存放的是操作数的完整地址（EA = (Ri)），而基址寻址中基址寄存器存放的是段起始地址，需与形式地址相加（EA = (BR) + A）。

**场景三：磁盘调度算法推演**

SCAN 算法推演题几乎每年必考。需手动模拟磁头移动方向和服务顺序，计算总移动磁道数。关键步骤：先确定当前磁头位置和移动方向，沿当前方向服务所有请求，到达最远后反向。建议画数轴辅助推演。

**场景四：TCP 滑动窗口与拥塞控制联合计算**

发送窗口 = min(rwnd, cwnd) 是网络部分的核心公式。考试中常给出 ssthresh、MSS 和超时/快重传事件，要求计算各阶段的发送窗口大小。需注意慢开始阶段 cwnd 指数增长，拥塞避免阶段线性增长，超时后 cwnd 重置为 1。

## 代码/协议/SQL 示例

### 示例 1：DFS 判环算法完整 C 实现

```c
#include <stdio.h>
#include <stdlib.h>
#define MAXVEX 100

typedef struct EdgeNode {
    int adjvex;
    struct EdgeNode* next;
} EdgeNode;

typedef struct {
    EdgeNode* adjList[MAXVEX];
    int numVex, numEdge;
} ALGraph;

int visited[MAXVEX];  /* 0=白(未访问), 1=灰(在栈中), 2=黑(已完成) */

/* DFS 判环：遇到灰色且非父节点的邻接点即为回边 → 有环 */
int DFS_cycle(ALGraph* G, int u, int parent) {
    visited[u] = 1;  /* 标记为灰色（入栈） */
    EdgeNode* p = G->adjList[u];
    while (p) {
        int v = p->adjvex;
        if (visited[v] == 0) {
            /* 未访问顶点，递归 DFS */
            if (DFS_cycle(G, v, u))
                return 1;
        } else if (visited[v] == 1 && v != parent) {
            /* 灰色顶点且不是父节点 → 发现回边 → 有环 */
            return 1;
        }
        p = p->next;
    }
    visited[u] = 2;  /* 标记为黑色（出栈，已完成） */
    return 0;
}

int hasCycle(ALGraph* G) {
    int i;
    for (i = 0; i < G->numVex; i++)
        visited[i] = 0;
    for (i = 0; i < G->numVex; i++) {
        if (visited[i] == 0) {
            if (DFS_cycle(G, i, -1))
                return 1;  /* 非连通图需检查每个连通分量 */
        }
    }
    return 0;
}
```

### 示例 2：SCAN（电梯）磁盘调度算法 Python 模拟

```python
def scan_scheduling(requests, head, direction, max_track=199):
    """
    SCAN（电梯）磁盘调度算法模拟
    :param requests: 请求磁道号列表
    :param head: 当前磁头位置
    :param direction: 1 表示向内（磁道号增大），-1 表示向外（磁道号减小）
    :param max_track: 最大磁道号
    """
    req = sorted(set(requests))
    order = []
    total_move = 0

    if direction == 1:
        # 先向内（增大方向）服务，再反向
        inner = [r for r in req if r >= head]
        outer = [r for r in req if r < head]
        order = inner + outer[::-1]
        if inner:
            total_move = (inner[-1] - head) + (inner[-1] - order[-1])
        else:
            total_move = head - order[-1] if order else 0
    else:
        # 先向外（减小方向）服务，再反向
        outer = [r for r in req if r <= head][::-1]
        inner = [r for r in req if r > head]
        order = outer + inner
        if outer:
            total_move = (head - outer[-1]) + (order[-1] - outer[-1])
        else:
            total_move = order[-1] - head if order else 0

    print(f"服务顺序: {order}")
    print(f"总移动磁道数: {total_move}")
    return order, total_move

# 示例：磁头在 100，方向向内，请求队列
scan_scheduling([55, 58, 39, 18, 90, 160, 150, 38, 184], 100, 1)
# 服务顺序: [150, 160, 184, 90, 58, 55, 39, 38, 18]
```

## 自测题与参考答案

**题目 1**：对无向图进行 DFS 遍历，利用回边可以判断？

<details>
<summary>参考答案</summary>

图中是否存在环。DFS 遍历无向图时，为每个顶点维护三种颜色：白色（未访问）、灰色（在递归栈中）、黑色（已完成）。当从顶点 u 探索邻接点 v 时，若 v 为灰色且 v 不是 u 的父节点，则 (u, v) 是一条回边，说明图中存在环。BFS 无法直接判环，因为 BFS 生成树中同一层顶点间的交叉边不构成环的充分条件。
</details>

**题目 2**：寄存器间接寻址中，操作数地址存放在？

<details>
<summary>参考答案</summary>

寄存器中。寄存器间接寻址的核心特征是：指令的地址码字段给出寄存器编号，而该寄存器中存放的是操作数在主存中的地址（EA = (Ri)）。CPU 需先读取寄存器获得地址，再根据该地址访问主存取出操作数。注意区分：直接寻址中地址在指令中，间接寻址中地址在主存单元中，寄存器间接寻址中地址在寄存器中。
</details>

**题目 3**：SCAN（电梯）磁盘调度算法的特点是？

<details>
<summary>参考答案</summary>

磁头沿一个方向移动，服务沿途请求，到达最远后反向。SCAN 算法类似电梯往返运行：沿当前方向移动并服务所有经过的请求，到达该方向最远请求后反向，再服务反方向的请求。这种策略避免了 SSTF 可能导致的远端请求饥饿问题，每个请求最终都会被服务。与 C-SCAN 的区别在于：C-SCAN 回程时不服务请求，直接快速返回起点。
</details>

**题目 4**：TCP 滑动窗口机制的主要作用是？

<details>
<summary>参考答案</summary>

流量控制。TCP 滑动窗口的核心作用是流量控制——接收方通过 TCP 首部中的窗口字段（rwnd）告知发送方自己的接收缓冲区剩余大小，发送方据此控制未收到确认前可以连续发送的报文段数量。实际发送窗口 = min(rwnd, cwnd)，同时受接收方能力和网络拥塞程度的双重约束。这样既提高了信道利用率（不必逐条等待 ACK），又避免了发送过快导致接收方缓冲区溢出或网络拥塞。
</details>

**题目 5**：Dijkstra 算法要求图中边的权值？

<details>
<summary>参考答案</summary>

非负。Dijkstra 算法基于贪心策略，每次选取当前距离最小的未确定顶点，并认为其最短路径已确定。这一贪心选择性质要求边权非负——如果存在负权边，已确定的最短路径可能被后续经过负权边的路径更新，导致算法输出错误结果。边权可以为零，不要求必须为正或必须为整数。处理含负权边的图应使用 Bellman-Ford 算法（时间 O(VE)）。
</details>

## 考点精讲

**高频考点一：图的遍历应用**

对无向图进行 DFS 遍历，利用回边可以判断？

A. 图是否连通
B. 图中是否存在环
C. 图是否有向
D. 图的顶点数

**答案：B**。DFS 遍历无向图时，如果遇到一条边指向灰色（在递归栈中）顶点，且该顶点不是当前顶点的父节点，则这条边是回边，说明图中存在环。这是 DFS 在图论中的经典应用之一。BFS 无法直接判环，因为 BFS 层间的交叉边不构成环的充分条件。

**高频考点二：指令寻址方式**

寄存器间接寻址中，操作数地址存放在？

A. 指令的地址码字段中
B. 寄存器中
C. 主存单元中
D. 程序计数器 PC 中

**答案：B**。寄存器间接寻址的核心特征是：指令的地址码字段给出寄存器编号，而该寄存器中存放的是操作数在主存中的地址。CPU 需要先读取寄存器获得地址，再根据该地址访问主存取出操作数。注意区分：直接寻址中地址在指令中，间接寻址中地址在主存单元中，寄存器间接寻址中地址在寄存器中。

**高频考点三：磁盘调度算法**

SCAN（电梯）磁盘调度算法的特点是？

A. 按请求到达顺序服务
B. 每次选择最近磁道服务
C. 磁头沿一个方向移动，服务沿途请求，到达最远后反向
D. 磁头单方向移动，到达尽头后快速返回起点

**答案：C**。SCAN 算法又称电梯算法，磁头沿当前方向移动并服务沿途所有请求，直到到达该方向上最远的请求，然后反向移动并服务反方向的请求。选项 A 是 FCFS，选项 B 是 SSTF，选项 D 是 C-SCAN。SCAN 的优势在于避免了 SSTF 的饥饿问题，每个请求最终都会被服务。

**高频考点四：TCP 滑动窗口**

TCP 滑动窗口机制的主要作用是？

A. 差错检测，通过校验和发现数据损坏
B. 流量控制，允许发送方在未收到确认时连续发送多个报文段
C. 路由选择，确定数据包的最佳传输路径
D. 拥塞避免，通过减小窗口来降低网络负载

**答案：B**。TCP 滑动窗口的核心作用是流量控制——接收方通过 TCP 首部中的窗口字段（rwnd）告知发送方自己的接收缓冲区剩余大小，发送方据此控制未收到确认前可以连续发送的报文段数量。这样既提高了信道利用率（不必逐条等待 ACK），又避免了发送过快导致接收方缓冲区溢出。注意滑动窗口是流量控制机制，与拥塞控制（cwnd）是不同层面的概念。

**高频考点五：最短路径算法**

Dijkstra 算法要求图中边的权值？

A. 必须为正
B. 非负
C. 必须为整数
D. 必须互不相同

**答案：B**。Dijkstra 算法基于贪心策略，每次选取当前距离最小的未确定顶点，并认为其最短路径已确定。这一贪心选择性质要求边权非负——如果存在负权边，已确定的最短路径可能被后续经过负权边的路径更新，导致算法输出错误结果。边权可以为零，不要求必须为正或必须为整数，也不要求互不相同。处理含负权边的图应使用 Bellman-Ford 算法。

| 术语 | 一句话说明 |
| --- | --- |
| DFS 回边 | 指向递归栈中灰色顶点的边，无向图中回边等价于有环。 |
| 寄存器间接寻址 | 寄存器中存放操作数的内存地址，EA = (Ri)。 |
| SCAN 调度 | 磁头单方向移动服务请求，到最远后反向，避免饥饿。 |
| TCP 滑动窗口 | 发送窗口 = min(rwnd, cwnd)，实现流量控制。 |
| Dijkstra 算法 | 贪心最短路径，要求边权非负，时间 O(V²) 或 O((V+E)logV)。 |
| 基址寻址 | EA = (BR) + A，利于程序重定位，BR 由操作系统管理。 |
| SSTF | 最短寻道优先，可能饥饿远端请求。 |
| 拥塞窗口 cwnd | 发送方根据网络拥塞动态调整的窗口，与 rwnd 共同约束发送速率。 |
