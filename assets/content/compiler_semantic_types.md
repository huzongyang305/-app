## 原理与运行机制

### 机制总览

**教材衔接：核心知识**

### 1. 符号表与作用域链

符号表记录每个名字的含义，作用域决定同名符号谁生效；进入作用域压入一层，退出时弹出。

查找从最内层向外逐层搜索，内层声明遮蔽外层同名符号；函数参数与局部变量在同一层的处理顺序影响重定义判断。

在语义分析与类型系统里可以这样验证：写一段包含全局变量与函数局部同名变量的程序，标出每一处引用的绑定目标。

边界：遮蔽会让读者误判引用对象，很多语言禁止或警告同层重复声明，但允许内层遮蔽。

工程视角：为每个符号记录声明位置与类型，报错时能指出冲突的两处位置。

### 2. 类型检查与类型推导

类型检查判断表达式是否符合类型规则，推导则在缺少显式标注时推断出类型。

自底向上为子表达式求类型，再按规则合并；数字与字符串相加这类不匹配在检查阶段直接报错。

在语义分析与类型系统里可以这样验证：为 `let x = 1 + 2` 与 `let y = "a" + 1` 分别做推导，观察哪一处报错以及错误位置。

边界：推导越强实现的复杂度越高，泛型与子类型会让规则迅速膨胀，需要在表达力与可解释性之间取舍。

工程视角：错误信息要明确指出冲突的两侧类型与位置，必要时展示推导路径。

### 3. 静态检查与运行期契约

静态检查覆盖能在编译期确定的问题，其余留给运行期：数组越界、空引用与外部输入合法性通常属于后者。

类型系统把一部分错误提前，剩余错误靠断言、边界检查与异常处理覆盖；两者共同构成可靠性保障。

在语义分析与类型系统里可以这样验证：对比一段类型正确但运行时会数组越界的代码，说明静态检查为什么无法覆盖它。

边界：过度依赖运行期检查会把错误推迟到用户侧，过度依赖静态检查会让表达变得僵硬。

工程视角：对外部输入做运行期校验，对内部接口用静态类型约束，边界处显式转换并记录失败原因。

### 4. 语义错误的诊断质量

未定义变量、重复声明、类型不匹配是三类高频语义错误，良好的诊断要指出位置、原因与修复方向。

分析器记录候选符号与作用域范围，报错时展示最近似名称或可选类型，帮助用户快速修正。

在语义分析与类型系统里可以这样验证：故意把变量名拼错，观察编译器是否给出相似名称建议与声明位置。

边界：自动纠正有风险，猜测错误可能引入新的语义问题，通常只建议不自动修改。

工程视角：维护错误码与提示模板，重要错误附最小示例与文档链接，避免只报「类型错误」。

### 自测问答

**问 1**：内层作用域声明同名变量后，名字查找会发生什么？

**答**：引用内层声明，外层被遮蔽。查找沿作用域链从内向外进行，内层声明优先命中，这就是遮蔽；是否允许同层重复声明与是否允许跨层遮蔽是两条不同的规则。 正确选项「引用内层声明，外层被遮蔽」对应《语义分析与类型系统》的要点「符号表与作用域链」：符号表记录每个名字的含义，作用域决定同名符号谁生效；进入作用域压入一层，退出时弹出。判断「符号表与作用域链」时先确认前提是否成立，再回到《语义分析与类型系统》的示例核对一次；把别的语言或框架的默认做法直接搬到符号表与作用域链上，往往会在本课的边界条件里失效。

**问 2**：下面哪一类错误通常无法靠静态类型检查发现？

**答**：数组下标越界。数组下标是否越界取决于运行期数据，除非类型系统引入长度信息；其余三类都能在编译期通过类型与符号检查发现。 正确选项「数组下标越界」对应《语义分析与类型系统》的要点「类型检查与类型推导」：类型检查判断表达式是否符合类型规则，推导则在缺少显式标注时推断出类型。判断「类型检查与类型推导」时先确认前提是否成立，再回到《语义分析与类型系统》的示例核对一次；借鉴相邻主题的经验之前，先核对类型检查与类型推导的前提是否成立。

**问 3**：一条高质量的语义错误信息应包含哪些内容？（多选）

**答**：出错位置；冲突的类型或候选名称；修复方向或示例。位置、冲突详情与修复方向直接帮助用户修改代码；构建时间戳与问题定位无关，只会增加噪声。 正确选项「出错位置；冲突的类型或候选名称；修复方向或示例」对应《语义分析与类型系统》的要点「静态检查与运行期契约」：静态检查覆盖能在编译期确定的问题，其余留给运行期：数组越界、空引用与外部输入合法性通常属于后者。判断「静态检查与运行期契约」时先确认前提是否成立，再回到《语义分析与类型系统》的示例核对一次；记住静态检查与运行期契约的结论之外还要记住适用条件，换一个输入往往就不成立了。

**问 4**：请按语义分析的执行顺序排列步骤。

**问 5**：阅读作用域代码，哪项判断正确？

**答**：lookup 会沿父链查找，因此内层遮蔽外层。lookup 先查当前层再沿父链向上，因此内层声明优先；declare 在发现同名符号时直接抛错，父链为空时会报未定义而不是返回空值。 正确选项「lookup 会沿父链查找，因此内层遮蔽外层」对应《语义分析与类型系统》的要点「符号表与作用域链」：符号表记录每个名字的含义，作用域决定同名符号谁生效；进入作用域压入一层，退出时弹出。判断「符号表与作用域链」时先确认前提是否成立，再回到《语义分析与类型系统》的示例核对一次；把符号表与作用域链的做法换到别的约束下未必成立，先确认边界再决定答案。

### 结论与下一步

- **符号表未按作用域分层**：典型现象是所有变量放进一个全局表，内层遮蔽外层时查找结果错误；正确做法是按作用域分层建表并沿父链查找，退出作用域时弹出该层。

- **把运行期错误当成编译期可查**：典型现象是认为类型正确就不会数组越界或空引用；正确做法是在边界处补充运行期校验与断言，明确哪些错误留给运行期。

```javascript
// 极简作用域链：声明、查找与遮蔽
class Scope {
  constructor(parent = null) {
    this.parent = parent;
    this.symbols = new Map();
  }
  declare(name, type, line) {
    if (this.symbols.has(name)) {
      throw new Error(`重复声明 ${name}，位置 第 ${line} 行`);
    }
    this.symbols.set(name, { type, line });
  }
  lookup(name) {
    if (this.symbols.has(name)) return this.symbols.get(name);
    if (this.parent) return this.parent.lookup(name);
    throw new Error(`未定义的变量 ${name}`);
  }
}

const global = new Scope();
global.declare('rate', 'number', 1);
const fn = new Scope(global);
fn.declare('rate', 'number', 5);
console.log('内层 rate 声明行:', fn.lookup('rate').line);
console.log('外层 rate 声明行:', global.lookup('rate').line);
```
