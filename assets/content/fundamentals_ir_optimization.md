## 原理与运行机制

### 机制总览

**教材衔接：为什么需要中间表示（IR）**

IR 是介于源码与机器码之间的抽象形式，让优化只写一遍就能服务所有前端与后端。常见形态：

| IR | 特点 |
| --- | --- |
| 三地址码 | 每条指令最多一个运算，接近汇编但无寄存器细节 |
| 抽象语法树 | 保留结构信息，适合高层优化 |
| SSA（静态单赋值） | 每个变量只被赋值一次，数据流分析极其方便 |
| 控制流图 CFG | 基本块 + 跳转边，是大多数优化的载体 |

**教材衔接：基础块与数据流分析**

把代码切成基本块（入口出口唯一、内部无跳转），再用数据流分析回答问题：某个变量在此处是否活跃？这个常量能否传播到这里？这段代码是否可达？

**教材衔接：中间表示速查**

| IR 形式 | 特点 | 用途 |
| --- | --- | --- |
| 三地址码 | 每条指令最多一个运算 | 教学与基础优化 |
| SSA | 每个变量只赋值一次 | 现代编译器主流 |
| 控制流图（CFG） | 基本块 + 边 | 数据流分析与优化 |
| 有向无环图（DAG） | 复用公共子表达式 | 局部优化 |
| 字节码 | 面向虚拟机 | Java、Python、C# |

## 典型应用场景

- **忽略副作用就做消除**：典型现象是程序行为改变；正确做法是只有无副作用且结果未被使用的代码才能删。
- **存在未定义行为仍激进优化**：典型现象是结果与预期完全不符；正确做法是先消除 UB，再谈优化。
- **不做别名分析就重排访存**：典型现象是读写顺序被破坏；正确做法是需要别名分析确认安全。
- **浮点优化假设结合律**：典型现象是结果精度变化；正确做法是浮点不满足结合律，需要 `-ffast-math` 才允许。

## 代码/协议/SQL 示例

### 最小可验证示例

```python
import ast

class ConstantFolder(ast.NodeTransformer):
    """极简常量折叠：把字面量的二元运算在编译期算好。"""

    def visit_BinOp(self, node):
        self.generic_visit(node)
        left, right = node.left, node.right
        if isinstance(left, ast.Constant) and isinstance(right, ast.Constant):
            try:
                value = eval(compile(ast.Expression(node), "<const>", "eval"))
            except Exception:
                return node
            return ast.copy_location(ast.Constant(value=value), node)
        return node

source = "result = 3 * 4 + 2"
tree = ConstantFolder().visit(ast.parse(source))
ast.fix_missing_locations(tree)
print(ast.unparse(tree))          # result = 14
```

## 时间/空间复杂度或性能分析

```text
经验规律：程序 90% 的时间花在 10% 的循环上

因此编译器在循环上投入的优化最多：
  · 循环展开：减少循环控制开销，增加指令级并行
  · 循环融合/分裂：改善缓存局部性
  · 循环交换：让内存访问更连续（矩阵遍历的经典优化）

  for i: for j: sum += m[i][j]     ← 连续访问，快
  for j: for i: sum += m[i][j]     ← 跨行跳跃，慢（可能差数倍）
```

### 考点 7：`IR`

- **要点**：IR 是介于源码与机器码之间的抽象形式，让优化只写一遍就能服务所有前端与后端。常见形态。
- **IR 的边界**：只在「IR 是介于源码与机器码之间的抽象形式，让优化只写一遍就能服务所有前端与后端」这一前提下成立，换输入或换环境要重新验证。

### 考点 8：`SSA`

- **要点**：静态单赋值中间表示，每个变量只被赋值一次，便于数据流分析。
- **SSA 的边界**：易错：无法表达数组与内存；正确做法是内存可用 SSA 形式 + 别名分析表达。

### 考点 9：`常量折叠`

- **要点**：编译期直接算出常量表达式的值，用结果替换表达式以减少运行开销。
- **常量折叠 的边界**：静态检查只在编译期成立，运行期输入仍需校验。

### 考点 10：`死代码`

- **要点**：永远不会被执行或结果永远用不到的代码，删除或证明其不可达可减少维护成本。
- **死代码 的边界**：只在「永远不会被执行或结果永远用不到的代码，删除或证明其不可达可减少维护成本」这一前提下成立，换输入或换环境要重新验证。

### 考点 11：`循环优化`

- **要点**：减少循环内重复计算、提升数据局部性或展开迭代以降低开销。
- **循环优化 的边界**：只在「减少循环内重复计算、提升数据局部性或展开迭代以降低开销」这一前提下成立，换输入或换环境要重新验证。

### 考点 12：排错——忽略副作用就做消除

- **现象**：程序行为改变。
- **处理**：只有无副作用且结果未被使用的代码才能删。

### 考点 13：排错——存在未定义行为仍激进优化

- **现象**：结果与预期完全不符。
- **处理**：先消除 UB，再谈优化。

### 考点 14：综合辨析——`IR` 与 `循环优化`

- **辨析点**：`IR` 的定义是 IR 是介于源码与机器码之间的抽象形式，让优化只写一遍就能服务所有前端与后端。常见形态；`循环优化` 的定义是 减少循环内重复计算、提升数据局部性或展开迭代以降低开销。
- **答题要求**：面对 `中间代码与优化` 的题目，先判断描述的是 `IR` 还是 `循环优化`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 15：排错评分点

- **现象分**：能写出 程序行为改变，而不是只写“程序有错”。
- **证据分**：保留触发 忽略副作用就做消除 的输入、版本和错误原文。
- **修复分**：按 只有无副作用且结果未被使用的代码才能删 只改一处，并同时回归正常路径与边界路径。
