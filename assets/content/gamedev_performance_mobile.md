## 本节知识框架

想象你开了一家外卖店。厨房只有一口锅（CPU）和一个灶台（GPU），但你同时接了 100 份订单。如果你不管三七二十一把所有食材都堆进厨房（一次性加载全部资源），厨房直接爆炸；如果你让厨师从头到尾只做一道菜（每帧分配对象），效率低到顾客全跑了。

移动端性能优化的核心就是：**在有限的时间和空间里，把事情安排得明明白白**。

**本课主线**：从帧预算、发热降频讲到内存占用、加载时间与电量控制。

**学完本课你应当能够**：
- 用"厨房"类比说清 `帧预算` 与 `降频` 的含义与区别
- 用本课示例验证 `长稳测试` 的行为，记录输入、输出与失败条件
- 遇到「只看帧率不看功耗与温度」这类问题时，能说出触发条件与修复顺序

## 原理与运行机制

### 1. 帧预算与目标帧率——"每道菜的烹饪时间"

**类比**：想象你要在 1 秒内做 60 道菜（60 帧），每道菜只有 16.7 毫秒。如果你某道菜花了 20 毫秒，后面 59 道菜就全部延迟——这就是掉帧。

**关键规则**：
- 一帧内的逻辑、渲染、物理、音频必须都在预算内完成
- CPU 和 GPU 可以并行工作，但最慢的一项决定上限
- 只在模拟器上测性能会低估真实设备差异，模拟器显卡与真机完全不同

```csharp
// 帧预算计时器：把一帧拆成逻辑、渲染与其余部分分别统计
struct FrameProfile {
    public float LogicMs;
    public float RenderMs;
    public float OtherMs;
    public float TotalMs => LogicMs + RenderMs + OtherMs;
}

void Update() {
    var sw = Stopwatch.StartNew();
    UpdateGameplay();
    profile.LogicMs = (float)sw.Elapsed.TotalMilliseconds;

    sw.Restart();
    RenderScene();
    profile.RenderMs = (float)sw.Elapsed.TotalMilliseconds;

    // 帧预算按目标帧率计算：60 帧约 16.7 ms，30 帧约 33.3 ms
    float budget = TargetFps == 60 ? 16.7f : 33.3f;
    if (profile.TotalMs > budget) {
        WarnThrottled(profile, budget);   // 记录超支帧与主要原因
    }
}

// 纹理按目标机型分档，低端机使用半分辨率
int TextureSize(Tier tier) => tier == Tier.Low ? 1024 : 2048;
```

**工程做法**：按机型分档设定目标帧率与画质，最低档机型作为性能验收基线。

### 2. 发热与降频——"厨房太热，厨师被强制减速"

**类比**：厨房连续工作 10 分钟后温度飙升，老板为了保护设备强制让厨师放慢速度。这就是手机的"降频"——温度上升后 CPU/GPU 频率被限制，性能曲线在几分钟后出现明显下降。

**关键规则**：
- 只看开局 30 秒的帧率会得到过于乐观的结论
- 长时间稳定性才是真实体验
- 降频后的帧率才是真正的验收指标

**工程做法**：做长稳测试并把降频后的帧率作为验收指标，必要时提供画质档位让玩家自行取舍。

### 3. 内存与加载时间——"厨房里的食材堆积"

**类比**：如果你把一整天的食材一次性堆进厨房（一次性加载全部资源），厨房直接爆炸——内存超限被系统终止进程。正确做法是按场景划分资源加载与释放边界。

**关键规则**：
- 纹理、网格与音频占用峰值内存
- 加载时若一次性读入全部资源会出现长时间卡顿甚至闪退
- 只优化平均内存不关注峰值，仍会在切换场景时被系统杀掉进程

```text
错误示范：
void LoadLevel() {
    // 一次性加载整关所有资源——内存峰值爆炸
    LoadAllTextures();
    LoadAllMeshes();
    LoadAllAudio();
}

正确做法：
void LoadLevel() {
    // 按场景划分，按需加载并释放
    LoadResourcesForScene("scene_01");
    // 进入场景后释放上一场景资源
    UnloadResourcesForScene("scene_00");
}
```

**工程做法**：按场景划分资源加载与释放边界，给出目标机型的峰值内存上限并纳入自动检查。

### 关键流程总览

```text
确定目标帧率与机型分档 → 分别测量 CPU 与 GPU 耗时 → 定位内存峰值与加载瓶颈 → 做十分钟长稳测试观察降频 → 把指标写入发布检查清单
```

1. 确定目标帧率与机型分档
2. 分别测量 CPU 与 GPU 耗时
3. 定位内存峰值与加载瓶颈
4. 做十分钟长稳测试观察降频
5. 把指标写入发布检查清单

## 典型应用场景

### 场景 1：帧预算与目标帧率

**问题**：游戏在高端机上跑 60 帧很流畅，但低端机上卡成 PPT。

**根因**：没有按机型分档设定目标帧率与画质。

**修复**：
- 高端机：60 帧 + 2K 纹理
- 中端机：30 帧 + 1K 纹理
- 低端机：30 帧 + 半分辨率纹理

**自检**：在最低档机型上跑长稳测试，帧率是否稳定在目标值。

### 场景 2：发热与降频

**问题**：游戏开局 5 分钟很流畅，10 分钟后帧率暴跌。

**根因**：只看开局帧率，没做长稳测试，降频后帧率不达标。

**修复**：
- 连续运行 10 分钟记录帧率曲线
- 找出降频发生的时间点
- 把降频后的帧率作为验收指标
- 提供画质档位让玩家自行取舍

**自检**：长稳测试后帧率是否稳定在目标值，温度是否超过设备阈值。

### 场景 3：内存与加载时间

**问题**：切换场景时卡顿 5 秒，低端机直接闪退。

**根因**：一次性加载全部资源，内存峰值过高。

**修复**：
- 按场景划分资源加载与释放边界
- 给出目标机型的峰值内存上限
- 纳入自动检查

**自检**：在最低档机型上切换场景，内存峰值是否超过阈值，加载耗时是否达标。

## 时间/空间复杂度或性能分析

**性能关注点**：帧预算决定体验——记录帧率与帧时间分布、峰值内存与加载耗时，低端机型要单独跑一遍。

**测量方法**：固定输入跑一遍记录基线，再把规模或并发度提高一个数量级复测；两次结果的差值与波动范围才是结论依据。

## 与其他知识点的关系

- **先修**：《游戏循环与时间步长》——帧预算是从"每一帧有多少毫秒可花"推算出来的，先理解固定步长与变步长，才能看懂为什么掉帧往往从逻辑阶段开始。
- **先修**：《移动端渲染管线》——Draw Call、批次合并与 Overdraw 决定了 GPU 侧的时间开销，本课的功耗优化大多落在这几个指标上。
- **后续**：《实体组件系统与性能剖析》——定位到具体是哪个系统吃掉了帧时间，需要 Profiler 与 ECS 的按系统计时配合。
- **相关概念**：
  - **资源管线与按需加载**：首包大小、纹理压缩格式直接影响冷启动时间与内存峰值，加载优化应与资源分档一起做。
  - **后台线程与任务调度**：把解算、解压挪到工作线程可以保住主线程帧预算，但线程过多会推高功耗，需要按冷热区权衡。
  - **热管理与降频**：SoC 的温度墙是硬约束，短时跑满不代表能长跑；长稳测试的本质就是在降频后的帧预算下重新验证一遍。

- **题目**：目标六十帧时每帧的时间预算约为？
- **选项**：A. 33.3 毫秒 B. 60 毫秒 C. 6 毫秒 D. 16.7 毫秒
- **正确项**：D. 16.7 毫秒
- **判断依据**：本题正确项是16.7 毫秒。术语 帧预算（移动端性能与功耗优化）：每帧允许消耗的最长时间，由目标帧率决定，本题取16.7 毫秒这条。易错点是只看帧率不看功耗与温度，会造成手机发热降频，帧率随后下滑，改法是同时监控帧时间、占用率与温度。易错点是每帧分配对象，会造成垃圾回收造成周期性卡顿，改法是复用对象与缓冲池，避免热路径分配。

### 考点 3：第 3 题

- **正确项**：A、B、C
- **判断依据**：本题正确项是帧率与帧时间分布。术语 帧预算（移动端性能与功耗优化）：每帧允许消耗的最长时间，由目标帧率决定，本题取帧率与帧时间分布这条。易错点是资源规格不分档，会造成低端设备显存不足直接崩溃，改法是按设备分档资源，控制纹理尺寸与压缩格式。

### 考点 4：第 4 题

- **题目**：请按一次移动端性能优化的顺序排列。
- **选项**：A. 确定目标帧率与机型分档 B. 在真机上采集性能数据 C. 定位超支环节与内存峰值 D. 实施针对性优化 E. 长稳复测并归档指标
- **正确项**：A → B → C → D → E
- **判断依据**：本题正确项是确定目标帧率与机型分档。术语 内存峰值（移动端性能与功耗优化）：运行过程中占用内存的最大值，本题取确定目标帧率与机型分档这条。易错点是只看帧率不看功耗与温度会造成手机发热降频，帧率随后下滑，改法是同时监控帧时间、占用率与温度。

### 考点 5：第 5 题

- **题目**：阅读这段加载代码，最可能导致什么问题？
```text

    LoadAllMeshes();
    LoadAllAudio();

```
- **选项**：A. 一次性加载全部资源，进入关卡时内存峰值过高 B. 纹理尺寸过小 C. 帧率被限制在三十 D. 加载顺序按名称排序
- **正确项**：A. 一次性加载全部资源，进入关卡时内存峰值过高
- **判断依据**：这道题检验内存峰值的概念。把整关资源一次性读入会让内存峰值大幅升高，低端机在切换场景时容易被系统终止，应按需加载并释放。
