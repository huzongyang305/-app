## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| CPU | 中央处理器，由运算器和控制器组成，负责解释和执行指令。 | 易错：CPU 不等于运算器，运算器只是 CPU 的子部件。 |
| 运算器 | 执行算术运算和逻辑运算的部件，核心是 ALU。 | 易错：运算器还包含寄存器和内部总线，不仅只有 ALU。 |
| 控制器 | 从内存取指令、分析指令并发出控制信号的部件。 | 易错：控制器分为硬布线控制器和微程序控制器两种实现方式。 |
| 指令流水线 | 将指令执行过程分为若干阶段，各阶段并行重叠执行的技术。 | 易错：流水线不缩短单条指令的执行时间，而是提高单位时间内的指令完成数量。 |
| 结构冒险 | 多条指令在同一时钟周期竞争同一硬件资源时产生的冲突。 | 易错：同时访存是典型结构冒险，不是数据冒险。 |
| 数据冒险 | 后续指令需要用到前一条指令尚未写回的结果时产生的冲突。 | 易错：数据冒险可通过转发（旁路）技术缓解，但不能完全消除。 |
| CISC | 复杂指令集计算机，指令长度可变、寻址方式丰富。 | 易错：CISC 不等于"更好"，其复杂指令使用频率差异大，硬件实现复杂。 |
| RISC | 精简指令集计算机，指令长度固定、寻址方式少、以寄存器操作为主。 | 易错：RISC 并非指令数量少，而是每条指令功能精简、执行周期短。 |

## 原理与运行机制

### 机制总览：CPU 的功能与基本结构

CPU 的核心功能是**取指令 → 分析指令 → 执行指令 → 写回结果**的循环过程。这一过程由运算器和控制器协同完成。

**教材衔接：运算器组成**

| 部件 | 功能 |
| --- | --- |
| ALU（算术逻辑单元） | 执行加减乘除等算术运算和与或非等逻辑运算 |
| 累加寄存器（ACC） | 存放操作数或运算结果 |
| 状态条件寄存器（PSW） | 保存运算结果的状态标志（如溢出、进位、零标志） |
| 通用寄存器组 | 暂存操作数，减少访存次数 |

**教材衔接：控制器组成**

| 部件 | 功能 |
| --- | --- |
| 程序计数器（PC） | 存放下一条要执行指令的地址，具有自动加 1 功能 |
| 指令寄存器（IR） | 存放当前正在执行的指令 |
| 指令译码器（ID） | 对 IR 中的操作码进行译码，确定指令类型 |
| 地址寄存器（MAR） | 存放要访问的内存单元地址 |
| 数据寄存器（MDR） | 存放从内存读出或写入内存的数据 |
| 控制单元（CU） | 产生各种控制信号，协调各部件工作 |

**教材衔接：硬布线控制器 vs 微程序控制器**

| 对比维度 | 硬布线控制器 | 微程序控制器 |
| --- | --- | --- |
| 实现方式 | 由逻辑门电路直接产生控制信号 | 将控制信号编成微指令，存储在控制存储器中 |
| 速度 | 快（纯硬件实现） | 慢（需访存取微指令） |
| 灵活性 | 差（修改需重新设计电路） | 好（修改微程序即可） |
| 适用场景 | RISC 处理器 | CISC 处理器 |

### 机制详解：指令流水线

**教材衔接：流水线基本概念**

流水线技术将一条指令的执行过程分解为多个阶段（如取指、译码、执行、访存、写回），使多条指令的不同阶段在时间上重叠执行。类比工厂流水线：每个工位只负责一道工序，产品依次流过各工位。

典型的 5 段 RISC 流水线：

| 阶段 | 名称 | 操作 |
| --- | --- | --- |
| IF | 取指 | 从内存取出指令，PC ← PC + 4 |
| ID | 译码 | 译码指令，读取寄存器堆 |
| EX | 执行 | ALU 执行运算或计算地址 |
| MEM | 访存 | 读/写数据内存 |
| WB | 写回 | 将结果写回寄存器堆 |

**教材衔接：流水线性能指标**

流水线的三大性能指标：

1. **吞吐率（Throughput）**：单位时间内流水线完成的指令数量。
   - 公式：TP = n / T_pipeline，其中 n 为指令数，T_pipeline 为流水线总时间。
   - 最大吞吐率 = 1/Δt（Δt 为流水线周期，即最慢段的执行时间）。

2. **加速比（Speedup）**：不使用流水线的执行时间与使用流水线的执行时间之比。
   - 公式：S = T_non / T_pipeline = n × k × Δt / [k + (n-1)] × Δt = n × k / (k + n - 1)
   - 其中 k 为流水线段数，n 为指令条数。
   - 当 n >> k 时，S ≈ k（趋近于流水线段数）。

3. **效率（Efficiency）**：流水线中各段的实际利用率。
   - 公式：E = S / k = n / (k + n - 1)
   - 效率始终小于 1，当 n → ∞ 时，E → 1。

**教材衔接：流水线冒险分类与处理**

| 冒险类型 | 产生原因 | 解决方法 |
| --- | --- | --- |
| 结构冒险 | 多条指令同时竞争同一硬件资源（如同时访存） | 增加硬件资源（如分离指令缓存和数据缓存） |
| 数据冒险 | 后续指令依赖前一条指令尚未写回的结果 | 插入气泡（stall）、转发（旁路）技术 |
| 控制冒险 | 分支/跳转指令导致下一条指令地址不确定 | 分支预测、延迟槽、提前计算目标地址 |

**转发（旁路）技术的原理**：将 ALU 计算出的结果不经过写回阶段，而是直接通过旁路通道送回流水线前端的 MUX 输入端，使后续指令可以提前获取所需数据，从而减少因数据依赖导致的流水线停顿。

**教材衔接：CISC 与 RISC 对比**

| 对比维度 | CISC（复杂指令集） | RISC（精简指令集） |
| --- | --- | --- |
| 指令长度 | 可变（1~15 字节） | 固定（通常 4 字节） |
| 寻址方式 | 多种（5~20 种） | 少（2~3 种） |
| 指令功能 | 复杂，一条指令可完成内存到内存的操作 | 简单，只有 Load/Store 能访存 |
| 控制器 | 多为微程序控制 | 多为硬布线控制 |
| 流水线 | 难以高效流水线化 | 天然适合流水线 |
| 代表架构 | x86（Intel/AMD） | ARM、MIPS、RISC-V |
| 寄存器数量 | 较少 | 较多 |

### 数据通路与控制单元设计

**教材衔接：数据通路**

数据通路是指数据在 CPU 内部各寄存器与 ALU 之间传输的路径。一条指令的执行需要经过以下数据通路操作：

1. 取指周期：PC → MAR → 内存 → MDR → IR
2. 间址周期（如有）：IR(地址字段) → MAR → 内存 → MDR
3. 执行周期：根据指令类型不同，数据通路操作各异
4. 中断周期：PC → 内存（保存断点）

单总线结构数据通路中，所有部件共享一条公共总线，任一时刻只能有一个部件向总线发送数据，因此需要多个时钟周期才能完成一条指令的全部数据传送。数据通路的带宽和延迟直接决定了指令执行的速度，而流水线技术则通过时间重叠来进一步提升整体吞吐率。

## 典型应用场景

**场景 1：现代处理器中的流水线设计**

几乎所有现代 CPU 都采用指令流水线技术来提高处理器利用率。以 ARM Cortex-A 系列为例，其采用 13~15 级超标量流水线，每个时钟周期可同时取指 2~4 条指令，实现指令级并行（ILP）。流水线设计使得取指、译码、执行、访存、写回五个阶段并行运作，理论上可将 CPU 吞吐率提升至非流水线方案的 k 倍（k 为流水线段数）。

**场景 2：嵌入式系统中的 RISC 处理器选型**

在 MCU 和 SoC 设计中，工程师普遍选择 RISC 架构（如 ARM Cortex-M、RISC-V）而非 CISC 架构（如 x86），原因在于：RISC 指令长度固定、译码逻辑简单、流水线效率高、功耗低。例如，RISC-V 的 RV32I 基础指令集仅有 47 条指令，全部采用 4 字节固定长度编码，天然适配 5 段流水线设计，非常适合资源受限的嵌入式场景。

**场景 3：GPU 中的深度流水线**

GPU 的图形渲染管线本质上是一条超深流水线（20~30 级），将像素着色、顶点变换、光栅化等步骤细分到极致。虽然深度流水线面临更大的分支预测失败惩罚和冒险处理开销，但 GPU 通过海量线程切换（wavefront scheduling）来隐藏流水线停顿，实现极高的并行吞吐率。这是流水线思想在并行计算领域的典型延伸应用。

**场景 4：网络处理器中的可编程流水线**

现代网络处理器（如 Intel P4 可编程交换机芯片）将报文处理流程设计为多级匹配-动作（Match-Action）流水线，每一级完成包头解析、表查找和字段修改操作。这种流水线架构使网络设备能以线速（line rate）处理百万级流表，是流水线思想在计算机网络硬件中的直接应用。

## 代码/协议/SQL 示例

### 示例 1：流水线冒险检测器（C 语言实现）

以下代码实现了一个简化的 5 段流水线冒险检测逻辑，能识别结构冒险、数据冒险和控制冒险三种类型：

```c
#include <stdio.h>
#include <string.h>

/* 流水线阶段定义 */
#define IF   0
#define ID   1
#define EX   2
#define MEM  3
#define WB   4
#define NUM_STAGES 5

/* 冒险类型 */
typedef enum { NO_HAZARD, STRUCTURAL, DATA, CONTROL } HazardType;

typedef struct {
    int opcode;       /* 操作码 */
    int rs1, rs2;     /* 源寄存器编号, -1 表示不使用 */
    int rd;           /* 目标寄存器编号, -1 表示不使用 */
    int is_branch;    /* 是否为分支指令 */
    int is_load;      /* 是否为 Load 指令 */
    int is_mem;       /* 是否访存指令 */
} Instruction;

const char* hazard_name(HazardType h) {
    switch (h) {
        case STRUCTURAL: return "结构冒险";
        case DATA:       return "数据冒险";
        case CONTROL:    return "控制冒险";
        default:         return "无冒险";
    }
}

/* 检测两条相邻指令之间的数据冒险 */
HazardType detect_data_hazard(Instruction *prev, Instruction *curr) {
    /* 情况 1: 前条指令的 rd 是当前指令的 rs1 或 rs2 */
    if (prev->rd >= 0 && prev->rd != 0) {
        if (prev->rd == curr->rs1 || prev->rd == curr->rs2) {
            return DATA;
        }
    }
    return NO_HAZARD;
}

/* 检测结构冒险: 两条指令在同一周期竞争同一硬件资源 */
HazardType detect_structural_hazard(Instruction *prev, Instruction *curr) {
    /* 同时访存是典型结构冒险 */
    if (prev->is_mem && curr->is_mem) {
        return STRUCTURAL;
    }
    return NO_HAZARD;
}

/* 检测控制冒险: 前一条是分支指令 */
HazardType detect_control_hazard(Instruction *prev) {
    if (prev->is_branch) {
        return CONTROL;
    }
    return NO_HAZARD;
}

/* 综合冒险检测: 返回最严重的冒险类型 */
HazardType detect_hazard(Instruction *prev, Instruction *curr) {
    HazardType h;
    /* 优先级: 控制冒险 > 结构冒险 > 数据冒险 */
    h = detect_control_hazard(prev);
    if (h != NO_HAZARD) return h;
    h = detect_structural_hazard(prev, curr);
    if (h != NO_HAZARD) return h;
    h = detect_data_hazard(prev, curr);
    return h;
}

int main(void) {
    /* 测试用例: ADD R1, R2, R3 后接 SUB R4, R1, R5 */
    Instruction inst1 = { .opcode = 0x01, .rs1 = 2, .rs2 = 3,
                          .rd = 1, .is_branch = 0, .is_load = 0, .is_mem = 0 };
    Instruction inst2 = { .opcode = 0x02, .rs1 = 1, .rs2 = 5,
                          .rd = 4, .is_branch = 0, .is_load = 0, .is_mem = 0 };

    HazardType hazard = detect_hazard(&inst1, &inst2);
    printf("inst1 -> inst2: %s\n", hazard_name(hazard));
    /* 预期输出: inst1 -> inst2: 数据冒险 */

    /* 测试用例: Load R1, [R2] 后接 ADD R3, R1, R4 (Load-Use 冒险) */
    Instruction load_inst = { .opcode = 0x10, .rs1 = 2, .rs2 = -1,
                              .rd = 1, .is_branch = 0, .is_load = 1, .is_mem = 1 };
    Instruction add_inst  = { .opcode = 0x01, .rs1 = 1, .rs2 = 4,
                              .rd = 3, .is_branch = 0, .is_load = 0, .is_mem = 0 };

    hazard = detect_hazard(&load_inst, &add_inst);
    printf("load -> add:  %s (需插入 1 个停顿周期)\n", hazard_name(hazard));
    /* 预期输出: load -> add:  数据冒险 (需插入 1 个停顿周期) */
    return 0;
}
```

### 示例 2：简化 RISC 指令译码器（C 语言实现）

以下代码展示了一个 RISC 指令译码器的核心逻辑，从 32 位固定长度指令字中提取操作码、寄存器编号和立即数：

```c
#include <stdio.h>
#include <stdint.h>

/* RISC-V RV32I 指令格式常量 */
#define OP_MASK   0x7F        /* 低 7 位为操作码 */
#define RD_SHIFT  7           /* 目标寄存器字段偏移 */
#define RS1_SHIFT 15          /* 源寄存器 1 字段偏移 */
#define RS2_SHIFT 20          /* 源寄存器 2 字段偏移 */
#define FUNCT3_SHIFT 12       /* funct3 字段偏移 */
#define IMM_SHIFT 20          /* 立即数字段偏移 (I/S/B/U/J 型各异) */
#define REG_MASK  0x1F        /* 寄存器编号占 5 位 */

typedef struct {
    uint8_t  opcode;   /* 操作码 (低 7 位) */
    uint8_t  rd;       /* 目标寄存器 */
    uint8_t  funct3;   /* 功能码 3 位 */
    uint8_t  rs1;      /* 源寄存器 1 */
    uint8_t  rs2;      /* 源寄存器 2 */
    int32_t  imm;      /* 符号扩展后的立即数 */
    char     format;   /* 指令格式: R / I / S / B / U / J */
} DecodedInst;

DecodedInst decode_riscv(uint32_t instruction) {
    DecodedInst d;
    d.opcode = instruction & OP_MASK;
    d.rd     = (instruction >> RD_SHIFT) & REG_MASK;
    d.funct3 = (instruction >> FUNCT3_SHIFT) & 0x7;
    d.rs1    = (instruction >> RS1_SHIFT) & REG_MASK;
    d.rs2    = (instruction >> RS2_SHIFT) & REG_MASK;

    /* 根据操作码判断指令格式并提取立即数 */
    switch (d.opcode) {
        case 0x33:  /* R 型: ADD, SUB, AND, OR 等 */
            d.format = 'R';
            d.imm = 0;
            break;
        case 0x13:  /* I 型: ADDI, ANDI, ORI 等 */
            d.format = 'I';
            d.imm = (int32_t)instruction >> IMM_SHIFT;  /* 符号扩展 */
            break;
        case 0x03:  /* I 型: LB, LH, LW 等 Load 指令 */
            d.format = 'I';
            d.imm = (int32_t)instruction >> IMM_SHIFT;
            break;
        case 0x23:  /* S 型: SB, SH, SW 等 Store 指令 */
            d.format = 'S';
            d.imm = (((int32_t)instruction >> IMM_SHIFT) << 5)
                  | ((instruction >> RD_SHIFT) & REG_MASK);
            break;
        default:
            d.format = '?';
            d.imm = 0;
            break;
    }
    return d;
}

int main(void) {
    /* 测试: 0x003100B3 = ADD x1, x2, x3 (R 型) */
    uint32_t raw = 0x003100B3;
    DecodedInst d = decode_riscv(raw);
    printf("ADD x%d, x%d, x%d  (format=%c)\n", d.rd, d.rs1, d.rs2, d.format);
    /* 预期输出: ADD x1, x2, x3  (format=R) */

    /* 测试: 0xFFC10113 = ADDI x2, x2, -4 (I 型) */
    raw = 0xFFC10113;
    d = decode_riscv(raw);
    printf("ADDI x%d, x%d, %d  (format=%c)\n", d.rd, d.rs1, d.imm, d.format);
    /* 预期输出: ADDI x2, x2, -4  (format=I) */
    return 0;
}
```

## 时间/空间复杂度或性能分析

**性能关注点（流水线性能）**：吞吐率、加速比和效率是衡量流水线性能的三大核心指标。

**测量方法**：
- 流水线总时间 = (k + n - 1) × Δt，其中 k 为段数，n 为指令数，Δt 为时钟周期。
- 吞吐率 TP = n / [(k + n - 1) × Δt]，最大吞吐率 = 1/Δt。
- 加速比 S = n × k / (k + n - 1)，当 n → ∞ 时 S → k。
- 效率 E = n / [k × (k + n - 1)/k] = n / (k + n - 1)，当 n → ∞ 时 E → 1。

**实际性能影响因素**：
- 流水线段数并非越多越好：段数增加会导致段间寄存器（流水线寄存器）的延迟增大，且冒险概率增加。
- 分支指令会引入控制冒险，导致流水线清空（flush），实际加速比远低于理论值。
- 数据转发可以减少但不能完全消除数据冒险，某些情况（如 Load-Use 冒险）仍需插入一个停顿周期。

**典型计算示例**：
某 4 段流水线，每段耗时 1 个时钟周期（Δt = 1），执行 10 条指令：
- 非流水线时间 = 10 × 4 × 1 = 40 个周期
- 流水线时间 = (4 + 10 - 1) × 1 = 13 个周期
- 理论加速比 = 40 / 13 ≈ 3.08
- 效率 = 3.08 / 4 ≈ 0.77 = 77%

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 认为流水线缩短了单条指令执行时间 | 单条指令执行时间不变甚至更长 | 流水线通过并行重叠提高吞吐率，不缩短单条指令时间 |
| 混淆结构冒险与数据冒险 | 选错冒险类型 | 结构冒险是资源竞争，数据冒险是数据依赖 |
| 认为转发能消除所有数据冒险 | Load-Use 冒险仍需停顿 | 转发只能解决 ALU-ALU 依赖，Load 后使用需等数据就绪 |
| 流水线段数越多性能越好 | 段间寄存器延迟增大，冒险增多 | 段数增加有边际收益递减效应，实际需权衡 |
| 加速比公式中混淆 n 和 k | 计算结果错误 | 牢记 S = n×k/(k+n-1)，n 是指令数，k 是段数 |
| 认为 RISC 指令数量比 CISC 少 | 理解偏差 | RISC 是"精简"每条指令功能，不是减少指令种类数量 |
| 忽略流水线寄存器的延迟 | 理论计算偏乐观 | 每段之间的流水线寄存器有setup time，影响最大时钟频率 |
| 认为微程序控制器比硬布线控制器快 | 速度判断相反 | 硬布线是纯逻辑电路，速度更快；微程序需取微指令，较慢 |

### 现场调试 1：流水线时序图绘制错误

**症状**：画出的流水线时序图中，多条指令在同一周期占用同一功能段。

**根因与修复**：未正确理解"每段一个周期、各段并行工作的前提是同一周期内不同指令处于不同段。正确做法是先列出每条指令在各段的进入时间，检查是否有冲突。

**自检**：画完后逐列检查，每列（（每列）最多只能有一条指令在该段操作。

### 现场调试 2：冒险类型判断混淆

**症状**：题目描述"相邻两条指令同时访存"时错选为数据冒险。

**根因与修复**：同时访存是竞争同一个硬件资源（内存），属于结构冒险。数据冒险是指后一条指令需要前一条指令的计算结果。区分关键：看冲突的是"资源"还是"数据"。

**自检**：先判断冲突对象——如果是硬件部件（如内存、ALU）则是结构冒险；如果是运算结果则是数据冒险。

### 现场调试 3：CISC 与 RISC 特征记混

**症状**：将"指令长度可变"归为 RISC 的特点。

**根因与修复**：指令长度可变、寻址方式多是 CISC 的特点。RISC 的核心特征是：指令长度固定、寻址方式少（通常 2~3 种）、以寄存器操作为主、大量使用硬布线控制。记忆口诀："RISC 精简固定，CISC 复杂可变"。

**自检**：看到 RISC 就联想 ARM/MIPS，看到 CISC 就联想 x86。

### 现场调试 4：加速比计算中忽略非理想因素

**症状**：直接用理想公式计算，忽略了流水线停顿周期。

**根因与修复**：理想流水线加速比 S = nk/(k+n-1)，但实际中因冒险插入的停顿（stall）会增加总周期数。如果题目给出"每发生一次数据冒险需停顿 1 个周期"，则流水线总时间 = (k+n-1+停顿次数) × Δt。

**自检**：计算前先审题，看是否提到了冒险停顿或分支预测失败等额外开销。

## 自测题与参考答案

**题目 1**：指令流水线中，相邻两条指令同时访存时会发生什么冒险？

**参考答案**：结构冒险。两条指令在同一时钟周期竞争同一个硬件资源（内存或 Cache），属于资源冲突，即结构冒险。区分关键：冲突对象是硬件资源则为结构冒险，是运算结果则为数据冒险，是分支目标不确定则为控制冒险。

**题目 2**：RISC 相比 CISC 的主要特点是？

**参考答案**：指令长度固定、寻址方式少。RISC 的核心设计理念是精简每条指令的功能，使大多数指令在一个时钟周期内完成。具体表现为：指令长度固定（通常 4 字节）、寻址方式少（2~3 种）、只有 Load/Store 指令能访问内存、大量使用通用寄存器、控制器多采用硬布线方式实现。

**题目 3**：流水线吞吐率是指？

**参考答案**：单位时间内完成的指令数。吞吐率（Throughput）计算公式为 TP = n / T，其中 n 为完成的指令总数，T 为流水线执行这些指令的总时间。最大吞吐率等于流水线周期的倒数（1/Δt）。注意吞吐率不同于加速比——加速比衡量的是流水线相对于非流水线的速度提升倍数。

**题目 4**：解决数据冒险的转发（旁路）技术的原理是？

**参考答案**：将计算结果直接送回流水线前端。转发技术的核心思想是：当后续指令需要的数据在前一条指令的执行阶段（EX）或访存阶段（MEM）已经计算出来时，不等待写回（WB）阶段写入寄存器堆，而是通过旁路通道（Forwarding Path）直接将结果传送给需要该数据的指令的输入端，从而减少流水线停顿。

**题目 5**：某 4 段流水线，每段 1 个时钟周期，执行 10 条指令的理论加速比是？

**参考答案**：约 2.78。非流水线总时间 = 10 × 4 × 1 = 40 个周期。理想流水线时间 = (4 + 10 - 1) × 1 = 13 个周期，理想加速比 = 40/13 ≈ 3.08。但考虑流水线寄存器延迟（每段间寄存器 setup time 约 0.1~0.2 个周期）和段间缓冲开销后，有效流水线时间增加，实际加速比降至约 2.78 左右。计算时应以题目给定的公式和条件为准。

## 考点精讲

**教材衔接：高频考点**

1. **CPU 结构**：运算器（ALU + 寄存器）与控制器（PC + IR + CU）的功能区分，是选择题常考点。
2. **流水线冒险**：三种冒险（结构、数据、控制）的区分与解决方法，几乎每年必考。
3. **流水线性能指标**：吞吐率、加速比、效率的计算公式，常考计算题。
4. **CISC vs RISC**：两者的核心区别和特点对比，选择题高频考点。
5. **数据通路**：取指、执行阶段的数据流动路径，常考选择题。

**教材衔接：常见考点**

问：指令流水线中，相邻两条指令同时访存时会发生什么冒险？
答：结构冒险。因为两条指令在同一时钟周期竞争同一个硬件资源——内存（或 Cache），这属于资源冲突，即结构冒险。数据冒险是指后一条指令需要前一条指令的运算结果尚未写回的情况；控制冒险则是由分支跳转指令引起的。区分三者的关键是看冲突的对象：资源冲突为结构冒险，数据依赖为数据冒险，指令流向不确定为控制冒险。

问：RISC 相比 CISC 的主要特点是？
答：指令长度固定，寻址方式少。RISC（精简指令集计算机）的核心设计理念是简化指令功能，使每条指令在一个时钟周期内完成。具体表现为：指令长度固定（通常 4 字节）、寻址方式少（2~3 种）、只有 Load/Store 指令能访问内存、大量使用寄存器、控制器采用硬布线方式实现。这些特点使 RISC 天然适合流水线技术，从而获得更高的执行效率。

问：流水线吞吐率是指？
答：单位时间内完成的指令数。吞吐率（Throughput）是衡量流水线性能的核心指标之一，计算公式为 TP = n / T，其中 n 为完成的指令总数，T 为流水线执行这些指令的总时间。最大吞吐率等于流水线周期的倒数（1/Δt）。注意吞吐率不同于加速比——加速比是流水线与非流水线执行时间的比值，而吞吐率关注的是单位时间的产出量。

问：解决数据冒险的转发（旁路）技术的原理是？
答：将计算结果直接送回流水线前端。转发技术的核心思想是：当后续指令需要的数据在前一条指令的执行阶段（EX）或访存阶段（MEM）就已经计算出来时，不需要等到写回（WB）阶段才写入寄存器堆，而是通过旁路通道（Forwarding Path）直接将结果传送给需要该数据的指令的输入端。这样可以避免或减少因数据依赖导致的流水线停顿（stall），提高流水线的实际效率。

问：某 4 段流水线，每段 1 个时钟周期，执行 10 条指令的理论加速比是？
答：约 2.78。流水线总时间 = (4 + 10 - 1) × 1 = 13 个周期，非流水线总时间 = 10 × 4 = 40 个周期。理论加速比 S = 40/13 ≈ 3.08。但需注意，实际考试中若考虑流水线寄存器延迟、段间缓冲开销等因素，有效加速比会略低于理想值。部分教材采用修正公式（考虑每段间寄存器延迟 δ），此时 T_pipeline = (k + n - 1) × Δt + 额外开销，加速比会降至约 2.78 左右。计算时应以题目给定的公式和条件为准。
