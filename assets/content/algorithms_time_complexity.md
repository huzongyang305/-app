## 原理与运行机制

### 机制总览

**教材衔接：分析方法与常见误判**

1. 只保留最高阶项：`3n² + 5n + 100` → O(n²)。
2. 循环看迭代次数，嵌套相乘；但内层依赖外层时要单独分析（如 `for i: for j in range(i)` 是 O(n²/2) = O(n²)）。
3. 递归用递推式：`T(n)=2T(n/2)+O(n)` → O(n log n)；快速排序最坏 `T(n)=T(n-1)+O(n)` → O(n²)。
4. 别忽略隐藏成本：字符串拼接、切片、`in` 判断、哈希冲突、内存分配都可能改变实际复杂度。
5. 均摊分析：动态数组 `append` 单次可能 O(n)，但均摊为 O(1)。

**教材衔接：数据规模与算法选择**

| n 的规模 | 可接受复杂度 | 常见做法 |
| --- | --- | --- |
| ≤ 10 | O(n!) | 全排列、暴力搜索 |
| ≤ 20 | O(2ⁿ) | 状态压缩、子集枚举 |
| ≤ 500 | O(n³) | 区间 DP、Floyd |
| ≤ 5000 | O(n²) | 双重循环、简单 DP |
| ≤ 10⁶ | O(n log n) | 排序、二分、堆 |
| ≤ 10⁸ | O(n) | 一次扫描、前缀和 |

常见代码与复杂度对照：

```python
# O(1)：执行次数与 n 无关
def first(nums):
    return nums[0]

# O(n)：一次遍历
def total(nums):
    result = 0
    for x in nums:
        result += x
    return result

# O(n²)：嵌套两层循环
def pairs(nums):
    count = 0
    for a in nums:
        for b in nums:
            count += 1
    return count
```

**教材衔接：如何分析**

1. 只看最高阶项，忽略常数和低阶项：`3n² + 5n + 100` 记作 `O(n²)`。
2. 顺序执行取最大的复杂度：先 `O(n)` 再 `O(n²)`，整体是 `O(n²)`。
3. 循环看迭代次数，嵌套循环用乘法。
4. 递归用递推式或递归树分析。

```python
# 对数复杂度：每次规模减半
def count_halving(n):
    steps = 0
    while n > 1:
        n = n // 2
        steps += 1
    return steps      # 约等于 log2(n)
```

**教材衔接：最好、最坏与平均**

以线性查找为例：

```python
def find(nums, target):
    for i, value in enumerate(nums):
        if value == target:
            return i
    return -1
```

- 最好情况：第一个就是目标，`O(1)`。
- 最坏情况：目标在末尾或不存在，`O(n)`。
- 平均情况：约 `O(n)`。

不加说明时，通常讨论**最坏时间复杂度**。

## 时间/空间复杂度或性能分析

**复杂度证据**：本课正文出现 `O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n²)`、`O(2ⁿ)` 等量级表达式；使用前要同时确认输入规模、最好/平均/最坏情况以及常数项来源。

**教材衔接：为什么需要复杂度**

**教材衔接：空间复杂度**

复杂度不只描述时间。额外申请一个长度为 n 的数组，空间复杂度就是 `O(n)`；只用几个变量则是 `O(1)`。

```python
def copy_list(nums):
    return nums[:]        # 额外 O(n) 空间
```

| 复杂度 | 名称 | n=10³ 量级 | 典型算法 |
| --- | --- | --- | --- |
| O(1) | 常数 | 1 | 哈希查找、数组下标 |
| O(log n) | 对数 | 约 10 | 二分查找、平衡树查找 |
| O(n) | 线性 | 1000 | 一次遍历、前缀和 |

| O(n²) | 平方 | 10⁶ | 冒泡/插入排序、双重循环 |
| O(n³) | 立方 | 10⁹ | 朴素矩阵乘法、区间 DP |
| O(2ⁿ) | 指数 | 巨大 | 子集枚举、朴素递归 |
| O(n!) | 阶乘 | 不可行 | 全排列暴力 |

| 结构 | 访问 | 查找 | 插入 | 删除 |
| --- | --- | --- | --- | --- |

| 技巧 | 说明 |
| --- | --- |

### 考点 7：`复杂度`

- **要点**：描述输入规模增长时时间或空间消耗的变化趋势。
- **复杂度 的边界**：易错：复杂度判断错误；正确做法是常数因子忽略，`2n` 仍是 O(n)。

### 考点 8：`空间复杂度`

- **要点**：复杂度不只描述时间。额外申请一个长度为 n 的数组，空间复杂度就是 O(n)；只用几个变量则是 O(1)。
- **空间复杂度 的边界**：易错：内存溢出；正确做法是同时评估时间与空间。

### 考点 9：`性能`

- **要点**：系统在给定负载下表现出的吞吐、延迟、资源占用和稳定性。
- **性能 的边界**：结论随输入规模变化，小规模成立不代表大规模成立，需要重新测量。

### 考点 10：`摊还复杂度`

- **要点**：把偶发的高成本操作平摊到一串操作上，例如动态数组扩容，描述的是平均每次的代价。
- **摊还复杂度 的边界**：只在「把偶发的高成本操作平摊到一串操作上，例如动态数组扩容，描述的是平均每次的代价」这一前提下成立，换输入或换环境要重新验证。

### 考点 11：排错——把 O(2n) 当成 O(n²)

- **现象**：复杂度判断错误。
- **处理**：常数因子忽略，`2n` 仍是 O(n)。

### 考点 12：排错——忽略 Python 内置函数是 C 实现

- **现象**：自己写循环反而更慢。
- **处理**：优先用 `sum`、`sorted`、`in` 等内置。

### 考点 13：综合辨析——`复杂度` 与 `摊还复杂度`

- **辨析点**：`复杂度` 的定义是 描述输入规模增长时时间或空间消耗的变化趋势；`摊还复杂度` 的定义是 把偶发的高成本操作平摊到一串操作上，例如动态数组扩容，描述的是平均每次的代价。
