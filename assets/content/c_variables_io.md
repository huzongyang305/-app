## 原理与运行机制

### 机制总览

**教材衔接：一句话入门**

声明变量并用 printf/scanf 交换数据。

**教材衔接：C 语言基础机制速览**

### 编译、链接与程序结构

C 源码经过预处理、编译、汇编和链接生成可执行文件。`#include` 引入声明，函数定义提供实现，链接器负责解析外部符号。`main` 返回 0 表示成功，非 0 表示失败。理解头文件、声明与定义的区别，能区分“找不到函数声明”的编译错误和“找不到符号”的链接错误。

### 类型、变量与内存表示

C 是静态类型语言，基本类型的大小依赖平台，使用 `sizeof` 而不是硬编码字节数。整数有有符号和无符号之分，混合运算会发生转换；无符号回绕有定义，有符号溢出通常是未定义行为。浮点数遵循 IEEE 754 近似表示，比较时使用容差。字符类型、字符串和数组的关系需要清楚：字符串以 `\0` 结尾，`char` 数组不一定是字符串。

### 指针、数组与字符串

指针保存地址，`*` 解引用，`&` 取地址；指针算术按所指类型大小移动。数组名在大多数表达式中退化为首元素指针，但 `sizeof` 和取地址时不是。函数参数中的数组声明等价于指针，长度信息会丢失，必须额外传长度。字符串函数要保证目标缓冲区足够大，优先使用带长度限制的函数，防止溢出。

### 函数、结构体与内存管理

函数原型要在调用前可见，参数按值传递；要修改调用方变量就传指针。结构体可以按值复制，较大结构体通常传指针；`struct` 的内存可能有填充，`sizeof` 不一定等于成员大小之和。`malloc/free`、`calloc`、`realloc` 必须成对使用，释放后指针置空，不能访问已释放内存。栈内存自动回收但生命周期受作用域限制，返回局部数组地址是典型错误。

### 预处理器、未定义行为与调试

宏在预处理阶段替换文本，要加括号并避免多次求值副作用；`#include` 保护防止重复包含。未定义行为包括越界访问、解引用空指针、未初始化读取、有符号溢出和不匹配的格式化参数，编译器优化后可能产生难以预测的结果。使用编译器警告、静态分析、sanitizer 和调试器定位内存问题；测试要覆盖空输入、边界长度、内存分配失败和错误路径。

### 考点 6：`数据类型`

- **要点**：int、double、char 等决定变量占用的字节数与可表示范围。
- **数据类型 的边界**：换编码、换字节序或换平台都可能改变结果，处理前先固定输入编码。

### 考点 7：`变量声明与初始化`

- **要点**：声明给出类型和名字，初始化在声明时给初值。
- **变量声明与初始化 的边界**：静态检查只在编译期成立，运行期输入仍需校验。

### 考点 8：`scanf`

- **要点**：按格式串从标准输入读取数据，参数要传变量地址。
- **scanf 的边界**：易错：输入失败后继续使用未初始化变量；正确做法是检查返回值，失败时清空缓冲并重新提示。

### 考点 9：`格式化占位符`

- **要点**：%d、%f、%c 分别对应整数、浮点数、字符，类型不匹配会读错数据。
- **格式化占位符 的边界**：静态检查只在编译期成立，运行期输入仍需校验。

### 考点 10：`输入缓冲区`

- **要点**：输入先进入缓冲区再被读取，残留换行符常导致后续读取被跳过。
- **输入缓冲区 的边界**：只在「输入先进入缓冲区再被读取，残留换行符常导致后续读取被跳过」这一前提下成立，换输入或换环境要重新验证。

### 考点 11：`数组`

- **要点**：数组名在大多数表达式中退化为首元素指针，但 sizeof 和取地址时不是
- **数组 的边界**：越界、悬垂引用与释放顺序会破坏结论，必须在边界输入下复验。

### 考点 12：排错——scanf 不检查返回值

- **现象**：输入失败后继续使用未初始化变量。
- **处理**：检查返回值，失败时清空缓冲并重新提示。

### 考点 13：排错——格式符与变量类型不匹配

- **现象**：读取越界或结果错乱。
- **处理**：格式符严格对应变量类型，长度修饰符写全。

### 考点 14：综合辨析——`数据类型` 与 `数组`

- **辨析点**：`数据类型` 的定义是 int、double、char 等决定变量占用的字节数与可表示范围；`数组` 的定义是 数组名在大多数表达式中退化为首元素指针，但 sizeof 和取地址时不是。
