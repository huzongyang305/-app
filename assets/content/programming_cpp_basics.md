## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| main | `main` 忘记 `return` 时 C++ 会隐式返回 0，但其他有返回值的函数不写 `return` 是未定义行为。 |
| C++ | C++ 是编译型语言：你写的源码要先整体"翻译"成机器码，才能运行。 |
| 编译 | 把源代码转换成目标机器代码或中间表示，并在此过程中检查语法和类型。 |
| 链接 | 把多个目标文件和库合并成一个可执行程序的过程。 |
| namespace | 把标识符组织到独立作用域、避免命名冲突的语言结构。 |
| 预处理 | 编译的第一步，处理 `#include`、`#define` 等以 `#` 开头的指令。 |

## 原理与运行机制

### 从源码到可执行文件的四个阶段

```text
hello.cpp（源代码）
    ↓ ① 预处理（Preprocessing）
    ↓    展开 #include，替换 #define，删除注释
hello.i（预处理后的源码）
    ↓ ② 编译（Compilation）
    ↓    检查语法和类型，翻译成汇编语言
hello.s（汇编代码）
    ↓ ③ 汇编（Assembly）
    ↓    把汇编翻译成机器码
hello.o（目标文件）
    ↓ ④ 链接（Linking）
    ↓    合并多个 .o 文件和库
hello.exe（可执行程序）
```

就像出版一本书：预处理是把所有"参见附录 A"替换成真正的附录内容；编译是把中文翻译成印刷排版；汇编是制作印刷模板；链接是把所有章节装订在一起。

### 预处理：展开头文件

```cpp
#include <iostream>
```

预处理阶段，编译器把这行替换成 `iostream` 头文件的完整内容。这就是为什么忘了 `#include` 就会报"未声明的标识符"——因为编译器不知道 `std::cout` 是什么。

你可以用 `g++ -E hello.cpp` 只看预处理的结果，会看到一大段展开后的代码。

### 编译：检查语法和类型

编译器读取预处理后的代码，检查：
- 语法是否正确（分号、花括号是否匹配）
- 类型是否合法（不能把字符串赋给 int 变量）
- 函数是否声明了再调用

如果一切正常，编译器输出汇编代码。

### 汇编：生成目标文件

汇编器把汇编代码翻译成 CPU 能直接执行的机器码，保存在 `.o`（或 `.obj`）文件里。这个文件还不能直接运行——它可能引用了其他文件里的函数。

### 链接：合并成可执行程序

链接器把所有 `.o` 文件和需要的库（如标准库）合并成一个完整的可执行程序。它会：
- 把函数调用指向真正的函数地址
- 检查是否有"声明了但没定义"的符号
- 处理库之间的依赖关系

### 命名空间：避免名字冲突

```cpp
namespace app {
    std::string name = "demo";
}

int main() {
    std::cout << app::name << '\n';
}
```

想象两个人都叫"小明"——在一个班里会混乱。命名空间就像给每个人加了一个姓氏前缀：`app::name` 和 `other::name` 就不会冲突了。`std` 就是标准库的"姓氏"。

### 头文件保护

```cpp
#pragma once  // 防止头文件被重复包含
#ifndef MY_HEADER_H
#define MY_HEADER_H
// 头文件内容
#endif
```

如果一个头文件被多个源文件包含，或者被间接包含多次，里面的声明就会重复出现导致编译错误。`#pragma once` 或 include guard 防止头文件被重复包含。

## 典型应用场景

理解编译流程对日常开发非常重要：

- **多文件项目**：大型项目把代码分成多个 `.cpp` 文件分别编译，改动一个文件只需重编该文件
- **第三方库**：使用别人的库时需要正确链接，否则报"未定义引用"
- **编译选项**：`-Wall` 打开所有警告，`-O2` 优化性能，`-g` 加入调试信息
- **跨平台开发**：不同平台的编译器和标准库实现可能有差异
- **调试编译错误**：知道错误发生在哪个阶段（预处理/编译/链接），才能对症下药

### 一个实际的小例子

```cpp
// math_utils.h
#pragma once
int add(int a, int b);

// math_utils.cpp
#include "math_utils.h"
int add(int a, int b) { return a + b; }

// main.cpp
#include <iostream>
#include "math_utils.h"
int main() {
    std::cout << "Hello, C++!" << "\n";
    std::cout << add(3, 5) << "\n";
    return 0;
}
```

编译命令：

```bash
g++ -std=c++17 -Wall main.cpp math_utils.cpp -o demo
./demo
```

## 代码/协议/SQL 示例

### 最小可运行示例

```cpp
#include <iostream>
#include <string>

namespace app {
    std::string name = "demo";
}

int main() {
    std::cout << app::name << '\n';
    // 不推荐在头文件里写 using namespace std;
    return 0;
}
```

输出：

```text
Hello, C++!
```

### 多文件编译示例

```bash
# 分别编译
g++ -c main.cpp -o main.o
g++ -c math_utils.cpp -o math_utils.o

# 链接
g++ main.o math_utils.o -o demo

# 或者一步完成
g++ main.cpp math_utils.cpp -o demo
```

分开编译的好处是：改动一个文件只需重编该文件，其他文件的 `.o` 可以复用。大型项目中这能节省大量编译时间。

### 常用编译选项

```bash
g++ -std=c++17    # 使用 C++17 标准
    -Wall          # 打开所有警告
    -Wextra        # 打开额外警告
    -O2            # 优化等级 2
    -g             # 加入调试信息
    -o output      # 指定输出文件名
```

## 时间/空间复杂度或性能分析

编译流程的性能关注点：

- **编译时间**：头文件越多、模板越复杂，预处理和编译越慢。`#pragma once` 可以避免重复处理
- **增量编译**：分开编译多个 `.cpp` 文件，改动一个只重编该文件，大幅节省时间
- **优化等级**：`-O0`（不优化，编译快）→ `-O2`（平衡）→ `-O3`（激进优化，编译慢但运行快）
- **链接时间**：库越多链接越慢；使用 `-flto`（链接时优化）可以改善运行时性能

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 忘写分号 | 报错常常指向下一行 | 看报错行号的上一行 |
| 头文件重复包含 | 编译报"重复定义" | 使用 `#pragma once` 或 include guard |
| 在头文件里写 `using namespace std;` | 所有包含该头文件的文件都被污染 | 头文件里只用 `std::` 前缀 |
| 链接时找不到符号 | 报 `undefined reference` | 确认所有 `.cpp` 文件都参与编译 |
| 忽略编译器警告 | 隐藏潜在的未定义行为 | 打开 `-Wall -Wextra`，把警告当错误修 |

### 现场 1：忘写分号

**症状**：编译器报错指向某一行，但那一行看起来没问题。

**根因与修复**：分号漏写时，编译器把下一行当作同一语句的延续。看报错行号的上一行，补上分号。
