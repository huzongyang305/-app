## 典型应用场景

- **在虚拟线程里长时间持锁**：典型现象是载体线程被占用，扩展性消失；正确做法是缩小临界区，必要时改用可重入锁。
- **把虚拟线程当线程池复用**：典型现象是语义不符，收益有限；正确做法是每个任务创建虚拟线程，用结构化并发组织。
- **忽略阻塞式本地调用**：典型现象是载体线程仍被占满；正确做法是识别真正的阻塞点，改用异步 API 或独立线程池。

- **答题要求**：面对 `Java 虚拟线程与结构化并发` 的题目，先判断描述的是 `虚拟线程` 还是 `线程池`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 13：排错评分点

- **现象分**：能写出 载体线程被占用，扩展性消失，而不是只写“程序有错”。
- **证据分**：保留触发 在虚拟线程里长时间持锁 的输入、版本和错误原文。
- **修复分**：按 缩小临界区，必要时改用可重入锁 只改一处，并同时回归正常路径与边界路径。
