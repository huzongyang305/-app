## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| record | 编译器自动生成值相等、`ToString`、`Deconstruct` 与 `with` 支持的类型，主构造函数参数默认是 init-only 属性。 | 值对象适合；需要稳定身份与生命周期管理的实体不要用 record，值语义会与标识语义冲突。 |
| 模式匹配 | 用 `switch` 表达式或 `is` 模式按类型、属性、位置、关系和列表结构分支并提取变量。 | 分支要从具体到宽泛；宽泛分支会截胡后面的具体分支，非穷尽 switch 只给编译警告，不是错误。 |
| 不可变 | 对象创建后状态不再改变，修改通过 `with` 或集合操作生成新实例。 | 默认只是浅不可变：引用类型属性仍被共享，集合内容仍可能被改，需要 `ImmutableArray`、`FrozenDictionary` 等结构。 |
| with | record 的复制表达式，生成浅拷贝并覆盖指定属性，原实例保持不变。 | 浅拷贝只复制引用，嵌套对象被修改时新旧实例一起变；高频 with 会带来额外分配。 |

## 原理与运行机制

### record 的编译产物

写下 `record Point(int X, int Y)`，编译器会生成：

- 主构造函数与两个 `init`-only 属性 `X`、`Y`；
- 逐字段比较的 `Equals`、`GetHashCode`，以及 `==`、`!=` 运算符；
- 带属性名的 `ToString`，输出形如 `Point { X = 2, Y = 3 }`；
- `Deconstruct(out int X, out int Y)`，供位置模式使用；
- 一个受保护的拷贝构造函数和 `<Clone>$` 方法，`with` 表达式靠它复制。

`record class` 可以有继承，但相等性要求运行时类型一致；`record struct` 没有继承，适合字段少、生命周期短的值。默认的 `record` 属性是 `init`-only，想真正不可变就不该再给它们加 `set`。

### 值相等与哈希的约束

`new Point(2, 3) == new Point(2, 3)` 为 `true`，但两者不是同一个对象。值相等意味着：

- 放进 `HashSet`、`Dictionary` 后，字段不能再变；一旦可变，哈希值改变，集合按旧哈希找不到元素。
- 用 `with` 生成新实例而不是就地赋值，才能保持"旧值不动、新值独立"。
- 属性是引用类型（如 `List<int>`）时，两个 record 可以比较相等，之后共享的列表被修改，相等关系又悄悄改变。

如果字段很多、相等比较在热路径上，record 的逐字段比较和哈希计算会成为成本，需要实测后再决定是否缓存或改用其他结构。

### 模式匹配的形态与顺序

C# 常见模式：

| 模式 | 示例 | 说明 |
| --- | --- | --- |
| 类型 | `Circle c` | 判断运行时类型并绑定变量 |
| 属性 | `{ Radius: > 0 }` | 读取属性后做关系判断 |
| 位置 | `(0, 0)` | 调用 `Deconstruct` 提取字段 |
| 关系与逻辑 | `<= 0`、`> 0 and < 10` | 组合数值约束 |
| 列表 | `[1, .., 3]` | 匹配序列首尾与任意中段 |

`switch` 表达式自上而下匹配，第一个命中的分支生效，所以顺序必须从具体到宽泛。编译器只对明显不穷尽的 switch 给 CS8509 警告，不会阻止运行；`_` 是兜底分支，`null` 不会匹配类型模式，需要单独处理。

### 不可变与持久化数据结构

`init`-only 属性和 `readonly` 字段只能挡住属性重新赋值，挡不住集合内容修改。要真正不可变，需要换成持久化集合：

- `ImmutableArray<T>`：底层是数组，`Add` 复制整个数组，适合元素少、读多写少的场景。
- `ImmutableList<T>`：平衡树实现，`Add` 是 O(log n)，新旧版本共享大部分节点。
- `FrozenDictionary<TKey, TValue>`：一次性构建、之后只读，查询比 `Dictionary` 更快，适合启动时定型的配置。

`IReadOnlyList<T>` 只是接口视图，持有者仍可能把底层 `List<T>` 转型后修改，不能当作不可变保证。

### with 的浅拷贝成本

`with` 先调用拷贝构造函数复制所有字段，再对指定属性赋值，所以每次都会产生一个新对象。复制是浅的：

- 值类型字段逐位复制；
- 引用类型字段只复制引用，新旧实例指向同一个列表或子对象；
- 要改嵌套 record，需要逐层 `with`，例如 `order with { Address = order.Address with { City = "上海" } }`。

`record struct` 的 `with` 在栈上复制，不产生堆分配；`record class` 的 `with` 每次分配一个对象，高频更新要评估 GC 压力。

### 版本与升级

record 从 C# 9 开始，列表模式从 C# 11 开始。升级 SDK 前先用现有测试覆盖相等性、模式匹配顺序和序列化行为，再对照官方发布说明检查新语法与破坏性变更。

| 场景 | 写法 | 关键点 |
| --- | --- | --- |

| 配置快照 | `record Settings(...)` + `ImmutableDictionary` | 发布后下游无法修改共享配置 |

### 建模步骤

1. 先判断值对象还是实体：有唯一 ID、需要跟踪生命周期的是实体，用 class；按字段比较的是值对象，用 record。
2. 选择 `record class` 或 `record struct`：字段少、生命周期短、复制频繁时优先 `readonly record struct`。
3. 集合属性改成 `ImmutableArray<T>`、`ImmutableList<T>` 或 `FrozenDictionary<TKey,TValue>`，不要只暴露 `IReadOnlyList<T>`。
4. 用 `switch` 表达式把分支从具体写到宽泛，并保留 `_` 或异常分支，避免新增类型时静默走错路径。
5. 测试三件事：值相等、`with` 的深浅拷贝、模式顺序改变后的分支结果。

### 最小验证场景

- 准备：运行代码示例，记录 `Point` 输出、`circle area`、`bigger area`、`equal`、`tags` 五行基线。
- 观察：给 `Point` 的 `X` 加 `set`，把它放进 `HashSet` 后修改 `X`，再调用 `Contains`；把 `Circle` 的属性分支移到宽泛分支之后，观察哪个分支先命中。
- 判定：五行基线必须完全一致；改动后若 `Contains` 返回 `false` 或宽泛分支截胡，说明不可变或模式顺序被破坏。
- 失败信号：`with` 后旧实例也跟着变、相同字段的两个对象比较为 `false`、新增子类型没有触发警告。

### 选择与边界

- `record` 适合值对象与消息；需要唯一标识、可变生命周期的实体用 class。
- `模式匹配` 要先具体后宽泛，并用 `_` 或显式异常兜底；编译器警告不能当作可忽略的提示。
- `不可变` 默认只到属性层，集合与嵌套对象要单独处理，持久化集合有复制与内存成本。
- `with` 是浅拷贝，改嵌套字段要逐层复制，高频更新要评估分配与 GC 压力。

## 代码/协议/SQL 示例

### 最小可验证示例

**教材衔接：最小可运行示例**

下面的代码同时演示值相等、位置模式、属性模式、`with` 与不可变集合，先原样运行，再按小节说明改一处：

```csharp
using System;
using System.Collections.Immutable;

public abstract record Shape;
public sealed record Circle(double Radius) : Shape;
public sealed record Rectangle(double Width, double Height) : Shape;

public record Point(int X, int Y);

public static class Program
{
    public static double Area(Shape shape) => shape switch
    {
        Circle { Radius: <= 0 } => throw new ArgumentOutOfRangeException(nameof(shape)),
        Circle c => Math.PI * c.Radius * c.Radius,
        Rectangle { Width: var w, Height: var h } when w > 0 && h > 0 => w * h,
        Rectangle => throw new ArgumentOutOfRangeException(nameof(shape)),
        _ => throw new ArgumentException("unknown shape", nameof(shape)),
    };

    public static void Main()
    {
        var point = new Point(2, 3);
        var label = point switch
        {
            (0, 0) => "origin",
            (_, 0) => "x-axis",
            _ => "plane",
        };
        Console.WriteLine($"{point} -> {label}");

        var circle = new Circle(2);
        Console.WriteLine($"circle area={Area(circle):F2}");
        var bigger = circle with { Radius = 3 };
        Console.WriteLine($"bigger area={Area(bigger):F2}");
        Console.WriteLine($"equal={circle == new Circle(2)}");

        var tags = ImmutableArray.Create("a", "b");
        var updated = tags.Add("c");
        Console.WriteLine($"tags={string.Join(",", tags)} updated={string.Join(",", updated)}");
    }
}
```

**教材衔接：预期输出**

```text
Point { X = 2, Y = 3 } -> plane
circle area=12.57
bigger area=28.27
equal=True
tags=a,b updated=a,b,c
```

`Point` 的 `(0, 0)`、`(_, 0)` 是位置模式，编译器调用 `Deconstruct` 提取两个字段；`with` 生成新实例，所以 `circle` 仍是半径 2，`bigger` 是半径 3；`equal=True` 来自逐字段值相等；`ImmutableArray.Add` 返回新数组，原 `tags` 保持 `a,b`。

### 只改一个值：触发守卫分支

把 `new Circle(2)` 改成 `new Circle(0)`，`Area` 会命中 `Circle { Radius: <= 0 }` 并抛 `ArgumentOutOfRangeException`；把 `(0, 0)` 分支改成 `(_, _)`，所有点都会输出 `origin`，说明分支顺序和具体程度直接决定结果。两种改动都不影响 `Point` 的值相等语义。

## 时间/空间复杂度或性能分析

**record 的相等成本**：`Equals` 与 `GetHashCode` 按字段逐个计算，字段数为 f 时是 O(f)。相等比较在 `Dictionary`、`HashSet` 和 LINQ 去重里是高频操作，字段很多的 record 要考虑是否值得。

**模式匹配的成本**：类型模式是一次类型检查加一次变量绑定，属性模式会调用对应 getter；`switch` 自上而下执行，宽泛分支放在前面会让后面的具体分支永远走不到，同时浪费判断。列表模式还要检查长度与切片边界。

**with 与不可变集合的分配**：`record class` 的每次 `with` 分配一个新对象并复制所有字段，引用字段只复制指针；`record struct` 的 `with` 在栈上复制。`ImmutableArray.Add` 是 O(n) 复制，`ImmutableList.Add` 是 O(log n) 并共享大部分节点，`FrozenDictionary` 构建一次后查询接近 O(1)。

**测量方法**：用 BenchmarkDotNet 固定输入测相等比较、模式分支与 `with` 的吞吐，用 `GC.GetAllocatedBytesForCurrentThread()` 记录分配量，再把字段数或集合规模提高一个数量级复测，比较 P99 与分配而不是只看平均值。

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 给 record 加可变属性 | 值语义被破坏，比较结果不符合预期。 | 保持不可变，修改时用 with 生成新实例。 |
| 模式匹配顺序写反 | 前面的宽泛模式吞掉后面的具体分支。 | 从具体到宽泛排列，并做穷尽性检查。 |
| 把 record 当实体到处传 | 值语义与标识语义混淆。 | 值对象用 record，需要唯一标识的实体用 class。 |
| 可变 record 放进 HashSet 后改属性 | 哈希值变化，`Contains` 和 `Remove` 找不到元素 | 属性设为 init-only，修改走 `with` 生成新实例。 |
| with 之后直接改嵌套集合 | 新旧实例共享同一个列表，旧快照被污染 | 嵌套对象也保持不可变，或改用 `ImmutableArray`。 |
| switch 缺少兜底分支 | 新增子类型后静默返回错误值 | 保留 `_` 或显式异常分支，并打开穷尽性警告。 |

### 现场 1：给 record 加可变属性

**症状**：值语义被破坏，比较结果不符合预期。

**根因与修复**：保持不可变，修改时用 with 生成新实例。

**自检**：在本课示例里复现「给 record 加可变属性」，改成保持不可变，修改时用 with 生成新实例后重跑；如果症状消失且失败路径按预期变化，说明定位正确。

### 现场 2：模式匹配顺序写反

**症状**：前面的宽泛模式吞掉后面的具体分支。

**根因与修复**：从具体到宽泛排列，并做穷尽性检查。

**自检**：在本课示例里复现「模式匹配顺序写反」，改成从具体到宽泛排列，并做穷尽性检查后重跑；如果症状消失且失败路径按预期变化，说明定位正确。

### 现场 3：把 record 当实体到处传

**症状**：值语义与标识语义混淆。

**根因与修复**：值对象用 record，需要唯一标识的实体用 class。

**自检**：在本课示例里复现「把 record 当实体到处传」，改成值对象用 record，需要唯一标识的实体用 class后重跑；如果症状消失且失败路径按预期变化，说明定位正确。

### 现场 4：HashSet 里的 record 突然找不到了

**症状**：把 `Point` 放进 `HashSet` 后修改 `X`，再用同一个对象查询 `Contains` 返回 `false`。

**根因与修复**：`record` 的哈希基于字段，修改字段后哈希桶位置变了，集合按旧哈希找不到它。修复是把 `X`、`Y` 设为 init-only，修改时用 `with` 生成新对象，并重新加入集合。

### 现场 5：旧快照被 with 的新对象改坏

**症状**：用 `with` 复制订单快照后，旧快照里的商品列表也跟着变了。

**根因与修复**：`with` 是浅拷贝，两个 record 共享同一个 `List<Item>`。修复是把集合换成 `ImmutableArray<Item>`，或在复制时显式创建新集合并用嵌套 `with` 更新。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `record` | 自动生成值相等、`ToString`、`Deconstruct` 与 `with` 支持的类型。 |
| `record struct` | 值类型的 record，复制在栈上，没有继承与引用身份。 |
| `模式匹配` | 按类型、属性、位置、关系或列表结构选择分支并提取变量。 |
| `属性模式` | 用 `{ Radius: > 0 }` 形式读取属性并附加约束。 |
| `位置模式` | 调用 `Deconstruct` 按位置解构对象。 |
| `不可变` | 对象创建后状态不再改变，修改通过复制生成新实例。 |
| `init-only` | 只能在对象初始化阶段赋值的属性，之后不可修改。 |
| `with` | record 的复制表达式，生成浅拷贝并覆盖指定属性。 |
| `结构共享` | 持久化集合在复制时复用未修改的子树，降低复制成本。 |
| `穷尽性` | switch 覆盖所有可能输入；缺失分支时编译器给出 CS8509 警告。 |

**术语关系**：`record`（生成值相等与拷贝构造） → `init-only`（冻结字段） → `不可变`（状态不可原地修改） → `with`（浅拷贝生成新实例） → `模式匹配`（读取字段并分支） → 属性与位置模式（提取字段） → `record struct`（栈上值类型变体） → 结构共享与穷尽性（复制成本与分支完整性约束）。
