## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 多跳问题 | 需要串联两段以上分散证据才能回答的问题。 | 易错：多跳靠加大 top-k 就能解决，实际片段之间仍缺少连接关系。 |
| 全局归纳 | 答案依赖跨章节总体趋势而非某一段原文的问题。 | 易错：把全局问题拆成局部检索再拼接，会丢失统计性结论。 |
| GraphRAG | 抽取实体与关系构图，再对社区生成层次摘要以支持全局推理的框架。 | 易错：建图一次即可长期复用，实体漂移会让图逐渐失真。 |
| 社区摘要 | 对图上紧密相连的一簇节点与关系生成的概括文本。 | 易错：摘要由模型生成，幻觉会被固化进上层证据。 |
| RAPTOR | 递归聚类分块并生成上层摘要，形成可分层检索的摘要树。 | 易错：树越深越好，过深的摘要离原文太远，无法核查。 |
| Self-RAG | 用反思标记决定是否检索、是否采纳片段、输出是否可信。 | 易错：按需检索等于不用向量库，它仍依赖底层召回能力。 |
| 多模态检索 | 用统一嵌入空间检索图文表等异质证据并对齐到答案。 | 易错：把图片转成文字就够用，版式与图表语义会丢失。 |
| Query 改写 | 把口语问题改写为更利于检索的形式，含扩写、拆解与澄清。 | 易错：改写越多召回越全，改写会引入偏移并放大成本。 |
| Faithfulness | 答案中的论断能被检索上下文支撑的比例，度量幻觉。 | 易错：忠实度高不等于答案完整。 |

## 原理与运行机制

### 机制总览：两类失效对应两条扩展路线

基础检索的失效集中在两处：证据分散且彼此关联（多跳），以及答案需要总体概括（全局）。GraphRAG 与 RAPTOR 分别用「关系图」和「摘要层次」补足这两种能力，而 Self-RAG 改变的是「什么时候该检索」，多模态检索改变的是「证据来自什么介质」。

**教材衔接：GraphRAG 的离线索引与在线查询**

离线阶段把语料变成图与摘要，成本一次性；在线阶段按问题类型选择局部或全局模式。

```python
STEPS = [
    ('切分文本单元', '按语义块切，保留来源编号'),
    ('抽取实体与关系', '让模型输出类型化实体、关系与证据编号'),
    ('实体对齐去重', '同义与缩写合并，错误合并是最大质量杀手'),
    ('社区划分', '用图聚类算法得到层次化社区'),
    ('社区摘要', '自底向上生成，低层摘要作为高层输入'),
]

for i, (name, note) in enumerate(STEPS, start=1):
    print(i, name, note[:8])
```

**教材衔接：局部检索与全局检索的分派**

| 问题特征 | 推荐模式 | 工作原理 | 典型代价 |
| --- | --- | --- | --- |
| 某个实体的属性 | 局部检索 | 以实体为入口展开邻域与相关原文 | 建图成本一次性 |
| 两个概念之间的关系 | 局部检索 | 沿最短关系链收集证据 | 关系抽取错则链路断 |
| 整体趋势或主线 | 全局检索 | map-reduce 遍历社区摘要再汇总 | 调用量大，时延高 |
| 单点事实 | 基础向量检索 | 直接召回原文片段 | 无需建图 |

```json
{
  "entity": {"name": "供应链金融平台", "type": "PRODUCT", "evidence": ["chunk:128", "chunk:341"]},
  "relation": {"src": "供应链金融平台", "dst": "应收账款确权", "type": "DEPENDS_ON",
               "description": "确权流程是平台放款的前置条件", "evidence": ["chunk:341"]},
  "community": {"id": 7, "level": 1, "summary": "该社区围绕账期与确权风险展开……"}
}
```

**教材衔接：RAPTOR 与 Self-RAG 的机制对照**

RAPTOR 改变的是「索引形态」：把叶子块递归聚类并摘要，形成粗细并存的树，检索时可同时命中细节与概括。Self-RAG 改变的是「检索时机」：模型用反思标记判断是否需要证据、哪条证据可用、结论是否可信，从而在不需要知识的问题上省掉一整轮检索。

- 相同点：都以离线训练或离线构建为代价换取在线质量。
- 不同点：RAPTOR 属于数据结构层，可与任何检索器组合；Self-RAG 属于控制流层，需要额外的判别能力。
- 易混淆：把层次摘要树说成知识图谱，前者按语义聚类分层，后者按实体关系连边。

**教材衔接：多模态检索的证据对齐**

图像、表格与扫描件先落到统一表示空间，再在返回时保留「原媒体加文字说明」的双份证据。工程上最常见的错误是只回传识别出的文字，让模型看不到版式与图表结构。

```python
def build_evidence(item: dict) -> dict:
    return {
        'doc_id': item['doc_id'],
        'kind': item['kind'],                    # text / table / image
        'text': item['caption'] or item['ocr'],  # 检索用的文本表示
        'rendered': item.get('markdown'),        # 表格保留行列结构
        'page_image': item['page_ref'],          # 原始版面供人工核对
    }

print(build_evidence({'doc_id': 'd1', 'kind': 'table', 'caption': '',
                      'ocr': '季度毛利率', 'markdown': '| 季度 | 毛利率 |',
                      'page_ref': 'd1_p7.png'})['kind'])
```

**教材衔接：Query 改写的四种合法用法**

1. 指代消解：把多轮里的「它」还原成实体名，避免检索落空。
2. 术语归一：把口语说法映射到文档中的规范术语。
3. 问题拆解：把一个复合问题拆成若干可独立检索的子问题。
4. 反事实扩写：生成同义表达提升召回覆盖。

改写的前提是可回滚：每一步都要保留原始问题，最终生成时以原问题为准，防止改写偏差被放大成答案偏差。

## 典型应用场景

| 场景 | 典型输入或前提 | 期望产物 |
| --- | --- | --- |
| 年报趋势归纳 | 多年公告与纪要，问战略主线 | 全局社区摘要汇总加来源年份 |
| 合规条款串联 | 制度分散在多份文件，需串起前置条件 | 实体关系链加条款编号 |
| 图纸与手册问答 | 含图表的设备手册 | 图文双证据加操作步骤 |
| 客服工单聚类洞察 | 数万条短文本 | 层次摘要树加代表性样本 |

- 典型现象：全局问题用局部检索回答，答案只覆盖一两个部门。正确做法：切到全局模式，按社区摘要做 map-reduce 汇总。
- 典型现象：建图后质量反而下降。正确做法：先审实体对齐结果，错误合并会把不相关证据串在一起。
- 典型现象：忠实度满分但用户仍觉得没答到点上。正确做法：忠实度只度量有无依据，需要结合答案相关度判断切题性。

### 最小验证场景

- 准备：30 条局部事实题加 20 条全局归纳题，全部标注可接受的证据来源编号。
- 观察：基础向量、RAPTOR、GraphRAG 三种配置下，两类题各自的正确率、忠实度与平均成本。
- 判定：若全局题正确率提升超过十五个百分点而局部题无退化，则 GraphRAG 的建图成本可接受；否则优先做 Query 拆解这类便宜的改造。

## 代码/协议/SQL 示例

**教材衔接：用 RAGAS 口径组织评估数据**

评估的输入结构决定了能算出哪些指标。把问题、检索上下文与参考答案三元组固定下来，忠实度与相关度都能自动化。

```python
import json

rows = []
for q in questions:
    rows.append({
        'question': q['text'],
        'contexts': [c['text'] for c in retrieve(q['text'], top_k=5)],
        'ground_truth': q.get('answer', ''),
    })
with open('eval_set.jsonl', 'w', encoding='utf-8') as f:
    for r in rows:
        f.write(json.dumps(r, ensure_ascii=False) + '\n')
print(len(rows))
```

**教材衔接：区分检索层与生成层的失败**

按是否命中证据、是否被引用两步统计，可以一眼看出该优化检索还是该优化生成。

```sql
SELECT q_type,
       AVG(hit_evidence::int)                     AS recall_rate,
       AVG(cited::int)                            AS cite_rate,
       AVG(faithfulness)                          AS faith,
       AVG(answer_relevancy)                      AS relevancy
FROM eval_result
WHERE run_id = 'adv-rag-041'
GROUP BY q_type
ORDER BY q_type;
```

错误表现：为了提升全局题正确率，把社区摘要越写越长并全部塞进上下文。

```python
context = '\n'.join(all_community_summaries(level=1))   # 一次性塞进全部高层摘要
```

正确写法：全局模式用分批归约，先让模型对每份摘要抽取要点，再汇总，同时把摘要规模与来源数纳入成本预算。

```python
partial = [answer_from(summary) for summary in batch(summaries, size=8)]
final = merge(partial)                                    # map-reduce，可控 Token 与可追溯来源
```

## 时间/空间复杂度或性能分析

| 方案 | 离线成本 | 在线成本 | 主要收益 |
| --- | --- | --- | --- |
| 基础向量检索 | 嵌入一遍语料 | 一次近似检索加一次生成 | 时延与费用最低 |
| 混合检索加精排 | 多一份倒排索引 | 精排按候选数线性增长 | 排序质量提升 |
| RAPTOR | 递归聚类加多层摘要生成 | 跨层检索，候选数略增 | 粗细兼顾 |
| GraphRAG 局部 | 实体抽取与社区摘要，随语料量线性增长 | 图邻域展开，成本可控 | 多跳与关系题 |
| GraphRAG 全局 | 同上 | 遍历社区，调用次数与社区数成正比 | 全局归纳 |
| 多模态检索 | 图像编码与版面解析 | 检索成本接近文本 | 证据形态完整 |

GraphRAG 的成本结构决定了它不适合「高频小语料」场景：离线抽取阶段每条文本单元都要一次模型调用，语料翻倍则建图成本翻倍；而在线全局查询要把社区摘要分批喂给模型，调用次数与社区数量成正比。因此常见做法是只对确实需要全局推理的问题走该模式，其余全部回落基础检索。

评估指标本身也消耗算力。忠实度要求把答案拆成原子论断再逐条判定，一次评估的模型调用数约等于论断条数；若评估集有五百题、每题平均五条论断，一轮评估就是数千次调用。用固定随机种子和分层抽样控制成本，是进阶评估的必备工程手段。

摘要层次会带来「证据衰减」。层数越深，离原文越远，可追溯性越差；因此上层摘要必须保留来源编号，生成时优先引用低层证据，只在归纳性结论上使用高层摘要，并允许用户下钻核对原文。

## 常见误区与易错点

- **把所有问题都交给 GraphRAG。** 单点事实用图检索反而更慢更贵，还会引入抽取误差。
- **认为 top-k 调大就能解决多跳。** 片段之间缺少关系连接，堆量不会自动产生推理链。
- **忽视实体对齐。** 同名与缩写合并错误会让图传播错误证据，是建图的头号质量杀手。
- **把社区摘要当原文引用。** 摘要是模型生成物，会带幻觉，必须能下钻到原文。
- **摘要树做得过深。** 深层摘要脱离原文，既无法核查也抬高离线成本。
- **把 Self-RAG 理解成不需要向量库。** 它只决定何时检索，底层召回能力仍是前提。
- **多模态只保留 OCR 文本。** 表格行列与版面关系丢失后，答案经常错位。
- **无节制地改写查询。** 多条改写提升召回也放大偏移，必须保留原问题为锚。
- **只看忠实度下结论。** 忠实但答非所问的情况很常见，需要与相关度一起看。
- **评估集不固定就比方案。** 题目与标注一变，所有指标都失去可比性。

## 自测题与参考答案

**教材衔接：题号 1** — 用户问这家公司近三年战略变化的主线是什么，最合适的检索方式是？

**参考答案**：GraphRAG 的社区摘要自顶向下。

本题正确项是「GraphRAG 的社区摘要自顶向下」。全局性、跨章节的归纳问题需要把实体关系先聚成社区并生成层次化摘要，回答时从高层摘要往下展开，才能覆盖分散的证据。top-k 片段拼接只给局部线索，精确匹配漏掉同义表述，硬塞全文受窗口限制且成本失控，还容易让模型抓错重点。

**教材衔接：题号 2** — 评估框架里 Faithfulness 这一指标衡量的是？

**参考答案**：答案能否被检索到的上下文支撑。

本题正确项是「答案能否被检索到的上下文支撑」。忠实度把生成结果拆成若干论断，再逐条判断这些论断能否从召回上下文推出，用于量化幻觉，是 RAGAS 一类框架的核心项。简短程度属于长度偏好，检索耗时是性能指标而非质量指标，追问澄清是交互策略，都不反映答案与证据之间的支撑关系。

**教材衔接：题号 3** — RAPTOR 相对普通分块检索的主要增益来自？

**参考答案**：层次化摘要树的自顶向下召回。

本题正确项是「层次化摘要树的自顶向下召回」。RAPTOR 先对叶子分块递归聚类并生成上层摘要，检索时同时命中粗细两层，兼顾细节与全局视角，正适合跨多章节的综合问题。压缩维度只是存储优化，OCR 属于多模态数据接入，引用编号是可解释性手段，都不改变语料的层次结构。

**教材衔接：题号 4** — Self-RAG 与朴素 RAG 的关键差别是？

**参考答案**：模型自己判断是否需要检索并批判。

本题正确项是「模型自己判断是否需要检索并批判」。Self-RAG 用反思标记决定何时检索、是否采纳该片段以及输出是否可信，把检索从固定前置步骤变成按需动作，减少无关上下文带来的干扰。把检索固定前置正是朴素 RAG 的做法，向量与全文可以共存并不互斥，压缩提示词属于工程优化。

**教材衔接：题号 5** — 下面代码做查询改写后去重，print 输出是几条改写？
queries = ['退款政策', 'refund policy']
expanded = queries + [q.upper() for q in queries]
rewrite = list(dict.fromkeys(expanded))
print(len(rewrite))

**参考答案**：剩下 3 条。

本题正确项是「剩下 3 条」。expanded 先把两条原始查询和大写后的两条依次拼上共四项，但 str.upper() 对中文不生效，退款政策与其大写形式完全相同，dict.fromkeys 去重时把它折回一条，于是只剩退款政策、refund policy 和 REFUND POLICY。算成 4 是漏看去重，算成 2 是以为大写文本又与原文重合。

## 考点精讲

**教材衔接：高频考点**

1. 多跳与全局两类失效的区分，以及各自对应的结构扩展方案。
2. GraphRAG 离线建图流程中质量最脆弱的环节，实体对齐为常答点。
3. Faithfulness 与 Answer Relevancy 的度量对象差异。
4. Self-RAG 的按需检索机制与普通检索前置的区别。

**教材衔接：命题规律**

- 命题常给一个具体提问，要求选检索方案，判断依据是问题是否需要跨证据推理。
- 指标类题目喜欢制造混淆项，把耗时、成本或长度掺进质量指标里。
- 进阶方案的成本题通常考「离线一次性与在线线性关系」的差别。

**教材衔接：常见考点**

问：用户问这家公司近三年战略变化的主线是什么，最合适的检索方式是？
答：GraphRAG 的社区摘要自顶向下。

问：评估框架里 Faithfulness 这一指标衡量的是？
答：答案能否被检索到的上下文支撑。

问：RAPTOR 相对普通分块检索的主要增益来自？
答：层次化摘要树的自顶向下召回。

问：Self-RAG 与朴素 RAG 的关键差别是？
答：模型自己判断是否需要检索并批判。

问：下面代码做查询改写后去重，print 输出是几条改写？
queries = ['退款政策', 'refund policy']
expanded = queries + [q.upper() for q in queries]
rewrite = list(dict.fromkeys(expanded))
print(len(rewrite))
答：剩下 3 条。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| 多跳问题 | 需要串联两段以上分散证据才能回答的问题。 |
| 全局归纳 | 答案取决于跨章节总体趋势的问题类型。 |
| GraphRAG | 用实体关系图与社区摘要支撑多跳和全局推理的检索框架。 |
| 社区摘要 | 对图上紧耦合的一簇节点生成的概括文本，可分层引用。 |
| RAPTOR | 递归聚类并生成层次摘要树，检索时粗细兼顾。 |
| Self-RAG | 由模型自行判断是否检索、是否采信、是否可信的范式。 |
| Query 改写 | 提升召回的提问变形，必须保留原问题为锚。 |
| Faithfulness | 衡量答案论断能否被检索上下文支撑的幻觉指标。 |
