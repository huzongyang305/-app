## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| .NET | 微软的跨平台运行时与开发平台：C# 编译成 IL，由 CLR 加载并 JIT 执行。 | 先确认 SDK 版本再决定能否用新语法；升级重点在语法与裁剪行为，动手前先补一组回归用例，不可回退的改动单独拆成一次提交。 |
| System.CommandLine | .NET 的命令行解析库，用命令、选项与参数描述定义 CLI 的行为。 | 命令、选项与参数定义好后在 `SetHandler` 里接逻辑；若把业务逻辑也堆进入口，参数一变就要重写，也拆不出可测试的单元。 |
| xUnit | .NET 生态常用的单元测试框架，用事实与理论特性组织用例并输出断言结果。 | 业务逻辑堆在入口方法里就写不出可断言的用例，得先拆出服务层与仓储层才有测试单元。 |
| 参数校验 | 在命令入口检查参数组合与取值范围，不合格时给出用法提示并以非 0 退出码结束。 | 校验要落到可断言的用例上：超量出库必须失败、未知命令返回非零码并提示帮助；退出码为 0 或错误被静默吞掉说明校验没生效。 |
| SQLite | 单文件嵌入式关系数据库，无需独立服务进程，通过 C API 直接读写，适合本地存储 | 易错：以为单文件库没有并发问题——写入会被 SQLite 写锁串行化，压测延迟抬高要先分清锁等待还是分配速率上升，超上限再建索引。 |

### 复盘模板

- **业务逻辑写在入口方法里**：典型现象是无法单元测试，参数一变就要重写；正确做法是拆出服务层与仓储层，入口只负责参数解析与输出。
- **文件读写不考虑并发与损坏**：典型现象是多个实例同时写会丢数据；正确做法是先写临时文件再原子重命名，并加文件锁。
- **异常直接终止进程**：典型现象是用户看不到可操作的信息；正确做法是入口统一捕获，输出可读错误并返回非零退出码。
