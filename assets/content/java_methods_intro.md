## 本节知识框架

前几课你写了所有代码都挤在 `main` 方法里。但真实程序不可能把所有逻辑都塞在一个方法里——就像一家餐厅不可能让一个服务员同时当厨师、收银员、清洁工。你需要把不同的任务拆给不同的「工人」，在 Java 里这些工人就是**方法**。

方法是把一段逻辑打包起来，取个名字，需要的时候就调用它。方法可以接收参数（输入），也可以返回结果（输出）。这就像一台榨汁机：你塞进去水果（参数），它给你一杯果汁（返回值）。

**学完这一课，你会**：
- 知道怎么定义一个方法、传参数、拿返回值
- 理解 Java 的参数传递方式（一律按值传递）
- 避开「重载方法签名过于相似」「void 方法用 return 提前退出」这些常见陷阱

**先修**：《Java 循环入门》。**后续**：后续课程会大量使用方法。

### 复习清单

- [ ] 能不看正文写出 `static int add(int a, int b) { return a + b; }` 的方法定义。
- [ ] 能解释 Java 的参数传递是「按值传递」还是「按引用传递」。
- [ ] 能说出 `void` 方法中 `return;` 的作用。

## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| `方法签名` | 方法名加参数列表共同构成签名，是重载区分的依据。 |
| `参数与返回值` | 参数是输入，return 把结果交回调用方，类型必须匹配。 |
| `void` | 表示方法不返回任何值。 |
| `方法重载` | 同一个类里同名方法通过参数列表不同来区分。 |
| `访问修饰符` | public 对外可见，private 只在本类内可见，用来约束调用范围。 |
| `JVM` | Java 源码编译成平台无关的字节码，JVM 负责加载、验证、解释和即时编译。 |
| `形参 / 实参` | 声明里写的是形参（占位），调用点传的是实参（真实值），二者数量与类型必须对得上。 |
| `静态方法 / 实例方法` | `static` 方法属于类本身、直接由类名调用；实例方法需要先有对象，通过引用调用。 |
| `可变参数` | 形参写成 `String... args`，方法体里当作数组处理，同一个位置只能出现一次。 |
| `栈帧` | 每次方法调用在 JVM 调用栈上分配的一小块内存，存放局部变量、参数与返回地址。 |

## 原理与运行机制

### 方法就像一台机器

方法接收输入（参数），执行一段逻辑，交出结果（返回值）。

```java
static int square(int n) {
    return n * n;
}
```

- `static`：属于类本身，不需要创建对象就能调用
- `int`：返回值类型
- `square`：方法名
- `(int n)`：参数列表，n 是形参
- `return n * n;`：计算结果并返回

调用时传入实参：`square(7)` 返回 49。

### 参数传递：一律按值

Java 的参数传递永远是对值的拷贝：

- **基本类型**：拷贝值本身。方法里改参数不影响调用方的变量。
- **对象引用**：拷贝的是引用的副本。方法里可以通过引用修改对象内容，但不能让调用方的引用指向新对象。

```java
static void tryChange(int x) {
    x = 100;  // 只改了副本，调用方的变量不受影响
}

static void modifyArray(int[] arr) {
    arr[0] = 999;  // 通过引用副本修改了同一个对象的内容
}
```

### void 方法：不需要返回值

有些方法只是执行一个动作，不需要返回结果。用 `void` 声明：

```java
static void greet(String name) {
    System.out.println("你好，" + name + "！");
}
```

void 方法里也可以用 `return;` 提前退出——它不返回任何值，只是立即结束方法执行，把控制权交回调用方。

### 方法重载

同一个类里可以有多个同名方法，只要参数列表不同：

```java
static int add(int a, int b) { return a + b; }
static double add(double a, double b) { return a + b; }
static int add(int a, int b, int c) { return a + b + c; }
```

方法签名 = 方法名 + 参数列表。返回类型不参与签名区分——只改返回类型不算重载，算重复定义。

### 访问修饰符

- `public`：任何地方都能调用
- `private`：只有本类内部能调用
- 不写（包级私有）：同一个包内能调用

封装的核心思想：对外暴露尽量少的接口，把实现细节藏起来。

### 一次方法调用在 JVM 栈上做了什么

调用 `int r = square(7);` 大致发生五件事：

1. 在调用栈顶端压入一个新的**栈帧**，为参数 `n` 和局部变量预留空间。
2. 把实参 `7` **拷贝**到形参 `n` 的位置（基本类型拷值，引用类型拷引用的副本）。
3. 跳转到 `square` 的字节码入口开始执行。
4. 遇到 `return n * n;` 时，把结果放到操作数栈上，同时把栈帧弹出。
5. 回到调用点，把返回值弹出赋给 `r`。

整个过程与"复印一份文件递过去"很像：原件留在调用方，副本进了被调用方；被调用方在副本上写写画画，原件不受影响。这条心智模型能解释为什么 Java 是"一律按值传递"——传的都是拷贝，只是拷贝的对象可能是"引用"这一种特殊值。

### "传引用的副本"到底能改什么

Java 面试常考的一点：对象参数是引用的**副本**，不是引用本身。副本和被调用方仍然指向堆上同一个对象，所以：

- 能通过副本修改对象内容（`arr[0] = 999;` 会改到调用方那个数组）。
- 不能通过副本让调用方的引用指向新对象（`arr = new int[3];` 只影响本地副本，出了方法就作废）。

经典的 swap 陷阱：

```java
static void badSwap(int[] a, int[] b) {
    int[] tmp = a; a = b; b = tmp;  // 只换了两个本地副本，外面看不到
}

static void goodSwap(int[] pair) {
    int tmp = pair[0]; pair[0] = pair[1]; pair[1] = tmp;  // 改的是同一对象的内容
}
```

想把一个引用换成新对象，只能把新对象作为**返回值**给出去，或者把它装进一个可变容器（`AtomicReference`、单元素数组、包装类）传进去。这一条与"修改传入的可变对象"是同一枚硬币的两面：能改，但要清楚改的是内容而不是引用。

### 可变参数与常见误用

```java
static int max(int first, int... rest) {
    int best = first;
    for (int x : rest) if (x > best) best = x;
    return best;
}

// 调用形式都合法：
// max(1)              → rest 是长度为 0 的数组
// max(1, 2, 3, 4)     → rest 是 [2,3,4]
// max(1, new int[]{2,3}) → 传整块数组
```

限制：一个方法最多只能有一个可变参数，且必须放在参数列表最后；否则编译器无法判定"哪些实参归 varargs"。可变参数每次调用都会隐式分配一个数组，在热点路径里频繁调用时可以用显式重载替代，避免小对象带来的 GC 压力。

### 返回多个结果的三种做法

`return` 一次只能交回一个值，遇到"既要平均值又要最大值"这类需求有三条常用路：

1. **返回一个数组**：`int[] result = {max, min};`——快糙，但调用方要看注释才知道每个下标含义。
2. **返回一个小对象/记录**：Java 16+ 用 `record Stat(int max, int min) {}`，字段自带名字，可读性最好。
3. **用输出参数**：把 `int[] out = new int[2]` 传进去让方法填——Java 里不推荐，容易破坏"输入输出边界"，一般只在跟原生代码桥接时才见得到。

入门阶段优先选记录或简单包装类，让方法签名本身就把"我要交回什么"写清楚；把"结果藏在参数里"的写法留给性能极端敏感的场景。

### 递归方法的三要素

递归本质仍是方法调用，只不过调用者是它自己。任何递归都要显式回答三件事：

- **终止条件**：什么时候直接给出答案、不再往下调？
- **规模缩小**：每一次调用问题规模是否真的变小、朝终止条件靠近？
- **组合规则**：如何把子问题的结果组合成当前层的答案？

```java
static long factorial(int n) {
    if (n < 0)  return -1;         // 失败路径：负数返回哨兵
    if (n <= 1) return 1;          // 终止条件
    return n * factorial(n - 1);   // 规模缩小 + 组合
}
```

三条里少写任何一条，编译器都不会拦你，但轻则结果错、重则 StackOverflowError。写递归时先在纸面列出这三行，再动键盘，比事后 debug 快得多。

## 典型应用场景

### 场景一：定义并调用一个简单方法

```java
public class Main {
    static int square(int n) {
        return n * n;
    }

    public static void main(String[] args) {
        System.out.println("square(7)=" + square(7));
    }
}
```

### 场景二：带多个参数的方法

```java
public class Main {
    static double average(double a, double b, double c) {
        return (a + b + c) / 3;
    }

    public static void main(String[] args) {
        System.out.printf("平均分：%.1f%n", average(85, 92, 78));
    }
}
```

### 场景三：void 方法提前退出

```java
public class Main {
    static void printPositive(int n) {
        if (n <= 0) {
            return;  // 立即退出，不打印
        }
        System.out.println("正数：" + n);
    }

    public static void main(String[] args) {
        printPositive(5);   // 输出：正数：5
        printPositive(-3);  // 什么都不输出
    }
}
```

### 场景四：把校验与业务分开

```java
public class Main {
    static boolean isValidAmount(double amount) {
        return !Double.isNaN(amount) && amount > 0 && amount <= 1_000_000;
    }

    static double withdraw(double balance, double amount) {
        if (!isValidAmount(amount)) return -1;      // 失败路径：非法金额
        if (amount > balance)   return -2;          // 失败路径：余额不足
        return balance - amount;
    }

    public static void main(String[] args) {
        System.out.println("withdraw(100, 30) = " + withdraw(100, 30));   // 70
        System.out.println("withdraw(100, 200) = " + withdraw(100, 200)); // -2
        System.out.println("withdraw(100, -5) = " + withdraw(100, -5));   // -1
    }
}
```

把校验抽成 `isValidAmount` 而不是塞进 `withdraw` 里，好处是：单测时可以直接针对校验函数的边界（NaN、0、负数、超大值）跑一遍，不用先把余额准备好；业务函数只需要处理"金额已经合法"的世界，条件嵌套少一层。

### 场景五：私有辅助方法收敛细节

对外只暴露一个 `formatReport`，内部靠几个 `private static` 方法拼出结果：

```java
public class Report {
    public static String formatReport(int[] scores) {
        StringBuilder sb = new StringBuilder();
        sb.append(header(scores.length));
        sb.append(body(scores));
        sb.append(footer(average(scores)));
        return sb.toString();
    }

    private static String header(int n) { return "共 " + n + " 条:\n"; }
    private static String body(int[] arr) {
        StringBuilder sb = new StringBuilder();
        for (int v : arr) sb.append(v).append('\n');
        return sb.toString();
    }
    private static String footer(double avg) { return String.format("平均 %.1f\n", avg); }
    private static double average(int[] arr) {
        if (arr.length == 0) return 0;   // 空数组边界
        int s = 0; for (int v : arr) s += v;
        return (double) s / arr.length;
    }
}
```

每条 `private static` 都只做一件事，测试时可以用 `Report.formatReport(new int[]{})` 直接跑空数组这一档，也可以单独调 `average` 验证边界；对外接口仍然只有一个方法名——这就是"按单一职责拆分"的最小可行示范。

### 动手练一练

按下面的顺序自己实现一遍，每一步都用 `main` 打印调用结果，把"正常 / 边界 / 失败"三条路径都覆盖：

1. `static int clamp(int v, int lo, int hi)`：把 `v` 夹在 `[lo, hi]` 内；`lo > hi` 时抛 `IllegalArgumentException`。
2. `static String maskPhone(String s)`：把 11 位手机号中间 4 位替换成 `****`；`s` 为 null 或长度不对时返回原值。

写完再回来看：参数是不是最少必要？返回类型能否让调用方一眼看懂"失败"长什么样？有没有哪一条边界只写了 `if` 但没测过？三个问题都能答上来，才算把方法签名与调用约定吃透。

## 时间/空间复杂度或性能分析

方法调用本身的开销非常小——只是压栈、跳转、出栈。但有几个值得注意的点：

- **递归深度**：每次递归调用都会在栈上分配一帧。递归太深会导致 `StackOverflowError`。一般几千层就会出问题。
- **方法内创建对象**：如果方法每次调用都创建大量临时对象，GC 压力会增大。
- **JIT 内联**：JVM 会自动把短小的方法内联到调用处，消除调用开销。所以不用刻意为了避免调用开销而把代码写在一起。

测量方法：固定输入跑一遍记录基线，再提高规模复测，两次结果的差值才是结论依据。

### 栈帧与递归深度

每次方法调用都会压一帧栈，帧里装参数、局部变量、返回地址等。栈深是有限制的，`-Xss` 默认在多数 JVM 上是 512KB 到 1MB。粗算每帧几十到几百字节，能撑住大约几千到几万层递归；一旦超过就抛 `StackOverflowError`。写递归时如果预估深度会到千级，就要考虑改写成显式栈或循环，别指望把 `-Xss` 加大当万能药。

### 传大对象与传引用副本

Java 传对象时拷贝的只是引用（一般 4 或 8 字节），对象本体没有复制。因此 `void f(List<Integer> big)` 不会因为参数大就慢。**真正慢的是在方法里对参数做深拷贝**（例如 `new ArrayList<>(big)`），这时才付出 O(n) 代价。需要"只读语义"就复制；不需要就把引用直接传进去，但要在文档或方法名里明确"这个方法会改传入的集合"。

### 方法多小算小

JVM 的 JIT 会自动内联短小方法（HotSpot 默认阈值大致对应字节码 35 左右），把调用开销摊平。所以不用为了避免调用开销而刻意把逻辑堆成一个 200 行的方法——内联后没有额外代价，可读性反而更好。真正需要担心调用开销的只有两种：递归太深导致栈溢出，以及虚方法在多层继承里频繁分派。

## 常见误区与易错点

| 容易写错的做法 | 实际现象 | 原因与正确做法 |
| --- | --- | --- |
| 重载方法签名过于相似 | 调用被解析到意外的方法。 | 控制重载数量，让参数差异足够明确。 |
| 修改传入的可变对象 | 调用方状态被意外改变。 | 需要只读语义时复制或使用不可变对象。 |
| 一个方法承担多项职责 | 难测试也难复用。 | 按单一职责拆分方法。 |
| 只改返回类型想造重载 | 编译报"重复定义"。 | 重载必须参数列表不同；返回类型不参与签名。 |
| 在 `static` 方法里访问实例字段 | 编译期就报错。 | 需要 `this` 就把方法改成实例方法，或传入对象参数。 |
| 可变参数放在非末位 | 编译报"The last parameter must be an array type"。 | 一个方法最多一个可变参数，且必须在最后一位。 |

### 误区一：把方法写在 main 里面

Java 不支持嵌套方法定义。所有方法都必须写在类里面、其他方法外面。

### 误区二：以为方法能修改基本类型参数

传进去的是值的副本，改副本不影响调用方的变量。

### 误区三：重载只看返回类型

重载必须参数列表不同。只改返回类型编译器会报重复定义错误。

### 误区四：以为 Java 能像 C++ 那样传引用

C++ 里 `void f(int& x)` 真能改到调用方的 `x`。Java 没有对应语法——`void f(int x)` 里的 `x` 只是值的副本，`void f(Integer x)` 里的 `x` 是引用副本；两者都不能让调用方的变量指向新对象。想在方法里"带回"一个整数结果，唯一干净的做法是把它作为返回值给出，或者用 `int[] out = new int[1]` 之类的容器绕一步。

### 误区五：重载被自动装箱抢走

同时定义 `f(int)` 和 `f(Integer)`，调用 `f(5)` 会走 `int` 版（精确匹配优先）；调用 `f(nullRef)` 会走 `Integer` 版；调用 `f(5L)` 会先把 `long` 试着塞进 `int` 又塞进 `Integer`，最终编译报错。经验：**基本类型与它的包装类型不要放进同一组重载**，让调用点一眼看穿会走哪个方法；确需同时存在时用不同的方法名（`parseInt` / `parseOrNull`）而不是靠装箱语义区分。

### 概念地图

```text
方法签名（方法名 + 参数列表）
  └─ 参数与返回值（输入 → return → 输出）
       └─ void（不返回值）
            └─ 方法重载（同名不同参）
                 └─ 访问修饰符（控制可见范围）
```

### 方法入门与面向对象

本课只讲 `static` 方法——它属于类，调用点是 `类名.方法名`。到《类与对象》会引入**实例方法**：先 `new` 一个对象，再 `obj.method(...)`，此时隐含的 `this` 就是那个对象引用。同一份"形参/实参/返回值"的规则在两种方法里都成立，区别只是第一个隐藏参数是不是 `this`。

### 方法入门与泛型

`static <T> T firstOrDefault(List<T> list, T fallback)` 里的 `<T>` 是**方法级类型参数**——签名前多了一项"参数列表"，也是方法签名的组成部分。到《泛型》一课会详细讨论类型擦除如何让签名变成 `List` 与 `Object`；先把方法签名 = 方法名 + 参数类型列表这条记住。

### 方法入门与异常

本课的 `withdraw` 用返回码 `-1 / -2` 表示失败。到《异常处理》会看到另一种约定：`throws InsufficientFundsException`，让失败通过栈回溯到调用方。两条路各有取舍——返回值简单直观、类型安全；异常能把错误路径从主流程里剥离出去。入门阶段先用返回值把方法练熟，再引入异常，能少踩"吞异常"这种大坑。

## 自测题与参考答案

### 自测 1

**问**：方法签名由什么组成？

**答**：方法名加参数列表共同构成签名，是重载区分的依据。返回类型不是签名的一部分。

### 自测 2

**问**：Java 方法的参数传递方式是？

**答**：一律按值传递，对象传递的是引用的副本。基本类型传值的副本，对象传引用的副本。

### 自测 3

**问**：`void` 方法中 `return;` 的作用是什么？

**答**：立即结束方法执行，把控制权交回调用方。不返回任何值。

### 自测 4

**问**：为什么不能只靠返回类型来区分重载方法？

**答**：因为方法签名只包含方法名和参数列表。编译器在调用时根据实参类型选择方法，返回类型不参与选择。

### 自测 5

**问**：`static` 方法有什么限制？

**答**：static 方法不能直接访问实例字段和实例方法，因为它不依赖于任何对象实例。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| `方法签名` | 方法名加参数列表共同构成签名，是重载区分的依据。 |
| `参数与返回值` | 参数是输入，return 把结果交回调用方，类型必须匹配。 |
| `void` | 表示方法不返回任何值。 |
| `方法重载` | 同一个类里同名方法通过参数列表不同来区分。 |
| `访问修饰符` | public 对外可见，private 只在本类内可见，用来约束调用范围。 |
| `JVM` | Java 源码编译成平台无关的字节码，JVM 负责加载、验证、解释和即时编译。 |
| `形参 / 实参` | 声明里的占位与调用点传的真实值，数量与类型要对齐。 |
| `栈帧` | 每次方法调用在 JVM 调用栈上分配的一小块内存。 |
| `可变参数` | 形参写成 `String... args`，方法体里当作数组处理，且必须放最后一位。 |
| `静态方法 / 实例方法` | 是否绑定 `this`，决定它属于类还是属于对象。 |
| `返回类型协变` | 子类重写方法时，返回类型可以是父类返回类型的子类型。 |
