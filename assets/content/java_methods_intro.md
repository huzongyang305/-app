## Java 基础机制速览

### JDK、JVM 与字节码

Java 源码编译成平台无关的字节码，JVM 负责加载、验证、解释和即时编译。JDK 包含编译器和工具，JRE 只包含运行环境。类加载器按委托模型加载类，`main` 方法是程序入口。理解编译期与运行期的区别，能定位“编译通过但运行时找不到类”和“类型擦除导致的行为差异”。

### 类、对象与静态成员

类是对象的模板，对象保存实例字段，方法定义行为。`static` 成员属于类而不是实例，静态方法不能直接访问实例字段。构造器初始化对象，`this` 指向当前实例，`super` 调用父类成员。封装通过访问修饰符实现，继承表达“是一个”，组合表达“有一个”；优先使用组合降低耦合。`equals`、`hashCode` 和 `toString` 要根据值语义一致地重写。

### 类型、装箱与字符串

Java 有基本类型和引用类型，泛型不能直接使用基本类型，需要装箱成包装类。自动装箱方便但会增加对象分配，比较包装类应使用 `equals` 而不是 `==`。字符串不可变，拼接会产生新对象，循环中应使用 `StringBuilder`。`final` 表示引用不可重新赋值，不代表对象内容不可变。

### 集合、泛型与函数式接口

`List`、`Set`、`Map` 是集合接口，`ArrayList`、`HashSet`、`HashMap` 是常见实现。泛型在编译期提供类型检查，运行时发生类型擦除，因此不能创建泛型数组，也不能依赖运行时泛型信息。Stream 提供声明式的筛选、映射和聚合，但要注意惰性、短路和并行流的线程安全。Lambda 和函数式接口让行为可以作为参数传递。

### 异常、资源与并发

受检异常必须在签名中声明或捕获，非受检异常通常表示编程错误。`try-with-resources` 自动关闭实现 AutoCloseable 的资源。线程共享堆内存，必须使用同步、锁、原子类或并发集合保护共享状态；线程池避免频繁创建线程，但要合理设置队列、拒绝策略和超时。虚拟线程降低了高并发 I/O 的线程成本，但不会自动消除数据竞争。

## 故障现场

### 现场 1：重载方法签名过于相似

**症状**：在《Java 方法入门》的复现场景中，调用被解析到意外的方法。

**根因**：当出现“重载方法签名过于相似”时，执行路径已经绕过了《Java 方法入门》的关键约束，最终以“调用被解析到意外的方法”暴露出来；修复前必须先确认约束在哪里失效。

**修复**：针对《Java 方法入门》的问题，控制重载数量，让参数差异足够明确。

**验证**：在《Java 方法入门》中按“控制重载数量，让参数差异足够明确”调整后，从“重载方法签名过于相似”的触发条件重放同一条路径，确认“调用被解析到意外的方法”不再出现，并补一个相邻边界用例检查没有引入新问题。

### 现场 2：修改传入的可变对象

**症状**：在《Java 方法入门》的复现场景中，调用方状态被意外改变。

**根因**：触发点是把“修改传入的可变对象”当成安全做法。它没有满足《Java 方法入门》要求的前提，因此先表现为“调用方状态被意外改变”；排查时先完整复现这一段，再核对输入、配置与依赖。

**修复**：针对《Java 方法入门》的问题，需要只读语义时复制或使用不可变对象。

**验证**：先在《Java 方法入门》中记录“修改传入的可变对象”留下的失败证据，再执行“需要只读语义时复制或使用不可变对象”并重放；确认错误路径变为明确结果，且修复没有掩盖同类故障。

### 现场 3：一个方法承担多项职责

**症状**：在《Java 方法入门》的复现场景中，难测试也难复用。

**根因**：“难测试也难复用”只是表层结果。向上追溯会落到“一个方法承担多项职责”这一步，因为它省略了《Java 方法入门》的约束，使实现行为和预期模型发生了偏离。

**修复**：针对《Java 方法入门》的问题，按单一职责拆分方法。

**验证**：先在《Java 方法入门》中记录“一个方法承担多项职责”留下的失败证据，再执行“按单一职责拆分方法”并重放；确认错误路径变为明确结果，且修复没有掩盖同类故障。
