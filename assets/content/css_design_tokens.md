## 原理与运行机制

### 机制总览

**教材衔接：什么是设计令牌**

设计令牌（Design Token）是把颜色、间距、字号、圆角、阴影等**设计决策**抽成命名变量，让设计与代码共享同一套事实来源。它的价值不是「少写几行 CSS」，而是：改一处、全站一致、可被工具校验。

**教材衔接：命名约定速查**

| 类别 | 命名模式 | 示例 |
| --- | --- | --- |
| 颜色 | `--color-{用途}` | `--color-danger` |
| 背景 | `--color-surface` / `--color-bg` | `--color-bg-raised` |
| 间距 | `--space-{刻度}` | `--space-4` |
| 字号 | `--font-size-{尺寸}` | `--font-size-lg` |
| 圆角 | `--radius-{尺寸}` | `--radius-md` |
| 层级 | `--z-{用途}` | `--z-modal`、`--z-toast` |
| 动效 | `--duration-{速度}` / `--ease-{类型}` | `--duration-fast` |

**教材衔接：与设计工具协作**

设计侧与代码侧共享同一份令牌 JSON，构建时生成 CSS 变量与多端常量（如 Flutter、Android、iOS），避免「设计稿改了、代码没跟上」。

```python
import json

TOKENS = {
    "color": {
        "primary": "#2563eb",
        "surface": "#ffffff",
        "text": "#0f172a",
    },
    "space": {"sm": "0.5rem", "md": "1rem", "lg": "1.5rem"},
    "radius": {"sm": "4px", "md": "8px"},
}

def flatten(prefix: str, node: dict) -> list:
    """把嵌套令牌拍平成 CSS 变量列表，便于生成样式表。"""
    items = []
    for key, value in node.items():
        name = f"{prefix}-{key}" if prefix else key
        if isinstance(value, dict):
            items.extend(flatten(name, value))
        else:
            items.append((name, value))
    return items

def to_css(tokens: dict) -> str:
    lines = [":root {"]
    for name, value in flatten("", tokens):
        lines.append(f"  --{name}: {value};")
    lines.append("}")
    return "\n".join(lines)

def validate_contrast(foreground: str, background: str) -> float:
    """对比度检查：正文需达到 4.5:1，大字号需 3:1。"""
    def luminance(hex_color: str) -> float:
        raw = hex_color.lstrip("#")
        channels = [int(raw[i:i + 2], 16) / 255 for i in (0, 2, 4)]
        adjusted = [(c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4)
                    for c in channels]
        return 0.2126 * adjusted[0] + 0.7152 * adjusted[1] + 0.0722 * adjusted[2]

    l1, l2 = luminance(foreground), luminance(background)
    lighter, darker = max(l1, l2), min(l1, l2)
    return round((lighter + 0.05) / (darker + 0.05), 2)

print(to_css(TOKENS).splitlines()[1])
print(validate_contrast("#0f172a", "#ffffff"), validate_contrast("#94a3b8", "#ffffff"))
```

## 典型应用场景

- **组件里写死颜色值**：典型现象是换主题要改几十个文件；正确做法是组件只引用语义令牌。
- **只有原始令牌没有语义层**：典型现象是深色模式要逐条覆盖；正确做法是增加语义层做映射。
- **令牌命名按外观（`--blue`）**：典型现象是换品牌色后名字含义错乱；正确做法是按用途命名（`--color-primary`）。
- **令牌层级混用**：典型现象是组件直接引用原始令牌；正确做法是约定「组件只引用语义令牌」。

- **判断依据**：这道题落在术语 `原始令牌` 上：与业务无关的基础色阶和尺寸刻度，只描述可用的原始值。复习时把 `原始令牌` 的定义、适用边界和一个反例一起说清楚，再回到「核心概念定义」核对原文。

### 考点 7：`设计令牌`

- **要点**：把颜色、间距、字体等设计决策命名为可复用变量的系统。
- **设计令牌 的边界**：只在「把颜色、间距、字体等设计决策命名为可复用变量的系统」这一前提下成立，换输入或换环境要重新验证。

### 考点 8：`原始令牌`

- **要点**：与业务无关的基础色阶和尺寸刻度，只描述可用的原始值。
- **原始令牌 的边界**：易错：深色模式要逐条覆盖；正确做法是增加语义层做映射。

### 考点 9：`语义令牌`

- **要点**：表达用途的令牌，如主色或表面色，主题切换时映射到不同原始令牌。
- **语义令牌 的边界**：易错：换主题要改几十个文件；正确做法是组件只引用语义令牌。

### 考点 10：`组件令牌`

- **要点**：只服务某个组件内部结构的变量，如按钮内边距或卡片圆角。
- **组件令牌 的边界**：只在「只服务某个组件内部结构的变量，如按钮内边距或卡片圆角」这一前提下成立，换输入或换环境要重新验证。

### 考点 11：排错——组件里写死颜色值

- **现象**：换主题要改几十个文件。
- **处理**：组件只引用语义令牌。

### 考点 12：排错——只有原始令牌没有语义层

- **现象**：深色模式要逐条覆盖。
- **处理**：增加语义层做映射。

### 考点 13：综合辨析——`设计令牌` 与 `组件令牌`

- **辨析点**：`设计令牌` 的定义是 把颜色、间距、字体等设计决策命名为可复用变量的系统；`组件令牌` 的定义是 只服务某个组件内部结构的变量，如按钮内边距或卡片圆角。
- **答题要求**：面对 `设计令牌与样式架构` 的题目，先判断描述的是 `设计令牌` 还是 `组件令牌`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 14：排错评分点

- **现象分**：能写出 换主题要改几十个文件，而不是只写“程序有错”。
- **证据分**：保留触发 组件里写死颜色值 的输入、版本和错误原文。
- **修复分**：按 组件只引用语义令牌 只改一处，并同时回归正常路径与边界路径。
