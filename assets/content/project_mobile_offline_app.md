## 原理与运行机制

### 机制总览

**教材衔接：需求与约束**

| 维度 | 约束 |
| --- | --- |
| 离线 | 除首次初始化外，核心查看、创建和编辑流程无网可用 |
| 一致性 | 同一操作重复提交不产生重复数据，冲突有确定的合并规则 |
| 性能 | 冷启动首帧小于 1.5 秒，常用列表滚动保持流畅 |
| 隐私 | 本地敏感字段加密，日志不记录令牌和用户正文 |

**教材衔接：架构与数据流**

界面层只调用仓库接口，仓库同时写入本地数据库和同步队列；同步器在具备网络时按批次上传，使用操作标识保证幂等，并把服务端版本与本地版本合并后回写；诊断模块记录同步状态和性能采样。

```text
UI -> repository -> local db + outbox
                         |
                  sync worker -> API
                         |
                  merge/retry -> UI state
```

**教材衔接：实施步骤**

### 里程碑 1：先把本地主链路跑通

设计任务、标签和待同步操作表，使用客户端标识创建记录；在飞行模式下完成增删改查，并确认重启应用后数据仍存在。

### 里程碑 2：实现可靠同步

为每个操作生成唯一标识和重试次数，上传成功后按条件删除队列项；模拟超时、重复响应和进程终止，验证服务端最终只得到一次业务效果。

### 里程碑 3：处理冲突与性能验收

给记录增加版本或更新时间，定义字段级合并规则；用性能工具检查冷启动、滚动帧、内存和包体积，异常时保留采样报告再优化。

- 用数据库加密和密钥轮换保护敏感数据

## 典型应用场景

- 离线数据模型与仓库接口
- 待同步队列和冲突规则
- 断网、重试与进程中断集成测试
- 性能采样、发布包和体积报告

- **判断依据**：这道题检验本课主问题：用 Flutter 构建离线可用、冲突可合并、弱网可恢复的移动应用，并完成性能与发布验证。复习时先复述本课主问题，再举一个会让结论失效的输入。

### 考点 6：`Flutter`

- **要点**：用 Dart 编写、自带渲染引擎绘制界面的跨平台 UI 框架。
- **Flutter 的边界**：只在「用 Dart 编写、自带渲染引擎绘制界面的跨平台 UI 框架」这一前提下成立，换输入或换环境要重新验证。

### 考点 7：`离线优先`

- **要点**：默认本地可读写、联网只做同步，把网络当成可能失败的增强而不是前提。
- **离线优先 的边界**：网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。

### 考点 8：`本地数据库`

- **要点**：设备上的结构化存储（如 sqflite、Drift），承担离线数据、索引与待同步队列。
- **本地数据库 的边界**：索引命中与数据分布决定实际开销，判断前先看执行计划而不是只看结果是否正确。

### 考点 9：`同步`

- **要点**：把本地改动与远端合并的流程，要有重试、幂等与断点续传。
- **同步 的边界**：只在「把本地改动与远端合并的流程，要有重试、幂等与断点续传」这一前提下成立，换输入或换环境要重新验证。

### 考点 10：`冲突处理`

- **要点**：两端修改同一份数据时的裁决规则，常见有最后写入优先、版本向量与人工合并。
- **冲突处理 的边界**：不同版本与依赖组合的行为可能不同，升级或换环境前要按官方变更说明重新验证。

### 考点 11：`移动性能`

- **要点**：关注启动时间、帧率、内存与耗电，先测量再优化，避免在主线程做重活。
- **移动性能 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 12：排错——恢复网络后出现重复任务

- **现象**：恢复网络后出现重复任务。
- **处理**：为操作与创建请求使用稳定唯一标识，服务端按标识去重，客户端只删除确认成功的队列项。

### 考点 13：排错——离线修改覆盖了服务端更新

- **现象**：离线修改覆盖了服务端更新。
- **处理**：保留版本与更新时间，按字段合并并记录冲突；无法自动解决时让用户选择，不能静默丢弃数据。

### 考点 14：综合辨析——`Flutter` 与 `移动性能`

- **辨析点**：`Flutter` 的定义是 用 Dart 编写、自带渲染引擎绘制界面的跨平台 UI 框架；`移动性能` 的定义是 关注启动时间、帧率、内存与耗电，先测量再优化，避免在主线程做重活。
- **答题要求**：面对 `移动端离线优先 App 实战` 的题目，先判断描述的是 `Flutter` 还是 `移动性能`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 15：排错评分点

- **现象分**：能写出 恢复网络后出现重复任务，而不是只写“程序有错”。
- **证据分**：保留触发 恢复网络后出现重复任务 的输入、版本和错误原文。
- **修复分**：按 为操作与创建请求使用稳定唯一标识，服务端按标识去重，客户端只删除确认成功的队列项 只改一处，并同时回归正常路径与边界路径。
