### 最小可验证示例

```java
// 方式一：实现 Runnable（推荐，组合优于继承）

Thread thread = new Thread(task);

```

**教材衔接：创建线程**

**教材衔接：共享状态与同步**

```java
class Counter {
    private int count = 0;

    public synchronized void increase() { count++; }   // 方法级同步

    public int get() { return count; }
}

// 显式锁
private final ReentrantLock lock = new ReentrantLock();
public void increase2() {
    lock.lock();
    try { count++; } finally { lock.unlock(); }
}
```

`volatile` 保证可见性与有序性，但**不保证原子性**，`count++` 仍需加锁或改用 `AtomicInteger`。

```java
private final AtomicInteger atomicCount = new AtomicInteger();
atomicCount.incrementAndGet();
```

**教材衔接：CompletableFuture 组合异步任务**

```java
CompletableFuture<String> future = CompletableFuture
        .supplyAsync(() -> "结果")
        .thenApply(String::toUpperCase)
        .thenCompose(s -> CompletableFuture.completedFuture(s + "!"))
        .exceptionally(e -> "失败：" + e.getMessage());

System.out.println(future.join());
```

**教材衔接：虚拟线程（Java 21+）**

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> {
            Thread.sleep(1000);          // 阻塞不再是问题：虚拟线程自动让出载体线程
            return null;
        });
    }
}
```

虚拟线程极轻量，适合高并发 IO 场景，不需要再为了吞吐写复杂的异步回调。

## 时间/空间复杂度或性能分析

| 需求 | 推荐工具 | 说明 |
| --- | --- | --- |
| 简单互斥 | `synchronized` | 语法内置，自动释放 |
| 需要超时 / 可中断 / 公平 | `ReentrantLock` | 记得在 `finally` 中 `unlock()` |
| 读多写少 | `ReentrantReadWriteLock` | 读并发，写互斥 |
| 原子计数 | `AtomicInteger` / `LongAdder` | 高并发下 `LongAdder` 吞吐更好 |
| 线程安全 Map | `ConcurrentHashMap` | 用 `computeIfAbsent` 做原子初始化 |
| 任务执行 | `ThreadPoolExecutor` | 明确核心数、队列与拒绝策略 |
| 定时任务 | `ScheduledExecutorService` | 别用 `Timer`（单线程、异常即终止） |
| 结果聚合 | `CompletableFuture` | 组合多个异步任务 |
| 线程间协作 | `CountDownLatch` / `CyclicBarrier` | 一等一等多、循环复用 |
| 限流 | `Semaphore` | 控制同时访问的线程数 |

| 参数 | 含义 | 设置建议 |
| --- | --- | --- |
| `corePoolSize` | 常驻线程数 | 按 QPS 与单任务耗时估算 |
| `maximumPoolSize` | 最大线程数 | CPU 密集 ≈ 核数；IO 密集可放大 |
| `keepAliveTime` | 空闲回收时间 | 结合流量波动设置 |
| `workQueue` | 任务队列 | **必须有界**，否则容易内存溢出 |
| `threadFactory` | 线程命名 | 命名便于排查（如 `order-pool-1`） |
| `handler` | 拒绝策略 | 用 `CallerRunsPolicy` 做背压，或自定义记录后降级 |

| 创建方式 | 适用场景 | 注意 |

### 考点 7：`线程`

- **要点**：操作系统调度的执行单元，同一进程内的线程共享地址空间和大部分资源。
- **线程 的边界**：易错：内存暴涨、切换频繁；正确做法是用线程池。

### 考点 8：`线程池`

- **要点**：复用固定数量线程处理任务，避免频繁创建销毁，并需要定义队列和拒绝策略。
- **线程池 的边界**：易错：内存暴涨、切换频繁；正确做法是用线程池。

### 考点 9：`synchronized`

- **要点**：并发三件事：可见性（volatile/synchronized）、原子性（锁/原子类）、有序性（happens-before）。
- **synchronized 的边界**：易错：全局串扰，性能极差；正确做法是用专用 `private final Object lock = new Object()`。

### 考点 10：`AtomicInteger`

- **要点**：volatile 保证可见性与有序性，但不保证原子性，count++ 仍需加锁或改用 AtomicInteger。
- **AtomicInteger 的边界**：易错：结果偏小；正确做法是用 `AtomicInteger`。

### 考点 11：`虚拟线程`

- **要点**：虚拟线程、记录模式、结构化并发与分代 ZGC 是升级收益最大的部分。
- **虚拟线程 的边界**：易错：平台线程被钉住；正确做法是虚拟线程适合 IO 等待，避免长时 `synchronized`。

### 考点 12：`内存模型`

- **要点**：编程语言或硬件对多线程读写可见性、原子性和重排序给出的规则集合
- **内存模型 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 13：排错——用 `volatile` 做自增

- **现象**：结果偏小。
- **处理**：用 `AtomicInteger`。

### 考点 14：排错——手动 new 大量线程

- **现象**：内存暴涨、切换频繁。
- **处理**：用线程池。

### 考点 15：综合辨析——`线程` 与 `内存模型`

- **辨析点**：`线程` 的定义是 操作系统调度的执行单元，同一进程内的线程共享地址空间和大部分资源；`内存模型` 的定义是 编程语言或硬件对多线程读写可见性、原子性和重排序给出的规则集合。
- **答题要求**：面对 `多线程与并发` 的题目，先判断描述的是 `线程` 还是 `内存模型`，再归到对应定义，最后写出一个会让该定义失效的边界输入。
