## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| 标签（Tag） | 尖括号包起来的元素标记，成对的开始与结束标签界定内容范围 |
| 属性（Attribute） | 写在开始标签里的键值对，描述 id、链接、图片地址等附加信息 |
| 语义化标签 | 用 header、nav、main、article 等表达结构含义，而不是一律用 div |
| 文档骨架 | html、head、body 三层结构：head 放元信息，body 放可见内容 |
| alt 文本 | 图片的替代文字，加载失败或被屏幕阅读器朗读时使用 |
| 块级元素 | 独占一行、能容纳其他元素的盒状主体，如 div、p、h1、section |
| 行内元素 | 不换行、只包住自己那点内容，如 span、a、strong、code |
| 自闭合标签 | 没有结束标签的空元素，如 img、br、input、meta |
| DOM 树 | 浏览器把标签嵌套关系解析成的节点树，CSS 与 JS 都挂在这棵树上 |
| WAI-ARIA 角色 | 语义标签缺位时用 role 属性补结构含义，如 role="navigation" |

## 原理与运行机制

把网页想象成一份报纸。报纸有标题、正文、列表、图片、链接——HTML 标签就是告诉浏览器"这段内容是标题""那段内容是列表"的标记。你可以把 HTML 理解成网页的骨架，CSS 是皮肤和衣服，JavaScript 是肌肉和神经系统。骨架决定了页面的基本结构，没有骨架，其他东西都搭不起来。

浏览器打开一个网页时，会从上到下扫描 HTML 代码。遇到 `<h1>` 就知道这是大标题，遇到 `<p>` 就知道这是段落，遇到 `<ul>` 就知道这是一个无序列表。这个过程就像读报纸时自动识别版面一样。浏览器把扫描结果组织成一棵 DOM 树（文档对象模型），后续的 CSS 样式和 JavaScript 交互都挂在这棵树上。

HTML 标签不仅决定"看起来是什么"，更决定内容的语义。`h1`～`h6` 表示标题层级，`p` 表示段落，`ul` 和 `ol` 表示无序与有序列表，`a` 表示链接，`img` 表示图片。浏览器、搜索引擎、屏幕阅读器都依赖这些语义来理解页面。比如搜索引擎看到 `<h1>` 会认为这是页面最重要的主题，看到 `<nav>` 会知道这是导航区域。

如果把所有元素都写成 `div`，再靠 CSS 模拟外观，页面能显示，但键盘操作、朗读顺序和表单行为都会变差。就像把报纸所有内容都塞进一个文本框，虽然能看，但失去了版面结构。屏幕阅读器遇到一堆 `div` 时，无法告诉视障用户哪里是标题、哪里是导航、哪里是正文。

一个基本文档包含 `<!DOCTYPE html>`、`html`、`head` 和 `body`。`head` 放元信息，例如字符集、视口、标题；`body` 放用户可见内容。字符集通常使用 UTF-8，移动端要设置 `viewport`，否则页面会按桌面宽度缩放。可以把 `head` 想象成快递包裹上的标签——收件地址、重量、易碎标记都写在这里，而 `body` 才是包裹里的实物。

标签还有嵌套和闭合规则。大多数标签成对出现：`<p>` 开头，`</p>` 结尾，中间是内容。少数标签是自闭合的，比如 `<img>` 和 `<br>`，它们不需要结束标签。块级元素（如 `div`、`p`、`h1`）可以包含行内元素（如 `span`、`a`、`strong`），但行内元素一般不能反过来包含块级元素。列表项 `li` 必须直接位于列表容器 `ul` 或 `ol` 内，不能随便放到别的地方。属性值要用引号包起来，布尔属性（如 `disabled`、`checked`）只写属性名即可。`img` 必须提供有意义的 `alt`：图片传达信息时描述信息，纯装饰图片使用空 `alt`。

表单控件要有关联的 `label`，这样点击文字也能聚焦输入框，屏幕阅读器也能读出字段含义。按钮要使用 `button` 或 `input type="button"`，不要用 `div` 模拟点击。链接用于导航，按钮用于触发动作，混用会让用户预期落空。记住一个简单的原则：能跳转的用 `a`，能点击做事的用 `button`。

### 标签、元素、内容是三个不同的词

初学时最容易混用的就是这三个术语。**标签**指 `<p>` 和 `</p>` 这两处书写记号；**元素**指这两个标签以及中间所有内容组成的整体；**内容**指标签之间的文字或子元素。写成 `<a href="...">示例网站</a>` 时，你写了一个 `a` 元素、两个标签（开始标签带一个 href 属性）、一段链接文字"示例网站"。后面学到 CSS 选择器和 DOM 操作时，"选中元素"和"读标签名"操作的对象完全不同，一开始就分清楚能少走很多弯路。

### 浏览器怎么补全你没写的结构

HTML 解析器有容错机制：只写 `<html><body>你好</body></html>` 也能正常显示，因为浏览器会自动补 `head`；漏写 `</p>` 时解析器遇到下一个块级标签会替你闭合。容错不等于正确——漏写 `</ul>` 时后面的段落会被卷进列表项里，页面看着"少了一行缩进"却找不到原因。用浏览器开发者工具的 Elements 面板对照你写的源码，看浏览器实际补成了什么树，是排查结构错误最快的方法，也是理解 DOM 树最好的练习。

### 三种列表各有分工

| 列表标签 | 表达什么 | 典型内容 |
| --- | --- | --- |
| ul | 条目之间没有先后，顺序换掉不影响理解 | 技术栈清单、导航项、特性要点 |
| ol | 顺序即含义，颠倒就出错 | 安装步骤、烹饪流程、排名榜 |
| dl | 名称与说明成对出现 | 术语表、参数说明、问答对 |

`dl` 的结构是 `<dl>` 包若干组 `<dt>`（术语名）加 `<dd>`（解释），一个 `dt` 后面可以跟多个 `dd`。有序列表的编号由浏览器自动算，不要自己在文字里手写 "1." ——屏幕阅读器会把 "1." 当成正文逐字读出来，而 `ol` 的编号是由辅助技术自己播报的。同理，`ul` 的项目符号也是浏览器给的，不要用 `·` 手动加在文字前面。

### 语义化标签的地盘划分

把一篇网页当餐厅菜单来理解：`header` 是店招和营业时间（品牌名、站点头部），`nav` 是翻到别的页码的指引（导航），`main` 是这页真正要看的菜品列表（整页只允许一个），`article` 是可以独立拿出来仍然成立的一块内容（一篇博文、一件商品），`section` 是按主题切的一段（带 `h2` 小标题的那种分区），`aside` 是等位区的小广告（相关推荐、侧边栏），`footer` 是页脚版权与联系方式。这套标签在浏览器眼里不产生任何视觉效果，它们唯一的价值就是"说清楚这块是什么"，所以视觉一律交给 CSS。

`main` 的排他性值得单独记：一个页面只有一个 `main`，且它不能嵌在 `article`、`aside`、`nav`、`header`、`footer` 里面。屏幕阅读器用户按快捷键直接跳到 `main` 开始读，跳过所有店招和导航——如果 `main` 写了两个或漏写，这个跳转就失效了。

### 标题层级是一棵树不是七个字号

`h1` 到 `h6` 的区别不是"字号从大到小"，而是目录层级。一篇长文的结构应该能投影成大纲：一个 `h1` 是题目，若干 `h2` 是章节，`h3` 是章节里的小节。如果从 `h2` 直接跳到 `h5`，辅助技术生成的页面大纲就会出现空洞，用户按"跳到下一个标题"时会莫名跳过整段。另一个常见误解是"每个页面都要一个 h1"——单页应用里多个视图各自带 `h1` 会让大纲失去唯一入口，实践上通常整站只保留首页 `h1`，其余页面用 `h1` 写页面名但不再嵌套多份。

### 特殊字符要写成实体

尖括号本身是标记语法的一部分，想在页面上显示它们必须换成实体名：`&lt;` 显示小于号，`&gt;` 显示大于号，`&amp;` 显示与号，`&copy;` 显示版权符号，`&nbsp;` 是不换行空格。讲 HTML 的教程里满屏 `&lt;p&gt;` 就是这个原因。URL 里的 `?a=1&b=2` 严格写法也应该是 `?a=1&amp;b=2`，虽然浏览器能容错，但校验工具会报错。

## 典型应用场景

- 写博客文章：用 `h1` 做标题，`h2` 做章节标题，`p` 写正文，`ul`/`ol` 列要点，`a` 插入参考链接
- 做导航菜单：用 `nav` 包裹，`a` 做链接，`ul`/`li` 做列表项。这样屏幕阅读器可以直接跳到导航区
- 展示产品列表：用 `article` 包裹每个产品，`img` 放图片，`h3` 做产品名，`p` 写描述
- 写简历页面：用 `header` 放个人信息，`section` 分区，`dl` 做技能列表，`footer` 放联系方式
- 做表单页面：用 `form` 包裹，`label` 关联每个 `input`，`button` 提交数据

### 反向案例：什么时候确实该用 div

语义化不等于"消灭 div"。当你只是需要一个盒子来放内边距、控制栅格列宽或挂一个 JS 定位锚点，这块内容本身没有任何结构含义，此时 `div` 就是正确标签——硬套 `section` 反而会凭空多出一个大纲节点，让辅助技术的标题跳转列表变长。判断口诀是：**先问这块内容"是什么"，答得出来就用对应语义标签；只答得出"它占多大位置"，就用 div 或 span。** 类似地，`span` 用来给句中几个字挂样式或脚本，不改变句子结构，这也是它存在的意义。

### 语义化改写：从一堆 div 到分区标签

```html
<!-- 改写前：结构全靠 class 名字猜 -->
<div class="top">
  <div class="menu"><a href="/">首页</a><a href="/post">博客</a></div>
</div>
<div class="content">
  <div class="post-title">我的第一篇文章</div>
  <div class="post-body">正文从这里开始。</div>
</div>

<!-- 改写后：含义写在标签名上，不依赖 CSS 也能读懂 -->
<header>
  <nav aria-label="主导航">
    <ul>
      <li><a href="/">首页</a></li>
      <li><a href="/post">博客</a></li>
    </ul>
  </nav>
</header>
<main>
  <article>
    <h1>我的第一篇文章</h1>
    <p>正文从这里开始。</p>
  </article>
</main>
```

改写带来的实际差别是三件事：键盘用户可以按 Tab 依次停在两个链接上；屏幕阅读器进入页面时先播报"导航，两项列表"再播报"文章，一级标题"；校验工具不再报未闭合。视觉上一行 CSS 都没写。

### 图片、说明文字与链接的三种 alt 写法

`alt` 不是"图片文件名"，而是"这张图在说什么"。判断标准很直接：假设图片永远加载不出来，只看这句替代文字，你还缺不缺关键信息。

```html
<!-- 图片本身承载信息：alt 要把信息写全 -->
<figure>
  <img src="chart.png" alt="2026 年第三季度销量逐月上升，9 月达到 1200 件">
  <figcaption>图 1：第三季度月度销量</figcaption>
</figure>

<!-- 纯装饰：alt 写成空字符串，屏幕阅读器会跳过它 -->
<img src="divider.svg" alt="">

<!-- 图片只是链接的内容时，alt 要写目的地而不是描述像素 -->
<a href="/pricing"><img src="btn.png" alt="查看价格方案"></a>
```

`figure` 与 `figcaption` 配套使用，表示"这段图注是可独立引用的一整块"，`figcaption` 放在 `figure` 内部的第一位或最后一位都合法。链接与按钮的选择另有一条硬指标：`href` 为空或写 `javascript:void(0)` 的 `a` 标签在新标签页打开、鼠标中键点击、右键复制链接时行为全都不同，用它做"点击展开"之类的动作必然出错，这类交互只能用 `button`。

### 练习：把一段纯文本笔记标成结构化页面

```html
<!-- 下面这段原始笔记，请补上合适的标签 -->
前端学习路线
HTML 是结构
CSS 是表现
JavaScript 是行为
常见疑问：什么是语义化？
语义化就是用标签名说明内容含义。

<!-- 参考答案骨架 -->
<main>
  <h1>前端学习路线</h1>
  <ol>
    <li>HTML 是结构</li>
    <li>CSS 是表现</li>
    <li>JavaScript 是行为</li>
  </ol>
  <section>
    <h2>常见疑问</h2>
    <dl>
      <dt>什么是语义化？</dt>
      <dd>用标签名说明内容含义，而不只是控制外观。</dd>
    </dl>
  </section>
</main>
```

三条自检清单，写完页面后逐条过一遍：一是把 CSS 全部注释掉，页面还能不能靠缩进和编号看出层次；二是从 `h1` 往下念标题，中间有没有跳级；三是每个 `img` 是否都有 `alt`，每个 `input` 是否都被某个 `label` 的 `for` 指向。

## 时间/空间复杂度或性能分析

HTML 页面本身的"复杂度"不在算法层面，而在渲染层面。浏览器解析 HTML 时会构建 DOM 树，标签嵌套越深、节点越多，构建时间越长。

性能关注点：浏览器渲染是关键路径——关注首屏时间、重排与重绘次数、资源体积。

小文件看元数据开销，大文件看吞吐，两者要分别测量。测量方法：固定输入跑一遍记录基线，再把规模提高一个数量级复测；两次结果的差值与波动范围才是结论依据。

优化建议：
- 减少不必要的嵌套层级
- 避免过深的 DOM 结构（一般不超过 15 层）
- 图片使用合适的尺寸和格式
- 把 CSS 放在 `head`，JavaScript 放在 `body` 底部或使用 `defer`

## 常见误区与易错点

| 错误 | 现象 | 修法 |
| --- | --- | --- |
| 全用 div 堆结构 | 无障碍工具与搜索引擎读不懂页面 | 按语义选择 nav、main、article 等标签 |
| 标签没有闭合 | 浏览器容错掩盖结构错误 | 保持标签配对，并用校验工具检查 |
| 属性值不加引号 | 属性解析出错，图片无法被辅助技术读出 | 属性统一加引号，图片补齐 alt 文本 |
| 用 div 模拟按钮 | 键盘用户无法操作，屏幕阅读器识别不了 | 用 button 或 input type="button" |
| 标题层级跳级 | 搜索引擎和辅助技术无法理解页面结构 | 按 h1→h2→h3 顺序使用，不要跳过 |
| 手写编号代替 ol | 屏幕阅读器把 "1." 当正文读，列表项数也统计不出 | 用 ol 让浏览器生成编号 |
| img 省略 alt 属性 | 校验工具报错，读屏软件只能念出文件名 | 有信息写清楚，纯装饰写 alt="" |
| 一个页面多个 main | 跳转地标失效，读屏用户找不到正文入口 | main 全站唯一且不嵌套在 header、nav、footer 内 |
| 用 a 充当展开按钮 | 中键点击与新标签页打开行为不可控 | 交互用 button，导航用带真实 href 的 a |

## 与其他知识点的关系

HTML 标签是前端三件套的第一块。学完本课后，下一步是《CSS 选择器入门》，用 CSS 给 HTML 标签加样式。打个比方：HTML 是房子的框架，CSS 是装修风格，JavaScript 是智能家居系统。你得先搭好框架，才能谈装修和自动化。

概念关系：
- `标签（Tag）` 是 HTML 的基本单位，`属性（Attribute）` 是标签的附加信息——标签决定"是什么"，属性决定"长什么样、怎么行为"
- `语义化标签` 是标签的一种用法，强调用正确的标签表达正确的含义，而不是什么都用 div
- `文档骨架` 是 HTML 文档的整体结构，所有标签都嵌套在里面，就像房子的地基和楼层
- `alt 文本` 是 `img` 标签的一个属性，用于图片无法加载时的替代说明，也是无障碍的重要组成部分

后续课程会用到：
- CSS 选择器：通过标签名、类名、id 选中元素并添加样式
- JavaScript DOM 操作：通过标签创建、修改、删除元素，实现动态交互
- 表单处理：用 `input`、`button`、`form` 等标签收集用户输入

## 自测题与参考答案

**自测 1**：不看正文，写出 `标签（Tag）` 的定义，并说明它与 `属性（Attribute）` 的区别。

参考答案：标签是尖括号包起来的元素标记，成对的开始与结束标签界定内容范围。属性是写在开始标签里的键值对，描述 id、链接、图片地址等附加信息。标签是容器，属性是容器的配置。

**自测 2**：本课错误表记录了"全用 div 堆结构"这类做法。请写出它会出现的现象和修复方法。

参考答案：现象是无障碍工具与搜索引擎读不懂页面。修复方法是按语义选择 nav、main、article 等标签，让每个区域都有明确含义。

**自测 3**：运行本课的 `html` 示例，改动其中一个输入后重新运行，记录输出与错误信息。

**自测 4**：阅读本课开头的 `html` 示例，说明它体现了 `标签（Tag）` 的哪一条性质。

参考答案：示例中 `<h1>`、`<p>`、`<ul>`、`<li>` 都是成对出现的标签，开始标签和结束标签之间的内容就是该标签的作用范围。这体现了标签界定内容范围的性质。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| 标签（Tag） | 尖括号包起来的元素标记，成对的开始与结束标签界定内容范围 |
| 属性（Attribute） | 写在开始标签里的键值对，描述 id、链接、图片地址等附加信息 |
| 语义化标签 | 用 header、nav、main、article 等表达结构含义，而不是一律用 div |
| 文档骨架 | html、head、body 三层结构：head 放元信息，body 放可见内容 |
| alt 文本 | 图片的替代文字，加载失败或被屏幕阅读器朗读时使用 |
| ul / ol / dl | 无序列表、有序列表、术语定义列表 |
| header / nav / main / footer | 页面四个主分区，main 全站只能有一个 |
| figure / figcaption | 可独立引用的插图块与其图注 |
| 实体引用 | 用 &amp;lt; 这类记号在页面上显示特殊字符 |
