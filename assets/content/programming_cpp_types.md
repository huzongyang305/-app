## 典型应用场景

- **整数除法丢小数**：典型现象是`5 / 2 == 2`；正确做法是至少一侧转成 `double`。
- **有符号与无符号混用**：典型现象是比较结果反直觉；正确做法是统一类型，或用 `std::ssize`。
- **整数溢出**：典型现象是结果变成负数；正确做法是换 `long long`，或提前判断范围。
- **未初始化变量**：典型现象是输出垃圾值；正确做法是定义即赋初值。

**教材衔接：const 与 constexpr**

```cpp
const int max_size = 100;              // 运行期常量，不可修改
constexpr int square(int x) { return x * x; }   // 编译期可求值

const int* p1;          // 指向常量的指针：不能通过 p1 改值
int* const p2 = nullptr; // 常量指针：不能改指向
const int* const p3 = nullptr;  // 两者都不能改
```

能用 `constexpr` 就优先用它，编译期计算不占运行时开销。

**教材衔接：运算符**

```cpp
int a = 7, b = 2;
std::cout << a / b << ' ' << a % b << '\n';   // 3 1，整数除法会截断
a += 3;  ++a;  a--;                            // 复合与自增自减

bool both = (a > 0) && (b > 0);                // 短路求值
int  flags = 0b1010 & 0b0110;                  // 位运算
```

`&&` 和 `||` 会短路：左边能确定结果时右边不会执行，因此可写成 `if (ptr && ptr->valid())`。

- **类型推导 的边界**：静态检查只在编译期成立，运行期输入仍需校验。

### 考点 11：排错——整数除法丢小数

- **现象**：`5 / 2 == 2`。
- **处理**：至少一侧转成 `double`。

### 考点 12：排错——有符号与无符号混用

- **现象**：比较结果反直觉。
- **处理**：统一类型，或用 `std::ssize`。

### 考点 13：综合辨析——`auto` 与 `类型推导`

- **辨析点**：`auto` 的定义是 `auto` 只是让编译器推导类型，不会降低类型安全；`decltype(x)` 用于取表达式的类型；`类型推导` 的定义是 auto 与模板按初始化表达式推断类型，注意引用与常量限定会被剥掉一部分。
- **答题要求**：面对 `变量、类型与运算符` 的题目，先判断描述的是 `auto` 还是 `类型推导`，再归到对应定义，最后写出一个会让该定义失效的边界输入。
