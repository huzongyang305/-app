## 核心概念定义

| 术语 | 一句话说明 |
| --- | --- |
| auto | `auto` 只是让编译器推导类型，不会降低类型安全，`decltype(x)` 用于取表达式的类型。 |
| constexpr | 能用 `constexpr` 就优先用它，编译期计算不占运行时开销。 |
| 类型 | 值允许的表示、取值范围和可执行操作集合。 |
| 类型推导 | `auto` 与模板按初始化表达式推断类型，注意引用与常量限定会被剥掉一部分。 |
| static_cast | 编译期类型转换，用于安全的向上/向下转换和数值类型转换。 |
| 未定义行为 | 程序行为不可预测：可能崩溃、可能产生错误结果、可能看似正常但换编译器就出问题。 |
| size_t | 无符号的"大小/长度"类型，做减法或和负数比较时会回绕成极大值。 |
| 通常算术转换 | `int` 与无符号混算时先把负数转成无符号，比较结果常违反直觉。 |

## 原理与运行机制

### 类型就是规则

想象你有一个只能装整数的盒子和一个只能装小数的盒子。C++ 的类型系统就是这些"盒子规则"——它在你写代码时就告诉你"这个值不能放进那个盒子"，而不是等到运行时才炸。

```cpp
int count = 42;        // 整数盒子
double price = 9.99;   // 小数盒子
char grade = 'A';      // 单个字符盒子
bool flag = true;      // 真/假盒子
```

### auto：让编译器帮你填类型

```cpp
auto x = 42;         // 编译器推导 x 是 int
auto pi = 3.14;      // 编译器推导 pi 是 double
auto name = "hello"; // 编译器推导 name 是 const char*
```

`auto` 不是"任意类型"——它是由编译器根据初始化表达式推导出的静态类型。一旦推导出来，就和你手写类型完全一样。`auto` 的好处是代码更简洁，尤其是类型名很长的时候（比如 `std::vector<std::pair<int, std::string>>::iterator`）。

### const 与 constexpr

```cpp
const int max_size = 100;       // 运行时不能改的常量
constexpr int buffer_size = 256; // 编译期就能算出的常量
```

- `const`：表示"这个值不能被修改"，但它的值可能在运行时才确定
- `constexpr`：表示"这个值在编译期就能算出来"，编译器会直接替换成数字

能用 `constexpr` 就优先用它，编译期计算不占运行时开销。

### 四种类型转换

```cpp
double d = 3.9;
int i = static_cast<int>(d);        // 3，明确的截断

const char* text = "hello";
void* raw = const_cast<void*>(static_cast<const void*>(text));

Base* base = new Derived();
Derived* derived = dynamic_cast<Derived*>(base);   // 多态类型的安全向下转换

auto bits = reinterpret_cast<std::uintptr_t>(base); // 重新解释位模式，慎用
```

- `static_cast`：最常用的转换，用于数值类型之间、指针向上/向下转换
- `const_cast`：去掉或添加 `const` 限定
- `dynamic_cast`：运行时检查的多态类型转换，失败返回 `nullptr`
- `reinterpret_cast`：重新解释位模式，非常危险，慎用

### 未定义行为（UB）

```cpp
int arr[5];
arr[10] = 42;  // 越界！未定义行为

int x = INT_MAX + 1;  // 有符号整数溢出！未定义行为
```

未定义行为意味着编译器可以做任何事情——程序可能崩溃、可能产生错误结果、可能看似正常但换一个编译器就出问题。C++ 标准对 UB 不做任何保证。

### 整数除法

```cpp
std::cout << 5 / 2;      // 输出 2，不是 2.5！
std::cout << 5.0 / 2;    // 输出 2.5
std::cout << 5 / 2.0;    // 输出 2.5
```

两个整数相除，结果还是整数——小数部分直接截断。至少一侧转成 `double` 才能得到小数结果。

### 无符号数的陷阱

```cpp
size_t n = 0;
n = n - 1;  // n 变成 18446744073709551615（最大值），不是 -1！
```

把负数赋给 `size_t` 或无符号变量时会发生按模转换成一个很大的正数。这是 C++ 的一个经典陷阱。

### 整型提升：混用 int 和 size_t 的隐式陷阱

`int` 与无符号类型（如 `size_t`）一起参与运算时，标准会做"通常算术转换"：负数被先转成无符号，于是比较结果常常违反直觉。最经典的现场是循环边界：

```cpp
std::vector<int> v;            // 空 vector，size() 返回 0
for (size_t i = 0; i < v.size() - 1; ++i) {
    // size() - 1 回绕成一个极大的无符号数，循环根本停不下来
}
```

`v.size()` 是 `size_t`（无符号），`0 - 1` 不会得到 `-1`，而是回绕成最大值——这和"把负数赋给无符号"其实是同一个坑的两种表现。改成 `for (size_t i = 0; i + 1 < v.size(); ++i)`，或先用一个有符号变量存长度，就避开了。生活化类比：无符号数像一辆只有前进挡、里程表会翻圈的车，倒退一格不是 `-1` 而是跳到最大读数。

### 浮点类型别用 == 直接比

`double` 存的是近似值，`0.1 + 0.2 == 0.3` 往往是 `false`。要判等就比误差：`std::abs(a - b) < 1e-9`。涉及金额时优先用整数存"分"或专门定点类型，别拿浮点连续累加。

### 怎么验证一个类型结论

类型行为依赖编译器和语言标准，验证要像做实验一样留下可复现记录：

1. 先说清楚这个表达式的输入、输出和失败路径——正常值、边界值（`INT_MAX`、`size() == 0`）、异常值分别是什么。
2. 写一个最小示例，固定编译器与标准（如 GCC 13 + `-std=c++17`），记录基线结果。
3. 只改一个变量（比如把 `5 / 2` 换成 `5.0 / 2`），再观察输出怎样变化。
4. 把结论写成"在某个标准/版本下、对哪些输入成立"的记录，不要拿一次运行当成所有编译器都成立——未定义行为尤其危险，换个优化等级结果就可能不同。

## 典型应用场景

类型系统在日常开发中的应用：

- **数值计算**：用 `double` 处理小数，用 `int64_t` 处理大整数，避免溢出
- **常量定义**：用 `constexpr` 定义数组大小、缓冲区尺寸等编译期常量
- **类型安全**：用 `static_cast` 替代 C 风格强制转换，让转换意图明确
- **避免 UB**：检查数组边界、避免整数溢出、不访问空指针
- **代码可读性**：用 `auto` 简化冗长的类型名，但不滥用

### 一个实际的小例子

```cpp
#include <iostream>

constexpr double PI = 3.14159265358979;

double circleArea(double radius) {
    return PI * radius * radius;
}

int main() {
    auto r = 5.0;
    std::cout << "半径 " << r << " 的圆面积是 " << circleArea(r) << "\n";
    return 0;
}
```

## 代码/协议/SQL 示例

### 最小可运行示例

```cpp
#include <iostream>
#include <cstdint>

int main() {
    double d = 3.9;
    int i = static_cast<int>(d);
    std::cout << "d=" << d << " i=" << i << "\n";

    constexpr int size = 10;
    auto x = size * 2;
    std::cout << "x=" << x << "\n";

    return 0;
}
```

输出：

```text
d=3.9 i=3
x=20
```

### 完整示例：类型转换对比

```cpp
#include <iostream>
#include <string>
#include <cstdint>

int main() {
    // static_cast：数值转换
    double pi = 3.14159;
    int n = static_cast<int>(pi);  // 截断为 3
    std::cout << "static_cast: " << n << "\n";

    // 整数除法陷阱
    std::cout << "5/2 = " << 5 / 2 << "\n";       // 2
    std::cout << "5.0/2 = " << 5.0 / 2 << "\n";   // 2.5

    // 无符号数陷阱
    unsigned int u = 0;
    u = u - 1;  // 回绕成最大值
    std::cout << "unsigned underflow: " << u << "\n";

    return 0;
}
```

## 时间/空间复杂度或性能分析

类型选择影响内存和性能：

| 类型 | 典型大小 | 适用场景 |
| --- | --- | --- |
| `bool` | 1 字节 | 标志位 |
| `int` | 4 字节 | 一般整数 |
| `long long` | 8 字节 | 大整数 |
| `float` | 4 字节 | 低精度小数 |
| `double` | 8 字节 | 高精度小数 |
| `std::string` | 32+ 字节 | 文本 |

`constexpr` 在编译期计算，零运行时开销。`auto` 不引入额外开销——它只是让编译器帮你写类型。

还要注意窄化转换：把 `int` 赋给 `short`、`double` 赋给 `int` 都可能丢数据，用花括号初始化 `{}` 能让编译器在发生窄化时直接报错，比 C 风格强转安全得多。类型本身不改变算法复杂度，但选错类型（该用 `long long` 却用 `int`）会让大输入直接溢出，效果等同于结果错误——这类问题往往只在边界规模才暴露，正好印证"固定版本、覆盖边界输入"的验证方法。

## 常见误区与易错点

| 容易犯的错误 | 会出现什么 | 怎么修 |
| --- | --- | --- |
| 整数除法丢小数 | `5 / 2 == 2` | 至少一侧转成 `double` |
| 整数溢出 | 结果变成负数或不正确的值 | 换 `long long`，或提前判断范围 |
| 把负数赋给无符号变量 | 按模转换成一个很大的正数 | 用有符号类型，或先检查值 |
| 有符号整数溢出 | 未定义行为 | 避免溢出，用更大类型或检查范围 |
| 用 C 风格强制转换 | 跳过类型安全检查 | 用 `static_cast` 等 C++ 转换 |
| 滥用 auto | 类型不明确，可读性下降 | 只在类型名很长或明显时使用 |
| 混用 `int` 和 `size_t` 做循环 | 空容器时 `size() - 1` 回绕成极大值，循环失控 | 改成 `i + 1 < v.size()`，或先用有符号变量存长度 |
| 用 `==` 比较两个 `double` | `0.1 + 0.2 == 0.3` 结果为 false | 比较绝对误差 `< 1e-9`，金额用整数"分"表示 |

### 现场 1：整数除法丢小数

**症状**：`5 / 2` 结果是 `2` 而不是 `2.5`。

**根因与修复**：两个整数相除结果是整数。至少一侧转成 `double`：`5.0 / 2`。

### 现场 2：整数溢出

**症状**：计算结果突然变成负数或一个很大的数。

**根因与修复**：换 `long long`，或提前判断范围。
