## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 时序数据库 | 专门存储按时间到达的数据点，优化时间范围查询、聚合和过期清理。 | 易错：写入与查询都随数据量恶化；正确做法是用时序数据库或分区表，按时间分片并启用压缩。 |
| 标签 | 附加在数据点上的键值维度，用于筛选、聚合和分组，但不应频繁变化。 | 只在「附加在数据点上的键值维度，用于筛选、聚合和分组，但不应频繁变化」这一前提下成立，换输入或换环境要重新验证。 |
| 降采样 | 把高频采样点按时间窗口聚合成低频数据（如 1 秒变 1 分钟），用于长期存储与趋势查询。 | 易错：存储成本无限增长；正确做法是定义原始、分钟、小时多级保留策略。 |
| 保留策略 | 规定数据保存多久、何时归档或删除，并满足审计和合规要求。 | 易错：存储成本无限增长；正确做法是定义原始、分钟、小时多级保留策略。 |

### 最小可验证示例

**教材衔接：最小可运行示例**

下面示例用于验证 时序数据库 的最小输入、处理和输出。先原样运行，再只修改一个值：

```sql
WITH samples(ts, value) AS (
  VALUES (TIMESTAMP '2026-10-05 10:00', 12.0),
         (TIMESTAMP '2026-10-05 10:05', 15.0),
         (TIMESTAMP '2026-10-05 10:10', 9.0)
)
SELECT date_trunc('hour', ts) AS bucket, avg(value) AS avg_value
FROM samples
GROUP BY bucket;
```

```text
2026-10-05 10:00:00 |      12.0
```
