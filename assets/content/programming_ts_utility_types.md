## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| TypeScript | 在 JavaScript 上增加静态类型系统的语言，编译后可运行在浏览器或 Node.js。 | TypeScript 的类型编译后即擦除，浏览器或 Node 里进来的 JSON 字段不受它约束，边界输入要靠 zod 等运行时校验。 |
| 工具类型 | 工具类型让你从已有类型派生新类型，而不是重复声明。 | 工具类型派生的是类型，接口加字段时派生结果自动跟着变，但运行时数据不会补上；手写展开就丢了这层同步。 |
| 映射类型 | TypeScript 根据已有类型批量生成属性变换后的新类型。 | 映射类型只在编译期把 T 的属性逐个做变换，运行时的对象值不会因此改变，深层结构也不会自动递归。 |
| 声明文件 | .d.ts 为无类型的第三方库补类型：declare module 'legacy-lib' { export function run(x: string): void }。 | 易错：编译错误或语义混乱；正确做法是声明文件只放类型与签名。 |
| Partial<T> / Required<T> | 全部可选 / 全部必填 | 易错：Partial 把关键字段也变可空导致漏校验，Required 又强制全部补齐，应改用 Pick / Omit 精确表达。 |
| Pick<T, K> / Omit<T, K> | 挑选字段 / 排除字段 | 易错：K 用字符串写，键名拼错时编译不报错，要用 satisfies 或常量联合约束键。 |
| Record<K, V> | 构造键值映射类型 | `Record<K, V>` 要求 K 是能当对象键的类型，值类型写宽（如 `any`）就等于放弃检查，运行时也不会替你补齐缺失的键。 |
| Readonly<T> | 全部只读 | 只锁顶层属性，内层对象仍可改写，深层只读得自定义递归类型。 |
| ReturnType<F> / Parameters<F> | 提取函数返回值 / 参数类型 | `ReturnType` 与 `Parameters` 取的是声明层面的签名，函数运行时真实返回什么、参数有没有传错，它们一概不管。 |
| Awaited<T> | 提取 Promise 的结果类型 | `Awaited` 解的是类型里的 Promise 外壳（`Awaited<Promise<number>>` 得 `number`），既不等待真实异步，也不拆嵌套层。 |
| Exclude / Extract / NonNullable | 联合类型的筛选 | 三者都在类型层做筛选：Exclude、Extract 只对联合有意义，NonNullable 去掉可空后运行时的 null 值照样可能炸。 |
| Partial<T> | 全部属性可选 | `Partial<T>` 给每个属性都加上可选标记，读出来逐个变 `undefined`；用它表达入参等于默认允许漏填关键字段。 |
| Required<T> | 全部属性必填 | 把源类型中本就可选的属性一律变必填，数据确实缺项时调用方被迫补占位值。 |
| Readonly<T> | 全部属性只读 | 只读约束只在顶层属性生效，数组或对象值内部仍可增删改。 |
| Pick<T, K> | 只保留指定字段 | Pick 只留下列出的几项，丢掉的字段在结果类型中不存在，别把它当完整对象用。 |
| Omit<T, K> | 排除指定字段 | 要排除的键名拼错时不报错，字段其实没被去掉；键用常量联合或 satisfies 兜住。 |
| Record<K, V> | 键值映射 | 图省事写 Record<string, any> 等于放弃检查，值类型要按实际收窄。 |
| Exclude<T, U> | 从联合中排除 | 只在 T 是联合类型时有意义，传入单个非联合类型时等于没变化。 |
| Extract<T, U> | 取联合交集 | 只对联合类型做成员筛选，拿它去筛对象或函数的结构不会得到想要结果。 |
| NonNullable<T> | 去掉 null 与 undefined | NonNullable 只在类型层去掉可空，运行期值仍可能是 null，需 strictNullChecks 与运行时校验。 |
| ReturnType<F> | 取函数返回值类型 | `ReturnType<F>` 取的是签名里声明的返回类型，函数运行时真返回 `null` 或抛异常，它给不出任何预警。 |
| Parameters<F> | 取参数元组 | `Parameters<F>` 取到的是形参元组，可选参数会体现为元组里的可选项；它无法校验调用时真实传进来的参数值。 |
| Awaited<T> | 解开 Promise | Awaited 只还原类型层面的结果，不等待真实 Promise，同步或异步都要另测。 |
| T[K] | 索引访问类型 | `T[K]` 里的 K 必须是 `keyof T` 的键，取不存在的键编译就报错；它拿到的是属性类型，运行时对象有没有这个键不保证。 |
| keyof T | 键的联合 | keyof 得到的是编译期键联合，类型擦除后运行时拿不到它来校验真实对象键。 |
| Partial<T> | 全部选项变成「可填可不填」 | `Partial<T>` 让每个属性都可填可不填，当返回值时调用方读每个字段都得判 `undefined`，必填项应改用 `Pick` 单列出来。 |
| Required<T> | 全部变成必填 | 把可选标记全抹平成必填，若源数据本就允许缺省，调用方会被迫补上假值。 |
| Pick<T, K> | 只保留几项 | Pick 结果只含列出的几项，缺的字段不在类型里，误当完整对象传参会报错。 |
| Omit<T, K> | 去掉几项 | 去掉的项用字符串列举，写错键名不报错，原字段悄悄留着，键要固定成常量联合。 |
| Record<K, V> | 建一张映射表 | Record 建的映射表只约束形状，运行时对象少几个键也不会报错，需自行补校验。 |
| Readonly<T> | 全部只读 | Readonly 只作用到第一层属性，嵌套对象照样能改，深层只读需自定义递归类型。 |
| Extract<T, U> | 取出 T 中属于 U 的部分 | 按可赋值取属于 U 的成员，两个联合不相交时选不出任何一项，别拿来筛字段。 |
| Exclude<T, U> | 从 T 中排除 U | 只从联合 T 里删掉属于 U 的成员，对非联合类型起不了筛选作用。 |
| NonNullable<T> | 去掉 null 与 undefined | 它擦除的是类型上的 null 与 undefined，不保证真实数据非空，取到空值照样炸。 |
| ReturnType<F> | 取函数返回值类型 | `ReturnType<F>` 与上一行取的是同一件事，但遇到重载或泛型函数时只匹配到最后一条签名，未必是你想要的那个返回类型。 |
| Parameters<F> | 取函数参数类型元组 | `Parameters<F>` 取函数参数元组，但遇到重载函数时只匹配到最后一条签名，参数列表可能与实际调用的那条不符。 |
| Awaited<T> | 解开 Promise 的包裹 | 它拆的是类型上的 Promise 层，传进来的若不是 Promise 就只能原样返回。 |
| 到处复制字段 | 加字段时漏改 | 到处复制字段就是手写多份几乎相同的接口，给 User 加一个字段时另一份忘了同步，两套类型当场对不上。 |
| 用 Omit 去掉必填字段后忘了补 | 结构不完整 | Omit 删掉的字段若下游仍需要，类型会缺项；正确做法是 Omit 叠加 Partial 明确补回。 |
| 索引签名写成 any | 失去检查 | 索引签名写成 any 让任意值蒙混过关，改成 Record<string, T> 明确值类型才保留检查。 |
| 误以为 Readonly 是深层的 | 内层仍可改 | Readonly 只锁第一层，内层对象仍可改写；要深层只读得自定义递归只读类型。 |
| 用 Partial 当返回值 | 调用方到处判 undefined | 返回值用 Partial 会让每个字段都可能是 undefined，调用方被迫到处判空，只在输入侧用。 |
| 模板字面量类型滥用 | 类型报错难读 | 易错：类型报错难读；正确做法是复杂场景退回普通联合。 |
| 忘了 as const | 推断成 string 而不是字面量 | 忘了 as const 时字面量被推成 string 而非具体字面量，需要字面量类型的键或联合就匹配不上；给常量补 as const 即可。 |

## 原理与运行机制

### 机制总览

**教材衔接：声明文件**

`.d.ts` 为无类型的第三方库补类型：`declare module 'legacy-lib' { export function run(x: string): void }`。全局类型放 `global.d.ts`，通过 `tsconfig` 的 `types`/`include` 引入。

**教材衔接：工程实践**

1. 类型放在 `types/` 或与实现同文件，避免全局污染。
2. 用 `type` 定义联合与工具类型，`interface` 定义对象契约（可扩展、可合并）。
3. 生成类型而非手写：从后端 OpenAPI/GraphQL schema 生成客户端类型，避免契约漂移。
4. 类型也要测试：用 `expectType` 或 `tsd` 校验类型行为。

**教材衔接：.d.ts 声明速查**

| 场景 | 写法 |
| --- | --- |
| 声明全局函数 | `declare function greet(name: string): void;` |
| 声明模块 | `declare module "my-lib" { export const version: string; }` |
| 声明命名空间 | `declare namespace NodeJS { interface ProcessEnv { ... } }` |
| 扩展第三方类型 | 新建 `types/xxx.d.ts` 用 `declare module` 增强 |
| 只声明类型 | `export type { Foo };` |
| 声明资源模块 | `declare module "*.svg" { const url: string; export default url; }` |
| 全局类型 | `declare global { interface Window { __APP__: AppConfig } }` |

## 代码/协议/SQL 示例

### 最小可验证示例

```ts
interface User {
  id: string;
  name: string;
  password: string;
  createdAt: Date;
}

// 对外返回去掉密码，创建时不需要 id 与时间
type UserDto = Omit<User, "password">;
type CreateUserInput = Omit<User, "id" | "createdAt" | "password"> & {
  password: string;
};

// 补丁更新：只允许传需要改的字段
type UserPatch = Partial<Pick<User, "name" | "password">>;

// 用映射类型批量转换：把字段都变成可空的
type Nullable<T> = { [K in keyof T]: T[K] | null };

// 条件类型 + infer：取 Promise 内部类型
type Unwrap<T> = T extends Promise<infer U> ? U : T;
type Value = Awaited<Promise<number>>;   // number
```
