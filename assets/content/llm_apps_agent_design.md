## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| 智能体循环 | 模型在「思考—行动—观察」之间反复推进直到满足终止条件。 | 易错：把循环当成自由发散，缺预算上限就会失控计费。 |
| ReAct | 每轮根据最新观察决定下一步动作，边做边规划。 | 易错：步数越多越好，实际后期轮次的信息增量迅速衰减。 |
| Plan-and-Execute | 先产出完整计划再逐步执行，必要时整体重排。 | 易错：计划一次成型不改，前期误判会被后续步骤放大。 |
| Reflexion | 失败后把原因写成经验条目，下一轮把它放进上下文。 | 易错：只记录「失败了」而不写可执行的改法。 |
| 情节记忆 | 保存具体交互过程与结果，按时间与会话组织。 | 易错：全量塞回提示词，很快挤占有效上下文。 |
| 语义记忆 | 从交互中提炼的稳定事实与偏好，可跨会话复用。 | 易错：不写淘汰策略，错误事实会长期污染后续回答。 |
| 工具注册表 | 当前 Agent 可见的工具集合与调用权限。 | 易错：所有 Agent 共享全量工具，越权与选错率同时上升。 |
| 状态机 | 用节点、边与共享状态描述流程的显式结构。 | 易错：边没有条件判断，状态图退化成一条直线。 |
| 监督者 | 负责拆分任务、路由子任务与验收结果的中枢角色。 | 易错：监督者自己下场执行，上下文迅速膨胀。 |

## 原理与运行机制

### 机制总览：循环的五个必备部件

一个可用的智能体至少需要目标表示、规划器、动作空间、观察回灌、终止判定五个部件。缺任何一个都会表现为「看起来能跑，但一上量就崩」：没有终止判定会无限自问自答，没有观察回灌则每轮都在重复同一个错误。

**教材衔接：两种范式的逐步对比**

| 维度 | 每轮重新规划 | 先出全局计划 |
| --- | --- | --- |
| 适应变化 | 强，下一步直接依赖最新观察 | 中，需要显式触发重排 |
| 步骤间一致性 | 弱，容易绕圈 | 强，先有整体结构 |
| 可解释性 | 需要逐轮解释 | 计划本身就是交付物 |
| Token 成本 | 每轮携带全部历史 | 规划一次，执行阶段可裁剪 |
| 失败定位 | 难，问题常在中间轮次 | 易，能对齐到某个计划项 |

**教材衔接：一轮循环的可执行骨架**

```python
def agent_loop(goal, act, observe, done, budget=8):
    scratch, history = goal, []
    for step in range(budget):
        if done(scratch):
            return {'answer': scratch, 'steps': step + 1}
        action = act(scratch)
        scratch = observe(scratch, action)
        history.append(action)
    return {'answer': scratch, 'steps': budget, 'stopped': 'budget'}
```

预算耗尽时返回的不是失败，而是一种显式的工程结论：它把「没做完」和「做错」区分开，便于上层决定是否升级模型、换工具或转人工。

**教材衔接：反思机制的写入与读取**

反思的价值在于把一次性的失败转成可复用的约束。写条目时要满足三个条件：可判定（能说清什么情况下成立）、可执行（指明下一步怎么做）、可淘汰（有失效条件）。

```python
def reflect(attempt: dict) -> dict:
    return {
        'when': '查询结果条目超过 200 条',
        'do': '先按时间倒序取前 20 条再判断是否需要翻页',
        'expires': '换成带分页参数的接口后失效',
    }

notes = [reflect({})]
print(len(notes), all('do' in n for n in notes))
```

**教材衔接：记忆分层与写入路径**

会话内的原始轨迹进情节层；跨会话仍成立的偏好与事实经过提炼进语义层；工具与技能本身进能力层。三层读取方式不同：情节层按会话与时间检索，语义层按向量与标签检索，能力层按当前意图裁剪后挂载。

| 记忆层 | 写入时机 | 读取方式 | 淘汰策略 |
| --- | --- | --- | --- |
| 工作记忆 | 每轮循环 | 直接拼进上下文 | 轮次窗口截断 |
| 情节记忆 | 会话结束 | 按会话与关键词检索 | 过期时间加条数上限 |
| 语义记忆 | 从情节中提炼 | 向量检索加过滤 | 冲突时以新覆盖旧 |
| 能力记忆 | 工具变更时 | 按意图裁剪挂载 | 版本下线即移除 |

**教材衔接：用状态图描述流程**

显式状态图的最大好处不是「更聪明」，而是可审计、可重放、可中断恢复。节点是一次函数调用，边是条件转移，状态是随流程累积的共享字典。条件路由函数必须对同一状态给出确定结果，否则重放会出现分叉。

```python
def route(state):
    return 'tool' if state['tool_calls'] else 'end'

print(route({'tool_calls': []}), route({'tool_calls': ['q']}))
```

**教材衔接：多 Agent 的角色与权限**

拆分 Agent 的理由通常只有三个：权限需要隔离、上下文需要隔离、提示词目标冲突。仅仅「看起来更专业」不构成拆分理由，因为每一次交接都要付序列化的代价。

| 角色 | 职责 | 可见工具 | 禁止动作 |
| --- | --- | --- | --- |
| 监督者 | 拆任务、路由、验收 | 只读检索 | 直接执行业务写入 |
| 执行者 | 完成单个子任务 | 该子集工具 | 修改全局计划 |
| 评审者 | 按验收标准打分 | 只读与静态检查 | 直接改代码 |
| 记录者 | 写轨迹与经验条目 | 记忆存储 | 参与决策 |

## 典型应用场景

| 场景 | 推荐范式 | 关键设计点 |
| --- | --- | --- |
| 竞品资料调研并出摘要 | 先规划再执行 | 计划项与来源 URL 绑定，防编造 |
| 线上告警根因定位 | 每轮重新规划 | 观察是日志与指标，需强截断策略 |
| 多文件代码重构 | 执行加评审分离 | 评审意见必须落到可验证检查项 |
| 客服工单自动处理 | 状态图加人工闸口 | 高风险动作停在待确认状态 |
| 长周期个人助理 | 分层记忆 | 语义记忆需要冲突消解与失效 |

- 典型现象：Agent 反复调用同一个查询从不收尾。正确做法：给每个工具加「本会话已调用次数」计数，超阈值时返回结构化提示要求换路径。
- 典型现象：计划里出现无法执行的步骤。正确做法：规划阶段就注入工具清单与参数 Schema，让计划项必须引用存在的动作。
- 典型现象：多 Agent 之间互相转交任务形成乒乓。正确做法：消息加跳数上限，并禁止「仅转交不产出」的回复。

### 最小验证场景

- 准备：一个三步任务（检索、比较、结论），固定预算为六轮，工具中故意让第二步失败一次。
- 观察：是否在失败后产生反思条目、是否改变了第二步的参数、是否避免了重复第一步。
- 判定：三步任务在四到五轮内结束且结论引用了第二步的真实返回值；若回到第一步重跑，说明失败信息没有写进工作记忆。

## 代码/协议/SQL 示例

**教材衔接：把终止条件写成可测函数**

终止判定要独立于模型的自我声明。常见组合是「目标谓词成立」或「预算耗尽」或「触发熔断」，三者任一成立即退出。

```python
def should_stop(state: dict, budget: int = 6) -> str | None:
    if state.get('verified'):
        return 'done'
    if state['turns'] >= budget:
        return 'budget'
    if state['errors'] >= 3:
        return 'circuit'
    return None

print(should_stop({'verified': False, 'turns': 6, 'errors': 1}))
```

**教材衔接：轨迹落库与成本统计**

不落地轨迹就无法做优化。把每一轮的轮次号、动作、耗时、输入输出 Token 与是否失败写进一张表，就能直接看出哪一轮最贵、哪个工具最常导致返工。

```sql
SELECT agent_name,
       ROUND(AVG(turns), 2)                       AS avg_turns,
       SUM(total_tokens)                          AS tokens,
       ROUND(100.0 * SUM(failed::int) / COUNT(*),1) AS fail_rate
FROM agent_run
WHERE started_at >= now() - INTERVAL '7 day'
GROUP BY agent_name
ORDER BY tokens DESC;
```

## 时间/空间复杂度或性能分析

| 指标 | 随什么增长 | 典型区间 | 优化手段 |
| --- | --- | --- | --- |
| 每轮输入 Token | 历史轮次的累积 | 近似二次增长 | 窗口截断加轨迹摘要 |
| 端到端时延 | 轮次乘单次往返 | 线性 | 并行独立子任务 |
| 总成本 | 轮次与上下文长度共同作用 | 超线性 | 早期收敛加缓存 |
| 工作记忆占用 | 观察结果体积 | 常由日志撑爆 | 结构化压缩，只留关键字段 |
| 长期存储 | 情节条目数 | 线性 | 分层归档加去重 |

轮次数与成本不是线性关系。第 k 轮通常要携带前 k-1 轮的全部轨迹，因此累计输入 Token 约与轮次的平方成正比。把十轮压到六轮，成本降幅往往超过四成，这也是「先优化收敛，再优化模型」这条工程顺序的原因。

多 Agent 的成本结构不同：单 Agent 的上下文是累积膨胀，多 Agent 是每段上下文各自小但份数多。通信内容需要序列化，序列化会丢信息，于是需要额外轮次澄清。经验法则是：当交接次数超过两次仍说不清一件事，就应该合并角色，或把共享信息沉到记忆层而不是塞进消息。

反思机制对成本的影响是双向的。一次失败反思带来一条短经验条目，体积通常远小于重跑整条轨迹；但如果反思条目无限累积且不去重，它会变成新的上下文负担。合理做法是给经验条目设上限并按命中次数排序，只保留最有解释力的若干条。

## 常见误区与易错点

- **把智能体当聊天框。** 没有显式状态与终止条件的循环，等于没有终点的高速公路。
- **让模型自己判断是否完成。** 必须叠加可验证的外部判据，例如测试通过或字段齐备。
- **不设轮次与成本预算。** 一个失败的评审循环能在十分钟内耗尽一天额度。
- **观察结果原样入栈。** 大段日志或网页会挤掉真正有用的指令区。
- **反思只写结论不写改法。** 下一轮无法据此改变动作，等于没写。
- **语义记忆只增不改。** 过期事实与新事实冲突时，检索会带回互相矛盾的两条。
- **所有 Agent 共享全量工具。** 选错工具的概率与越权风险同时上升。
- **为拆而拆。** 交接序列化丢信息，多角色反而多花轮次。
- **评审与执行同一个模型同一份上下文。** 自我评审容易自我确认，返工理由含糊。
- **忽略幂等与重放。** 有写操作的节点必须可重入，否则恢复时会重复扣款。
- **状态图无边条件。** 图退化成直线，出现分支需求时只能重写。

## 自测题与参考答案

**教材衔接：题号 1** — 任务步骤多于八步且中途可能改路线，Plan-and-Execute 相比 ReAct 的优势是？

**参考答案**：先出全局计划便于中途重排。

本题正确项是「先出全局计划便于中途重排」。显式计划把目标拆成可检查的步骤清单，一旦某步失败或前提变化，重规划的代价只是改局部步骤，进度也能对外展示。ReAct 每步都靠即时观察决定下一步，长任务容易绕圈；两种范式都仍需工具落实动作，上下文长度取决于裁剪与摘要策略。

**教材衔接：题号 2** — 情节记忆与长期语义记忆的区别在于？

**参考答案**：前者记录具体交互过程与结果。

本题正确项是「前者记录具体交互过程与结果」。情节记忆保存某次任务的时间、动作、结果和反馈，用于回放与复盘；语义记忆沉淀可复用的事实与偏好，用于跨任务检索。两者都能用向量或结构化方式实现，容量都受存储与检索策略约束，把它们说成无限或不依赖窗口是把分层概念当成了魔法。

**教材衔接：题号 3** — 多 Agent 协作里，评审 Agent 反复要求返工导致死循环，应先检查？

**参考答案**：返工次数上限与终止条件是否设置。

本题正确项是「返工次数上限与终止条件是否设置」。循环的直接成因是缺少终止判据，必须先给最大轮次、验收标准和升级出口，让分歧在有限步内收敛或转人工。同模型与否影响的是视角多样性，温度一致与否不是终止条件，检索工具只补充证据，都不解决没有刹车这一根本问题。

**教材衔接：题号 4** — Reflexion 相对普通重试的核心增益来自？

**参考答案**：把失败反思写成可复用的经验。

本题正确项是「把失败反思写成可复用的经验」。Reflexion 在失败后让模型总结教训并存入记忆，下次尝试携带该经验，从而避免重复同一个错误，把重试变成有信息增量的迭代。提高温度只是让采样更发散，可能换一种错法；并发调用提升吞吐而不改变决策质量，压缩提示词省的是成本。

**教材衔接：题号 5** — 下面这个状态机路由函数的两次打印结果是？
def route(state):
    return 'tool' if state['tool_calls'] else 'end'

print(route({'tool_calls': []}), route({'tool_calls': ['q']}))

**参考答案**：end 和 tool。

本题正确项是「end 和 tool」。三元表达式看的是列表本身是否为真值，空列表在 Python 里等价于 False，因此第一次走 end 分支，只有一个元素的列表为 True 则走 tool 分支。把空列表当成真值就会得到 tool 和 end，误以为路由依赖字段是否存在则两次都判成 tool，短路判断的布尔语义是状态机的关键。

## 考点精讲

**教材衔接：高频考点**

1. 两种规划范式的适用边界：步数、可重排性、成本三者如何权衡。
2. 终止条件的三件套：目标达成、预算耗尽、熔断触发。
3. 情节记忆与语义记忆在写入路径与淘汰策略上的差异。
4. 多 Agent 死循环的第一排查项是返工上限与终止条件，而非温度参数。

**教材衔接：命题规律**

- 偏爱给出具体步数或结构（八步以上、中途改路线），要求据此选出范式。
- 故障排错题常以「反复返工」「不断重跑第一步」为现象，正确项指向缺失的显式约束。
- 记忆类题目喜欢用「只存向量」「容量无限」等绝对化表述作为排除项。

**教材衔接：常见考点**

问：任务步骤多于八步且中途可能改路线，Plan-and-Execute 相比 ReAct 的优势是？
答：先出全局计划便于中途重排。

问：情节记忆与长期语义记忆的区别在于？
答：前者记录具体交互过程与结果。

问：多 Agent 协作里，评审 Agent 反复要求返工导致死循环，应先检查？
答：返工次数上限与终止条件是否设置。

问：Reflexion 相对普通重试的核心增益来自？
答：把失败反思写成可复用的经验。

问：下面这个状态机路由函数的两次打印结果是？
def route(state):
    return 'tool' if state['tool_calls'] else 'end'

print(route({'tool_calls': []}), route({'tool_calls': ['q']}))
答：end 和 tool。

## 术语速查

| 术语 | 一句话说明 |
| --- | --- |
| 智能体循环 | 思考、行动、观察三者反复推进直到满足终止条件。 |
| ReAct | 每轮依据最新观察决定下一步，适合路径不确定的任务。 |
| Plan-and-Execute | 先出整体计划再执行，便于重排与对齐交付物。 |
| Reflexion | 把失败写成可复用经验条目并在下一轮注入上下文。 |
| 情节记忆 | 记录具体交互过程与结果，按会话与时间检索。 |
| 语义记忆 | 跨会话稳定的事实与偏好，需要冲突消解。 |
| 工具注册表 | 当前可见的工具集合，是权限与作用域的边界。 |
| 状态机 | 用节点、条件边与共享状态显式描述流程的结构。 |
| 监督者 | 拆分与路由子任务并验收结果的中枢角色。 |
