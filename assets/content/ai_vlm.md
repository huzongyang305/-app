### 图像是怎么变成 token 送进语言模型的

主线里的「跨模态对齐」不神秘，拆开就是下面这条流水线，看懂它就能理解为什么分辨率会直接决定成本：

```text
原始图像(高 × 宽 × 3)
  → 视觉编码器(ViT / CLIP 那类)：把图切成 patch 网格，逐块编码成一串向量
  → 投影层：把视觉向量映射到和文字词嵌入同一个空间
  → 拼接成一条序列  [img_1 … img_n][你的提问 token …]
  → 语言模型照常自回归，输出答案 / 坐标 / 表格

投影层没对齐好，就会出现「图看对了、答的却是另一回事」，也就是答非所图。
```

## 典型应用场景

- **把整张图当成完整信息源**：典型现象是小字与细节被误读；正确做法是对关键区域裁剪放大后二次提问，并交叉核对。

### 完整示例：估算一张图占多少视觉 token

本课反复说「分辨率和切块影响质量与成本」，这里用一个不依赖任何库的小函数把这句话变成能算的数：先按 patch 切网格，再按 merge×merge 合并，得到的就是送进语言模型的视觉 token 数量级。

```python
def visual_tokens(width, height, patch=16, merge=2):
    """估算送进 LLM 的视觉 token 数：网格数除以 merge 的平方。"""
    cols = width // patch
    rows = height // patch
    return (cols // merge) * (rows // merge)

print(visual_tokens(448, 448))    # 常见的单图输入尺寸
print(visual_tokens(1024, 768))   # 换更大分辨率，token 涨得更凶
```

```text
196
768
```

动手练一练：把 merge 改成 1 再跑，观察 token 数正好变成四倍；这解释了为什么高清输入账单会跳涨。真做读表或密集小目标时，还会把整图切成若干 tile 分别提问，token 要再乘上块数——所以精确数字最好交给 OCR，视觉只负责定位与理解。

## 与其他知识点的关系

**教材衔接：复习与迁移**

VLM 站在纯文本 LLM 的肩膀上，多出来的只是视觉编码器和一层投影：把它接进 RAG 就成了图文混合检索，接进 Agent 就让它负责「看懂截图再决定点哪」。和 OCR 的分工要拎清楚——本课错误表里那条「精确计数与读表」正是提醒：数字、表格、小字这类要百分之百对的活交给 OCR 或结构化解析，VLM 只用来理解和定位，两边结果互相校验。评测维度也和 LLM 相通，只是额外多了空间关系和视觉幻觉这两类要专门盯的坑。
