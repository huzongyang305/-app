## 原理与运行机制

### 机制总览

1. **建立输入**：把「抓包」按本课定义整理成可观察、可重复的输入条件。
2. **执行转换**：围绕「Wireshark」执行本课的核心步骤；每一步都记录中间状态，避免只看最终输出。
3. **产生输出**：得到「TCP」后，用正文示例或协议/SQL 结果核对输出是否符合预期。
4. **改变一个条件**：只替换一个边界条件或环境参数，观察「网络抓包与协议分析实战」的结论是否仍然成立。

| 阶段 | 关注对象 | 失败时应检查 |
| --- | --- | --- |
| 输入 | 抓包 | 类型、范围、编码、版本或前置状态是否满足定义。 |
| 处理 | Wireshark | 顺序、可见性、锁、路由、事务或调度规则是否被破坏。 |
| 输出 | TCP | 结果是否可复现，错误是否被正确传播而不是被吞掉。 |

本课的机制结论要用「网络抓包与协议分析实战」自己的示例验证。「网络抓包与协议分析实战」没有给出某个数量级、吞吐或内存数据时，本课把该判断标为“材料未提供”，不从相邻主题外推。

**教材衔接：实施步骤**

### 里程碑 1：搭一套可重复的链路

用容器启动 nginx、一个慢接口与一个正常接口，固定并发、请求次数和客户端机器，保证每次实验的输入一致。

抓取 8080 与 443 端口的流量，分别用 http、dns、tcp.flags.reset 和 tcp.analysis_retransmission 过滤，记录每条过滤命令的输出。

### 里程碑 3：按阶段做时间线并复测

把 DNS、握手、TLS、首字节和最后字节的时间戳写进表格，找出占比最大的阶段；只改一个变量后复测同一组请求并对比 P95 与重传次数。
