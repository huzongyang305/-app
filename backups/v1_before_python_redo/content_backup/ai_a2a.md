## 典型应用场景

- **把 A2A 当成普通模型接口**：典型现象是只用自然语言约定调用，缺少任务、角色与能力描述；正确做法是按 Agent Card 声明能力，用任务与消息结构描述状态和结果。
- **任务状态不幂等**：典型现象是重复投递同一任务导致对方 Agent 重复执行；正确做法是任务带唯一 ID 与状态机，接收方按 ID 去重并回传终态。
- **长任务只等一次响应**：典型现象是请求超时后直接重试，任务被重复触发；正确做法是用流式事件或回调跟踪进度，超时后先查任务状态再决定是否重试。

### 最小验证场景

- 准备：保留 `text` 示例的原始输入，先记录 `A2A Agent 协作协议` 的基线输出和完整运行命令。
- 观察：先核对 调用了 `score()`，再改变一个与 `A2A` 相关的条件。
- 判定：新结果与 `A2A Agent 协作协议` 的基线不同不等于错误；只有当差异破坏了 `A2A` 的定义或错误表中的约束，才判定为失败。

### 选择与边界

- 使用 `任务委派` 时，先满足它的定义：把子目标连同上下文交给另一个 Agent 执行，再汇总各自结果；只在「把子目标连同上下文交给另一个 Agent 执行，再汇总各自结果」这一前提下成立，换输入或换环境要重新验证。
