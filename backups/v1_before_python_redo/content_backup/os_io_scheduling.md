### 机械盘与 SSD 的目标不同

机械盘的主要成本是寻道与旋转延迟，调度目标是把相邻请求合并、减少磁头来回移动，
经典算法有电梯（SCAN）与 CFQ。SSD 没有机械寻道，但有擦除块、写放大与并行通道，
更适合多队列、低开销的调度器，过度合并反而增加尾延迟。设备类型不同，最优策略不同。

### 队列深度与延迟

提高队列深度能提升吞吐，但每个请求的排队时间也变长。交互式负载关心 P99 延迟，
批处理负载关心总吞吐，两者对调度器的要求相反。Linux 的 mq-deadline 优先保证
读延迟，kyber 控制同步与异步请求的排队目标，none 则把决策交给更快的硬件。
选择前先测量设备与负载特征。

### 从应用到设备的完整链路

一次磁盘 I/O 会经过文件系统页缓存、块层队列、调度器、设备驱动与控制器缓存。
「I/O 慢」可能来自页缓存命中率低、队列拥塞、写放大或应用自身的小块随机访问。
排查时先看 iostat 的 await、队列长度与利用率，再看应用是否把顺序访问写成了
逐条小请求。调度器只是链路中的一环，不能替代对访问模式的分析。

## 典型应用场景

- **只换调度器不看负载类型**：典型现象是随机与顺序负载的表现相反；正确做法是按负载特征选择调度策略并用指标验证。
- **盲目加大队列深度**：典型现象是延迟升高，尾延迟更差；正确做法是结合延迟与队列深度一起调整。
- **忽略文件系统与缓存层**：典型现象是磁盘指标正常但应用仍慢；正确做法是分段观察缓存命中、文件系统与设备层。

### 选择与边界

- 使用 `IO 调度` 时，先满足它的定义：在多个块设备请求之间决定合并与执行顺序，平衡吞吐和延迟；结论随输入规模变化，小规模成立不代表大规模成立，需要重新测量。
- 使用 `块设备` 时，先满足它的定义：按固定大小块读写数据的设备，如磁盘和 SSD；只在「按固定大小块读写数据的设备，如磁盘和 SSD」这一前提下成立，换输入或换环境要重新验证。
- 使用 `队列` 时，先满足它的定义：按先进先出顺序存取元素的数据结构或消息容器；易错：延迟升高，尾延迟更差；正确做法是结合延迟与队列深度一起调整。
- 使用 `公平性` 时，先满足它的定义：调度或限流在等待时间、资源份额和优先级之间维持可接受的分配结果；只在「调度或限流在等待时间、资源份额和优先级之间维持可接受的分配结果」这一前提下成立，换输入或换环境要重新验证。
- 使用 `机械盘` 时，先满足它的定义：机械盘的主要成本是寻道与旋转延迟，调度目标是把相邻请求合并、减少磁头来回移动；结论随输入规模变化，小规模成立不代表大规模成立，需要重新测量。
