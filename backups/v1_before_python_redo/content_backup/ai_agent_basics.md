## 核心概念定义

| 术语 | 操作性定义 | 常见边界与风险 |
| --- | --- | --- |
| Agent | Agent = LLM + 工具 + 记忆 + 循环。 | 易错：Agent 越权操作；正确做法是工具层做白名单与参数校验，不依赖提示词。 |
| ReAct | ReAct = Reasoning + Acting，是最经典的 Agent 模式。 | 只在「ReAct = Reasoning + Acting，是最经典的 Agent 模式」这一前提下成立，换输入或换环境要重新验证。 |
| 工具调用 | 模型按结构化参数请求外部函数或服务，并把结果带回后续推理。 | 易错：无法发现绕路与危险调用；正确做法是评测完整轨迹与工具调用序列。 |
| MCP | Model Context Protocol，用统一协议把工具和数据源暴露给模型客户端。 | 网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。 |

### 机制总览

**教材衔接：记忆**

| 类型 | 说明 |
| --- | --- |
| 短期记忆 | 当前对话的上下文窗口 |
| 长期记忆 | 向量库存放的事实与偏好，按需检索 |
| 情景记忆 | 过去任务的过程与结果，用于复盘 |
| 语义记忆 | 抽象出的规则与知识 |

上下文过长时需要**压缩与遗忘策略**：摘要历史、保留关键事实、按相关性检索，而不是无脑全塞。

**教材衔接：设计清单**

1. 工具描述写清楚用途、参数与返回结构，模型才会用对。
2. 所有工具调用都要有超时、重试与幂等设计。
3. 关键操作（转账、删除、发邮件）必须人工确认（Human-in-the-loop）。
4. 设置最大步数、最大 token 与预算上限。
5. 全程记录 trace，方便回放与定位问题。

**教材衔接：ReAct 循环的可运行骨架**

```python
import json

MAX_STEPS = 6                     # 必须设上限，否则可能无限调用

TOOLS = {
    "get_weather": lambda city: {"city": city, "temp": 24, "desc": "多云"},
    "search_docs": lambda q: {"hits": ["..."]},
}

def run_agent(question: str) -> str:
    messages = [
        {"role": "system", "content":
         "你可以调用工具。需要时输出 JSON："
         '{"action":"工具名","args":{...}}；可以直接回答时输出 '
         '{"action":"final","args":{"answer":"..."}}'},
        {"role": "user", "content": question},
    ]
    for step in range(MAX_STEPS):
        raw = llm(messages)                       # 模型只负责决策
        plan = json.loads(raw)
        if plan["action"] == "final":
            return plan["args"]["answer"]
        tool = TOOLS.get(plan["action"])          # 白名单校验，未知工具直接拒绝
        if tool is None:
            messages.append({"role": "user", "content": "工具不存在，请重试"})
            continue
        try:
            result = tool(**plan["args"])         # 由我们的代码真正执行
        except Exception as exc:
            result = {"error": str(exc)}
        messages.append({"role": "user",
                         "content": "工具返回：" + json.dumps(result, ensure_ascii=False)})
    return "已达最大步数，未能完成任务"
```

三个安全边界：**工具白名单**（模型不能调用未注册能力）、**参数校验与异常兜底**（工具失败要回传错误而非崩溃）、**最大步数**（防止无限循环烧钱）。生产环境还要加超时、权限校验与人工确认点。

**教材衔接：Agent 组成速查**

| 组成 | 作用 | 设计要点 |
| --- | --- | --- |
| 模型 | 推理与决策 | 按任务难度选择，支持工具调用 |
| 系统提示 | 定义角色、边界、输出规范 | 版本化管理，配合评测 |

| 反思 | 自我检查与纠错 | 明确的验收标准 |
| 护栏 | 权限与安全 | 白名单、速率限制、敏感操作二次确认 |
| 可观测性 | 排查与优化 | 记录完整轨迹、Token 与耗时 |

### 五、AI 工程补充

在AI Agent 基础里，模型输出只是系统的一部分：输入要先经过权限与数据质量检查，检索或工具调用要有超时和降级，输出要经过引用核验或规则校验，最后记录 token、延迟、失败类型和人工反馈。评测时至少准备固定题、边界题和对抗题，并把 Agent 与 ReAct 的指标分开记录；否则一次提示词改动看似提升体验，实际可能只是评测样本泄漏或随机波动。

### 机制拆解：每一步的输入、动作与输出

#### 1. `Agent`
- 输入：`Agent`；本步把 Agent = LLM + 工具 + 记忆 + 循环 当作判断规则。
- 动作：围绕 `Agent` 保留中间状态，并记录它与 `ReAct` 的对应关系。
- 输出：`ReAct`，它可以被下一段代码、测试或记录继续使用。
- `Agent` 的失败条件：当无权限控制时，会出现Agent 越权操作。

#### 2. `ReAct`
- 输入：`Agent`；本步把 ReAct = Reasoning + Acting，是最经典的 Agent 模式 当作判断规则。
- 动作：围绕 `ReAct` 保留中间状态，并记录它与 `工具调用` 的对应关系。
- 输出：`工具调用`，它可以被下一段代码、测试或记录继续使用。
- `ReAct` 的失败条件：只在「ReAct = Reasoning + Acting，是最经典的 Agent 模式」这一前提下成立，换输入或换环境要重新验证。

#### 3. `工具调用`
- 输入：`ReAct`；本步把 模型按结构化参数请求外部函数或服务，并把结果带回后续推理 当作判断规则。
- 动作：围绕 `工具调用` 保留中间状态，并记录它与 `MCP` 的对应关系。
- 输出：`MCP`，它可以被下一段代码、测试或记录继续使用。
- `工具调用` 的失败条件：当只评测最终答案时，会出现无法发现绕路与危险调用。

#### 4. `MCP`
- 输入：`工具调用`；本步把 Model Context Protocol，用统一协议把工具和数据源暴露给模型客户端 当作判断规则。
- 动作：围绕 `MCP` 保留中间状态，并记录它与 `run_agent` 的对应关系。
- 输出：`run_agent`，它可以被下一段代码、测试或记录继续使用。
- `MCP` 的失败条件：网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。

## 典型应用场景

- **不给步数上限**：典型现象是无限循环，成本失控；正确做法是明确最大步数与超时。
- **工具描述模糊**：典型现象是模型传错参数、反复重试；正确做法是写清用途、参数含义与返回结构。
- **工具无幂等保护**：典型现象是重试导致重复下单；正确做法是引入幂等键，写操作加确认。
- **把所有内容塞进上下文**：典型现象是成本高、注意力涣散；正确做法是只放必要信息，长文档走检索。

### 最小验证场景

- 准备：保留 `text` 示例的原始输入，先记录 `AI Agent 基础` 的基线输出和完整运行命令。
- 观察：先核对 调用了 `run_agent()`，再改变一个与 `Agent` 相关的条件。
- 判定：新结果与 `AI Agent 基础` 的基线不同不等于错误；只有当差异破坏了 `Agent` 的定义或错误表中的约束，才判定为失败。

### 选择与边界

- 使用 `Agent` 时，先满足它的定义：Agent = LLM + 工具 + 记忆 + 循环；易错：Agent 越权操作；正确做法是工具层做白名单与参数校验，不依赖提示词。
- 使用 `ReAct` 时，先满足它的定义：ReAct = Reasoning + Acting，是最经典的 Agent 模式；只在「ReAct = Reasoning + Acting，是最经典的 Agent 模式」这一前提下成立，换输入或换环境要重新验证。
- 使用 `工具调用` 时，先满足它的定义：模型按结构化参数请求外部函数或服务，并把结果带回后续推理；易错：无法发现绕路与危险调用；正确做法是评测完整轨迹与工具调用序列。
- 使用 `MCP` 时，先满足它的定义：Model Context Protocol，用统一协议把工具和数据源暴露给模型客户端；网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。

## 代码/协议/SQL 示例

**教材衔接：Agent 与普通对话的区别**

```text
普通 LLM：输入 -> 输出（一轮问答）
Agent   ：目标 -> 思考 -> 调用工具 -> 观察结果 -> 再思考 -> …… -> 完成
```

一个 Agent 通常由四部分组成：

| 组成 | 作用 |
| --- | --- |
| 模型（大脑） | 决策、规划、生成 |
| 工具（手脚） | 搜索、计算、数据库、代码执行、API |
| 记忆 | 保存对话、事实与历史经验 |
| 循环控制 | 决定何时继续、何时结束、何时交给人 |

**教材衔接：ReAct 循环**

ReAct = Reasoning + Acting，是最经典的 Agent 模式：

```text
Thought     我需要知道今天的汇率
Action      调用 tool: get_exchange_rate(currency="USD", date="today")
Observation {"rate": 7.12}
Thought     已经拿到数据，可以回答了
Answer      今天美元兑人民币约为 7.12
```

要点：每一步都要**可观察、可中断、可重试**；循环必须有最大步数上限，否则可能无限调用工具。

**教材衔接：工具调用（Function Calling）**

```python
tools = [{
    "type": "function",
    "function": {
        "name": "query_orders",
        "description": "按用户 ID 查询订单列表",
        "parameters": {
            "type": "object",
            "properties": {
                "user_id": {"type": "string", "description": "用户唯一标识"},
                "limit": {"type": "integer", "default": 10},
            },
            "required": ["user_id"],
        },
    },
}]
```

流程：把工具描述交给模型 → 模型返回「要调用哪个函数、参数是什么」→ 你的程序真正执行 → 把结果回传给模型 → 模型决定下一步。**模型只负责决定，执行必须由你的代码控制并做权限校验。**

**教材衔接：循环与终止条件速查**

| 环节 | 说明 |
| --- | --- |
| 观察（Observe） | 读取输入、工具返回与中间结果 |
| 思考（Think） | 分析现状、决定下一步 |
| 行动（Act） | 调用工具或给出答案 |
| 终止 | 得到最终答案、达到步数上限、超时、预算耗尽、需要人工介入 |

```text
你可以使用以下工具：
- search_docs(query: string) -> 返回最相关的 5 个片段
- run_sql(sql: string) -> 只允许 SELECT，最多返回 100 行

工作规则：
1. 先检索资料再回答，禁止凭记忆编造字段名。
2. 每次只调用一个工具，观察结果后再决定下一步。
3. 最多调用 6 次工具；仍无法确定时，说明缺少什么信息。
4. 最终回答必须引用来源片段编号。
```
