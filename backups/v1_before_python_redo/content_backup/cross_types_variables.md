## 原理与运行机制

### 机制总览

**教材衔接：一句话目标**

变量「怎么声明、能不能改、能不能换类型」，最能体现一门语言的性格。
本文把九种语言放在同一张表里对照。

**教材衔接：空值怎么表达**

| 语言 | 空值 | 检查方式 |
| --- | --- | --- |
| Python | `None` | `if x is None:` |
| JavaScript | `null` / `undefined` | `x == null` 或 `x === undefined` |
| TypeScript | 同 JavaScript，加 `strictNullChecks` | 用 `?.` 与 `??` |
| Java | `null` | `Optional` 或判空 |
| C# | `null`（可空引用类型） | `?.` 与 `??` |
| C++ | `nullptr` | 判空或 `std::optional` |
| Go | `nil`（仅指针、切片、map、接口等） | `if x == nil` |
| Rust | 没有 null，用 `Option<T>` | `match`、`?`、`unwrap_or` |
| Shell | 空字符串 `""` | `[[ -z "$x" ]]` |

**Rust 用类型系统消灭了空指针**：想表达「可能没有」，就必须用 `Option<T>`，编译器强制你处理。

## 典型应用场景

- **用一门语言的类型规则套另一门**：典型现象是隐式转换与溢出行为完全不同；正确做法是先查目标语言的数据模型与转换规则再迁移代码。
- **忽略数值宽度与默认类型**：典型现象是整型溢出或浮点精度丢失；正确做法是明确位宽与精度，必要时显式指定类型。
- **把空值与缺失混为一谈**：典型现象是不同语言里空、未定义与默认值语义不同；正确做法是明确区分空值、缺失与默认值，并在序列化时写清约定。

## 代码/协议/SQL 示例

**教材衔接：数字与字符串的坑：九种语言对比**

```python
# Python：类型错误会直接抛异常
"1" + 1          # TypeError
"1" + str(1)     # "11"
int("1") + 1     # 2
```

```javascript
// JavaScript：会隐式转换，最容易踩坑
"1" + 1          // "11"（字符串拼接）
"1" - 1          // 0（转成数字）
Number("1") + 1  // 2
```

```typescript
// TypeScript：编译期就拦住
const a: number = 1;
// a + "1" 会被允许（结果为 string），但类型会变化
```

```java
// Java：字符串与数字相加会拼接，且顺序影响结果
System.out.println(1 + 2 + "a");   // "3a"
System.out.println("a" + 1 + 2);   // "a12"
```

```csharp
// C#：字符串插值是更安全的写法
Console.WriteLine($"{1 + 1}");      // "2"
```

```cpp
// C++：整数除法丢小数是最经典的坑
double a = 5 / 2;                  // 2.0，不是 2.5
double b = 5 / 2.0;                // 2.5
```

```go
// Go：类型严格，必须显式转换
var a int = 1
// var b float64 = a        // 编译错误
b := float64(a) + 1.5
```

```rust
// Rust：同样严格，整数与浮点不能混算
let a = 1i32;
let b = a as f64 + 1.5;
```

```bash
# Shell：一切皆字符串，需要算术时用 (( ))
a=1
b=$((a + 2))
echo "$b"                        # 3
echo "$a + 2"                    # 1 + 2（字符串）
```

- **不可变 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 9：`装箱与拆箱`

- **要点**：值类型转成堆上对象再取回，每次都会分配或复制，是循环里常见的隐形开销。
- **装箱与拆箱 的边界**：静态检查只在编译期成立，运行期输入仍需校验。

### 考点 10：`隐式转换`

- **要点**：编译器自动完成的类型转换，可能静默丢精度或改变比较结果，跨类型运算时要显式写清。
- **隐式转换 的边界**：易错：隐式转换与溢出行为完全不同；正确做法是先查目标语言的数据模型与转换规则再迁移代码。

### 考点 11：排错——用一门语言的类型规则套另一门

- **现象**：隐式转换与溢出行为完全不同。
- **处理**：先查目标语言的数据模型与转换规则再迁移代码。

### 考点 12：排错——忽略数值宽度与默认类型

- **现象**：整型溢出或浮点精度丢失。
- **处理**：明确位宽与精度，必要时显式指定类型。

### 考点 13：综合辨析——`变量` 与 `隐式转换`

- **辨析点**：`变量` 的定义是 类型与变量：九种语言横向对照解决了什么问题，而不是只背术语；`隐式转换` 的定义是 编译器自动完成的类型转换，可能静默丢精度或改变比较结果，跨类型运算时要显式写清。
- **答题要求**：面对 `类型与变量：九种语言横向对照` 的题目，先判断描述的是 `变量` 还是 `隐式转换`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 14：排错评分点

- **现象分**：能写出 隐式转换与溢出行为完全不同，而不是只写“程序有错”。
- **证据分**：保留触发 用一门语言的类型规则套另一门 的输入、版本和错误原文。
- **修复分**：按 先查目标语言的数据模型与转换规则再迁移代码 只改一处，并同时回归正常路径与边界路径。
