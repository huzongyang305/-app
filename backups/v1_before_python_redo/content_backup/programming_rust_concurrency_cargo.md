**教材衔接：异步生态**

`async/await` 由编译器生成状态机，需要运行时（最常用 tokio）。要点：异步函数返回 Future，必须被 await 或 spawn 才会执行；CPU 密集任务不要放在异步任务里阻塞运行时，应用 `spawn_blocking`。

- **闭包忘了 `move`**：典型现象是生命周期不够长；正确做法是加 `move` 转移所有权。

- **锁使用过久**：典型现象是性能差甚至死锁；正确做法是缩小临界区，尽早释放。

## 代码/协议/SQL 示例

### 最小可验证示例

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();

    for _ in 0..4 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            for _ in 0..1000 {
                let mut value = counter.lock().unwrap();
                *value += 1;
            }
        }));
    }

    for handle in handles {
        handle.join().unwrap();
    }
    println!("{}", *counter.lock().unwrap());   // 4000
}
```

- **要点**：Mutex 提供内部可变性并保证同一时刻只有一个线程访问数据，注意避免死锁与长时间持锁。
- **互斥锁 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 11：排错——闭包忘了 `move`

- **现象**：生命周期不够长。
- **处理**：加 `move` 转移所有权。

### 考点 12：排错——直接共享 `Rc`

- **现象**：`Rc` 不能跨线程。
- **处理**：改 `Arc`。

### 考点 13：综合辨析——`Send` 与 `互斥锁`

- **辨析点**：`Send` 的定义是 Rust 用两个标记 trait 保证并发安全：`Send`（可在线程间转移所有权）、`Arc<Mutex<T>>` 是跨线程共享可变状态的经典组合；`互斥锁` 的定义是 Mutex 提供内部可变性并保证同一时刻只有一个线程访问数据，注意避免死锁与长时间持锁。
