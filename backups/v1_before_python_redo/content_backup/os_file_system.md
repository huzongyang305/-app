**教材衔接：常见文件系统**

| 系统 | 特点 |
| --- | --- |
| ext4 | Linux 主流，稳定成熟，支持日志 |
| XFS | 大文件与高并发表现好 |
| Btrfs / ZFS | 支持快照、校验和、压缩 |
| NTFS | Windows 主流，支持权限与日志 |

**教材衔接：元数据与结构速查**

| 概念 | 说明 |
| --- | --- |
| inode | 存放元数据与数据块指针，不含文件名 |
| 目录项 | 文件名到 inode 的映射 |
| 数据块 | 实际数据存储单位，常见 4KB |
| 超级块 | 文件系统整体信息 |
| 日志（journal） | 记录元数据变更，崩溃后快速恢复 |
| 挂载点 | 文件系统在目录树中的位置 |
| 硬链接 | 多个名字指向同一 inode |
| 软链接 | 独立文件，内容为目标路径 |

```bash

# 权限与所有权

chown app:app /data
getfacl /data              # 查看 ACL
```

```python
import os
from pathlib import Path
from collections import defaultdict

def disk_usage_report(root: str, top_n: int = 5) -> dict:
    """按目录汇总大小，找出占用最大的若干项。"""
    totals = defaultdict(int)
    for dirpath, _dirnames, filenames in os.walk(root):
        for name in filenames:
            path = Path(dirpath) / name
            try:
                size = path.stat().st_size
            except OSError:
                continue
            parts = path.relative_to(root).parts
            key = parts[0] if len(parts) > 1 else "(files)"
            totals[key] += size
    ordered = sorted(totals.items(), key=lambda item: -item[1])[:top_n]
    return {
        "root": root,
        "top": [(k, round(v / 1024 / 1024, 2)) for k, v in ordered],
        "total_mb": round(sum(totals.values()) / 1024 / 1024, 2),
    }

def can_hardlink(src: str, dst: str) -> bool:
    """硬链接要求同一文件系统。"""
    return os.stat(src).st_dev == os.stat(Path(dst).parent).st_dev

print(disk_usage_report(".").get("top"))
```

## 典型应用场景

- **只看 `df` 空间不看 `df -i`**：典型现象是报「空间不足」但明明有空间；正确做法是inode 耗尽，需清理小文件。
- **删了文件空间没释放**：典型现象是`df` 没变化；正确做法是文件仍被进程持有，需重启或清空句柄。
- **认为硬链接能跨文件系统**：典型现象是报错；正确做法是跨文件系统用软链接。
- **删除源文件后软链接仍可用**：典型现象是悬空链接；正确做法是软链接保存路径，源删除即失效。

## 代码/协议/SQL 示例

**教材衔接：inode 与元数据**

- **inode**：保存文件的元数据（大小、权限、时间戳、数据块位置），不含文件名。
- **目录项**：文件名到 inode 的映射。
- **数据块**：真正存放文件内容的磁盘块。

```text
目录项 "report.txt" -> inode #12345 -> [块 100, 块 101, 块 210]
```

硬链接是多个文件名指向同一 inode；符号链接是保存目标路径的独立文件。

**教材衔接：日志与一致性**

断电时正在写的数据可能只写了一半。日志（journaling）先把元数据操作写入日志区，再真正落盘，崩溃后可重放或回滚，避免文件系统结构损坏。

```text
1. 写日志（intent）
2. 提交日志
3. 写入实际位置（checkpoint）
```

### 考点 7：`文件系统`

- **要点**：文件系统把块设备抽象成文件与目录，负责：空间分配、目录管理、权限控制、崩溃恢复与缓存。
- **文件系统 的边界**：易错：报错；正确做法是跨文件系统用软链接。

### 考点 8：`inode`

- **要点**：inode：保存文件的元数据（大小、权限、时间戳、数据块位置），不含文件名。
- **inode 的边界**：易错：报「空间不足」但明明有空间；正确做法是inode 耗尽，需清理小文件。

### 考点 9：`目录`

- **要点**：文件系统中组织和索引文件的特殊节点。
- **目录 的边界**：易错：长时间阻塞；正确做法是用分批删除或工具加速。

### 考点 10：`日志`

- **要点**：文件系统 = inode + 目录 + 数据块 + 日志。
- **日志 的边界**：易错：磁盘被日志写满；正确做法是配 `logrotate` 或应用级切割。

### 考点 11：`ext4`

- **要点**：Linux 常用的日志文件系统，提供大文件、目录索引和崩溃恢复支持。
- **ext4 的边界**：索引命中与数据分布决定实际开销，判断前先看执行计划而不是只看结果是否正确。

### 考点 12：`NTFS`

- **要点**：Windows 常用的日志文件系统，支持权限、加密、压缩和大卷。
- **NTFS 的边界**：权限与密钥策略变化会让结论失效，按最小权限并用真实凭据流程复验。

### 考点 13：排错——只看 `df` 空间不看 `df -i`

- **现象**：报「空间不足」但明明有空间。
- **处理**：inode 耗尽，需清理小文件。

### 考点 14：排错——删了文件空间没释放

- **现象**：`df` 没变化。
- **处理**：文件仍被进程持有，需重启或清空句柄。

### 考点 15：综合辨析——`文件系统` 与 `NTFS`

- **辨析点**：`文件系统` 的定义是 文件系统把块设备抽象成文件与目录，负责：空间分配、目录管理、权限控制、崩溃恢复与缓存；`NTFS` 的定义是 Windows 常用的日志文件系统，支持权限、加密、压缩和大卷。
- **答题要求**：面对 `文件系统基础` 的题目，先判断描述的是 `文件系统` 还是 `NTFS`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 16：排错评分点

- **现象分**：能写出 报「空间不足」但明明有空间，而不是只写“程序有错”。
- **证据分**：保留触发 只看 `df` 空间不看 `df -i` 的输入、版本和错误原文。
- **修复分**：按 inode 耗尽，需清理小文件 只改一处，并同时回归正常路径与边界路径。
