## 原理与运行机制

### 机制总览

**教材衔接：核心知识**

### 1. 调试接口与连接

SWD 用两根信号线就能完成烧录与调试，比 JTAG 更省引脚。

调试器通过 SWDIO 与 SWCLK 访问芯片的调试访问口，读取内核寄存器与内存，断点由硬件比较器或软件指令实现。

在嵌入式调试与追踪里可以这样验证：在本课示例里用调试器读取栈指针与 PC，确认芯片停在预期的位置。

边界：低功耗模式下调试逻辑被关闭会断开连接，调低功耗问题前要明确调试口是否保持供电。

工程视角：把调试接口保留在测试点上并标注引脚顺序，量产固件提供一次性解锁或关闭调试的配置。

### 2. 非侵入式追踪

追踪输出执行流而不暂停 CPU，适合排查时序敏感的问题。

内核把程序计数采样或事件数据从 SWO、ETM 等通道送出，调试器收集后还原调用序列与时间关系。

在嵌入式调试与追踪里可以这样验证：在本课示例里用追踪记录中断服务程序的进入次数，观察中断密度与任务响应时间的对应关系。

边界：追踪带宽有限，全量输出会造成丢包，只应打开关心的通道与事件。

工程视角：把追踪配置写成脚本，让每次复现使用同一组通道与触发条件，便于对比。

### 3. 故障现场保存与栈回溯

异常发生时先保留现场，再离线分析，比在设备上反复试错高效。

异常入口把关键寄存器压入指定内存区并写入异常原因寄存器，重启后由上位机解析栈内容与调用返回地址。

在嵌入式调试与追踪里可以这样验证：在本课示例里手动触发一次除零异常，读出压栈寄存器并还原到出错函数。

边界：栈被破坏后回溯会得到错误地址，此时应以异常原因寄存器与最近一次正常日志为准。

工程视角：给故障区加魔数与版本号，固件升级后仍能解析旧故障记录。

### 机制拆解：每一步的输入、动作与输出

#### 1. `SWD`
- 输入：`SWD`；本步把 ARM 的两线调试接口，用 SWDIO 与 SWCLK 访问内核 当作判断规则。
- 动作：围绕 `SWD` 保留中间状态，并记录它与 `硬件断点` 的对应关系。
- 输出：`硬件断点`，它可以被下一段代码、测试或记录继续使用。
- `SWD` 的失败条件：当调试器连不上目标时，会出现只接了 SWDIO 与 SWCLK，没有共地与参考电压。

#### 2. `硬件断点`
- 输入：`SWD`；本步把 由内核比较器实现的断点，不修改程序内容 当作判断规则。
- 动作：围绕 `硬件断点` 保留中间状态，并记录它与 `SWO` 的对应关系。
- 输出：`SWO`，它可以被下一段代码、测试或记录继续使用。
- `硬件断点` 的失败条件：只在「由内核比较器实现的断点，不修改程序内容」这一前提下成立，换输入或换环境要重新验证。

#### 3. `SWO`
- 输入：`硬件断点`；本步把 单线追踪输出通道，可输出事件与采样数据 当作判断规则。
- 动作：围绕 `SWO` 保留中间状态，并记录它与 `CFSR` 的对应关系。
- 输出：`CFSR`，它可以被下一段代码、测试或记录继续使用。
- `SWO` 的失败条件：当加了日志后故障消失时，会出现用串口打印调试时序敏感问题。

#### 4. `CFSR`
- 输入：`SWO`；本步把 可配置故障状态寄存器，记录异常的具体原因位 当作判断规则。
- 动作：围绕 `CFSR` 保留中间状态，并记录它与 `栈回溯` 的对应关系。
- 输出：`栈回溯`，它可以被下一段代码、测试或记录继续使用。
- `CFSR` 的失败条件：缓存与状态残留会让结果过期，先明确失效策略再判断正确性。

#### 5. `栈回溯`
- 输入：`CFSR`；本步把 按栈中返回地址还原函数调用链的过程 当作判断规则。
- 动作：围绕 `栈回溯` 保留中间状态，并记录它与 `__attribute__` 的对应关系。
- 输出：`__attribute__`，它可以被下一段代码、测试或记录继续使用。
- `栈回溯` 的失败条件：当栈回溯得到错误函数时，会出现栈已经被越界写坏仍按返回地址回溯。

### 自测问答

**问 1**：排查时序敏感的偶发问题时，优先选择的调试手段是？

**答**：非侵入式追踪。打印与断点都会改变时序，非侵入式追踪在不暂停内核的前提下采集执行流，更适合偶发时序问题。 正确选项「非侵入式追踪」对应《嵌入式调试与追踪》的要点「调试接口与连接」：SWD 用两根信号线就能完成烧录与调试，比 JTAG 更省引脚。判断「调试接口与连接」时先确认前提是否成立，再回到《嵌入式调试与追踪》的示例核对一次；把别的语言或框架的默认做法直接搬到调试接口与连接上，往往会在本课的边界条件里失效。

**问 2**：异常处理里先把 LR 与栈指针保存下来的目的是？

**答**：确定使用哪个栈并还原出错现场。异常可能使用主栈或进程栈，只有先判断栈指针来源，才能正确取出压栈的寄存器与出错地址。 正确选项「确定使用哪个栈并还原出错现场」对应《嵌入式调试与追踪》的要点「非侵入式追踪」：追踪输出执行流而不暂停 CPU，适合排查时序敏感的问题。判断「非侵入式追踪」时先确认前提是否成立，再回到《嵌入式调试与追踪》的示例核对一次；借鉴相邻主题的经验之前，先核对非侵入式追踪的前提是否成立。

**问 3**：以下哪些信息有助于定位一次硬件异常？（多选）

**答**：故障状态寄存器的原因位；压栈保存的出错 PC；异常发生前的最后一段日志。原因位说明异常类型，出错 PC 指向指令位置，之前的日志提供上下文，三者结合能快速缩小范围。 正确选项「故障状态寄存器的原因位；压栈保存的出错 PC；异常发生前的最后一段日志」对应《嵌入式调试与追踪》的要点「故障现场保存与栈回溯」：异常发生时先保留现场，再离线分析，比在设备上反复试错高效。判断「故障现场保存与栈回溯」时先确认前提是否成立，再回到《嵌入式调试与追踪》的示例核对一次；记住故障现场保存与栈回溯的结论之外还要记住适用条件，换一个输入往往就不成立了。

**问 4**：请按一次完整调试流程的顺序排列。

**答**：稳定复现问题。先能稳定复现，才有可对比的现场；定位到根因后再修改，最后用回归测试确认问题不再出现。 正确选项「稳定复现问题；采集现场数据；解析寄存器与调用链；修改代码修复根因；补回归测试并验证」对应《嵌入式调试与追踪》的要点「调试接口与连接」：SWD 用两根信号线就能完成烧录与调试，比 JTAG 更省引脚。判断「调试接口与连接」时先确认前提是否成立，再回到《嵌入式调试与追踪》的示例核对一次；干扰项常常是相邻主题里成立的结论，只有按调试接口与连接的输入与约束判断才能排除。

**问 5**：阅读这段故障采集代码，能得出什么结论？

### 考点 6：`SWD`

- **要点**：ARM 的两线调试接口，用 SWDIO 与 SWCLK 访问内核。
- **SWD 的边界**：易错：只接了 SWDIO 与 SWCLK，没有共地与参考电压；正确做法是确认共地、参考电压与复位线连接，降低调试时钟后重试并对目标做复位连接。

### 考点 7：`硬件断点`

- **要点**：由内核比较器实现的断点，不修改程序内容。
- **硬件断点 的边界**：只在「由内核比较器实现的断点，不修改程序内容」这一前提下成立，换输入或换环境要重新验证。

### 考点 8：`SWO`

- **要点**：单线追踪输出通道，可输出事件与采样数据。
- **SWO 的边界**：易错：用串口打印调试时序敏感问题；正确做法是改用缓冲日志或 SWO 追踪等非阻塞方式采集，避免打印改变时序。

### 考点 9：`CFSR`

- **要点**：可配置故障状态寄存器，记录异常的具体原因位。
- **CFSR 的边界**：缓存与状态残留会让结果过期，先明确失效策略再判断正确性。

### 考点 10：`栈回溯`

- **要点**：按栈中返回地址还原函数调用链的过程。
- **栈回溯 的边界**：易错：栈已经被越界写坏仍按返回地址回溯；正确做法是先看故障原因寄存器与最后一次有效日志，再对照内存保护单元配置缩小范围。

### 考点 11：排错——调试器连不上目标

- **现象**：只接了 SWDIO 与 SWCLK，没有共地与参考电压。
- **处理**：确认共地、参考电压与复位线连接，降低调试时钟后重试并对目标做复位连接。

### 考点 12：排错——加了日志后故障消失

- **现象**：用串口打印调试时序敏感问题。
- **处理**：改用缓冲日志或 SWO 追踪等非阻塞方式采集，避免打印改变时序。

### 考点 13：综合辨析——`SWD` 与 `栈回溯`

- **辨析点**：`SWD` 的定义是 ARM 的两线调试接口，用 SWDIO 与 SWCLK 访问内核；`栈回溯` 的定义是 按栈中返回地址还原函数调用链的过程。
- **答题要求**：面对 `嵌入式调试与追踪` 的题目，先判断描述的是 `SWD` 还是 `栈回溯`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 14：排错评分点

- **现象分**：能写出 只接了 SWDIO 与 SWCLK，没有共地与参考电压，而不是只写“程序有错”。
