## 原理与运行机制

### 机制总览

**教材衔接：一句话入门**

用 cargo new、run 和 check 创建项目。

**教材衔接：Rust 基础机制速览**

### Cargo、crate 与模块

Cargo 负责创建项目、管理依赖、编译和测试。包由 crate 组成，库 crate 对外暴露 API，二进制 crate 提供可执行入口。模块用 `mod` 组织代码，`pub` 控制可见性，`use` 把路径引入当前作用域。`Cargo.toml` 声明依赖和版本，`Cargo.lock` 固定可复现的依赖解析结果。

### 所有权、借用与生命周期

Rust 用所有权在编译期管理内存：每个值有唯一所有者，所有者离开作用域时值被释放；赋值或传参会移动所有权，除非类型实现了 Copy。借用分为共享借用 `&T` 和可变借用 `&mut T`，同一时间要么多个共享借用，要么一个可变借用，不能同时存在。生命周期标注描述引用之间的关系，不是延长引用存活时间；大多数简单函数可以由编译器自动推导。

### 可变性、模式匹配与控制流

`let` 默认不可变，需要修改时加 `mut`。`if`、`match`、`while let` 和 `for` 都是表达式或控制结构，`match` 必须覆盖所有可能分支。`Option<T>` 表示可能有值，`Result<T,E>` 表示成功或失败，二者迫使调用方显式处理缺失和错误。`?` 运算符把错误向上传播，适合库函数；二进制入口可以决定是否记录并退出。

### 结构体、枚举与 trait

结构体组合数据，枚举表达互斥状态，trait 定义共享行为。泛型让函数和类型适用于多种具体类型，trait bound 约束泛型能力；单态化会在编译期为具体类型生成代码，因此运行时不牺牲性能但会增加二进制体积。迭代器是惰性的，`map`、`filter`、`collect` 等适配器可以组合成清晰的数据流水线，也要注意分配和借用限制。

### 并发与不安全代码

Rust 的类型系统能在编译期阻止数据竞争：`Send` 表示类型可以跨线程转移，`Sync` 表示可以安全共享引用。`Arc<Mutex<T>>` 是共享可变状态的常见组合，`Rc<RefCell<T>>` 只适合单线程。`unsafe` 不会关闭借用检查，而是把某些安全证明责任交给开发者；使用前必须写清前置条件、后置条件和失败后果。

### 一句话说清它是什么

Rust 用 cargo 管理项目：cargo new 建工程、cargo run 编译并运行、cargo build 只编译；程序入口是 fn main。

### 用生活比喻理解

把 cargo 想成装修队：你只说要建什么，它负责买材料（依赖）、施工（编译）和交钥匙（运行）。你不用手动搬每一块砖。

### 完整可运行代码

```rust
fn main() {
    println!("你好，Rust");
}
```

### 逐行拆开看

- `fn main()` 定义程序入口，fn 是 function 的缩写，函数体用花括号包围。
- `println!` 末尾的叹号表示这是一个宏，不是普通函数；它负责把格式化内容打印到标准输出。
- 字符串字面量用双引号，Rust 的字符串是 UTF-8 编码，中文可以直接写。
- Rust 语句以分号结尾，但表达式块的值可以省略分号作为返回值。
- 用 cargo new 生成的项目里有 src/main.rs 和 Cargo.toml，后者记录项目名和依赖。

### 把程序跑一遍

- 执行 `cargo new hello` 创建项目目录。
- 进入目录执行 `cargo run`，cargo 先编译再运行。
- 程序进入 main，执行 println 宏，屏幕输出「你好，Rust」。
- 编译产物放在 target/debug 下，正式发布用 `cargo build --release`。

### 新手最容易踩的坑

- 把 `println!` 的叹号漏掉：编译器会提示找不到名为 println 的函数。
- 用 rustc 单独编译带依赖的项目：依赖不会自动下载，应该用 cargo。
- 在函数外部写语句：Rust 只允许在函数里执行代码，顶层只能写声明。
- 以为调试构建够快：debug 与 release 的性能差距可能达到数倍。
- 修改 Cargo.toml 后忘记重新编译：旧产物不会自动反映新依赖。

- 修改输出文字，重新执行 cargo run。
- 用 cargo build 编译一次，找到生成的可执行文件路径。
- 在 Cargo.toml 里改项目名，观察编译产物的名字变化。

### 考点 7：`cargo new`

- **要点**：创建新项目，同时生成 Cargo.toml 与 src/main.rs。
- **cargo new 的边界**：只在「创建新项目，同时生成 Cargo.toml 与 src/main.rs」这一前提下成立，换输入或换环境要重新验证。

### 考点 8：`Cargo.toml`

- **要点**：项目清单，记录包名、版本与依赖。
- **Cargo.toml 的边界**：不同版本与依赖组合的行为可能不同，升级或换环境前要按官方变更说明重新验证。

### 考点 9：`fn main`

- **要点**：可执行程序的入口函数。
- **fn main 的边界**：只在「可执行程序的入口函数」这一前提下成立，换输入或换环境要重新验证。

### 考点 10：`cargo check`

- **要点**：只做类型与借用检查、不产出二进制，是最快的反馈手段。
- **cargo check 的边界**：换编码、换字节序或换平台都可能改变结果，处理前先固定输入编码。

### 考点 11：`Cargo`

- **要点**：Cargo 负责创建项目、管理依赖、编译和测试
- **Cargo 的边界**：不同版本与依赖组合的行为可能不同，升级或换环境前要按官方变更说明重新验证。

### 考点 12：`借用`

- **要点**：借用分为共享借用 &T 和可变借用 &mut T，同一时间要么多个共享借用，要么一个可变借用，不能同时存在
- **借用 的边界**：共享状态与调度顺序会改变结论，单线程或串行测试通过不等于并发下成立。

### 考点 13：排错——不区分调试与发布配置

- **现象**：两种配置下行为与性能不同却当成一回事。
- **处理**：明确使用的配置，并记录切换方式。

### 考点 14：排错——依赖不锁版本

- **现象**：构建结果不可复现。
- **处理**：提交锁文件并定期更新依赖。

### 考点 15：综合辨析——`cargo new` 与 `借用`

- **辨析点**：`cargo new` 的定义是 创建新项目，同时生成 Cargo.toml 与 src/main.rs；`借用` 的定义是 借用分为共享借用 &T 和可变借用 &mut T，同一时间要么多个共享借用，要么一个可变借用，不能同时存在。
- **答题要求**：面对 `Rust Cargo 第一个程序` 的题目，先判断描述的是 `cargo new` 还是 `借用`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 16：排错评分点

- **现象分**：能写出 两种配置下行为与性能不同却当成一回事，而不是只写“程序有错”。
- **证据分**：保留触发 不区分调试与发布配置 的输入、版本和错误原文。
- **修复分**：按 明确使用的配置，并记录切换方式 只改一处，并同时回归正常路径与边界路径。
