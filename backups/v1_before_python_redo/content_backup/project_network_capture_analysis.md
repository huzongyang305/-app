### 从概念到验证的学习链条

1. `抓包`：先掌握 在网卡或代理处复制流经的报文并保存，用来还原真实交互而不是只看应用日志，再用它解释 `Wireshark` 为什么会出现。
2. `Wireshark`：先掌握 图形化协议分析器，可按会话与流跟踪报文，配合密钥文件解密 TLS，再用它解释 `TCP` 为什么会出现。
3. `TCP`：先掌握 面向连接的传输层协议，靠握手、序号确认、重传与拥塞控制保证可靠字节流，再用它解释 `DNS` 为什么会出现。
4. `DNS`：先掌握 把域名解析成 IP 的层次化系统，排查时要区分递归解析器、权威服务器与本地缓存，再用它解释 `TLS` 为什么会出现。
5. `TLS`：先掌握 在 TCP 之上提供加密与身份校验的握手协议，抓包里只能看到 SNI、证书与密文长度，再用它解释 `延迟` 为什么会出现。
6. `延迟`：先掌握 一次交互的端到端耗时，要拆成 DNS、连接握手、首字节、传输与渲染各段分别测量，再用它解释 本课示例的观察结果 为什么会出现。

**先修与衔接**：本课是「项目实战」分类的第 6 课。先修内容：《HTTP 基础》、《TCP/IP 协议栈》、《DNS 域名解析》。《HTTP 基础》里的 `状态码`、`Cookie` 是本课的前提。《TCP/IP 协议栈》里的 `tcpdump`、`IP` 是本课的前提。相关或后续课程：《图解一次网页请求的完整链路》、《图解 TCP 握手、挥手与拥塞控制》、《网络性能调优》。

## 原理与运行机制

### 机制总览

**教材衔接：需求与约束**

| 维度 | 约束 |
| --- | --- |
| 功能 | 覆盖 HTTP、HTTPS 与 DNS 三类请求 |
| 性能 | 抓包对目标服务吞吐的影响控制在 5% 以内 |
| 可靠性 | 能定位丢包、重传与连接重置 |
| 安全 | pcap 必须脱敏，不保存 Cookie、Token 与真实用户数据 |

**教材衔接：架构与数据流**

客户端通过本地反向代理访问服务，抓包点部署在代理所在主机；每个阶段记录时间戳与连接四元组，再用请求 ID 把 pcap、代理日志与应用日志关联起来。

```text
client -> tcpdump -> nginx -> app -> database
           |          |        |
        DNS/TLS    retrans   slow query
```

**教材衔接：实施步骤**

### 里程碑 1：搭一套可重复的链路

用容器启动 nginx、一个慢接口与一个正常接口，固定并发、请求次数和客户端机器，保证每次实验的输入一致。

### 里程碑 2：抓包并建立过滤器

抓取 8080 与 443 端口的流量，分别用 http、dns、tcp.flags.reset 和 tcp.analysis_retransmission 过滤，记录每条过滤命令的输出。

### 里程碑 3：按阶段做时间线并复测

把 DNS、握手、TLS、首字节和最后字节的时间戳写进表格，找出占比最大的阶段；只改一个变量后复测同一组请求并对比 P95 与重传次数。

**教材衔接：扩展任务**

- **DNS 的边界**：缓存与状态残留会让结果过期，先明确失效策略再判断正确性。

### 考点 10：`TLS`

- **要点**：在 TCP 之上提供加密与身份校验的握手协议，抓包里只能看到 SNI、证书与密文长度。
- **TLS 的边界**：网络延迟、超时与版本协商会改变行为，只在真实链路或多版本客户端上验证才算数。

### 考点 11：`延迟`

- **要点**：一次交互的端到端耗时，要拆成 DNS、连接握手、首字节、传输与渲染各段分别测量。
- **延迟 的边界**：换编码、换字节序或换平台都可能改变结果，处理前先固定输入编码。

### 考点 12：排错——抓不到任何数据包

- **现象**：抓不到任何数据包。
- **处理**：用 tcpdump -D 列出网卡，改抓 any 或 docker0，并确认端口映射方向。

### 考点 13：排错——HTTPS 只能看到密文

- **现象**：HTTPS 只能看到密文。
- **处理**：测试环境导出 SSLKEYLOGFILE 后让 Wireshark 解密；生产环境优先分析握手与证书链。

### 考点 14：综合辨析——`抓包` 与 `延迟`

- **辨析点**：`抓包` 的定义是 在网卡或代理处复制流经的报文并保存，用来还原真实交互而不是只看应用日志；`延迟` 的定义是 一次交互的端到端耗时，要拆成 DNS、连接握手、首字节、传输与渲染各段分别测量。
- **答题要求**：面对 `网络抓包与协议分析实战` 的题目，先判断描述的是 `抓包` 还是 `延迟`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 15：排错评分点

- **现象分**：能写出 抓不到任何数据包，而不是只写“程序有错”。
- **证据分**：保留触发 抓不到任何数据包 的输入、版本和错误原文。
- **修复分**：按 用 tcpdump -D 列出网卡，改抓 any 或 docker0，并确认端口映射方向 只改一处，并同时回归正常路径与边界路径。
