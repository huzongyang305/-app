### 最小可验证示例

```javascript
console.log("1 sync");
setTimeout(() => console.log("4 macrotask"), 0);
Promise.resolve().then(() => console.log("3 microtask"));
console.log("2 sync");
// 输出顺序：1 sync → 2 sync → 3 microtask → 4 macrotask
```

**教材衔接：事件循环速查**

| 队列 | 例子 | 执行时机 |
| --- | --- | --- |
| 宏任务（task） | `setTimeout`、事件回调、网络回调 | 每轮取一个执行 |
| 微任务（microtask） | Promise 回调、`queueMicrotask`、`MutationObserver` | 每个宏任务之后清空全部 |
| 渲染步骤 | 样式、布局、绘制、合成 | 需要呈现时在宏任务之间执行 |
| 空闲回调 | `requestIdleCallback` | 帧末尾有空闲时 |

关键结论：**微任务会在渲染之前全部执行完**。如果微任务里再产生微任务，会一直占住主线程，导致页面不刷新。

**教材衔接：渲染管线速查**

| 阶段 | 何时发生 | 代价 |
| --- | --- | --- |
| 样式计算 | 选择器匹配、变量变化 | 中 |
| 布局 | 几何属性变化 | 高 |
| 绘制 | 颜色、阴影、背景变化 | 中 |
| 合成 | transform、opacity | 低 |

避免布局抖动的关键：**不要把读操作与写操作交错执行**，否则每写一次都会强制同步布局。

```javascript
// 反例：读-写-读-写 交错，触发多次强制同步布局
function bad(elements) {
  for (const el of elements) {
    el.style.height = `${el.offsetHeight + 10}px`;   // 写后立刻读，强制回流
  }
}

// 正例：先批量读，再批量写
function good(elements) {
  const heights = elements.map((el) => el.offsetHeight);   // 只读
  elements.forEach((el, index) => {
    el.style.height = `${heights[index] + 10}px`;          // 只写
  });
}
```

```javascript
// 长任务拆片：把大批量处理切到多帧，保证输入响应（改善 INP）
async function processInIdle(items, handler) {
  const CHUNK = 200;
  for (let index = 0; index < items.length; index += CHUNK) {
    const slice = items.slice(index, index + CHUNK);
    slice.forEach(handler);
    // 让出主线程：下一轮事件循环继续
    await new Promise((resolve) => setTimeout(resolve, 0));
  }
}

// 用 PerformanceObserver 观察长任务
if ("PerformanceObserver" in window) {
  new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      if (entry.duration > 50) {
        console.warn("长任务", Math.round(entry.duration), "ms");
      }
    }
  }).observe({ entryTypes: ["longtask"] });
}
```

## 时间/空间复杂度或性能分析

```text
把元素提升为独立合成层的常见方式
  · transform: translateZ(0) 或 will-change: transform
  · position: fixed、video、canvas 天然可能独立成层

好处：动画由 GPU 合成，主线程只更新少量属性
代价：每个层都要显存，层过多会拖慢合成与内存

结论：will-change 只在动画开始前短时间加上，结束后移除
```

### 考点 7：`事件循环`

- **要点**：运行时从任务队列取出回调并执行的调度循环，负责协调同步栈与异步任务。
- **事件循环 的边界**：越界、悬垂引用与释放顺序会破坏结论，必须在边界输入下复验。

### 考点 8：`微任务`

- **要点**：关键结论：微任务会在渲染之前全部执行完。
- **微任务 的边界**：易错：顺序与预期不符；正确做法是宏任务要等当前任务与微任务清空。

### 考点 9：`强制同步布局`

- **要点**：读写布局属性交替执行时浏览器被迫立即重排，是页面卡顿的常见原因。
- **强制同步布局 的边界**：易错：强制同步布局，掉帧严重；正确做法是先批量读、再批量写。

### 考点 10：`渲染管线`

- **要点**：样式计算、布局、绘制、合成四步；改几何属性要走完整流程，改 transform 与 opacity 可以只做合成。
- **渲染管线 的边界**：只在「样式计算、布局、绘制、合成四步；改几何属性要走完整流程，改 transform 与 opacity 可以只做合成」这一前提下成立，换输入或换环境要重新验证。

### 考点 11：排错——认为 `setTimeout(0)` 立即执行

- **现象**：顺序与预期不符。
- **处理**：宏任务要等当前任务与微任务清空。

### 考点 12：排错——在微任务里递归排队

- **现象**：页面完全卡死。
- **处理**：改用宏任务或拆片让出线程。

### 考点 13：综合辨析——`事件循环` 与 `渲染管线`

- **辨析点**：`事件循环` 的定义是 运行时从任务队列取出回调并执行的调度循环，负责协调同步栈与异步任务；`渲染管线` 的定义是 样式计算、布局、绘制、合成四步；改几何属性要走完整流程，改 transform 与 opacity 可以只做合成。
- **答题要求**：面对 `浏览器渲染与事件循环深入` 的题目，先判断描述的是 `事件循环` 还是 `渲染管线`，再归到对应定义，最后写出一个会让该定义失效的边界输入。

### 考点 14：排错评分点

- **现象分**：能写出 顺序与预期不符，而不是只写“程序有错”。
- **证据分**：保留触发 认为 `setTimeout(0)` 立即执行 的输入、版本和错误原文。
- **修复分**：按 宏任务要等当前任务与微任务清空 只改一处，并同时回归正常路径与边界路径。
